## Core Web Vitals 2025-2026 기준

### 목표 지표

| 지표 | Good | Needs Improvement | Poor |
|------|------|-------------------|------|
| **LCP** (Largest Contentful Paint) | ≤ 2.5초 | 2.5-4.0초 | > 4.0초 |
| **INP** (Interaction to Next Paint) | ≤ 200ms | 200-500ms | > 500ms |
| **CLS** (Cumulative Layout Shift) | ≤ 0.1 | 0.1-0.25 | > 0.25 |
| **FCP** (First Contentful Paint) | ≤ 1.8초 | 1.8-3.0초 | > 3.0초 |
| **TTFB** (Time to First Byte) | ≤ 800ms | 800-1800ms | > 1800ms |

> **참고**: 2024년 3월부터 FID(First Input Delay)는 공식적으로 **INP(Interaction to Next Paint)**로 완전 대체되었습니다. INP는 페이지 전체 수명 주기 동안 발생하는 모든 상호작용의 지연을 측정하며, FID가 첫 번째 입력만 측정한 것과 달리 전체적인 응답성을 더 정확히 반영합니다.

### INP 최적화 전략

INP를 개선하기 위한 핵심 전략:

```typescript
// 1. 긴 태스크를 분할하여 메인 스레드 양보
function processLargeList(items: Item[]) {
  const CHUNK_SIZE = 50;

  async function processChunk(startIndex: number) {
    const end = Math.min(startIndex + CHUNK_SIZE, items.length);
    for (let i = startIndex; i < end; i++) {
      processItem(items[i]);
    }
    if (end < items.length) {
      // scheduler.yield()로 메인 스레드 양보 (Chrome 129+)
      if ('scheduler' in globalThis && 'yield' in scheduler) {
        await scheduler.yield();
      } else {
        await new Promise(resolve => setTimeout(resolve, 0));
      }
      await processChunk(end);
    }
  }

  return processChunk(0);
}

// 2. 이벤트 핸들러에서 비시각적 작업 분리
function handleClick(e: React.MouseEvent) {
  // 시각적 피드백은 즉시 처리
  setIsActive(true);

  // 비시각적 작업은 requestIdleCallback으로 지연
  requestIdleCallback(() => {
    sendAnalyticsEvent('button_clicked');
    updateExternalState();
  });
}
```

> **팁**: Chrome DevTools의 Performance 탭에서 "Total Blocking Time" 및 "Long Tasks"를 확인하여 INP 병목을 진단하세요.

### 2. Lazy Loading

**Intersection Observer 활용**

```typescript
import { useEffect, useRef, useState } from 'react';

function useLazyImage(src: string) {
  const [imageSrc, setImageSrc] = useState<string | null>(null);
  const imgRef = useRef<HTMLImageElement>(null);

  useEffect(() => {
    const observer = new IntersectionObserver(
      ([entry]) => {
        if (entry.isIntersecting) {
          setImageSrc(src);
          observer.disconnect();
        }
      },
      { rootMargin: '100px' } // 뷰포트 100px 전에 로딩 시작
    );

    if (imgRef.current) {
      observer.observe(imgRef.current);
    }

    return () => observer.disconnect();
  }, [src]);

  return { imgRef, imageSrc };
}

// 사용
function LazyImage({ src, alt }: { src: string; alt: string }) {
  const { imgRef, imageSrc } = useLazyImage(src);

  return (
    <img
      ref={imgRef}
      src={imageSrc || 'data:image/gif;base64,R0lGODlhAQABAIAAAAAAAP///yH5BAEAAAAALAAAAAABAAEAAAIBRAA7'}
      alt={alt}
      loading="lazy"
    />
  );
}
```

```typescript
import { useVirtualizer } from '@tanstack/react-virtual';
import { useRef } from 'react';

function VirtualList({ items }: { items: string[] }) {
  const parentRef = useRef<HTMLDivElement>(null);

  const virtualizer = useVirtualizer({
    count: items.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 50, // 예상 아이템 높이
    overscan: 5, // 뷰포트 밖에 미리 렌더링할 아이템 수

  return (
    <div ref={parentRef} style={{ height: '600px', overflow: 'auto' }}>
      <div
        style={{
          height: `${virtualizer.getTotalSize()}px`,
          position: 'relative',
        }}
      >
        {virtualizer.getVirtualItems().map((virtualItem) => (
          <div
            key={virtualItem.key}
            style={{
              position: 'absolute',
              top: 0,
              left: 0,
              width: '100%',
              height: `${virtualItem.size}px`,
              transform: `translateY(${virtualItem.start}px)`,
            }}
          >
            {items[virtualItem.index]}
          </div>
        ))}
      </div>
    </div>
  );
}
```

## React Server Components 성능 전략

React Server Components(RSC)는 서버에서 렌더링되어 클라이언트 JavaScript 번들에 포함되지 않으므로, 올바르게 활용하면 번들 크기를 대폭 줄이고 초기 로딩 성능을 크게 개선할 수 있습니다.

### 1. 서버/클라이언트 경계 설계 원칙

```
Page (Server)              ← 데이터 fetching, 레이아웃
├── Header (Server)        ← 정적 콘텐츠
│   └── SearchBar (Client) ← 사용자 입력 필요
├── ProductList (Server)   ← DB 직접 조회
│   └── AddToCart (Client) ← onClick 핸들러 필요
└── Footer (Server)        ← 정적 콘텐츠
```

**핵심 원칙**: `'use client'` 경계를 가능한 한 트리의 아래쪽(leaf)에 배치하여 클라이언트 번들을 최소화합니다.

```typescript
// ❌ Bad: 페이지 전체를 클라이언트 컴포넌트로 만듦
'use client';
export default function ProductPage() {
  const [qty, setQty] = useState(1);
  const products = useQuery(['products'], fetchProducts); // 클라이언트에서 fetch
  return <div>...</div>;
}

// ✅ Good: 서버 컴포넌트에서 데이터를 가져오고, 상호작용 부분만 클라이언트로 분리

        <ProductItem key={p.id} product={p}>
          <AddToCartButton productId={p.id} /> {/* 클라이언트 경계 */}

  );
}
```

### 1. HTTP/2 & HTTP/3

**Vite 개발 서버 HTTP/2 활성화**

**특징**:
- 멀티플렉싱: 하나의 연결로 여러 리소스 동시 전송
- 헤더 압축: HPACK 알고리즘
- Server Push: (HTTP/2만)

### 2. 리소스 힌트

```html
<!-- Preconnect: DNS + TCP + TLS 사전 연결 -->
<link rel="preconnect" href="https://cdn.example.com" />

<!-- DNS Prefetch: DNS만 미리 조회 -->
<link rel="dns-prefetch" href="https://analytics.example.com" />

<!-- Preload: 중요 리소스 우선 로드 -->
<link rel="preload" href="/fonts/inter.woff2" as="font" type="font/woff2" crossorigin />
<link rel="preload" href="/hero-image.webp" as="image" />

<!-- Prefetch: 다음 페이지 리소스 미리 로드 (낮은 우선순위) -->
<link rel="prefetch" href="/next-page-bundle.js" />
```

**vite.config.ts**
```typescript
import { VitePWA } from 'vite-plugin-pwa';

export default defineConfig({
  plugins: [
    VitePWA({
      registerType: 'autoUpdate',
      workbox: {
        globPatterns: ['**/*.{js,css,html,ico,png,svg,webp}'],
        runtimeCaching: [
          {
            urlPattern: /^https:\/\/api\.example\.com\/.*/i,
            handler: 'NetworkFirst',
            options: {
              cacheName: 'api-cache',
              expiration: {
                maxEntries: 100,
                maxAgeSeconds: 60 * 60 * 24, // 24시간

              cacheableResponse: {
                statuses: [0, 200],
              },
            },
          },
          {
            urlPattern: /^https:\/\/cdn\.example\.com\/.*/i,
            handler: 'CacheFirst',
            options: {
              cacheName: 'image-cache',
              expiration: {
                maxEntries: 200,
                maxAgeSeconds: 60 * 60 * 24 * 30, // 30일
              },
            },
          },
        ],
      },
    }),
  ],
});
```

## 캐싱 전략

### 1. 브라우저 캐싱

**Cache-Control 헤더 설정**

```nginx
# Nginx 설정
location ~* \.(jpg|jpeg|png|webp|avif|svg|ico)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}

location ~* \.(css|js)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}

location ~* \.html$ {
    expires -1;
    add_header Cache-Control "public, max-age=0, must-revalidate";
}
```

**Vite 빌드 시 Hash 파일명**
```typescript
export default defineConfig({
  build: {
    rollupOptions: {
      output: {
        entryFileNames: 'assets/[name]-[hash].js',
        chunkFileNames: 'assets/[name]-[hash].js',
        assetFileNames: 'assets/[name]-[hash][extname]',
      },
    },
  },
});
```

### 2. React Query 캐싱

```typescript
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 1000 * 60 * 5, // 5분간 fresh
      gcTime: 1000 * 60 * 30, // 30분간 캐시 유지 (v5에서 cacheTime -> gcTime으로 변경)
      refetchOnWindowFocus: false,
      retry: 1,
    },
  },
});

function App() {
  return (
    <QueryClientProvider client={queryClient}>
      <YourApp />
    </QueryClientProvider>
  );
}
```
