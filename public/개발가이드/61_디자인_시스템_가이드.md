> **"디자인 시스템은 컴포넌트 모음이 아니라, 팀의 일관된 언어이자 효율적인 협업 도구다."**
> 본 가이드는 Tailwind CSS v4와 최신 Headless UI 라이브러리를 활용하여 견고하고 확장 가능한 디자인 시스템을 구축하는 방법을 다룹니다.

## 1. 스타일링 기초: Tailwind CSS v4

Tailwind v4는 더 이상 별도의 설정 파일(`tailwind.config.js`)을 요구하지 않으며, CSS 내에서 직접 테마를 정의하는 CSS-first 방식을 따릅니다.

### 1.1 테마 정의 (Theming)
```css
/* app.css */
@import "tailwindcss";

@theme {
  --color-primary: #007bff;
  --color-secondary: #6c757d;
  --font-sans: "Pretendard", sans-serif;
  --spacing-unit: 0.25rem;
}
```

### 1.2 디자인 토큰 관리
토큰은 코드뿐만 아니라 피그마(Figma) 등 디자인 도구와 동기화되어야 합니다.

*   **Semantic Colors**: `red-500`이 아닌 `color-error`와 같이 의미 중심의 이름을 사용하세요.
*   **Spacing System**: 4px(0.25rem) 그리드 시스템을 표준으로 채택합니다.

---

## 2. 컴포넌트 설계: Headless UI 전략

직접 모든 로직(접근성, 키보드 인터랙션 등)을 구현하기보다, 검증된 **Headless UI** 라이브러리를 기반으로 스타일을 입히는 것을 권장합니다.

*   **Radix UI / React Aria**: 가장 성숙한 라이브러리로, 접근성 표준(WCAG)을 자동으로 준수합니다.
*   **CVA (Class Variance Authority)**: 컴포넌트의 다양한 변형(Variant)을 타입 안전하게 관리합니다.

```tsx
// components/Button.tsx
import { cva, type VariantProps } from "class-variance-authority";

const buttonVariants = cva(
  "inline-flex items-center justify-center rounded-md text-sm font-medium transition-colors",
  {
    variants: {
      variant: {
        primary: "bg-primary text-white hover:bg-primary/90",
        outline: "border border-input bg-background hover:bg-accent",
      },
      size: {
        sm: "h-9 px-3",
        md: "h-10 px-4 py-2",
        lg: "h-11 px-8",
      },
    },
    defaultVariants: {
      variant: "primary",
      size: "md",
    },
  }
);
```

## 3. 문서화 및 검증: Storybook

컴포넌트의 독립적인 개발과 테스트를 위해 Storybook을 사용합니다.

*   **Interaction Testing**: Storybook 내부에서 Playwright 기반의 인터랙션 테스트를 수행합니다.
*   **Visual Snapshot**: Chromatic 등을 활용하여 UI의 의도치 않은 변경을 감지합니다.
