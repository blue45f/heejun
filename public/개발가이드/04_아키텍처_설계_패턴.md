## 1. Feature-Sliced Design (FSD) 표준

FSD는 프로젝트를 6개의 계층(Layers)으로 나누어 의존성을 단방향으로 흐르게 하는 아키텍처입니다.

### 1.1 계층 구조 (Top-Down)
1.  **app**: 전역 설정, 라우터, 전역 스타일 (최상위)
2.  **pages**: 실제 서비스의 페이지 단위 컴포넌트
3.  **widgets**: 여러 features가 조합된 복합 컴포넌트
4.  **features**: 비즈니스 가치를 가진 기능 단위 (예: `UpdateSelectionModel`, `Login`)
5.  **entities**: 도메인 데이터 구조 및 비즈니스 로직 (예: `Entity`, `User`)
6.  **shared**: 재사용 가능한 공통 컴포넌트 및 유틸리티 (최하위)

*   **핵심 규칙**: 상위 계층은 하위 계층을 참조할 수 있지만, 그 역은 절대 불가합니다. 동일 계층 내에서도 슬라이스 간 참조는 금지됩니다.

## 2. React 19 Server Components (RSC) 배치

React 19 시대의 아키텍처는 클라이언트와 서버의 배치가 중요합니다.

*   **RSC (Server Components)**: 주로 **pages**와 **widgets** 계층에서 데이터를 페칭하는 '지능형 컨테이너'로 활용합니다.
*   **RCC (Client Components)**: **features**나 **shared** 계층에서 인터랙션(버튼, 입력 등)이 필요한 말단 컴포넌트로 구현합니다.
*   **데이터 흐름**: 서버에서 데이터를 가져와 Props로 클라이언트 컴포넌트에 주입하는 단방향 흐름을 유지하세요.

## 3. 의존성 역전 (DIP)과 어댑터 패턴

API 통신이나 외부 라이브러리 의존성은 **entities**나 **shared**에 직접 구현하지 않고 인터페이스를 통해 분리합니다.

```typescript
// domain/repository.ts (인터페이스)
export interface UserRepository {
  getUser(id: string): Promise<User>;
}

// infrastructure/api-user-repository.ts (구현체)
export class ApiUserRepository implements UserRepository {
  async getUser(id: string) {
    return fetch(`/api/user/${id}`).then(res => res.json());
  }
}

// application/use-user.ts (사용부)
// 실제 구현체가 아닌 인터페이스에 의존하여 테스트가 쉬워집니다.
function useUser(repo: UserRepository, id: string) {
  return use(repo.getUser(id));
}
```

## 4. 모듈 경계 검증 (Module Boundary)

아키텍처 규칙이 지켜지는지 자동으로 검사해야 합니다. `eslint-plugin-boundaries`를 사용하여 계층 위반을 방지합니다.

```json
// .eslintrc.json 예시
"rules": {
  "boundaries/element-types": [2, {
    "default": "disallow",
    "rules": [
      { "from": "features", "allow": ["entities", "shared"] },
      { "from": "widgets", "allow": ["features", "entities", "shared"] },
      { "from": "pages", "allow": ["widgets", "features", "entities", "shared"] }
    ]
  }]
}
```
