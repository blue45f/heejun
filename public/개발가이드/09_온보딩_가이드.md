## 온보딩 철학과 원칙

온보딩의 본질은 신규 멤버가 **최단 시간 안에 독립적으로 가치를 창출**할 수 있도록 돕는 것이다. 2026년 기준, AI 도구의 성숙으로 기존 온보딩 방식은 근본적 재설계가 필요하다.

### 핵심 원칙

| 원칙 | 설명 |
|------|------|
| **AI First** | 반복 질문, 코드 분석, 환경 셋업 등 자동화 가능한 모든 영역에 AI를 적용한다 |
| **자동화 우선** | 사람이 개입하는 셋업 단계를 0으로 만든다 |
| **비동기 기본** | 원격/하이브리드 환경을 전제로 모든 프로세스를 설계한다 |
| **측정 가능** | 온보딩 품질을 정량 지표로 추적하고 매 분기 개선한다 |
| **문서 = 코드** | 문서화되지 않은 지식은 존재하지 않는 지식이다 |

## AI 기반 온보딩 혁신

### Claude Code를 활용한 코드베이스 자동 분석

신규 멤버가 코드베이스를 파악하는 데 기존에는 2~3주가 걸렸다. Claude Code를 활용하면 이를 2~3일로 단축할 수 있다.

#### 프롬프트 예시 1: 아키텍처 전체 파악

```bash
claude "이 프로젝트의 전체 아키텍처를 분석해줘.
       1) 디렉토리 구조와 각 디렉토리의 역할
       2) 핵심 모듈 간 의존 관계를 mermaid 다이어그램으로
       3) 데이터 흐름 (사용자 액션 → API 호출 → 상태 업데이트 → UI 렌더링)
       4) 사용 중인 디자인 패턴과 그 이유"
```

#### 프롬프트 예시 2: 특정 도메인 비즈니스 로직 분석

```bash
claude "src/features/payment 디렉토리를 심층 분석해줘.
       1) 결제 플로우를 사용자 관점에서 단계별로 설명
       2) 에러 처리 전략 (네트워크 오류, 결제 실패, 타임아웃)
       3) 재시도 로직과 멱등성 보장 방법
       4) 이 코드를 수정할 때 주의해야 할 점"
```

#### 프롬프트 예시 3: 코딩 컨벤션 및 패턴 추출

```bash
claude "이 프로젝트의 코딩 컨벤션을 분석해서 신규 멤버용 가이드를 만들어줘.
       1) 네이밍 규칙 (변수, 함수, 컴포넌트, 파일)
       2) 폴더 구조 패턴 (새 feature를 추가할 때의 보일러플레이트)
       3) 상태 관리 패턴 (어떤 상태를 어디에 두는지)
       4) 테스트 작성 패턴 (테스트 파일 위치, 네이밍, 구조)
       실제 코드에서 예시를 뽑아서 보여줘."
```

### CLAUDE.md / .cursorrules로 프로젝트 컨텍스트 자동 제공

AI 도구가 프로젝트를 즉시 이해할 수 있도록 컨텍스트 파일을 유지 관리한다. 이 파일들은 신규 멤버에게도 프로젝트 개요 역할을 한다.

```markdown
<!-- CLAUDE.md (프로젝트 루트) -->
# 프로젝트 컨텍스트

## 기술 스택
- React 19 + TypeScript 5.8
- 상태 관리: Zustand v5 (클라이언트), TanStack Query v6 (서버)
- 스타일링: Tailwind CSS v4 + CSS Modules
- 테스트: Vitest (유닛) + Playwright (E2E)
- 빌드: Vite 6
- 패키지 매니저: pnpm 10

## 아키텍처
- Feature-Sliced Design (src/features/, src/shared/, src/app/)
- 각 feature는 독립 모듈: api/, model/, ui/, lib/ 하위 구조
- 라우팅: TanStack Router (파일 기반)

## 핵심 컨벤션
- 컴포넌트: PascalCase, named export만 사용
- 훅: use 접두사, 하나의 관심사만 담당
- API: queryOptions 팩토리 패턴으로 정의
- 타입: interface 우선, 유틸리티 타입 적극 활용
- 커밋: Conventional Commits (feat/fix/chore/docs/refactor)

## 자주 묻는 질문
- 새 페이지 추가: src/features/{도메인}/ui/pages/ 에 생성, 라우트 파일 자동 생성
- 새 API 연동: src/features/{도메인}/api/ 에 queryOptions 정의
- 환경변수: .env.local에 VITE_ 접두사로 추가
```

```plaintext
# .cursorrules (Cursor IDE용)
You are a senior frontend developer working on this project.
Follow the conventions defined in CLAUDE.md.
Always use named exports, never default exports.
Prefer composition over inheritance.
Write Vitest tests for all new functions.
Use TanStack Query for all server state management.
Follow Feature-Sliced Design architecture strictly.
```

### AI 멘토링 봇 구축 (Slack + Claude API)

Slack 채널에 AI 멘토링 봇을 연동하여 신규 멤버의 질문에 24시간 즉시 응답한다. 사람 멘토의 부담을 줄이면서도 응답 속도를 극대화한다.

```typescript
// ai-mentor-bot/src/bot.ts
import Anthropic from "@anthropic-ai/sdk";
import { App as SlackApp } from "@slack/bolt";
import { readFileSync } from "node:fs";
import { join } from "node:path";

// ── 타입 정의 ──────────────────────────────────────────────
interface ProjectContext {
  claudeMd: string;
  faq: FAQEntry[];
  recentADRs: string[];
}

interface FAQEntry {
  question: string;
  answer: string;
  category: "env" | "architecture" | "process" | "culture";
}

interface MentorBotConfig {
  slackBotToken: string;
  slackAppToken: string;
  anthropicApiKey: string;
  projectRoot: string;
}

// ── 컨텍스트 로더 ──────────────────────────────────────────
function loadProjectContext(projectRoot: string): ProjectContext {
  const claudeMd = readFileSync(
    join(projectRoot, "CLAUDE.md"),
    "utf-8"
  );

  const faqPath = join(projectRoot, "docs/onboarding-faq.json");
  const faq: FAQEntry[] = JSON.parse(readFileSync(faqPath, "utf-8"));

  return { claudeMd, faq, recentADRs: [] };
}

// ── 시스템 프롬프트 생성 ───────────────────────────────────
function buildSystemPrompt(context: ProjectContext): string {
  const faqText = context.faq
    .map((f) => `Q: ${f.question}\nA: ${f.answer}`)
    .join("\n\n");

  return `당신은 개발팀의 AI 온보딩 멘토입니다.

프로젝트 정보:
${context.claudeMd}

자주 묻는 질문:
${faqText}

응답 규칙:
1. 정확한 파일 경로와 코드 예시를 포함하여 답변하세요.
2. 답변의 근거가 되는 문서 링크를 항상 첨부하세요.
3. 확실하지 않은 내용은 "이 부분은 @멘토에게 확인해주세요"라고 안내하세요.
4. 보안에 민감한 정보(시크릿, 토큰, 비밀번호)는 절대 포함하지 마세요.
5. 한국어로 답변하세요.`;
}

// ── 봇 초기화 ──────────────────────────────────────────────
function createMentorBot(config: MentorBotConfig) {
  const anthropic = new Anthropic({ apiKey: config.anthropicApiKey });
  const context = loadProjectContext(config.projectRoot);
  const systemPrompt = buildSystemPrompt(context);

  const slack = new SlackApp({
    token: config.slackBotToken,
    appToken: config.slackAppToken,
    socketMode: true,
  });

  // 멘션 또는 DM으로 질문을 받으면 응답
  slack.event("app_mention", async ({ event, say }) => {
    const question = event.text.replace(/<@[A-Z0-9]+>/g, "").trim();

    const response = await anthropic.messages.create({
      model: "claude-sonnet-4-20250514",
      max_tokens: 2048,
      system: systemPrompt,
      messages: [{ role: "user", content: question }],
    });

    const answer =
      response.content[0].type === "text"
        ? response.content[0].text
        : "응답을 생성할 수 없습니다.";

    await say({
      text: answer,
      thread_ts: event.ts, // 스레드로 응답
    });
  });

  // #onboarding 채널의 모든 질문에 자동 응답
  slack.message(/\?$/, async ({ message, say }) => {
    if (message.subtype || !("text" in message)) return;

    const response = await anthropic.messages.create({
      model: "claude-sonnet-4-20250514",
      max_tokens: 1024,
      system: systemPrompt,
      messages: [{ role: "user", content: message.text ?? "" }],
    });

    const answer =
      response.content[0].type === "text"
        ? response.content[0].text
        : "";

    if (answer) {
      await say({ text: answer, thread_ts: message.ts });
    }
  });

  return slack;
}

// ── 실행 ───────────────────────────────────────────────────
const bot = createMentorBot({
  slackBotToken: process.env.SLACK_BOT_TOKEN!,
  slackAppToken: process.env.SLACK_APP_TOKEN!,
  anthropicApiKey: process.env.ANTHROPIC_API_KEY!,
  projectRoot: process.env.PROJECT_ROOT ?? ".",
});

bot.start().then(() => console.log("AI Mentor Bot is running"));
```

### GitHub Actions 자동 온보딩 파이프라인

새 멤버가 GitHub Organization에 추가되면 계정 생성부터 환경 셋업까지 전 과정을 자동화한다.

```yaml
# .github/workflows/onboarding-pipeline.yml
name: Automated Onboarding Pipeline

on:
  organization:
    types: [member_added]

permissions:
  issues: write
  contents: read
  members: read

jobs:
  # ── Step 1: 온보딩 이슈 생성 & 리포 접근 권한 ──────────
  create-onboarding-issue:
    runs-on: ubuntu-latest
    outputs:
      issue_number: ${{ steps.create_issue.outputs.result }}
      member: ${{ steps.get_member.outputs.login }}
    steps:
      - name: Get new member info
        id: get_member
        run: echo "login=${{ github.event.membership.user.login }}" >> "$GITHUB_OUTPUT"

      - name: Grant repository access
        uses: actions/github-script@v7
        with:
          script: |
            const member = '${{ steps.get_member.outputs.login }}';
            const repos = ['frontend', 'design-system', 'shared-configs'];
            for (const repo of repos) {
              await github.rest.repos.addCollaborator({
                owner: context.repo.owner,
                repo,
                username: member,
                permission: 'push'
              });
            }

      - name: Create onboarding issue with full checklist
        id: create_issue
        uses: actions/github-script@v7
        with:
          script: |
            const member = '${{ steps.get_member.outputs.login }}';
            const today = new Date().toISOString().split('T')[0];

            const issue = await github.rest.issues.create({
              owner: context.repo.owner,
              repo: 'onboarding',
              title: `[온보딩] ${member}님 환영합니다! (${today})`,
              body: `## 온보딩 시작일: ${today}

            ### Week 1: 환경 구축 & 팀 이해
            - [ ] devcontainer로 개발 환경 구축 완료
            - [ ] AI 도구 셋업 (Claude Code, Cursor)
            - [ ] Claude Code로 코드베이스 전체 분석 실행
            - [ ] 버디/멘토 매칭 확인
            - [ ] 팀 채널 합류 (#dev, #onboarding, #random)
            - [ ] good-first-issue 선정

            ### Week 2: 첫 기여
            - [ ] 첫 번째 PR 제출 및 머지
            - [ ] 코드 리뷰 참여 3건
            - [ ] 페어 프로그래밍 1회
            - [ ] 비동기 스탠드업 작성 시작

            ### Week 3: 도메인 심화
            - [ ] 담당 도메인 코드 분석 완료
            - [ ] 중간 규모 태스크 1건 완료
            - [ ] ADR 문서 학습
            - [ ] 장애 대응 프로세스 숙지

            ### Week 4: 자율 기여
            - [ ] 독립 태스크 수행
            - [ ] 온보딩 피드백 문서 작성
            - [ ] 30일 리뷰 미팅 완료

            ---
            **버디:** (매니저가 배정)
            **멘토:** (매니저가 배정)
            `,
              assignees: [member],
              labels: ['onboarding', 'auto-generated']
            });

            return issue.data.number;

  # ── Step 2: Slack 알림 & 웰컴 메시지 ───────────────────
  notify-team:
    needs: create-onboarding-issue
    runs-on: ubuntu-latest
    steps:
      - name: Send Slack welcome message
        uses: slackapi/slack-github-action@v2
        with:
          webhook: ${{ secrets.SLACK_ONBOARDING_WEBHOOK }}
          payload: |
            {
              "blocks": [
                {
                  "type": "header",
                  "text": {
                    "type": "plain_text",
                    "text": "새로운 팀원이 합류했습니다!"
                  }
                },
                {
                  "type": "section",
                  "text": {
                    "type": "mrkdwn",
                    "text": "*${{ needs.create-onboarding-issue.outputs.member }}* 님을 환영합니다!\n온보딩 이슈: #${{ needs.create-onboarding-issue.outputs.issue_number }}"
                  }
                }
              ]
            }

  # ── Step 3: 클라우드 개발 환경 프로비저닝 ───────────────
  provision-codespace:
    needs: create-onboarding-issue
    runs-on: ubuntu-latest
    steps:
      - name: Create Codespace for new member
        uses: actions/github-script@v7
        with:
          script: |
            const member = '${{ needs.create-onboarding-issue.outputs.member }}';
            console.log(`Codespace provisioning triggered for ${member}`);
            // Codespace API 호출 또는 내부 프로비저닝 시스템 트리거
```

### AI 기반 코드 리뷰 가이드 (신규 멤버 PR 자동 리뷰)

신규 멤버의 PR에 AI가 친절하고 교육적인 리뷰를 자동으로 달아준다. 사람 리뷰어의 부담을 줄이고, 신규 멤버는 빠른 피드백을 받는다.

```yaml
# .github/workflows/ai-review-for-newbies.yml
name: AI Code Review for New Members

on:
  pull_request:
    types: [opened, synchronize]

jobs:
  ai-review:
    runs-on: ubuntu-latest
    # 온보딩 라벨이 붙은 멤버의 PR에만 동작
    if: contains(github.event.pull_request.labels.*.name, 'onboarding-member')
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Get PR diff
        id: diff
        run: |
          DIFF=$(git diff origin/${{ github.event.pull_request.base.ref }}...HEAD)
          echo "diff<<DIFF_EOF" >> "$GITHUB_OUTPUT"
          echo "$DIFF" >> "$GITHUB_OUTPUT"
          echo "DIFF_EOF" >> "$GITHUB_OUTPUT"

      - name: AI Review
        uses: actions/github-script@v7
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        with:
          script: |
            const Anthropic = require('@anthropic-ai/sdk');
            const client = new Anthropic.default();

            const diff = `${{ steps.diff.outputs.diff }}`;
            const prTitle = context.payload.pull_request.title;
            const prBody = context.payload.pull_request.body || '';

            const response = await client.messages.create({
              model: 'claude-sonnet-4-20250514',
              max_tokens: 4096,
              system: `당신은 친절한 시니어 개발자이자 코드 리뷰어입니다.
            신규 팀원의 PR을 리뷰합니다. 다음 원칙을 따르세요:
            1. 칭찬부터 시작하세요. 잘한 점을 먼저 언급합니다.
            2. 개선점은 "~하면 어떨까요?" 형태로 제안합니다.
            3. 왜 그렇게 하는지 이유를 설명합니다 (단순히 "이렇게 해라"가 아닌).
            4. 관련 문서나 패턴의 링크를 첨부합니다.
            5. 심각한 버그나 보안 이슈는 명확히 지적합니다.
            6. 한국어로 리뷰합니다.`,
              messages: [{
                role: 'user',
                content: `PR 제목: ${prTitle}\nPR 설명: ${prBody}\n\nDiff:\n${diff}`
              }]
            });

            const review = response.content[0].text;

            await github.rest.pulls.createReview({
              owner: context.repo.owner,
              repo: context.repo.repo,
              pull_number: context.payload.pull_request.number,
              body: `## AI 코드 리뷰\n\n${review}\n\n---\n_이 리뷰는 AI가 자동 생성했습니다. 사람 리뷰어의 리뷰도 함께 진행됩니다._`,
              event: 'COMMENT'
            });
```

## 개발 환경 자동 셋업

신규 멤버의 환경 셋업 소요 시간 목표: **30분 이내**. 아래 4가지 방법 중 팀 상황에 맞게 선택한다.

### devcontainer (권장)

Docker 기반으로 완전히 동일한 개발 환경을 제공한다. VS Code, JetBrains, GitHub Codespaces에서 동작한다.

### mise (다중 런타임 관리)

mise는 Node.js, pnpm, Python 등 프로젝트별 런타임 버전을 선언적으로 관리한다.

```toml
# mise.toml
[tools]
node = "22.14"
pnpm = "10.8"

[env]
NODE_ENV = "development"

[tasks.setup]
description = "프로젝트 초기 셋업 (원커맨드)"
run = """
corepack enable
pnpm install
pnpm exec playwright install --with-deps
cp -n .env.example .env.local 2>/dev/null || true
echo "셋업 완료! pnpm dev로 개발 서버를 시작하세요."
"""

[tasks.dev]
description = "개발 서버 실행"
run = "pnpm dev"

[tasks.check]
description = "린트 + 타입체크 + 테스트 일괄 실행"
run = """
pnpm lint
pnpm typecheck
pnpm test
"""
```

### Nix flake (재현 가능한 환경)

빌드 재현성이 중요한 경우 Nix로 완전히 결정적인 환경을 구성한다.

```nix
# flake.nix
{
  description = "Frontend dev environment";

  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
    flake-utils.url = "github:numtide/flake-utils";
  };

  outputs = { self, nixpkgs, flake-utils }:
    flake-utils.lib.eachDefaultSystem (system:
      let
        pkgs = nixpkgs.legacyPackages.${system};
      in {
        devShells.default = pkgs.mkShell {
          buildInputs = with pkgs; [
            nodejs_22
            corepack_22
            playwright-driver.browsers
            git
            gh
          ];

          shellHook = ''
            export PLAYWRIGHT_BROWSERS_PATH="${pkgs.playwright-driver.browsers}"
            echo "Nix dev environment ready"
            echo "Node $(node -v) | pnpm $(pnpm -v)"
          '';
        };
      }
    );
}
```

### 원커맨드 셋업 스크립트

어떤 환경이든 하나의 명령으로 셋업이 완료되어야 한다.

```bash
#!/usr/bin/env bash
# scripts/setup.sh - 원커맨드 개발 환경 셋업
set -euo pipefail

GREEN='\033[0;32m'
RED='\033[0;31m'
NC='\033[0m'

log() { echo -e "${GREEN}[setup]${NC} $1"; }
err() { echo -e "${RED}[error]${NC} $1"; exit 1; }

log "개발 환경 셋업을 시작합니다"

# 1. 런타임 확인
command -v node &>/dev/null || err "Node.js가 필요합니다. mise install 또는 nvm install 22를 실행하세요."
NODE_MAJOR=$(node -v | cut -d'v' -f2 | cut -d'.' -f1)
[ "$NODE_MAJOR" -ge 22 ] || err "Node.js 22 이상이 필요합니다. 현재: $(node -v)"

# 2. 패키지 설치
log "패키지 설치 중..."
corepack enable
pnpm install --frozen-lockfile

# 3. 환경 변수
if [ ! -f .env.local ]; then
  cp .env.example .env.local
  log ".env.local 생성 완료 (필요한 값을 채워주세요)"
fi

# 4. Git hooks
log "Git hooks 설정 중..."
pnpm exec lefthook install

# 5. E2E 브라우저
log "Playwright 브라우저 설치 중..."
pnpm exec playwright install chromium --with-deps

# 6. 검증
log "타입 체크 실행 중..."
pnpm typecheck

echo ""
log "========================================="
log "  셋업 완료!"
log "  pnpm dev    : 개발 서버 실행"
log "  pnpm test   : 테스트 실행"
log "  pnpm build  : 프로덕션 빌드"
log "========================================="
```

### 비동기 우선 커뮤니케이션

원격 환경에서의 온보딩은 비동기 커뮤니케이션이 기본값이다.

#### 질문할 때

- Slack DM보다 **팀 채널**에 질문한다 (다른 팀원도 학습 가능)
- 질문 전 **시도한 내용**을 함께 공유한다
- 스크린샷, 코드 스니펫, 에러 로그를 첨부한다
- "급한 건 아닙니다"를 명시하여 응답 부담을 경감한다

#### 답변할 때

- **4시간 이내** 응답 원칙 (업무 시간 기준)
- 답변을 모르면 "확인 후 답변드리겠습니다"라도 즉시 회신한다
- 반복되는 질문은 FAQ에 추가한다

#### 동기 미팅 기준

동기 미팅은 다음 경우에만 사용한다:
- 텍스트로 5분 이상 설명이 필요한 복잡한 주제
- 화면 공유가 필요한 디버깅
- 감정이나 뉘앙스가 중요한 대화

### 온보딩 메트릭 대시보드

팀 전체의 온보딩 품질을 추적하고 개선하기 위한 메트릭 시스템이다.

```typescript
// onboarding-metrics/types.ts

/** 개인별 온보딩 메트릭 */
interface OnboardingMetrics {
  memberId: string;
  startDate: string; // ISO 8601

  // ── 시간 지표 ──────────────────────────────
  timeToFirstPRDays: number;       // 첫 PR 머지까지 일수
  timeToFirstReviewDays: number;   // 첫 코드 리뷰 참여까지 일수
  envSetupMinutes: number;         // 환경 셋업 소요 시간 (분)

  // ── 활동 지표 ──────────────────────────────
  prsAt30Days: number;
  prsAt60Days: number;
  prsAt90Days: number;
  reviewsAt30Days: number;
  independentTasksAt60Days: number;
  documentContributions: number;

  // ── 만족도 지표 ────────────────────────────
  npsScore: number;                // -100 ~ 100
  mentorSatisfaction: number;      // 1 ~ 5
  selfAssessment: number;          // 1 ~ 5
  buddySatisfaction: number;       // 1 ~ 5
}

/** 팀 벤치마크 (목표치) */
const TEAM_BENCHMARKS: Omit<
  OnboardingMetrics,
  "memberId" | "startDate"
> = {
  timeToFirstPRDays: 5,
  timeToFirstReviewDays: 7,
  envSetupMinutes: 30,
  prsAt30Days: 8,
  prsAt60Days: 20,
  prsAt90Days: 35,
  reviewsAt30Days: 10,
  independentTasksAt60Days: 5,
  documentContributions: 3,
  npsScore: 50,
  mentorSatisfaction: 4,
  selfAssessment: 3.5,
  buddySatisfaction: 4,
};

/** 메트릭 집계 함수 */
function calculateOnboardingHealth(
  allMetrics: OnboardingMetrics[]
): OnboardingHealthReport {
  const recent = allMetrics.filter((m) => {
    const start = new Date(m.startDate);
    const sixMonthsAgo = new Date();
    sixMonthsAgo.setMonth(sixMonthsAgo.getMonth() - 6);
    return start >= sixMonthsAgo;
  });

  const avg = (fn: (m: OnboardingMetrics) => number) =>
    recent.reduce((sum, m) => sum + fn(m), 0) / recent.length;

  return {
    totalOnboarded: recent.length,
    avgTimeToFirstPR: avg((m) => m.timeToFirstPRDays),
    avgEnvSetupTime: avg((m) => m.envSetupMinutes),
    avgNPS: avg((m) => m.npsScore),
    avgSelfAssessment: avg((m) => m.selfAssessment),
    graduationRate:
      recent.filter((m) => m.prsAt90Days >= TEAM_BENCHMARKS.prsAt90Days)
        .length / recent.length,
  };
}

interface OnboardingHealthReport {
  totalOnboarded: number;
  avgTimeToFirstPR: number;
  avgEnvSetupTime: number;
  avgNPS: number;
  avgSelfAssessment: number;
  graduationRate: number; // 0 ~ 1
}
```

```typescript
// onboarding-metrics/dashboard-api.ts

/** 대시보드 API 엔드포인트 예시 */
interface DashboardEndpoints {
  /** 전체 온보딩 현황 요약 */

  "GET /api/onboarding/trends": {

    response: {
      periods: string[];
      avgTimeToFirstPR: number[];
      avgNPS: number[];

    };
  };
```
