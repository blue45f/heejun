## 1. AI 기반 배포 자동화

> AI는 배포 파이프라인의 모든 단계에 개입한다.
> PR 분석 -> Preview 환경 생성 -> 릴리즈 노트 생성 -> 멀티 베타 배포 -> 이상 탐지 -> 자동 롤백까지 End-to-End 자동화가 핵심이다.

### 1.1 PR Diff 위험도 자동 분석

AI 모델이 PR diff, 변경 파일 범위, 과거 장애 이력을 종합해 배포 위험도를 자동 산출한다.

#### AI 프롬프트 1: 범용 위험도 분석

```text
당신은 시니어 SRE 엔지니어입니다.
아래 PR diff를 분석하여 배포 위험도를 LOW / MEDIUM / HIGH / CRITICAL로 판정하세요.

## 판정 기준
- DB 스키마 변경 또는 마이그레이션 포함 → HIGH 이상
- 인증/결제/개인정보 관련 코드 변경 → HIGH 이상
- API 엔드포인트 삭제 또는 시그니처 변경 → MEDIUM 이상
- 설정 파일(환경변수, feature flag) 변경 → MEDIUM
- 테스트만 변경, 문서만 변경 → LOW
- 동시에 10개 이상 파일 변경 → 1단계 상향

## 출력 형식
1. 위험도: [LOW|MEDIUM|HIGH|CRITICAL]
2. 근거: (3줄 이내)
3. 주의 파일: (최대 5개)
4. 권장 배포 시간대: [업무시간|비업무시간|동결기간]
5. 필요 검토자: [일반|시니어|아키텍트]
6. Preview 환경 테스트 권장 항목: (3개 이내)

## PR Diff:
{diff_content}
```

#### AI 프롬프트 2: 의존성/영향 범위 분석

```text
당신은 코드 아키텍트입니다.
아래 PR의 변경사항이 시스템 전체에 미치는 영향 범위를 분석하세요.

## 분석 항목
1. 직접 영향 범위: 변경된 모듈/서비스 목록
2. 간접 영향 범위: 변경 모듈을 import/의존하는 다른 모듈
3. API 계약 변경 여부: Request/Response 스키마 변화
4. 하위 호환성: 기존 클라이언트가 영향받는지 여부
5. 필요한 통합 테스트 시나리오: 최소 3개
6. 멀티 베타 배포 시 환경별 영향 분석: preview/beta/staging/production

## 출력 형식 (JSON)
{
  "directImpact": ["서비스A", "서비스B"],
  "indirectImpact": ["서비스C"],
  "breakingChanges": true | false,
  "requiredTests": ["시나리오1", "시나리오2"],
  "deployOrder": ["서비스B → 서비스A → 서비스C"],
  "estimatedRisk": "MEDIUM",
  "betaEnvironments": {
    "previewNeeded": true,
    "betaValidationRequired": ["성능 테스트", "호환성 테스트"],
    "rolloutStrategy": "0% → 1% → 10% → 50% → 100%"
  }
}

## PR Diff:
{diff_content}
```

#### GitHub Actions 위험도 분석 워크플로우

```yaml
# .github/workflows/ai-deploy-risk.yml
name: AI Deploy Risk Analysis

on:
  pull_request:
    types: [opened, synchronize]
    branches: [main, release/*]

jobs:
  risk-analysis:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Get PR Diff
        id: diff
        run: |
          DIFF=$(git diff origin/${{ github.base_ref }}...HEAD)
          echo "diff<<EOF" >> $GITHUB_OUTPUT
          echo "$DIFF" >> $GITHUB_OUTPUT
          echo "EOF" >> $GITHUB_OUTPUT

      - name: Analyze Risk with Claude
        id: risk
        uses: actions/github-script@v7
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        with:
          script: |
            const Anthropic = require('@anthropic-ai/sdk');
            const client = new Anthropic();

            const diff = `${{ steps.diff.outputs.diff }}`;
            const changedFiles = await exec.getExecOutput('git', [
              'diff', '--name-only', `origin/${context.payload.pull_request.base.ref}...HEAD`
            ]);

            const prompt = `
            시니어 SRE로서 아래 PR diff의 배포 위험도를 분석하세요.

            변경 파일 목록:
            ${changedFiles.stdout}

            Diff 내용:
            ${diff.substring(0, 8000)}

            JSON 형식으로 응답:
            {
              "risk": "LOW|MEDIUM|HIGH|CRITICAL",
              "reason": "...",
              "files": [...],
              "deployWindow": "...",
              "previewTestItems": ["항목1", "항목2"],
              "betaRolloutRecommendation": "0%→1%→10%→50%→100% 또는 즉시 100%"
            }
            `;

            const response = await client.messages.create({
              model: 'claude-sonnet-4-20250514',
              max_tokens: 1024,
              messages: [{ role: 'user', content: prompt }]
            });

            const result = JSON.parse(response.content[0].text);
            core.setOutput('risk', result.risk);
            core.setOutput('analysis', JSON.stringify(result));

      - name: Comment Risk Analysis
        uses: actions/github-script@v7
        with:
          script: |
            const analysis = JSON.parse('${{ steps.risk.outputs.analysis }}');
            const emoji = {
              LOW: ':white_check_mark:',
              MEDIUM: ':warning:',
              HIGH: ':rotating_light:',
              CRITICAL: ':no_entry:'
            };

            await github.rest.issues.createComment({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.issue.number,
              body: `## ${emoji[analysis.risk]} 배포 위험도: **${analysis.risk}**

            **분석 근거:** ${analysis.reason}

            **주의 파일:**
            ${analysis.files.map(f => '- \`' + f + '\`').join('\n')}

            **권장 배포 시간대:** ${analysis.deployWindow}

            **Preview 환경 테스트 항목:**
            ${(analysis.previewTestItems || []).map(i => '- ' + i).join('\n')}

            **베타 롤아웃 권장:** ${analysis.betaRolloutRecommendation || 'N/A'}`
            });

      - name: Block CRITICAL deployments
        if: steps.risk.outputs.risk == 'CRITICAL'
        run: |
          echo "::error::CRITICAL 위험도 - 아키텍트 승인 필요"
          exit 1
```

### 1.2 AI 릴리즈 노트 자동 생성

커밋 히스토리와 PR 내용을 기반으로 사용자 친화적 릴리즈 노트를 자동 생성한다.

```yaml
# .github/workflows/ai-release-notes.yml
name: AI Release Notes Generator

on:
  push:
    tags: ['v*']

permissions:
  contents: write

jobs:
  generate-notes:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Collect commits since last tag
        id: commits
        run: |
          PREV_TAG=$(git describe --tags --abbrev=0 HEAD^ 2>/dev/null || echo "")
          if [ -z "$PREV_TAG" ]; then
            COMMITS=$(git log --oneline --format="%h %s" HEAD)
          else
            COMMITS=$(git log --oneline --format="%h %s" ${PREV_TAG}..HEAD)
          fi
          echo "commits<<EOF" >> $GITHUB_OUTPUT
          echo "$COMMITS" >> $GITHUB_OUTPUT
          echo "EOF" >> $GITHUB_OUTPUT
          echo "prev_tag=$PREV_TAG" >> $GITHUB_OUTPUT

      - name: Generate Release Notes with AI
        id: notes
        uses: actions/github-script@v7
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        with:
          script: |
            const Anthropic = require('@anthropic-ai/sdk');
            const client = new Anthropic();

            const commits = `${{ steps.commits.outputs.commits }}`;

            const response = await client.messages.create({
              model: 'claude-sonnet-4-20250514',
              max_tokens: 2048,
              messages: [{
                role: 'user',
                content: `아래 커밋 목록을 기반으로 릴리즈 노트를 작성하세요.

            커밋 목록:
            ${commits}

            형식:
            ## 새로운 기능
            - ...
            ## 개선사항
            - ...
            ## 버그 수정
            - ...
            ## 기타
            - ...

            규칙:
            - 사용자 관점으로 작성 (코드 내부 용어 사용 금지)
            - 각 항목은 한 줄, 핵심만 간결하게
            - 해당 없는 섹션은 생략`
              }]
            });

            core.setOutput('notes', response.content[0].text);

      - name: Create GitHub Release
        uses: actions/github-script@v7
        with:
          script: |
            await github.rest.repos.createRelease({
              owner: context.repo.owner,
              repo: context.repo.repo,
              tag_name: context.ref.replace('refs/tags/', ''),
              name: `Release ${context.ref.replace('refs/tags/', '')}`,
              body: `${{ steps.notes.outputs.notes }}`,
              draft: false,
              prerelease: false
            });
```

### 1.3 AI 배포 위험도 자동 분석 (종합)

PR diff 수준을 넘어, 배포 전체의 위험도를 종합 분석하는 스크립트다. Preview/Beta 환경 결과, Feature Flag 상태, 의존성 변화를 모두 반영한다.

#### AI 프롬프트 3: 멀티 환경 배포 위험도 종합 분석

```text

## 입력 정보
1. PR diff 요약: {pr_summary}
2. Preview 환경 테스트 결과: {preview_results}
3. Beta 환경(N개) 메트릭: {beta_metrics}
4. Feature Flag 변경사항: {flag_changes}
5. 의존성 변경(package.json diff): {dep_changes}

## 출력 형식 (JSON)
{
  "overallRisk": "LOW|MEDIUM|HIGH|CRITICAL",
  "environmentRisks": {
    "preview": { "risk": "LOW", "issues": [] },
    "beta": { "risk": "MEDIUM", "issues": ["메모리 사용량 10% 증가"] },
    "staging": { "risk": "LOW", "issues": [] },
    "production": { "risk": "MEDIUM", "issues": ["신규 API 엔드포인트 부하 미검증"] }
  },
  "rolloutRecommendation": "0%→1%→10%→50%→100%",
  "rolloutPauseCriteria": ["에러율 0.5% 초과", "p99 레이턴시 500ms 초과"],
  "requiredApprovals": ["SRE", "도메인 오너"],
  "actionItems": ["Beta에서 부하 테스트 추가 실행", "Feature Flag fallback 로직 검증"]
}
```

```typescript
// deploy/comprehensive-risk-analysis.ts
import { execSync } from "node:child_process";

interface EnvironmentRisk {
  risk: "LOW" | "MEDIUM" | "HIGH" | "CRITICAL";
  issues: string[];
}

interface ComprehensiveRiskReport {
  overallRisk: "LOW" | "MEDIUM" | "HIGH" | "CRITICAL";
  environmentRisks: {
    preview: EnvironmentRisk;
    beta: EnvironmentRisk;
    staging: EnvironmentRisk;
    production: EnvironmentRisk;
  };
  rolloutRecommendation: string;
  rolloutPauseCriteria: string[];
  requiredApprovals: string[];
  actionItems: string[];
}

async function analyzeComprehensiveRisk(
  prNumber: number,
): Promise<ComprehensiveRiskReport> {
  // 1. PR diff 수집
  const prDiff = execSync(
    `gh pr diff ${prNumber} --repo $GITHUB_REPOSITORY`,
    { encoding: "utf-8" },
  );

  // 2. Preview 환경 테스트 결과 수집
  const previewResults = await fetchPreviewTestResults(prNumber);

  // 3. Beta 환경 메트릭 수집
  const betaMetrics = await fetchBetaEnvironmentMetrics();

  // 4. Feature Flag 변경사항 추출
  const flagChanges = extractFeatureFlagChanges(prDiff);

  // 5. 의존성 변경 추출
  const depChanges = extractDependencyChanges(prDiff);

  // 6. AI 종합 분석
  const prompt = buildComprehensivePrompt({
    prSummary: prDiff.substring(0, 5000),
    previewResults: JSON.stringify(previewResults),
    betaMetrics: JSON.stringify(betaMetrics),
    flagChanges: JSON.stringify(flagChanges),
    depChanges: JSON.stringify(depChanges),
  });

  const analysis = await callAI(prompt);
  return JSON.parse(analysis) as ComprehensiveRiskReport;
}

function extractFeatureFlagChanges(diff: string): string[] {
  const flagPatterns = [
    /featureKey:\s*['"]([^'"]+)['"]/g,
    /isEnabled\(['"]([^'"]+)['"]\)/g,
    /useFeatureFlag\(['"]([^'"]+)['"]\)/g,
  ];

  const flags = new Set<string>();
  for (const pattern of flagPatterns) {
    for (const match of diff.matchAll(pattern)) {
      flags.add(match[1]);
    }
  }
  return [...flags];
}

function extractDependencyChanges(diff: string): Record<string, string> {
  const changes: Record<string, string> = {};
  const depPattern = /[+-]\s*"([^"]+)":\s*"([^"]+)"/g;
  for (const match of diff.matchAll(depPattern)) {
    changes[match[1]] = match[2];
  }
  return changes;
}

export { analyzeComprehensiveRisk };
export type { ComprehensiveRiskReport };
```

### 1.4 AI 기반 롤백 판단 자동화

배포 후 메트릭을 실시간 수집하고, AI가 이상 여부를 판단하여 자동 롤백을 트리거한다.

```typescript
// deploy/auto-rollback.ts
interface DeployMetrics {
  errorRate: number;
  p99Latency: number;
  cpuUsage: number;
  memoryUsage: number;
  healthCheckPass: boolean;
}

interface RollbackDecision {
  shouldRollback: boolean;
  confidence: number;
  reason: string;
  severity: "WARNING" | "CRITICAL";
}

function evaluateStaticRules(
  current: DeployMetrics,
  baseline: DeployMetrics,
): RollbackDecision | null {
  if (!current.healthCheckPass) {
    return {
      shouldRollback: true,
      confidence: 1.0,
      reason: "헬스체크 연속 실패",
      severity: "CRITICAL",
    };
  }

  if (current.errorRate > baseline.errorRate * 5) {
    return {
      shouldRollback: true,
      confidence: 0.95,
      reason: `에러율 ${current.errorRate.toFixed(1)}% (기준: ${baseline.errorRate.toFixed(1)}%)`,
      severity: "CRITICAL",
    };
  }

  if (current.p99Latency > baseline.p99Latency * 3) {
    return {
      shouldRollback: true,
      confidence: 0.9,
      reason: `p99 레이턴시 ${current.p99Latency}ms (기준: ${baseline.p99Latency}ms)`,
      severity: "CRITICAL",
    };
  }

  return null;
}

async function evaluateWithAI(
  current: DeployMetrics,
  baseline: DeployMetrics,
  recentHistory: DeployMetrics[],
): Promise<RollbackDecision> {
  const prompt = `
배포 후 메트릭을 분석하여 롤백 필요 여부를 판단하세요.

## 기준선 (배포 전 30분 평균)
${JSON.stringify(baseline, null, 2)}

## 현재 (배포 후)
${JSON.stringify(current, null, 2)}

## 최근 5분 추이
${JSON.stringify(recentHistory, null, 2)}

JSON으로 응답: { "shouldRollback": boolean, "confidence": number, "reason": "..." }
  `;

  const response = await callAI(prompt);
  return JSON.parse(response);
}

async function monitorAndRollback(deployId: string): Promise<void> {
  const baseline = await getBaselineMetrics();
  const CHECK_INTERVAL_MS = 30_000;
  const MONITORING_DURATION_MS = 15 * 60_000;
  const recentHistory: DeployMetrics[] = [];

  const startTime = Date.now();

  while (Date.now() - startTime < MONITORING_DURATION_MS) {
    const current = await getCurrentMetrics();
    recentHistory.push(current);
    if (recentHistory.length > 10) recentHistory.shift();

    const staticResult = evaluateStaticRules(current, baseline);
    if (staticResult?.shouldRollback) {
      await executeRollback(deployId, staticResult);
      return;
    }

    if (recentHistory.length >= 5) {
      const aiResult = await evaluateWithAI(current, baseline, recentHistory);
      if (aiResult.shouldRollback && aiResult.confidence > 0.8) {
        await executeRollback(deployId, aiResult);
        return;
      }
    }

    await sleep(CHECK_INTERVAL_MS);
  }
```

```typescript
// deploy/anomaly-detection.ts
interface AnomalyAlert {
  type: "ERROR_SPIKE" | "LATENCY_REGRESSION" | "TRAFFIC_ANOMALY" | "MEMORY_LEAK";
  severity: "LOW" | "MEDIUM" | "HIGH" | "CRITICAL";
  metric: string;
  currentValue: number;
  expectedRange: { min: number; max: number };
  message: string;
}

async function detectAnomalies(deployId: string): Promise<AnomalyAlert[]> {
  const alerts: AnomalyAlert[] = [];
  const metrics = await getPostDeployMetrics(deployId);
  const historical = await getHistoricalMetrics(7);

  const errorBaseline = calculateBaseline(historical.errorRates);
  if (metrics.errorRate > errorBaseline.mean + errorBaseline.stdDev * 3) {
    alerts.push({
      type: "ERROR_SPIKE",
      severity: metrics.errorRate > errorBaseline.mean * 5 ? "CRITICAL" : "HIGH",
      metric: "error_rate",
      currentValue: metrics.errorRate,
      expectedRange: {
        min: 0,
        max: errorBaseline.mean + errorBaseline.stdDev * 2,
      },
      message: `에러율 ${metrics.errorRate.toFixed(2)}% (정상 범위: ~${(errorBaseline.mean + errorBaseline.stdDev * 2).toFixed(2)}%)`,
    });
  }

  const memoryTrend = calculateLinearRegression(metrics.memoryTimeSeries);
  if (memoryTrend.slope > 0.5 && memoryTrend.rSquared > 0.85) {
    alerts.push({
      type: "MEMORY_LEAK",
      severity: "HIGH",
      metric: "memory_usage",
      currentValue: metrics.memoryUsage,
      expectedRange: { min: 0, max: 80 },
      message: `메모리 사용량 선형 증가 감지 (기울기: ${memoryTrend.slope.toFixed(2)}%/min)`,
    });
  }

  if (alerts.length > 0) {
    const aiAnalysis = await analyzeWithAI(metrics, historical, alerts);
    return alerts.filter(
      (alert) => !aiAnalysis.falsePositives.includes(alert.type),
    );
  }

  return alerts;
}

function calculateBaseline(values: number[]): { mean: number; stdDev: number } {
  const mean = values.reduce((a, b) => a + b, 0) / values.length;
  const variance =
    values.reduce((sum, val) => sum + Math.pow(val - mean, 2), 0) / values.length;
  return { mean, stdDev: Math.sqrt(variance) };
}
```

```typescript
async function createPreviewEnvironment(

  const originDomain = `${bucketName}.s3-website.ap-northeast-2.amazonaws.com`;

      },

            Action: "s3:GetObject",
            Resource: `arn:aws:s3:::${bucketName}/*`,
          },
        ],
      }),
    }),
  );

  // 4. CloudFront 배포 생성
  const cfResult = await cf.send(
    new CreateDistributionCommand({
      DistributionConfig: {
        CallerReference: `preview-pr-${prNumber}-${Date.now()}`,

async function deletePreviewEnvironment(env: PreviewEnvironment): Promise<void> {
  // 1. S3 객체 전체 삭제
  const objects = await s3.send(
    new ListObjectsV2Command({ Bucket: env.bucketName }),
  );

  if (objects.Contents && objects.Contents.length > 0) {
    await s3.send(
      new DeleteObjectsCommand({
        Bucket: env.bucketName,
        Delete: {
          Objects: objects.Contents.map((obj) => ({ Key: obj.Key })),
        },
      }),
    );
  }

  // 2. S3 버킷 삭제
  await s3.send(new DeleteBucketCommand({ Bucket: env.bucketName }));

  // 3. CloudFront 배포 비활성화 및 삭제
  const dist = await cf.send(
    new GetDistributionCommand({ Id: env.distributionId }),
  );

  if (dist.Distribution && dist.ETag) {
    await cf.send(
      new DeleteDistributionCommand({
        Id: env.distributionId,
        IfMatch: dist.ETag,
      }),
    );
  }

  console.log(`[Preview] PR #${env.prNumber} 환경 삭제 완료`);
}
```

## 4. Feature Flag 기반 점진적 롤아웃

코드 배포와 기능 출시를 분리한다. 코드는 main에 머지하되, Feature Flag로 활성화 시점을 제어한다. 롤아웃 비율은 0% -> 1% -> 10% -> 50% -> 100%으로 단계적 확대한다.

### 4.1 해싱 기반 점진적 롤아웃 (자체 구현)

```typescript
// features/gradual-rollout.ts
import { createHash } from "crypto";

interface RolloutStage {
  name: string;
  percentage: number;
  minDuration: number;         // 최소 유지 시간 (분)
  gateCriteria: GateCriteria;
}

interface GateCriteria {
  maxErrorRate: number;        // 최대 허용 에러율 (%)
  maxP99Latency: number;       // 최대 p99 레이턴시 (ms)
  minSuccessRate: number;      // 최소 성공률 (%)
  customChecks?: string[];
}

interface RolloutConfig {
  featureKey: string;
  currentStage: number;        // 현재 단계 인덱스
  stages: RolloutStage[];
  allowList?: string[];
  blockList?: string[];
}

const DEFAULT_ROLLOUT_STAGES: RolloutStage[] = [
  {
    name: "canary",
    percentage: 1,
    minDuration: 30,
    gateCriteria: { maxErrorRate: 0.1, maxP99Latency: 500, minSuccessRate: 99.9 },
  },
  {
    name: "early-adopters",
    percentage: 10,
    minDuration: 60,
    gateCriteria: { maxErrorRate: 0.5, maxP99Latency: 500, minSuccessRate: 99.5 },
  },
  {
    name: "half",
    percentage: 50,
    minDuration: 120,
    gateCriteria: { maxErrorRate: 1.0, maxP99Latency: 800, minSuccessRate: 99.0 },
  },
  {
    name: "full",
    percentage: 100,
    minDuration: 0,
    gateCriteria: { maxErrorRate: 2.0, maxP99Latency: 1000, minSuccessRate: 98.0 },
  },
];

function isRolledOut(config: RolloutConfig, userId: string): boolean {
  if (config.allowList?.includes(userId)) return true;
  if (config.blockList?.includes(userId)) return false;

  const currentStage = config.stages[config.currentStage];
  if (!currentStage) return false;

  const hash = createHash("sha256")
    .update(`${config.featureKey}:${userId}`)
    .digest("hex");
  const bucket = parseInt(hash.substring(0, 8), 16) % 100;

  return bucket < currentStage.percentage;
}

async function evaluateGateAndPromote(
  config: RolloutConfig,
  metrics: { errorRate: number; p99Latency: number; successRate: number },
): Promise<{ promote: boolean; reason: string }> {
  const stage = config.stages[config.currentStage];
  if (!stage) return { promote: false, reason: "마지막 단계" };

  const criteria = stage.gateCriteria;

  if (metrics.errorRate > criteria.maxErrorRate) {
    return { promote: false, reason: `에러율 초과: ${metrics.errorRate}% > ${criteria.maxErrorRate}%` };
  }
  if (metrics.p99Latency > criteria.maxP99Latency) {
    return { promote: false, reason: `p99 초과: ${metrics.p99Latency}ms > ${criteria.maxP99Latency}ms` };
  }
  if (metrics.successRate < criteria.minSuccessRate) {
    return { promote: false, reason: `성공률 미달: ${metrics.successRate}% < ${criteria.minSuccessRate}%` };
  }

  return { promote: true, reason: "모든 게이트 기준 통과" };
}

export { isRolledOut, evaluateGateAndPromote, DEFAULT_ROLLOUT_STAGES };
export type { RolloutConfig, RolloutStage, GateCriteria };
```

```yaml
            P99=$(echo $METRICS | jq '.p99Latency')

            echo "Check $i: errorRate=${ERROR_RATE}, p99=${P99}"

            if (( $(echo "$ERROR_RATE > 2.0" | bc -l) )); then
              echo "::error::에러율 임계치 초과 - 롤백 필요"
              exit 1
            fi
          done
          echo "Gate criteria passed for ${{ inputs.target_stage }}"
```

### 4.3 React Feature Flag Provider

```typescript
// features/FeatureFlagProvider.tsx
import {
  createContext,
  useContext,
  useEffect,
  useState,
  type ReactNode,
} from "react";

interface FeatureFlags {
  [key: string]: boolean;
}

interface FeatureFlagContextValue {
  flags: FeatureFlags;
  isEnabled: (key: string) => boolean;
  loading: boolean;
}

const FeatureFlagContext = createContext<FeatureFlagContextValue>({
  flags: {},
  isEnabled: () => false,
  loading: true,
});

function FeatureFlagProvider({ children }: { children: ReactNode }) {
  const [flags, setFlags] = useState<FeatureFlags>({});
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    async function fetchFlags() {
      try {
        const response = await fetch("/api/features");
        const data = await response.json();
        setFlags(data.flags);
      } catch (error) {
        console.error("Feature flag 로드 실패:", error);
      } finally {
        setLoading(false);
      }
    }

    fetchFlags();

    // SSE로 실시간 업데이트 수신
    const eventSource = new EventSource("/api/features/stream");
    eventSource.onmessage = (event) => {
      const updated = JSON.parse(event.data);
      setFlags((prev) => ({ ...prev, ...updated }));
    };

    return () => eventSource.close();
  }, []);

  const isEnabled = (key: string): boolean => flags[key] ?? false;

  return (
    <FeatureFlagContext.Provider value={{ flags, isEnabled, loading }}>
      {children}
    </FeatureFlagContext.Provider>
  );
}

function useFeatureFlag(key: string): boolean {
  const { isEnabled } = useContext(FeatureFlagContext);
  return isEnabled(key);
}

export { FeatureFlagProvider, useFeatureFlag };
```

## 7. 배포 전략 비교

### 전략별 비교표

| 항목 | Canary | Blue-Green | Rolling |
|------|--------|------------|---------|
| **개념** | 소수 트래픽으로 새 버전 검증 후 점진 확대 | 두 환경을 전환하여 즉시 교체 | 인스턴스를 순차적으로 교체 |
| **롤백 속도** | 빠름 (트래픽 비율 조정) | 즉시 (환경 전환) | 느림 (순차 복원) |
| **인프라 비용** | 중간 | 높음 (2배 리소스) | 낮음 |
| **위험도** | 낮음 | 매우 낮음 | 중간 |
| **복잡도** | 높음 (트래픽 분배 필요) | 중간 | 낮음 |
| **무중단** | O | O | O (maxUnavailable 설정) |
| **멀티 베타 활용** | 각 Beta에서 Canary 검증 후 Production | Blue/Green을 Beta로 활용 | Beta 환경에 순차 적용 |
| **적합 상황** | 대규모 사용자, 위험 변경 | 빠른 롤백 필요, 충분한 인프라 | 일반적 업데이트, 비용 제한 |

## 8. 배포 자동화 파이프라인

### 4단계 파이프라인: 빌드 -> Beta(N개) -> Staging -> Production

```yaml
# .github/workflows/deploy-pipeline.yml
name: Full Deploy Pipeline

on:
  push:
    branches: [main]

concurrency:
  group: deploy-${{ github.ref }}
  cancel-in-progress: false

env:
  IMAGE_REGISTRY: ghcr.io/${{ github.repository }}

jobs:
  # ── Stage 1: 빌드 & 테스트 ────────────────────────────
  build:
    runs-on: ubuntu-latest
    outputs:
      image_tag: ${{ steps.meta.outputs.version }}
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - run: pnpm install --frozen-lockfile
      - run: pnpm lint
      - run: pnpm typecheck
      - run: pnpm test -- --coverage

      - name: Docker meta
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.IMAGE_REGISTRY }}
          tags: type=sha,prefix={{branch}}-

      - name: Build & Push Image
        uses: docker/build-push-action@v5
        with:
          context: .
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

  # ── Stage 2: 멀티 베타 동시 배포 ──────────────────────
  beta:
    needs: build
    runs-on: ubuntu-latest
    strategy:
      matrix:
        environment: [beta-1, beta-2, beta-3]
      fail-fast: false
    steps:
      - uses: actions/checkout@v4

      - name: Deploy to ${{ matrix.environment }}
        run: |
          kubectl set image deployment/my-service \
            app=${{ env.IMAGE_REGISTRY }}:${{ needs.build.outputs.image_tag }} \
            -n ${{ matrix.environment }}
          kubectl rollout status deployment/my-service \
            -n ${{ matrix.environment }} --timeout=300s

      - name: Health Check
        run: |
          URL="https://${{ matrix.environment }}.example.com/health"
          for i in $(seq 1 10); do
            STATUS=$(curl -s -o /dev/null -w "%{http_code}" "$URL")
            [ "$STATUS" = "200" ] && exit 0
            sleep 5
          done
          exit 1

  # ── Stage 3: Staging 배포 & 검증 ──────────────────────
  staging:
    needs: [build, beta]
    runs-on: ubuntu-latest
    environment: staging
    steps:
      - uses: actions/checkout@v4

      - name: Deploy to Staging
        run: |
          kubectl set image deployment/my-service \
            app=${{ env.IMAGE_REGISTRY }}:${{ needs.build.outputs.image_tag }} \
            -n staging
          kubectl rollout status deployment/my-service -n staging --timeout=300s

      - name: Run E2E Tests
        run: pnpm test:e2e -- --config baseUrl=https://staging.example.com

  # ── Stage 4: Production 배포 (점진적 롤아웃) ──────────
  production:
    needs: [build, staging]
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v4

      - name: Deploy to Production (Canary 1%)
        run: |
          kubectl set image deployment/my-service \
            app=${{ env.IMAGE_REGISTRY }}:${{ needs.build.outputs.image_tag }} \
            -n production
          kubectl rollout status deployment/my-service -n production --timeout=600s

      - name: Post-deploy Validation
        id: validate
        run: |
          sleep 30
          ERROR_RATE=$(curl -s "https://prometheus.example.com/api/v1/query?query=rate(http_errors_total[5m])" \
            | jq '.data.result[0].value[1]' -r)
          if (( $(echo "$ERROR_RATE > 0.05" | bc -l) )); then
            echo "error_rate_high=true" >> $GITHUB_OUTPUT
          else
            echo "error_rate_high=false" >> $GITHUB_OUTPUT
          fi

      - name: Auto Rollback on Failure
        if: steps.validate.outputs.error_rate_high == 'true'
        run: |
          echo "::error::에러율 초과 - 자동 롤백 실행"
          kubectl rollout undo deployment/my-service -n production

      - name: Notify Slack
        if: always()
        uses: slackapi/slack-github-action@v2
        with:
          webhook: ${{ secrets.SLACK_WEBHOOK_URL }}
          payload: |
            {
              "text": "${{ job.status == 'success' && ':white_check_mark: 프로덕션 배포 성공' || ':x: 프로덕션 배포 실패' }}\n커밋: `${{ github.sha }}`\n실행자: ${{ github.actor }}"
            }
```

## 9. 모바일 vs 웹 배포 비교

| 항목 | 웹 배포 | 모바일 앱 배포 |
|------|---------|---------------|
| **배포 속도** | 즉시 (서버 배포 완료 시점) | 스토어 심사 1~7일 (Apple 기준) |
| **롤백** | 즉시 가능 (이전 버전 배포) | 불가능 (새 버전 제출 필요) |
| **멀티 베타** | N개 S3+CF 환경 동적 생성 | TestFlight/Internal Testing 활용 |
| **Preview 환경** | PR별 자동 생성 | Expo Preview / 내부 배포 |
| **Feature Flag 중요도** | 높음 | 매우 높음 (롤백 불가하므로 필수) |
| **점진적 롤아웃** | Feature Flag 0%->100% | 스토어 Staged Rollout + Feature Flag |
| **버전 파편화** | 없음 (단일 버전) | 심함 (구 버전 사용자 상존) |
| **테스트 범위** | 브라우저 호환성 | OS 버전 + 기기 다양성 + 스토어 정책 |
| **핫픽스** | 수 분 내 배포 가능 | 스토어 긴급 심사 요청 (수 시간~1일) |
| **모니터링** | APM, 서버 로그 | Crashlytics, 스토어 리뷰 모니터링 |
