## 1. AI 기반 코드 리뷰 혁명

2026년 코드 리뷰의 패러다임은 **"AI First, Human Final"**이다. AI가 1차 리뷰를 수행하고, 사람은 비즈니스 맥락과 아키텍처 판단에 집중한다.

### 1.1 GitHub Copilot Code Review 설정 및 활용

GitHub Copilot Code Review는 PR이 열릴 때 자동으로 코드를 분석하고 인라인 코멘트를 남긴다.

```yaml
# .github/copilot-review.yml
review:
  auto_review: true
  review_language: "ko"
  focus_areas:
    - security
    - performance
    - error-handling
    - type-safety
    - accessibility
    - feature-flag-safety          # Feature Flag 관련 변경 탐지
  severity_threshold: "medium"
  ignore_paths:
    - "**/*.test.ts"
    - "**/*.spec.ts"
    - "**/*.stories.tsx"
    - "**/generated/**"
    - "**/migrations/**"
  custom_rules:
    - id: "no-any-type"
      description: "any 타입 사용 금지"
      severity: "high"
    - id: "async-error-handling"
      description: "async 함수에서 try-catch 필수"
      severity: "medium"
    - id: "feature-flag-cleanup"
      description: "Feature Flag에 만료일 주석이 없으면 경고"
      severity: "medium"
    - id: "env-specific-hardcode"
      description: "환경별 URL/설정 하드코딩 금지"
      severity: "high"
  auto_approve:
    enabled: false
  # 멀티 베타 환경별 리뷰 수준 분기
  environment_rules:
    beta:
      severity_threshold: "high"     # beta는 high 이상만 blocking
    staging:
      severity_threshold: "medium"
    production:
      severity_threshold: "low"      # production은 모든 severity blocking
```

**활용 팁:**

- PR 설명에 `@copilot review` 태그를 추가하면 수동 재리뷰 요청 가능
- 특정 파일만 집중 리뷰: `@copilot review --focus src/auth/`
- 리뷰 결과에 대해 `@copilot explain` 으로 추가 설명 요청
- Preview 환경 URL이 코멘트에 자동 첨부되어 시각적 검증 가능

### 1.2 CodeRabbit 설정 및 멀티 베타 커스텀 규칙

CodeRabbit은 PR을 자동 요약하고, 변경 파일 단위로 점진적 리뷰를 제공한다.

```yaml
# .coderabbit.yaml
language: "ko"
tone_instructions: "간결하고 실용적인 톤. 구체적인 수정 코드를 포함할 것."

early_access: true

reviews:
  auto_review:
    enabled: true
    drafts: false
    base_branches:
      - main
      - develop
      - "beta/**"           # 모든 베타 브랜치에 자동 리뷰
      - "preview/**"         # PR별 Preview 브랜치에도 자동 리뷰
  request_changes_workflow: true
  high_level_summary: true
  high_level_summary_placeholder: "@coderabbitai summary"
  poem: false

  path_instructions:
    - path: "src/api/**"
      instructions: |
        API 엔드포인트 변경 시 다음을 확인:
        - OpenAPI 스펙과의 일치 여부
        - 에러 응답 형식 표준 준수
        - Rate limiting 설정 적절성
        - 인증/인가 미들웨어 적용 여부
        - 환경별(beta/staging/prod) 분기 로직 유무
    - path: "src/components/**"
      instructions: |
        컴포넌트 변경 시 다음을 확인:
        - Props 인터페이스의 확장성
        - 접근성(a11y) 속성 누락
        - 불필요한 리렌더링 방지 (memo, useMemo, useCallback)
    - path: "src/feature-flags/**"
      instructions: |
        Feature Flag 변경 시 다음을 반드시 확인:
        - 만료일(expiry) 설정 유무
        - 폴백(fallback) 동작 정의
        - 모든 환경(beta/staging/prod)에서 일관된 기본값
        - Flag 제거 시 데드코드 잔존 여부
    - path: "infra/**"
      instructions: |
        인프라 변경 시 다음을 확인:
        - 멀티 베타 환경 간 리소스 격리
        - Preview 환경 자동 정리(TTL) 설정
        - 비용 영향 분석

  path_filters:
    - "!dist/**"
    - "!node_modules/**"
    - "!*.lock"
    - "!**/*.generated.ts"

  tools:
    eslint:
      enabled: true
    biome:
      enabled: true
    github-checks:
      enabled: true
    ast-grep:
      enabled: true
      packages:
        - "typescript-security-rules"

chat:
  auto_reply: true
```

### 1.3 AI vs 사람 역할 분담 매트릭스

| 리뷰 영역 | AI 담당 | 사람 담당 | 비고 |
|-----------|---------|----------|------|
| 코딩 컨벤션/포맷팅 | **주도** | 예외 승인 | Lint로 자동 차단, AI가 나머지 검출 |
| 일반 버그 패턴 | **주도** | 최종 확인 | null 참조, off-by-one, 타입 오류 |
| 보안 취약점 | **1차 스캔** | **최종 판단** | AI 스캔 + 사람의 맥락 기반 검증 |
| 성능 이슈 | **탐지** | **판단** | AI가 후보를 제시, 사람이 트레이드오프 결정 |
| 비즈니스 로직 | 보조 | **주도** | 도메인 지식 필요, AI는 논리 흐름만 분석 |
| 아키텍처 적합성 | 보조 | **주도** | 팀 컨텍스트, 장기 전략 고려 필요 |
| Feature Flag 안전성 | **주도** | 검증 | AI가 환경별 일관성/만료일 자동 점검 |
| Preview 환경 검증 | **자동 배포** | **시각적 확인** | AI가 배포, 사람이 UI/UX 확인 |
| 테스트 커버리지 | **측정** | 전략 결정 | 커버리지 수치는 AI, 무엇을 테스트할지는 사람 |
| PR 요약/영향 분석 | **주도** | 검증 | AI가 자동 생성, 사람이 정확성 확인 |

### 1.4 AI 리뷰 프롬프트 모음

**프롬프트 1 -- 보안 리뷰:**

```text
이 PR의 변경사항을 보안 관점에서 리뷰해줘.

중점 확인 항목:
- 사용자 입력 검증 누락 (XSS, SQL Injection, Path Traversal)
- 인증/인가 우회 가능성
- 민감 데이터 노출 (로그, 에러 메시지, API 응답)
- 환경변수/시크릿 하드코딩
- Feature Flag 우회로 인한 미공개 기능 노출 가능성

각 발견사항에 대해 [심각도: Critical/High/Medium/Low]와
구체적인 수정 코드를 제시해줘.
```

**프롬프트 2 -- 멀티 환경 호환성 리뷰:**

```text
이 PR이 멀티 베타 환경에서 안전하게 동작하는지 검증해줘.

확인 관점:
- 환경별 분기 로직이 누락된 곳이 있는가
- Feature Flag의 기본값이 모든 환경에서 안전한가
- 하드코딩된 URL, 도메인, API 엔드포인트가 환경 변수로 분리되어 있는가
- Preview 환경에서만 발생할 수 있는 edge case가 있는가
- 환경별 캐시 정책에 영향을 미치는 변경이 있는가

환경 목록: beta-1, beta-2, ..., beta-N, staging, production
```

**프롬프트 3 -- 성능 리뷰:**

```text
이 코드의 성능 병목을 분석해줘.

확인 관점:
- 불필요한 리렌더링 유발 패턴 (React)
- N+1 쿼리 또는 비효율적 데이터 페칭
- 메모리 누수 가능성 (이벤트 리스너, 구독 해제 누락)
- 번들 사이즈 영향 (tree-shaking 불가능 import)
- 큰 리스트의 가상화 미적용

각 항목에 대해 Before/After 코드와 예상 성능 개선 효과를 제시해줘.
```

**프롬프트 4 -- 아키텍처 리뷰:**

```text
이 PR이 기존 아키텍처에 미치는 영향을 분석해줘.

확인 관점:
- 레이어 간 의존성 방향 위반 (Clean Architecture)
- 도메인 로직이 인프라 계층에 누출되었는지
- 인터페이스 분리 원칙(ISP) 준수 여부
- 변경의 영향 범위와 결합도
- 멀티 환경에서 동작 시 환경 추상화 레이어가 적절한지

구체적인 의존성 다이어그램 변화와 대안 설계를 제시해줘.
```

**프롬프트 5 -- Feature Flag 변경 리뷰:**

```text
이 PR에 포함된 Feature Flag 변경사항을 리뷰해줘.

확인 관점:
- Flag 이름이 네이밍 컨벤션을 따르는가
- 만료일(expiry)이 설정되어 있는가
- Flag가 OFF일 때 폴백 동작이 안전한가
- Flag 제거 시 관련 데드코드가 완전히 정리되었는가
- beta, staging, production 환경별 기본값이 적절한가
- Flag 의존 관계(다른 Flag와 연쇄)가 문서화되어 있는가

각 항목에 대해 [통과 / 보완 필요 / 위험] 등급을 매기고,
구체적 수정 사항을 제시해줘.
```

### 1.5 AI 리뷰 결과 활용 원칙 -- 맹신 금지

AI 리뷰는 강력한 도구이나, 다음 원칙을 반드시 지킨다:

**검증 체크리스트:**

```markdown
## AI 리뷰 검증 체크리스트

- [ ] AI가 제안한 코드 변경이 현재 프로젝트 컨텍스트에 적합한가?
- [ ] AI가 놓친 비즈니스 로직 오류는 없는가?
- [ ] AI의 보안 경고 중 오탐(false positive)은 없는가?
- [ ] AI가 제안한 성능 개선이 실제로 측정 가능한 차이를 만드는가?
- [ ] AI의 리팩토링 제안이 팀 컨벤션과 일치하는가?
- [ ] AI가 참조한 라이브러리 API가 현재 사용 버전과 일치하는가?
- [ ] AI가 생성한 코드에 환각(hallucination) 패턴이 없는가?
- [ ] 멀티 베타 환경에서의 동작을 Preview URL로 직접 확인했는가?

## 2. 멀티 베타 환경별 코드 리뷰 정책

### 2.1 환경별 리뷰 정책 매트릭스

멀티 베타 환경에서는 환경의 위험도에 따라 리뷰 수준을 차등 적용한다.

| 정책 항목 | Preview (PR별) | Beta (N개) | Staging | Production |
|----------|:-:|:-:|:-:|:-:|
| AI 자동 리뷰 | 필수 | 필수 | 필수 | 필수 |
| 사람 리뷰어 수 | 0명 (AI만) | 1명 | 2명 | 2명 + 시니어 |
| 리뷰 SLA | 즉시 (AI) | 4시간 | 8시간 | 1영업일 |
| Feature Flag 체크 | 자동 | 자동 + 수동 | 전체 수동 | 전체 수동 |
| 보안 스캔 | 기본 | 기본 | 심화 | 심화 + 침투 테스트 |
| 시각적 리뷰 | 선택 | 선택 | 필수 | 필수 |
| Bundle Size 체크 | 경고만 | 경고만 | Blocking | Blocking |
| E2E 테스트 | Smoke만 | 주요 시나리오 | 전체 | 전체 |

### 2.2 환경별 리뷰 자동 분기 (GitHub Actions)

```typescript
// scripts/review-policy-router.ts
interface ReviewPolicy {
  environment: string;
  requiredApprovals: number;
  requiredReviewerRoles: string[];
  aiReviewRequired: boolean;
  securityScanLevel: "basic" | "deep" | "penetration";
  bundleSizeBlocking: boolean;
  e2eTestScope: "smoke" | "core" | "full";
  visualReviewRequired: boolean;
}

function resolveReviewPolicy(branchName: string): ReviewPolicy {
  if (branchName.startsWith("preview/") || branchName.startsWith("pr-")) {
    return {
      environment: "preview",
      requiredApprovals: 0,
      requiredReviewerRoles: [],
      aiReviewRequired: true,
      securityScanLevel: "basic",
      bundleSizeBlocking: false,
      e2eTestScope: "smoke",
      visualReviewRequired: false,
    };
  }

  if (branchName.startsWith("beta/") || branchName.match(/^beta-\d+/)) {
    return {
      environment: "beta",
      requiredApprovals: 1,
      requiredReviewerRoles: ["developer"],
      aiReviewRequired: true,
      securityScanLevel: "basic",
      bundleSizeBlocking: false,
      e2eTestScope: "core",
      visualReviewRequired: false,
    };
  }

  if (branchName === "staging" || branchName === "develop") {
    return {
      environment: "staging",
      requiredApprovals: 2,
      requiredReviewerRoles: ["developer", "senior"],
      aiReviewRequired: true,
      securityScanLevel: "deep",
      bundleSizeBlocking: true,
      e2eTestScope: "full",
      visualReviewRequired: true,
    };
  }

  // production (main)
  return {
    environment: "production",
    requiredApprovals: 2,
    requiredReviewerRoles: ["developer", "senior", "tech-lead"],
    aiReviewRequired: true,
    securityScanLevel: "penetration",
    bundleSizeBlocking: true,
    e2eTestScope: "full",
    visualReviewRequired: true,
  };
}

function generateBranchProtectionRules(
  policy: ReviewPolicy,
): Record<string, unknown> {
  return {
    required_approving_review_count: policy.requiredApprovals,
    require_code_owner_reviews: policy.environment === "production",
    dismiss_stale_reviews: true,
    required_status_checks: [
      "ai-review",
      ...(policy.bundleSizeBlocking ? ["bundle-size"] : []),
      `e2e-${policy.e2eTestScope}`,
      `security-scan-${policy.securityScanLevel}`,
    ],
  };
}

export { resolveReviewPolicy, generateBranchProtectionRules };
export type { ReviewPolicy };
```

### 2.3 GitHub Actions: 환경별 리뷰 게이트

```yaml
# .github/workflows/review-gate.yml
name: Environment Review Gate

on:
  pull_request:
    types: [opened, synchronize, ready_for_review]

jobs:
  resolve-policy:
    runs-on: ubuntu-latest
    outputs:
      environment: ${{ steps.policy.outputs.environment }}
      approvals: ${{ steps.policy.outputs.approvals }}
      e2e-scope: ${{ steps.policy.outputs.e2e_scope }}
    steps:
      - uses: actions/checkout@v4
      - id: policy
        run: |
          BRANCH="${{ github.head_ref }}"
          if [[ "$BRANCH" == preview/* ]] || [[ "$BRANCH" == pr-* ]]; then
            echo "environment=preview" >> $GITHUB_OUTPUT
            echo "approvals=0" >> $GITHUB_OUTPUT
            echo "e2e_scope=smoke" >> $GITHUB_OUTPUT
          elif [[ "$BRANCH" == beta/* ]] || [[ "$BRANCH" =~ ^beta-[0-9]+ ]]; then
            echo "environment=beta" >> $GITHUB_OUTPUT
            echo "approvals=1" >> $GITHUB_OUTPUT
            echo "e2e_scope=core" >> $GITHUB_OUTPUT
          elif [[ "$BRANCH" == "staging" ]] || [[ "$BRANCH" == "develop" ]]; then
            echo "environment=staging" >> $GITHUB_OUTPUT
            echo "approvals=2" >> $GITHUB_OUTPUT
            echo "e2e_scope=full" >> $GITHUB_OUTPUT
          else
            echo "environment=production" >> $GITHUB_OUTPUT
            echo "approvals=2" >> $GITHUB_OUTPUT
            echo "e2e_scope=full" >> $GITHUB_OUTPUT
          fi

  ai-review:
    needs: resolve-policy
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run AI Review
        uses: coderabbitai/ai-pr-reviewer@latest

## 3. PR별 Preview 환경에서 시각적 리뷰

### 3.1 Preview URL 자동 코멘트 시스템

PR이 생성되면 독립된 Preview 환경이 자동으로 프로비저닝되고, PR 코멘트에 URL이 첨부된다.

```typescript
// scripts/preview-comment.ts
import { Octokit } from "@octokit/rest";

interface PreviewEnvironment {
  prNumber: number;
  previewUrl: string;
  environment: string;
  deployedAt: string;
  expiresAt: string;
  commitSha: string;
}

async function postPreviewComment(
  octokit: Octokit,
  owner: string,
  repo: string,
  preview: PreviewEnvironment,
): Promise<void> {
  const commentBody = buildPreviewCommentBody(preview);

  // 기존 Preview 코멘트가 있으면 업데이트, 없으면 생성
  const { data: comments } = await octokit.issues.listComments({
    owner,
    repo,
    issue_number: preview.prNumber,
  });

  const existingComment = comments.find(
    (c) =>
      c.user?.login === "github-actions[bot]" &&
      c.body?.includes("Preview Environment"),
  );

  if (existingComment) {
    await octokit.issues.updateComment({
      owner,
      repo,
      comment_id: existingComment.id,
      body: commentBody,
    });
  } else {
    await octokit.issues.createComment({
      owner,
      repo,
      issue_number: preview.prNumber,
      body: commentBody,
    });
  }
}

function buildPreviewCommentBody(preview: PreviewEnvironment): string {
  return [
    "## Preview Environment",
    "",
    `| 항목 | 값 |`,
    `|------|-----|`,
    `| **URL** | [${preview.previewUrl}](${preview.previewUrl}) |`,
    `| **환경** | \`${preview.environment}\` |`,
    `| **커밋** | \`${preview.commitSha.slice(0, 7)}\` |`,
    `| **배포 시각** | ${preview.deployedAt} |`,
    `| **만료 시각** | ${preview.expiresAt} |`,
    "",
    "### 시각적 리뷰 체크리스트",
    "- [ ] 주요 페이지 레이아웃이 정상인가",
    "- [ ] 반응형 디자인이 모바일/태블릿에서 정상인가",
    "- [ ] 다크 모드 / 라이트 모드 전환이 정상인가",
    "- [ ] Feature Flag ON/OFF 상태에서 모두 정상인가",
    "- [ ] 에러 상태 / 빈 상태 / 로딩 상태가 정상인가",
    "",
    "> 이 Preview 환경은 PR이 닫히면 자동으로 삭제됩니다.",
  ].join("\n");
}

export { postPreviewComment, buildPreviewCommentBody };
export type { PreviewEnvironment };

- [ ] 모니터링 지표(성공/실패)가 정의되어 있는가

### 4.2 Feature Flag 변경 감지 자동화

```typescript
// scripts/feature-flag-review.ts
import { execSync } from "node:child_process";

interface FlagChange {
  flagName: string;
  changeType: "added" | "modified" | "removed";
  file: string;
  environments: string[];
  hasExpiry: boolean;
  hasFallback: boolean;
  hasTests: boolean;
}

interface FlagReviewResult {
  changes: FlagChange[];
  warnings: string[];
  blockers: string[];
}

function detectFlagChanges(baseSha: string, headSha: string): FlagReviewResult {
  const diff = execSync(
    `git diff ${baseSha}..${headSha} -- src/feature-flags/`,
    { encoding: "utf-8" },
  );

  const changes: FlagChange[] = [];
  const warnings: string[] = [];
  const blockers: string[] = [];

  // Flag 정의 파일에서 변경 감지
  const flagPattern = /(?:\+|-).*(?:flag|feature).*['"]([\w-]+)['"]/gi;
  let match: RegExpExecArray | null;
  while ((match = flagPattern.exec(diff)) !== null) {
    const flagName = match[1];
    const isAdded = match[0].startsWith("+");
    const isRemoved = match[0].startsWith("-");

    const changeType = isAdded && !isRemoved ? "added" : isRemoved && !isAdded ? "removed" : "modified";

    const hasExpiry = diff.includes(`expiry`) || diff.includes(`expiresAt`);
    const hasFallback = diff.includes(`fallback`) || diff.includes(`defaultValue`);

    // 테스트 파일 존재 여부
    const testFiles = execSync(
      `git diff --name-only ${baseSha}..${headSha} -- '**/*.test.ts' '**/*.spec.ts'`,
      { encoding: "utf-8" },
    );
    const hasTests = testFiles.includes(flagName);

    if (!hasExpiry && changeType === "added") {
      blockers.push(`[BLOCKER] Flag "${flagName}": 만료일(expiry) 미설정`);
    }

    if (!hasFallback && changeType === "added") {
      warnings.push(`[WARNING] Flag "${flagName}": 폴백 값 미정의`);
    }

    if (!hasTests) {
      warnings.push(`[WARNING] Flag "${flagName}": ON/OFF 테스트 미확인`);
    }

    changes.push({
      flagName,
      changeType,
      file: "src/feature-flags/flags.ts",
      environments: ["preview", "beta", "staging", "production"],
      hasExpiry,
      hasFallback,
      hasTests,
    });
  }

  return { changes, warnings, blockers };
}

export { detectFlagChanges };
export type { FlagChange, FlagReviewResult };
```

## 5. 코드 리뷰 마인드셋 2026

### 5.1 심리적 안전성 기반 리뷰

코드 리뷰는 코드의 품질을 높이는 과정이지, 사람을 평가하는 과정이 아니다.

**좋은 리뷰 vs 나쁜 리뷰 비교:**

| 상황 | 나쁜 예시 | 좋은 예시 |
|------|----------|----------|
| 로직 오류 발견 | "이 코드 왜 이렇게 짰어요?" | "이 부분에서 edge case가 발생할 수 있어요. `amount`가 0일 때 어떻게 동작할까요?" |
| 더 나은 방법 제안 | "이건 안티패턴입니다." | "suggestion: `useMemo`로 감싸면 리렌더링을 줄일 수 있어요. 관련 문서를 첨부합니다." |
| 이해 안 되는 코드 | "이건 뭐예요? 설명 좀..." | "question: 이 변환 로직의 의도가 궁금합니다. 어떤 시나리오를 처리하기 위한 건가요?" |
| 설계 의견 차이 | "이 설계는 틀렸습니다." | "thought: 다른 접근도 고려해볼 수 있을 것 같아요. Strategy 패턴을 쓰면 확장이 쉬워질 수 있는데, 어떻게 생각하세요?" |
| 좋은 코드 발견 | (코멘트 없음) | "praise: 이 에러 핸들링 방식 깔끔하네요. 팀 전체에 공유하면 좋겠어요." |
| 사소한 스타일 | "스타일 가이드 좀 읽으세요." | "nit: 네이밍이 `getUserList`보다 `fetchUsers`가 팀 컨벤션에 맞아요. 다만 blocking은 아닙니다." |

### 5.2 Conventional Comments 고도화

[Conventional Comments](https://conventionalcomments.org/) 형식에 **blocking/non-blocking 데코레이션**을 추가한다.

**형식:**

```
<label> (<decoration>): <subject>

[discussion]
```

**라벨과 데코레이션 체계:**

| 라벨 | 용도 | 기본 데코레이션 |
|------|------|----------------|
| `suggestion` | 개선 제안 | non-blocking |
| `issue` | 반드시 수정 필요 | **blocking** |
| `question` | 이해를 위한 질문 | non-blocking |
| `thought` | 아이디어 공유 | non-blocking |
| `nit` | 사소한 스타일 | non-blocking |
| `praise` | 칭찬 | non-blocking |
| `todo` | 후속 작업 필요 | non-blocking (if-minor) |
| `env` | 환경별 동작 확인 필요 | **blocking** |

### 6.3 AI 자동 PR 설명 생성 (GitHub Actions)

```yaml
# .github/workflows/pr-description.yml
name: Auto PR Description

on:
  pull_request:
    types: [opened]

permissions:
  pull-requests: write
  contents: read

jobs:
  generate-description:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Generate PR Summary
        uses: actions/github-script@v7
        with:
          github-token: ${{ secrets.GITHUB_TOKEN }}
          script: |
            const { execSync } = require('child_process');

            const baseSha = context.payload.pull_request.base.sha;
            const headSha = context.payload.pull_request.head.sha;

            const diff = execSync(
              `git diff --stat ${baseSha}...${headSha}`
            ).toString();

            const files = execSync(
              `git diff --name-only ${baseSha}...${headSha}`
            ).toString().split('\n').filter(Boolean);

            const flagChanges = files.filter(f => f.includes('feature-flag'));
            const infraChanges = files.filter(f => f.startsWith('infra/') || f.startsWith('cdk/'));

            const summary = [
              '## AI 생성 변경 요약',
              '',
              `**변경 파일 수:** ${files.length}개`,
              '',
              '### 변경된 영역',
              ...categorizeFiles(files),
              '',
              flagChanges.length > 0 ? '### Feature Flag 변경 감지\n' + flagChanges.map(f => `- ${f}`).join('\n') + '\n' : '',
              infraChanges.length > 0 ? '### 인프라 변경 감지\n' + infraChanges.map(f => `- ${f}`).join('\n') + '\n' : '',
              '### Diff 통계',
              '```',
              diff,
              '```',
              '',
              '> 이 요약은 자동 생성되었습니다. 정확성을 검증해주세요.',
            ].join('\n');

            const currentBody = context.payload.pull_request.body || '';
            await github.rest.pulls.update({
              owner: context.repo.owner,
              repo: context.repo.repo,
              pull_number: context.payload.pull_request.number,
              body: currentBody + '\n\n---\n\n' + summary,
            });

            function categorizeFiles(files) {
              const categories = {
                'API/Backend': files.filter(f => f.startsWith('src/api/')),
                'Components': files.filter(f => f.startsWith('src/components/')),
                'Feature Flags': files.filter(f => f.includes('feature-flag')),
                'Infrastructure': files.filter(f => f.startsWith('infra/') || f.startsWith('cdk/')),
                'Hooks': files.filter(f => f.startsWith('src/hooks/')),
                'Tests': files.filter(f => f.match(/\.(test|spec)\./)),
                'Config': files.filter(f => f.match(/\.(json|yaml|yml|toml)$/)),
              };

              return Object.entries(categories)
                .filter(([, fs]) => fs.length > 0)
                .map(([cat, fs]) => `- **${cat}:** ${fs.length}개 파일`);
            }

## 7. 리뷰 체크리스트 -- 4관점 심층 가이드

### 7.1 보안

| 체크 항목 | Bad | Good |
|----------|-----|------|
| 사용자 입력 검증 | `eval(userInput)` | `zod.parse(userInput)` |
| SQL 쿼리 | `` `SELECT * FROM users WHERE id = '${id}'` `` | `db.query('SELECT * FROM users WHERE id = $1', [id])` |
| 민감정보 로깅 | `console.log('Token:', token)` | `console.log('Token: [REDACTED]')` |

const UserSchema = z.object({
  id: z.string().uuid(),
  name: z.string().min(1),
  email: z.string().email(),
  role: z.enum(["admin", "member", "viewer"]),
  createdAt: z.string().datetime(),
});

type User = z.infer<typeof UserSchema>;

async function fetchUser(id: string): Promise<User> {

  if (!response.ok) {
    throw new HttpError(response.status, `사용자 조회 실패: ${id}`);

### 9.2 GitHub API 측정 스크립트

```typescript
// scripts/review-metrics.ts
import { Octokit } from "@octokit/rest";

interface ReviewMetrics {
  prNumber: number;
  title: string;
  linesChanged: number;
  targetEnvironment: string;
  timeToFirstReviewHours: number;
  timeToMergeHours: number;
  reviewRounds: number;
  reviewerCount: number;
  hasPreviewUrl: boolean;
  hasFeatureFlagChange: boolean;
}

async function collectReviewMetrics(
  owner: string,
  repo: string,
  days: number = 30,
): Promise<ReviewMetrics[]> {
  const octokit = new Octokit({ auth: process.env.GITHUB_TOKEN });
  const since = new Date(Date.now() - days * 24 * 60 * 60 * 1000);

  const { data: pulls } = await octokit.pulls.list({
    owner,
    repo,
    state: "closed",
    sort: "updated",
    direction: "desc",
    per_page: 100,
  });

  const mergedPRs = pulls.filter(
    (pr) => pr.merged_at && new Date(pr.created_at) >= since,
  );

  const metrics: ReviewMetrics[] = [];

  for (const pr of mergedPRs) {
    const { data: reviews } = await octokit.pulls.listReviews({
      owner,
      repo,
      pull_number: pr.number,
    });

    const { data: files } = await octokit.pulls.listFiles({
      owner,
      repo,
      pull_number: pr.number,
    });

    const humanReviews = reviews.filter(
      (r) => !r.user?.login?.includes("[bot]"),
    );

    const firstReview = humanReviews[0];
    const createdAt = new Date(pr.created_at).getTime();
    const mergedAt = new Date(pr.merged_at!).getTime();
    const firstReviewAt = firstReview
      ? new Date(firstReview.submitted_at!).getTime()
      : mergedAt;

    const reviewRounds = new Set(
      humanReviews
        .filter((r) => r.state === "CHANGES_REQUESTED")
        .map((r) => r.user?.login),
    ).size;

    // 환경 판별
    const baseBranch = pr.base.ref;
    let targetEnvironment = "production";
    if (baseBranch.startsWith("beta")) targetEnvironment = "beta";
    else if (baseBranch === "develop" || baseBranch === "staging")
      targetEnvironment = "staging";

    // Feature Flag 변경 감지
    const hasFeatureFlagChange = files.some((f) =>
      f.filename.includes("feature-flag"),
    );

    // Preview URL 존재 여부
    const { data: comments } = await octokit.issues.listComments({
      owner,
      repo,
      issue_number: pr.number,
    });
    const hasPreviewUrl = comments.some((c) =>
      c.body?.includes("Preview Environment"),
    );

    metrics.push({
      prNumber: pr.number,
      title: pr.title,
      linesChanged: (pr.additions ?? 0) + (pr.deletions ?? 0),
      targetEnvironment,
      timeToFirstReviewHours:
        Math.round(
          ((firstReviewAt - createdAt) / (1000 * 60 * 60)) * 10,
        ) / 10,
      timeToMergeHours:
        Math.round(((mergedAt - createdAt) / (1000 * 60 * 60)) * 10) /
        10,
      reviewRounds,
      reviewerCount: new Set(humanReviews.map((r) => r.user?.login)).size,
      hasPreviewUrl,
      hasFeatureFlagChange,
    });
  }

  return metrics;
}

async function printSummary(owner: string, repo: string): Promise<void> {
  const metrics = await collectReviewMetrics(owner, repo);

  if (metrics.length === 0) {
    console.log("측정 대상 PR이 없습니다.");
    return;
  }

  const avg = (arr: number[]) =>
    Math.round((arr.reduce((a, b) => a + b, 0) / arr.length) * 10) / 10;

  const avgFirstReview = avg(metrics.map((m) => m.timeToFirstReviewHours));
  const avgMergeTime = avg(metrics.map((m) => m.timeToMergeHours));
  const avgSize = avg(metrics.map((m) => m.linesChanged));
  const oversizedPRs = metrics.filter((m) => m.linesChanged > 500).length;
  const previewUsage = metrics.filter((m) => m.hasPreviewUrl).length;
  const flagChangePRs = metrics.filter((m) => m.hasFeatureFlagChange).length;

  // 환경별 통계
  const byEnv = Object.groupBy(metrics, (m) => m.targetEnvironment);

  console.log("=== 코드 리뷰 메트릭스 (최근 30일) ===");
  console.log(`분석 PR 수: ${metrics.length}개`);
  console.log(`평균 최초 리뷰 시간: ${avgFirstReview}시간 (목표: <4시간)`);
  console.log(`평균 머지 시간: ${avgMergeTime}시간 (목표: <24시간)`);
  console.log(`평균 PR 크기: ${avgSize}줄 (목표: <500줄)`);
  console.log(
    `500줄 초과 PR: ${oversizedPRs}개 (${Math.round((oversizedPRs / metrics.length) * 100)}%)`,
  );
  console.log(
    `Preview 환경 활용률: ${Math.round((previewUsage / metrics.length) * 100)}%`,
  );
  console.log(`Feature Flag 변경 PR: ${flagChangePRs}개`);

  console.log("\n=== 환경별 통계 ===");
  for (const [env, envMetrics] of Object.entries(byEnv)) {
    if (!envMetrics) continue;
    const envAvgMerge = avg(envMetrics.map((m) => m.timeToMergeHours));
    console.log(`  ${env}: ${envMetrics.length}개 PR, 평균 머지 ${envAvgMerge}시간`);
  }
}

// 실행
const [owner, repo] = (process.env.GITHUB_REPOSITORY ?? "/").split("/");
printSummary(owner, repo).catch(console.error);
```

## 10. 원격/비동기 팀 리뷰 전략

### 10.1 시차 대응 전략

| 전략 | 설명 | 적용 시점 |

| **시간대별 리뷰어 풀** | CODEOWNERS에 시간대별 그룹 구성 | PR 생성 시 |
| **AI 1차 리뷰 위임** | 비업무시간 PR은 AI가 즉시 1차 리뷰 | 자동 |
| **Preview 환경 활용** | 시차가 있어도 Preview URL로 비동기 시각적 검증 | 상시 |

### 10.2 Pair Review 패턴

| 상황 | 권장 방식 |
|------|----------|
| 500줄 이하, 단순 변경 | 비동기 리뷰 |
| 500줄 이상, 복잡한 로직 | **Pair Review** |
| 신규 아키텍처 도입 | **Pair Review** + 문서화 |
| 보안 민감 변경 | **Pair Review** (보안 전문가 참여) |
| Feature Flag 전략 변경 | **Pair Review** (환경 전문가 참여) |
| 멀티 베타 인프라 변경 | **Pair Review** (DevOps 참여) |

### 10.3 리뷰 문화 성숙도 모델

| 단계 | 특징 | 목표 |
|------|------|------|
| **Level 1: 기본** | 리뷰 의무화, 1명 이상 승인 | 리뷰 습관 형성 |
| **Level 2: 구조화** | Conventional Comments, PR 템플릿, SLA | 리뷰 품질 표준화 |
| **Level 3: 자동화** | AI 리뷰, CI 품질 게이트, CODEOWNERS | 사람의 리뷰 부담 감소 |
| **Level 4: 멀티 환경** | 환경별 리뷰 정책, Preview 리뷰, Feature Flag 체크 | 배포 안전성 확보 |
| **Level 5: 데이터 기반** | 메트릭스 측정, DORA 연계, 환경별 리포트 | 지속적 개선 |
| **Level 6: 문화** | 심리적 안전성, Pair Review, 멘토링 | 팀 역량 전체 향상 |
