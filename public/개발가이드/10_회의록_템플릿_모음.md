## 1. AI 회의록 자동 작성 도구 비교

### 1.1 도구 비교표

| 도구 | 실시간 전사 | 화자 구분 | AI 요약 | 액션 아이템 추출 | 한국어 지원 | 주요 연동 | 월 요금 (팀) |
|------|:---:|:---:|:---:|:---:|:---:|------|------|
| **Otter.ai** | O | O | O | O | 베타 | Zoom, Teams, Google Meet, Slack | $20/인 |
| **Fireflies.ai** | O | O | O | O | O | Zoom, Teams, Google Meet, Slack, HubSpot | $19/인 |
| **Clova Note** | O | O | O | O | 최적화 | 네이버 워크플레이스, Zoom | 무료~$10/인 |
| **tl;dv** | O | O | O | O | O | Zoom, Google Meet, HubSpot, Salesforce | $25/인 |
| **Granola** | O | - | O | O | 영어 | macOS 네이티브 (앱 단독) | $12/인 |

### 1.2 도구 선택 가이드

| 팀 상황 | 추천 도구 | 이유 |
|---------|----------|------|
| 한국어 회의 중심 | **Clova Note** | 한국어 전사 정확도 최고, 무료 플랜 제공 |
| 글로벌 팀 (영어 + 한국어) | **Fireflies.ai** | 다국어 지원 우수, 다양한 연동 |
| 영업/고객 미팅 다수 | **tl;dv** | CRM 연동, 고객 인사이트 자동 추출 |
| 소규모 팀 (macOS) | **Granola** | 가볍고 빠름, 회의 메모와 전사 결합 |
| 엔터프라이즈 | **Otter.ai** | 보안 인증, 대규모 팀 관리 기능 |

### 1.3 AI 회의록 활용 워크플로우

```
1. 회의 시작 전
   +-- AI 전사 도구 활성화 (자동 녹음 + 전사)
   +-- 참석자 전원에게 녹음 동의 확인

2. 회의 중
   +-- AI가 실시간 전사 수행
   +-- 참석자는 핵심 논점에만 집중
   +-- 수동으로 중요 포인트 태깅 (하이라이트)

3. 회의 직후 (5분 이내)
   +-- AI 요약 검토 및 수정
   +-- 액션 아이템 확인 및 담당자 지정
   +-- 잘못된 전사/요약 보정 (고유명사, 기술 용어)

4. 회의 후 (24시간 이내)
   +-- 정리된 회의록 팀 채널에 공유
   +-- 액션 아이템 이슈 트래커에 등록
   +-- 후속 회의 일정 확인
```

### 1.4 AI 회의록 사용 시 주의사항

- **프라이버시**: 녹음/전사 전 참석자 전원의 동의를 받는다
- **보안**: 민감한 정보(인사, 보안, 법률)가 다뤄지는 회의는 AI 전사를 비활성화한다
- **정확도 검증**: AI 전사/요약은 반드시 사람이 검토한다 (특히 고유명사, 기술 용어)
- **보관 정책**: 녹음 데이터의 보관 기간과 접근 권한을 명확히 정한다

## 2. Claude/GPT로 회의록 요약 및 액션 아이템 추출

AI 전사 도구가 없거나 더 정교한 요약이 필요할 때, Claude나 GPT에 회의 내용을 직접 입력하여 요약과 액션 아이템을 추출할 수 있다.

### 2.1 프롬프트 예시 1: 회의록 요약 + 액션 아이템 추출

```text
아래 회의 내용을 다음 형식으로 정리해줘:

[출력 형식]
## 회의 요약
- 핵심 논의 사항 3~5개를 bullet point로 정리
- 각 항목은 "누가 무엇을 논의/결정했는지" 형태로 작성

## 핵심 결정 사항
- 결정된 사항과 그 근거를 정리

## 액션 아이템
| 담당자 | 할 일 | 마감일 | 우선순위 |
으로 테이블 작성

## 미해결 사항
- 추가 논의가 필요한 사항

## 다음 회의 안건
- 이번 회의에서 이어져야 할 주제

[회의 내용]
{회의 전사 내용 또는 메모 붙여넣기}
```

### 2.2 프롬프트 예시 2: 기술 회의 심층 요약 + 의사결정 기록

```text
아래 기술 회의 내용을 분석하고 다음 형식으로 정리해줘:

[출력 형식]
## 회의 개요
- 일시, 참석자, 주요 안건을 1~2줄로 요약

## 기술 논의 요약
각 안건별로:
- **배경**: 왜 이 주제가 논의되었는지
- **논의 내용**: 제시된 의견들과 근거
- **결정**: 최종 결정 사항과 선택 이유
- **트레이드오프**: 선택으로 인해 포기한 것

## 아키텍처 결정 기록 (ADR)
| 결정 | 대안 | 선택 이유 | 리스크 |
으로 테이블 작성

## 액션 아이템
| 담당자 | 할 일 | 마감일 | 의존성 |
으로 테이블 작성 (의존성이 있으면 명시)

## 후속 검증 필요 사항
- POC/벤치마크가 필요한 항목

[기술 회의 내용]
{회의 전사 내용 또는 메모 붙여넣기}
```

### 2.3 활용 팁

- **전사 텍스트 + 수기 메모를 함께 입력**하면 AI 요약 정확도가 높아진다
- **프로젝트 맥락**(기술 스택, 팀 구조, 진행 중인 프로젝트)을 프롬프트에 포함하면 더 정확한 요약을 얻을 수 있다
- 요약 결과는 **반드시 참석자 1명 이상이 검토**한 뒤 공유한다
- 민감한 회의 내용은 AI에 입력하지 않는다

## 3. 위클리 미팅 템플릿

### 목적

- 지난주 진행 상황 리뷰 및 이번주 계획 공유
- 이슈 및 블로커 논의
- 팀 동기화 및 소통

### 템플릿

```markdown

**날짜**: YYYY-MM-DD (요일) HH:MM
**참석자**: @name1, @name2, @name3
**불참**: @name4 (사유)
**작성자**: @name1
**AI 전사**: [활성 / 비활성]

|--------|-------------|------|------|
| @name1 | {할 일} | 완료 / 진행중 / 미완료 | {비고} |

---

## 팀별 진행 상황

### {팀/파트 이름}

**진행**:
- {완료한 작업 1}
- {완료한 작업 2}

- {발생한 이슈}

**논의 필요**:
- {논의가 필요한 사항}

|--------|----------|----------|--------|

### Important
1. **{이슈 제목}**
   - 현상: {설명}

---

## 논의 사항

### {주제}
**제안**: @name
**내용**: {내용}
**의견**:
- @name: {의견}
```

## 5. 스프린트 회고 템플릿

### 목적

- 스프린트 동안 잘한 점 공유 및 개선점 식별
- 다음 스프린트 액션 아이템 도출
- 팀 성장과 학습 촉진

### 5.1 KPT (Keep / Problem / Try)

```markdown
# 스프린트 회고 (KPT) - Sprint {번호}

**날짜**: YYYY-MM-DD
**Sprint 기간**: YYYY-MM-DD ~ YYYY-MM-DD
**참석자**: @name1, @name2, @name3
**퍼실리테이터**: @name1

---

## Sprint Overview

- **완료**: {N}개 스토리 ({N} 포인트)
- **미완료**: {N}개 스토리 ({N} 포인트)
- **Velocity**: {N} (목표: {N})

---

## Keep (계속할 것)

1. **{제목}** - @name
   - 내용: {무엇이 잘 되었는지}
   - 효과: {어떤 긍정적 결과가 있었는지}

---

## Problem (문제점)

1. **{제목}** - @name
   - 문제: {무엇이 문제였는지}
   - 원인: {왜 발생했는지}
   - 영향: {어떤 부정적 영향이 있었는지}

---

## Try (시도할 것)

1. **{제목}** - @name
   - 제안: {무엇을 시도할 것인지}
   - 기대 효과: {어떤 개선이 예상되는지}
   - 담당: @name
   - 마감: {기한}

---

## Action Items

| 담당자 | Action Item | 마감일 | 측정 방법 |
|--------|-------------|--------|----------|
| @name | {할 일} | {마감} | {어떻게 측정할 것인지} |
```

```markdown
## Lacked (부족했던 것)

## Longed For (바라는 것)

- {다음 스프린트에서 갖고 싶은 것}
- {개선되었으면 하는 프로세스나 환경}

---

## Action Items

| 담당자 | Action Item | 마감일 |
|--------|-------------|--------|
| @name | {할 일} | {마감} |
```

## 6. 1:1 미팅 템플릿

### 목적

- 팀원의 성장과 만족도 확인
- 업무 장애물 제거
- 신뢰 관계 구축

### 템플릿

```markdown
# 1:1 미팅

**날짜**: YYYY-MM-DD (요일) HH:MM
**참석자**: @manager, @team-member
**장소**: {장소 또는 화상 회의 링크}

---

## 근황 체크

**컨디션**: {좋음 / 보통 / 힘듦}
**최근 하이라이트**: {좋았던 일}
**최근 어려웠던 점**: {힘들었던 일}

---

## 업무 논의

### 현재 진행 중인 업무
```

## 8. 비동기 회의 대안

### 8.1 비동기 커뮤니케이션이 적합한 경우

| 상황 | 비동기 적합 | 동기(회의) 적합 |
|------|:---:|:---:|
| 상태 공유/업데이트 | O | - |
| 코드 리뷰 논의 | O | - |
| 문서 리뷰/피드백 | O | - |
| 급한 장애 대응 | - | O |
| 감정이 얽힌 갈등 해결 | - | O |
| 브레인스토밍 | - | O |
| 1:1 피드백 | - | O |
| RFC 논의 | O (기본) | O (쟁점 시) |

### 8.2 Loom (비동기 영상 메시지)

**활용 시나리오**:
- 코드 리뷰 설명 (화면 공유 + 음성)
- 기술 의사결정 배경 설명
- 신규 기능 데모
- 온보딩 자료

**작성 가이드**:

```markdown
## Loom 녹화 가이드

1. 제목: [카테고리] 구체적 주제 (예: [코드리뷰] PR-123 인증 로직 변경 설명)
2. 길이: 5분 이내 권장 (최대 10분)
3. 구조:
   - 0:00 - 배경/목적 (30초)
   - 0:30 - 핵심 내용 (3~4분)
   - 4:30 - 요청 사항/질문 (30초)
4. 공유: 팀 채널에 링크 + 핵심 요약 1~2줄
5. 응답 기한: 2영업일 이내
```

### 8.3 Notion 코멘트 (비동기 문서 리뷰)

**활용 시나리오**:
- RFC 비동기 리뷰
- 문서 피드백
- 비동기 브레인스토밍

**코멘트 작성 규칙**:

```markdown
## 코멘트 유형 태그

[질문] - 답변이 필요한 질문
[제안] - 개선 제안 (반영 여부는 작성자 판단)
[우려] - 리스크나 우려 사항 (반드시 논의 필요)
[동의] - 해당 내용에 동의 (근거 1줄 이상)
[반대] - 해당 내용에 반대 (대안 제시 필수)

## 예시
[우려] 이 방식은 기존 API와의 하위 호환성을 깨뜨릴 수 있습니다.
대안으로 버전닝을 통한 점진적 전환을 제안합니다.
```

### 8.4 비동기 스탠드업

매일 동기 스탠드업 미팅 대신 비동기 스탠드업을 운영할 수 있다.

```markdown
## 비동기 스탠드업 - YYYY-MM-DD

### @name1
**어제**: {완료한 작업}
**오늘**: {오늘 할 작업}
**블로커**: {없음 / 블로커 설명}

### @name2
**어제**: {완료한 작업}
**오늘**: {오늘 할 작업}
**블로커**: {없음 / 블로커 설명}
```

**운영 규칙**:
- 매일 오전 10시까지 작성
- 블로커가 있으면 즉시 관련자 멘션
- 주 1회는 동기 미팅으로 진행 (팀 동기화)

### 8.5 비동기 회의 도구 비교

| 도구 | 유형 | 주요 특징 | 적합한 상황 |
|------|------|----------|-----------|
| **Loom** | 비동기 영상 | 화면 녹화 + 음성, AI 요약 | 코드 리뷰 설명, 데모, 온보딩 |
| **Notion 코멘트** | 비동기 텍스트 | 문서 인라인 코멘트, 스레드 | RFC 리뷰, 문서 피드백 |
| **Slack 스레드** | 비동기 텍스트 | 빠른 의견 교환, 이모지 반응 | 간단한 논의, 투표 |
| **GitHub Discussions** | 비동기 텍스트 | 코드 연동, 카테고리 분류 | 기술 결정, 오픈 논의 |
| **Figma 코멘트** | 비동기 텍스트 | 디자인 위 직접 코멘트 | UI/UX 리뷰 |
