## 1. 위클리 미팅 (Weekly Meeting)

### 목적
- 지난주 진행 상황 리뷰
- 이번주 계획 공유
- 이슈 및 블로커 논의
- 팀 협업 및 소통

### 템플릿

```markdown
# 📅 위클리 미팅 - {팀명}

**날짜**: YYYY-MM-DD (요일) HH:MM
**참석자**: @name1, @name2, @name3
**불참**: @name4 (사유: 연차)
**작성자**: @name1

---

## 🎯 지난주 Action Items 리뷰

| 담당자 | Action Item | 상태 | 비고 |
|-------|-------------|------|------|
| @name1 | API 문서 작성 | ✅ 완료 | [링크](url) |
| @name2 | 배포 자동화 | 🔄 진행중 | 80% 완료, 금요일 예정 |
| @name3 | 버그 수정 #123 | ❌ 미완료 | 다음주로 이월 |

---

**진행**:
- 결제 페이지 UI 리뉴얼 완료
- 성능 최적화 (LCP 2.8s → 2.1s)

**이슈**:
- API 응답 지연 (백엔드 팀과 협의 필요)

**논의 필요**:
- Next.js 14 업그레이드 검토

### Backend Team
**진행**:
- 주문 API 성능 개선 (응답시간 40% 감소)

**이슈**:
- 결제 API 간헐적 타임아웃 발생
```

## 3. 스프린트 회고 (Sprint Retrospective)

### 목적
- 스프린트 동안 잘한 점 공유
- 개선이 필요한 점 식별

### 템플릿

```markdown

**날짜**: YYYY-MM-DD
**Sprint 기간**: YYYY-MM-DD ~ YYYY-MM-DD
**참석자**: @name1, @name2, @name3, @name4
**퍼실리테이터**: @name1
**작성자**: @name2

---

- **Velocity**: 75 (목표: 80)

- ✅ {성과 2}
```

## 회의록 작성 팁

### 1. 회의 중 작성
- 회의 중에 실시간으로 작성 (회의 후 기억에 의존하지 않기)
- 공유 문서 사용 (Notion, Confluence, Google Docs)
- 참석자가 함께 볼 수 있도록

### 2. 명확한 Action Items
- ❌ "성능 개선 검토"
- ✅ "@name1이 LCP 2초 이하로 개선, 마감: 금요일"

### 3. 결정 사항 명확히
- ✅ 결정: Redis 도입
- ❌ 미결: 더 논의 필요
- ⏸️ 보류: 3개월 후 재검토

### 4. 24시간 내 공유
- 회의 직후 공유 (기억이 생생할 때)
- Slack에 링크 공유
- 관련 팀에 알림

### 5. Action Items 추적
- JIRA 티켓 생성
- 다음 회의에서 리뷰
- 완료 여부 확인

## 정리

효과적인 회의록은:
- **구조화**: 템플릿 사용으로 일관성
- **명확성**: 누가, 무엇을, 언제
- **추적 가능**: Action Items로 실행력
- **공유**: 팀 전체가 동기화

회의록은 단순한 기록이 아니라 **팀의 의사결정 히스토리**입니다!
