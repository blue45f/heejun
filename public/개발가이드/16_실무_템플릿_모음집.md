## 1. AI 기반 문서 자동 생성 전략

### 1.1 핵심 원칙

AI를 활용한 문서 생성에서 가장 중요한 것은 **"AI가 초안을 생성하고, 사람이 맥락을 검증한다"** 는 원칙이다. AI는 구조화, 데이터 분석, 문체 통일에 탁월하지만, 팀 고유의 맥락과 비즈니스 판단은 사람이 담당한다.

### 1.2 문서 유형별 AI 활용 전략

| 문서 유형 | AI 자동화 범위 | 추천 도구 | 사람 검토 수준 |
|----------|--------------|----------|:---:|
| 성능 리포트 | 데이터 분석, 개선 제안, 비교표 자동 생성 | Claude, GPT | 필수 |
| 기술 문서 | 초안 생성, 코드 예시 작성, API 문서화 | Claude, Copilot | 필수 |
| 버그 리포트 | 로그 분석, 원인 추정, 재현 단계 추출 | Claude, Sentry AI | 권장 |
| 릴리즈 노트 | Git 커밋/PR 기반 전체 자동 생성 | Release Drafter + Claude | 필수 |
| 포스트모템 | 타임라인 정리, 근본 원인 분석, 재발 방지 제안 | Claude, GPT | 필수 |
| 기술 블로그 | 구성 제안, 초안 생성, 비유/예시 보강 | Claude, GPT | 필수 |

### 1.3 AI 문서 생성 프롬프트 5가지

#### 프롬프트 1: 범용 문서 초안 생성

```text
당신은 시니어 테크니컬 라이터입니다. 아래 조건으로 {문서 유형}을 작성해주세요.

[배경]
- {상황 설명}

[포함 내용]
- {필수 포함 항목 나열}

[형식]
- 마크다운 형식
- 표와 코드 블록 활용
- 실행 가능한 액션 아이템 포함

[대상 독자]
- {독자 수준/역할}

[주의사항]
- 추측이 아닌 사실 기반 작성
- 출처가 불확실한 데이터는 "[확인 필요]" 표시
- 팀이 채워야 할 부분은 {placeholder}로 표시
```

#### 프롬프트 2: 성능 리포트 자동 분석

```text
아래 성능 측정 데이터를 분석하여 성능 리포트를 작성해주세요.

[측정 데이터]
{Lighthouse/RUM 결과 붙여넣기}

[출력 요구사항]
1. Executive Summary (3줄 이내)
2. Core Web Vitals 상세 분석 (LCP, INP, CLS)
3. 이전 측정 대비 변화 분석 (이전 데이터: {붙여넣기})
4. 문제 페이지 Top 3와 개선 방안
5. 비즈니스 영향 추정 (이탈률, 전환율 상관관계)
6. 우선순위별 Next Steps (단기/중기/장기)
```

#### 프롬프트 3: 버그 리포트 로그 분석

```text
아래 에러 로그와 스택 트레이스를 분석하여 버그 리포트를 작성해주세요.

[에러 로그]
{로그 붙여넣기}

[스택 트레이스]
{스택 트레이스 붙여넣기}

[출력 요구사항]
1. 버그 요약 (1줄)
2. 심각도 판단 (Critical/High/Medium/Low) + 근거
3. 추정 원인 (직접 원인 + 근본 원인)
4. 재현 단계 추정
5. 영향 범위 추정
6. 수정 방향 제안 (코드 레벨)
7. "[확인 필요]" 항목 목록 (AI 추정이라 검증이 필요한 부분)
```

#### 프롬프트 4: 기술 문서 자동 생성 (Copilot 연동)

```text
아래 소스 코드를 기반으로 기술 문서를 작성해주세요.

[소스 코드]
{코드 붙여넣기}

[출력 요구사항]
1. 개요: 이 코드가 해결하는 문제 (1-2문장)
2. 빠른 시작 가이드 (설치 -> 기본 사용법)
3. API 레퍼런스 (함수/메서드별 시그니처, 파라미터, 반환값)
4. 실전 예제 2-3개 (단순 -> 복잡 순)
5. 베스트 프랙티스 (Do / Don't)
6. 트러블슈팅 FAQ 3가지
```

#### 프롬프트 5: 주간/월간 개발 리포트 자동 생성

```text
아래 데이터를 기반으로 {주간/월간} 개발 리포트를 작성해주세요.

[Git 활동 요약]
{git shortlog --summary --since="1 week ago" 결과}

[완료된 PR 목록]
{PR 제목 및 번호 목록}

[배포 이력]
{배포 날짜, 버전, 주요 내용}

[이슈 현황]
- 신규: {N}건
- 해결: {N}건
- 미해결: {N}건

[출력 요구사항]
1. 핵심 성과 요약 (3줄)
2. 카테고리별 완료 항목 (기능/개선/버그/인프라)
3. 주요 수치 변화 (성능, 에러율, 테스트 커버리지)
4. 다음 주기 계획
5. 블로커/리스크
```

### 1.4 AI 생성 문서 품질 체크리스트

- [ ] AI가 생성한 데이터/수치의 정확성을 검증했는가
- [ ] 팀/프로젝트 고유 맥락이 정확히 반영되었는가
- [ ] 기술 용어가 정확하게 사용되었는가
- [ ] 실행 가능한 액션 아이템이 포함되었는가
- [ ] 불필요한 일반론이 제거되었는가
- [ ] "[확인 필요]" 표시된 항목이 모두 검증되었는가

## 5. AI 기반 릴리즈 노트 자동 생성

### 5.1 Release Drafter + AI 파이프라인

Release Drafter로 기본 릴리즈 노트를 자동 생성한 후, AI로 사용자 친화적 문구로 다듬는 2단계 파이프라인을 구성한다.

#### 1단계: Release Drafter 설정

```yaml
# .github/release-drafter.yml
name-template: 'v$RESOLVED_VERSION'
tag-template: 'v$RESOLVED_VERSION'
categories:
  - title: 'New Features'
    labels:
      - 'feature'
      - 'enhancement'
  - title: 'Bug Fixes'
    labels:
      - 'fix'
      - 'bugfix'
  - title: 'Performance'
    labels:
      - 'performance'
  - title: 'Documentation'
    labels:
      - 'documentation'
  - title: 'Dependencies'
    labels:
      - 'dependencies'
change-template: '- **$TITLE** (#$NUMBER) @$AUTHOR'
template: |
  ## Changes
  $CHANGES

  ## Contributors
  $CONTRIBUTORS
```

#### 2단계: AI로 릴리즈 노트 다듬기 프롬프트

```text
아래 Release Drafter가 자동 생성한 릴리즈 노트를 사용자 친화적으로 다듬어주세요.

[Release Drafter 출력]
{Release Drafter 결과 붙여넣기}

[다듬기 규칙]
1. PR 제목의 개발 용어를 사용자가 이해할 수 있는 설명으로 변환
2. "fix: 쿼리 N+1 문제 해결" -> "검색 결과 로딩 속도가 개선되었습니다"
3. Breaking Changes가 있으면 마이그레이션 가이드 추가
4. 성능 개선 항목은 Before/After 수치 포함
5. 내부 리팩토링은 "내부 개선" 카테고리로 요약
```

#### 3단계: Git 커밋 로그 기반 AI 릴리즈 노트 (Release Drafter 없이)

```text
아래 Git 커밋 로그를 기반으로 릴리즈 노트를 작성해주세요:

[커밋 로그]
{git log --oneline v1.2.0..HEAD 결과 붙여넣기}

[형식]
- 새로운 기능 / 개선 사항 / 버그 수정 / 성능 개선 / Breaking Changes 분류
- 각 항목에 PR 번호 포함
- 사용자 관점에서 이해할 수 있는 설명
- 기술적 세부사항은 최소화
- 주요 변경사항 상단에 하이라이트 배치
```

## 6. AI 기반 포스트모템 초안 자동 생성

### 6.1 AI 포스트모템 초안 생성 프롬프트

장애 발생 후, 로그와 타임라인 데이터를 AI에 입력하여 포스트모템 초안을 자동 생성한다.

```text
당신은 SRE 엔지니어입니다. 아래 장애 정보를 기반으로 포스트모템 리포트 초안을 작성해주세요.

[장애 개요]
- 발생 시각: {YYYY-MM-DD HH:MM}
- 복구 시각: {YYYY-MM-DD HH:MM}
- 영향 서비스: {서비스명}
- 영향 사용자 수: {추정 수}

[알림/모니터링 로그]
{알림 로그 붙여넣기}

[에러 로그 / 스택 트레이스]
{에러 로그 붙여넣기}

[대응 이력 (Slack/채팅 기록)]
{주요 대응 메시지 붙여넣기}

[배포 이력]
{장애 전후 배포 이력}

[출력 요구사항]
1. 요약 (2-3문장)
2. 타임라인 (시각별 이벤트 표)
3. 영향 분석 (사용자/비즈니스)
4. 근본 원인 분석 (직접 원인 + 근본 원인 + 기여 요인)
5. 대응 평가 (잘한 점 + 개선할 점)
6. 재발 방지 대책 (수정/예방/감지, 우선순위별)
7. 교훈 2-3가지
8. "[확인 필요]" 항목 목록
```

{장애 현상 설명}

[에러 로그]
{로그 붙여넣기}

[출력]

  Why 2: {왜 그런 직접 원인이 발생했는가}
    Why 3: {왜 그 상황이 가능했는가}
      Why 4: {왜 그 조건이 존재했는가}
        Why 5: {근본 원인}

[근본 원인 요약]
{1문장 요약}

[재발 방지 제안]

- 예방: {근본 원인 해결}

### 6.4 포스트모템 작성 원칙

1. **비난하지 않는다 (Blameless)**: 사람이 아닌 시스템과 프로세스에 집중한다
2. **사실 기반 작성**: 추측이 아닌 로그, 메트릭, 타임라인 기반으로 작성한다
3. **재발 방지에 집중**: "누가 실수했는가"가 아니라 "어떻게 방지할 것인가"에 초점
4. **48시간 이내 작성**: 기억이 선명할 때 작성하고, 1주 이내 리뷰 완료
5. **AI 보조 적극 활용**: 로그 분석, 타임라인 정리, 5 Whys 분석, 재발 방지 대책 초안을 AI로 생성하여 작성 시간 단축

## 7. AI 기반 기술 블로그 초안 자동 작성

### 7.1 블로그 초안 생성 프롬프트

```text
당신은 기술 블로그 에디터입니다. 아래 정보를 기반으로 기술 블로그 초안을 작성해주세요.

[주제]
{블로그 주제}

[우리 팀의 경험]
- 문제 상황: {겪은 문제}
- 시도한 방법: {시도 1}, {시도 2}, {시도 3}
- 최종 해결책: {채택한 방법}
- 결과: {Before/After 수치}

[대상 독자]
{주니어 개발자 / 같은 문제를 겪는 팀 / 등}

[출력 요구사항]
1. 독자의 관심을 끄는 제목 3가지 후보
2. 한 문장 요약 (이 글에서 무엇을 배울 수 있는지)
3. 글 구성:
   - 배경 (독자가 공감할 수 있는 문제 제시)
   - 문제 정의 (데이터와 수치로 구체화)
   - 해결 과정 (시행착오 포함, 단계별)
   - 결과 (Before/After 표)
   - 교훈 3가지
   - 독자가 바로 적용할 수 있는 팁 3가지
4. 핵심 코드 예시 삽입 위치 표시
5. 시각 자료(다이어그램, 차트) 삽입 제안
```

### 7.2 블로그 구성 개선 프롬프트

```text
아래 기술 블로그 초안을 리뷰하고 개선해주세요.

[초안]
{초안 붙여넣기}

[리뷰 관점]
1. 제목이 구체적이고 클릭을 유도하는가?
2. 도입부에서 독자의 문제 공감을 이끌어내는가?
3. 기술적 깊이와 접근성의 균형이 적절한가?
4. Before/After 데이터가 충분한가?
5. 코드 예시가 핵심만 담고 있는가?
6. 결론에서 독자가 바로 실행할 수 있는 액션이 있는가?

[출력]
- 섹션별 개선 제안
- 수정된 전체 초안
```

### 7.4 기술 블로그 작성 팁

1. **구체적인 제목**: "성능 개선기"보다 "LCP를 3.8초에서 1.2초로 줄인 방법"이 낫다
2. **데이터로 말하기**: 주관적 평가보다 Before/After 수치를 보여준다
3. **실패도 공유**: 시행착오 과정이 독자에게 더 큰 가치를 줄 수 있다
4. **코드는 핵심만**: 전체 코드가 아닌 핵심 로직만 발췌한다
5. **AI 초안 활용**: AI로 구조와 초안을 잡되, 팀의 실제 경험과 인사이트로 보완한다
6. **AI 리뷰 활용**: 완성된 초안을 AI에게 리뷰 요청하여 구성과 가독성을 개선한다
