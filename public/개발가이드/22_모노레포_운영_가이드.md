> **"모노레포는 단순히 코드를 한데 모으는 것이 아니라, 서비스 간의 경계를 허물고 재사용성을 극대화하는 플랫폼이다."**
> 본 가이드는 pnpm workspace와 Turborepo를 활용하여 거대 코드베이스를 효율적으로 관리하는 표준 구조를 제시합니다.

## 1. 모노레포 구조 설계 (Standard Layout)

모든 코드는 `apps`와 `packages`로 분리하여 관리합니다.

```text
root/
├── apps/               # 배포 가능한 독립 애플리케이션
│   ├── admin/          # 관리자 대시보드 (React 19)
│   └── web/            # 사용자 웹 사이트 (Next.js 15)
├── packages/           # 재사용 가능한 라이브러리 (Shared)
│   ├── ui/             # 공통 UI 컴포넌트 (Tailwind v4)
│   ├── config/         # ESLint, Biome, TypeScript 공통 설정
│   └── api/            # OpenAPI 기반 API 클라이언트 및 타입
├── pnpm-workspace.yaml # 워크스페이스 정의
└── turbo.json          # Turborepo 빌드 파이프라인
```

---

## 2. Turborepo v2: 고성능 빌드 파이프라인

Turborepo는 빌드 결과를 캐싱하여 이미 수행된 작업을 건너뜁니다.

### 2.1 `turbo.json` 설정 예시
```json
{
  "$schema": "https://turbo.build/schema.json",
  "pipeline": {
    "build": {
      "dependsOn": ["^build"], // 상위 의존성 패키지가 먼저 빌드되어야 함
      "outputs": ["dist/**", ".next/**", "!.next/cache/**"]
    },
    "test": {
      "outputs": []
    },
    "lint": {
      "outputs": []
    }
  }
}
```

### 2.2 원격 캐싱 (Remote Caching)
로컬에서의 빌드 캐시를 CI 환경이나 동료의 컴퓨터와 공유하여 팀 전체의 빌드 시간을 단축합니다. (Vercel 또는 자체 캐시 서버 활용)

---

## 3. 의존성 관리: pnpm Workspace

`pnpm`은 하드 링크를 사용하여 중복된 패키지 설치를 방지하고 속도가 매우 빠릅니다.

*   **Internal Package**: `packages/ui`를 `apps/web`에서 사용할 때 별도의 빌드 과정 없이 소스 코드를 직접 참조하도록 설정할 수 있습니다.
*   **Ghost Dependency 방지**: pnpm의 엄격한 구조는 선언되지 않은 패키지를 사용하는 실수를 사전에 차단합니다.

---

## 4. 지능형 CI: Selective Execution

모노레포 CI의 핵심은 **"바뀐 것만 테스트하는 것"**입니다.

```bash
# 변경된 패키지와 그에 영향을 받는 패키지만 빌드
turbo run build --filter=...[origin/main]
```

*   `--filter`: 특정 앱이나 패키지만 선택.
*   `...`: 의존성 그래프를 따라 영향을 받는 모든 패키지를 포함.
