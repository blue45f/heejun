### 2026 트렌드 고도화 체크포인트

- **AI 보안 격리**: 민감정보·시크릿이 개입되는 영역은 AI 산출물 자동 반영 전에 보안 게이트를 통과해야 합니다.
- **운영 지표 연동**: 성능(RUM p75), 장애율, 접근성/SEO 신호 중 최소 1개 이상의 지표와 조합해 채택·철회 여부를 판단합니다.
- **브라우저/디바이스 지속성**: Baseline/feature detection 기반으로 기능을 출시하고, 미지원군에 대한 fallback 및 감시 항목을 문서화합니다.
- **공급망 신뢰성**: lockfile 일치성, 의존성 감사, SBOM/attestation, secret scan 조건을 문서 체크리스트에 반영합니다.
- **회복탄력성 설계**: 실험 기능은 rollback, fallback, canary 또는 flag 기반으로 실패 조건을 명시합니다.
- **국제/접근성 동시 고려**: i18n, RTL, 다국어 텍스트 길이, 키보드/스크린리더, reduced-motion은 기능 도입 전 체크합니다.
- **재검토 주기**: 월 1회 운영 증적을 기준으로 고도화/축소/중단 결정을 갱신합니다.

## 1. 교차 검증 프로토콜

모든 가이드는 "권장한다"로 끝나지 않고, 권고가 어떤 근거로 유지되는지 함께 기록합니다.

| 검증 축 | 필수 질문 | 통과 기준 |
| :--- | :--- | :--- |
| **1차 출처** | 공식 릴리스, 표준, 보안 권고, 스펙 상태가 확인되는가 | 링크와 기준일을 기록 |
| **실행 증거** | 로컬 또는 CI에서 재현 가능한 검증이 있는가 | 명령, 테스트, report, screenshot 중 하나 제공 |
| **운영 증거** | 실제 사용자 영향과 회귀를 볼 수 있는가 | RUM, error rate, release health, incident timeline 연결 |
| **철회 가능성** | 실패하거나 전제가 바뀌면 되돌릴 수 있는가 | rollback, flag, migration, ADR supersede 조건 명시 |

### 1.1 권고 등급

| 등급 | 의미 | 문서화 기준 |
| :--- | :--- | :--- |
| **Baseline** | 지금 production 표준으로 적용 | 공식 stable 근거 + 자동 검증 |
| **Recommended** | 대부분의 팀에 권장 | 공식 근거 + 적용 조건 |
| **Conditional** | 특정 규모/도메인에서만 적용 | 도입 조건, 비용, 대안 |
| **Experimental Watch** | 관찰 또는 제한 PoC | draft/canary 표시, 철회 조건 |
| **Deprecated** | 제거 또는 마이그레이션 필요 | 제거 일정, 대체안, 영향 범위 |

### 1.2 2026 최신 트렌드 반영 기준
