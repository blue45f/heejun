## 문서 개요

이 종합 가이드는 실무 현장의 기술 문서를 기반으로 작성된 범용 프론트엔드 개발 가이드입니다.

### 특징
- 2025년 최신 기술 반영 (React 19, TypeScript 5.7 등)
- 실무에 즉시 적용 가능한 코드 예시
- 검증된 베스트 프랙티스
- 완전한 한글 문서

### 사용 방법

각 섹션은 독립적으로 읽을 수 있도록 구성되어 있습니다.

**추천 학습 순서:**
1. **신규 프로젝트**: 테스팅 → 아키텍처 → CI/CD
2. **기존 프로젝트 개선**: 성능 최적화 → 모니터링 → 프로세스
3. **팀 온보딩**: 온보딩 가이드 → 코드 리뷰 → 회의록 템플릿

## 주요 문서 요약

### 프론트엔드 테스팅 가이드
- Testing Trophy 전략으로 효율적인 테스트 구축
- Vitest + React Testing Library
- Playwright E2E 테스트
- 접근성 테스트 (axe-core), 성능 테스트 (Lighthouse CI)
- **핵심 포인트**: 통합 테스트에 가장 많은 리소스 투입, 커버리지 목표 60-80%

### 성능 최적화 가이드
- Core Web Vitals 2025 기준 달성: LCP ≤ 2.5초, INP ≤ 200ms, CLS ≤ 0.1
- **주요 기법**: Code Splitting, 이미지 최적화 (AVIF > WebP > JPEG), React 19 Compiler, Server Components

### TypeScript 심화 가이드
- TypeScript 5.7 고급 기능: Template Literal Types, Conditional Types & infer, Discriminated Unions, Branded Types
- **실전 패턴**: 타입 안전한 이벤트 시스템, API 엔드포인트 타입 관리, Redux Action 타입 안전성

### React 19 최신 기능
- 2024년 12월 정식 릴리즈
- React Compiler (자동 메모이제이션), Actions (useActionState, useFormStatus)
- use() Hook, ref as Prop (forwardRef 불필요), Server Components 완성

### 상태 관리 가이드

| 상황 | 라이브러리 |
|------|-----------|
| 서버 데이터 | TanStack Query |
| 전역 상태 | Zustand |
| Atomic 상태 | Jotai |
| 복잡한 로직 | Redux Toolkit |

- **베스트 프랙티스**: 서버 데이터 vs 클라이언트 데이터 구분, 전역 상태 남용 금지, Selector로 성능 최적화

### 브라우저 호환성 가이드
- Chrome/Firefox/Safari: 최신 2개 버전 지원
- core-js 또는 SWC로 Polyfill, Autoprefixer로 CSS 호환성, Feature Detection 필수

### CI/CD 파이프라인 가이드
- GitHub Actions로 자동화
- **CI 필수 항목**: Linting (ESLint), Type checking, Unit/Integration/E2E tests, 코드 커버리지
- **CD 전략**: 환경별 배포 (dev → staging → production), Canary 배포, 자동 롤백

### Sentry 모니터링
- 주간 리포트 문화
- **최적화 전략**: 에러 100% 캡처, 트랜잭션 5% 샘플링, 비용 95% 절감 가능
- **핵심 기능**: Session Replay, Source Map (debugId 기반), Web Vitals 통합

### 코드 리뷰 가이드
- **핵심 마인드셋**: 코드 리뷰는 교육의 기회, 비판이 아닌 개선, 명확하고 건설적인 피드백
- **MR 작성 가이드**: 500라인 이하, 하나의 주제에 집중, 스크린샷/GIF 포함

### 배포 체크리스트
- **D-1 (배포 전날)**: 배포 계획서 작성, RC 환경 검증, 롤백 계획 수립
- **D-Day (배포 당일)**: 모니터링 대시보드 준비, 15분 내 롤백 가능 확인, 배포 후 30분 집중 모니터링

### 장애 대응 프로세스
- **4단계 프레임워크**: 탐지 → 통보 (7분 내, Critical) → 대응 (4시간 내 복구) → 회고 (5 Whys + Poka-yoke)
- **핵심 원칙**: Blameless Post-mortem, 시스템적 해결책, 재발 방지 자동화

### 온보딩 가이드
- **4주 체계적 온보딩**: 1주차 팀 소개/환경 셋업, 2주차 팀 프로세스 학습, 3주차 업무 인수인계, 4주차 첫 PR 제출
- **성공 요소**: 돌보미(Buddy) 배정, 주 1회 1 on 1, 명확한 체크리스트

### 회의록 템플릿
- **위클리 미팅**: 지난주 Action Items 리뷰, 팀별 진행상황, 이번주 Action Items
- **기술 회의**: Discussion Items (테이블 형식), Decision/Action Items 구분

## 실무 적용 가이드

### 스타트업 (10-30명)
**우선 적용**: 코드 리뷰 가이드 → 배포 체크리스트 → 기본 테스팅 전략 → 온보딩 가이드

### 중소기업 (30-100명)
**시스템 구축**: CI/CD 파이프라인 → Sentry 모니터링 → 성능 최적화 전략 → 체계적 온보딩 프로세스

### 대기업 (100명+)
**완전한 거버넌스**: 아키텍처 표준화 → 통합 모니터링 시스템 → 장애 대응 프로세스 → 기술 문서 플랫폼
