## 0. 문서 품질 원칙

이 가이드는 "최신 기술 나열"이 아니라 팀이 바로 적용할 수 있는 **의사결정 기준**과 **품질 게이트**를 제공하는 것을 목표로 합니다.

| 원칙 | 적용 기준 |
| :--- | :--- |
| **공식 출처 우선** | 버전, 표준, 보안 권고는 공식 릴리스 노트와 표준 문서를 우선합니다. 블로그/벤치마크는 보조 자료로만 사용합니다. |
| **벤더 중립 표준화** | 특정 회사, 클라우드, SaaS, 협업 도구에 종속된 절차는 표준에서 제외하고, 품질 속성과 검증 기준만 남깁니다. |
| **검증 가능한 예제** | 설정 파일, CI, 테스트, 배포 예제는 실제 프로젝트에서 실행 가능한 형태를 우선합니다. 실행 불가능한 예제는 명시적으로 의사코드로 표기합니다. |
| **Stable과 Preview 분리** | production baseline, experimental watch, deprecated 항목을 섞지 않습니다. 실험 기능은 도입 조건과 철수 조건을 함께 적습니다. |
| **AI 산출물 검증** | AI가 생성한 코드/문서는 공식 문서, 로컬 테스트, 실제 코드베이스 중 최소 하나로 검증한 뒤 반영합니다. |
| **운영 지표 연결** | 모든 기술 선택은 성능, 접근성, 보안, 장애 대응, 배포 안정성 중 하나 이상의 지표와 연결합니다. |

### 0.1 교차 검증 매트릭스

| 권고 | 1차 출처 | 실행 증거 | 운영 증거 | 철회 조건 |
| :--- | :--- | :--- | :--- | :--- |
| 문서 권고 등급은 Baseline/Recommended/Conditional/Experimental Watch/Deprecated로만 표기 | 이 문서의 권고 등급 정의 | 전체 문서 구조 검사 | 표준 예외/혼선 감소 | 새 등급은 RFC 승인 전 사용 금지 |
| 기술 버전과 표준 상태는 공식 출처와 기준일을 함께 기록 | 공식 릴리스 노트, 표준 문서, 보안 권고 | README/00 공식 출처 표, 로컬 링크 검사 | stale guide report, 변경 이력 | 확인 불가 항목은 Experimental Watch 또는 삭제 |
| 문서 간 공통 정책은 단일 출처 문서에만 둔다 | 단일 출처 매트릭스 | 중복 섹션 점검, 연관 가이드 링크 | 리뷰 중 상충 기준 발견률 | 상충 시 00/15 기준으로 통합 |

### 0.2 운영 게이트

| Gate | Evidence | Owner | Rollback |
| :--- | :--- | :--- | :--- |
| 문서 구조 변경 | 단일 출처 매트릭스, 연관 가이드 링크, 변경 범위 요약 | Documentation owner | 이전 문서 구조로 회귀 또는 변경 범위 축소 |
| 최신성 검증 | 기준일, 공식 출처, 실행 가능한 검증 명령 | Section owner | Experimental Watch로 강등 또는 권고 삭제 |
| 벤더 중립성 | 특정 회사/제품 의존 표현 검색 결과 | Standards owner | 일반 원칙으로 재작성 |
| 링크 무결성 | 로컬 링크 검사, 깨진 링크 0건 | Documentation owner | 링크 수정 전 merge 보류 |

## 1. 교차 검증 프로토콜

모든 가이드는 "권장한다"로 끝나지 않고, 권고가 어떤 근거로 유지되는지 함께 기록합니다.

| 검증 축 | 필수 질문 | 통과 기준 |
| :--- | :--- | :--- |
| **1차 출처** | 공식 릴리스, 표준, 보안 권고, 스펙 상태가 확인되는가 | 링크와 기준일을 기록 |
| **실행 증거** | 로컬 또는 CI에서 재현 가능한 검증이 있는가 | 명령, 테스트, report, screenshot 중 하나 제공 |
| **운영 증거** | 실제 사용자 영향과 회귀를 볼 수 있는가 | RUM, error rate, release health, incident timeline 연결 |
| **철회 가능성** | 실패하거나 전제가 바뀌면 되돌릴 수 있는가 | rollback, flag, migration, ADR supersede 조건 명시 |

### 1.1 권고 등급

| 등급 | 의미 | 문서화 기준 |
| :--- | :--- | :--- |
| **Baseline** | 지금 production 표준으로 적용 | 공식 stable 근거 + 자동 검증 |
| **Recommended** | 대부분의 팀에 권장 | 공식 근거 + 적용 조건 |
| **Conditional** | 특정 규모/도메인에서만 적용 | 도입 조건, 비용, 대안 |
| **Experimental Watch** | 관찰 또는 제한 PoC | draft/canary 표시, 철회 조건 |
| **Deprecated** | 제거 또는 마이그레이션 필요 | 제거 일정, 대체안, 영향 범위 |

### 1.2 2026 최신 트렌드 반영 기준

| 트렌드 | 문서 반영 방식 | 검증 축 |
| :--- | :--- | :--- |
| **AI-assisted SDLC** | AI 결과는 초안으로 보고, 민감정보 차단·검증 명령·사람 승인을 필수화 | 실행 증거 + 철회 가능성 |
| **Supply-chain provenance** | lockfile, SBOM, artifact attestation, secret scan, 최소 권한 CI를 품질 게이트화 | 1차 출처 + 실행 증거 |
| **React/Server rendering maturity** | Server/Client 경계, RSC 보안 패치, Suspense/Error Boundary, cache contract 명문화 | 1차 출처 + 테스트 |
| **Field-data performance** | Core Web Vitals는 lab 점수보다 RUM p75 회귀 차단을 우선 | 1차 출처 + 운영 증거 |
| **Accessibility as release gate** | WCAG 2.2 AA, 키보드/스크린 리더 수동 검증, 증적 관리를 배포 조건으로 연결 | 1차 출처 + 실행 증거 |
| **Browser Baseline** | 기능 채택은 Baseline, feature detection, fallback, 크로스 브라우저 smoke로 결정 | 1차 출처 + 실행 증거 |
| **Operational excellence** | deploy/release 분리, progressive delivery, incident runbook, postmortem action item을 표준화 | 운영 증거 + 철회 가능성 |

## 2. 문서 재구성: 유사성 기반 정보 구조

문서 간 유사도를 확인한 결과, 본문 전체가 중복된 문서는 없지만 공통 운영 구조가 여러 문서에 반복되어 있었습니다. 따라서 공통 원칙은 이 문서와 전담 문서로 올리고, 개별 문서는 도메인별 실행 기준과 예외 기준만 책임지도록 재구성합니다.

### 2.1 중복 패턴 분석 결과

| 반복 패턴 | 관찰 결과 | 새 구성 원칙 |
| :--- | :--- | :--- |
| **교차 검증 매트릭스** | 거의 모든 문서에 동일한 검증 축이 반복됨 | 검증 축과 권고 등급은 00이 단일 출처, 개별 문서는 도메인별 행만 유지 |
| **공통 Baseline** | 문서마다 비슷한 "모든 프론트엔드 그룹 공통" 섹션 존재 | 문서의 최소 적용 조건만 남기고 전체 품질 철학은 00에 집중 |
| **체크리스트** | 많은 문서가 마지막에 체크리스트를 가짐 | 체크리스트는 문서별 release gate로 유지하되, 공통 CI/배포 절차는 11/14로 링크 |
| **AI 보조 입력** | 접근성, MFE, SEO, 모션, PWA에 AI 입력 형식이 반복됨 | 입력 구조와 보안 정책은 18이 단일 출처, 도메인 문서는 시나리오만 유지 |
| **벤더 종속 제외 설명** | 여러 운영 문서가 동일한 제외 원칙을 반복 | 제외 원칙은 00/README에 두고, 문서별로는 해당 도메인에서 제거한 항목만 짧게 명시 |
