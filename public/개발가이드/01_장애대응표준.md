## 1. AIOps & AI 기반 장애 대응

> AI를 장애 대응의 **모든 단계**에 투입한다. 탐지 -> 분류 -> 원인 분석 -> 롤백 판단 -> 핫픽스 -> Post-mortem까지 AI가 주도하고, 엔지니어는 **검증과 의사결정**에 집중한다.

### 1.1 AI 장애 분석 프롬프트 라이브러리

장애 상황별로 즉시 사용할 수 있는 5가지 표준 프롬프트. Claude, GPT 등 LLM에 그대로 붙여넣어 활용한다.

#### 프롬프트 1: 로그 분석

```text
당신은 시니어 SRE 엔지니어입니다. 아래 로그를 분석하세요.

[분석 대상 로그 붙여넣기]

다음을 수행하세요:
1. 에러/경고 패턴을 시간순으로 정리
2. 첫 번째 이상 징후가 나타난 시점과 해당 로그 라인 식별
3. 에러 간 인과 관계 추론 (예: DB 커넥션 풀 고갈 -> 타임아웃 -> 500 에러)
4. 영향받는 서비스/컴포넌트 목록
5. 즉각적 완화 조치 3가지 제안

출력 형식: 마크다운 테이블 + 타임라인 다이어그램(텍스트)
```

#### 프롬프트 2: 메트릭 상관관계 분석

```text
당신은 Observability 전문가입니다. 아래 메트릭 데이터의 상관관계를 분석하세요.

- 시간 범위: [장애 발생 전후 30분]
- CPU 사용률: [데이터]
- 메모리 사용률: [데이터]
- 요청 처리량 (RPS): [데이터]
- 응답 시간 (p50/p95/p99): [데이터]
- 에러율: [데이터]
- DB 커넥션 수: [데이터]

다음을 수행하세요:
1. 메트릭 간 상관계수가 높은 쌍 식별
2. 선행 지표(leading indicator)와 후행 지표(lagging indicator) 구분
3. 변곡점(inflection point) 시점과 원인 추정
4. 병목 지점 진단
5. 용량 계획 관점의 임계치 권고
```

#### 프롬프트 3: 분산 트레이스 분석

```text
당신은 분산 시스템 전문가입니다. 아래 트레이스 데이터를 분석하세요.

[OpenTelemetry 트레이스 JSON 또는 Jaeger 출력 붙여넣기]

다음을 수행하세요:
1. 전체 요청 흐름을 서비스 간 호출 다이어그램으로 시각화
2. 각 span의 duration 분석 -- 비정상적으로 긴 span 식별
3. 실패한 span의 에러 코드/메시지와 전파 경로
4. 재시도(retry) 패턴 탐지 및 재시도 폭풍(retry storm) 여부 판단
5. 서비스 간 타임아웃 설정 불일치 탐지
6. 최적화 포인트 3가지 제안
```

#### 프롬프트 4: 에러 패턴 분류

```text
당신은 소프트웨어 신뢰성 엔지니어입니다. 최근 24시간 에러 로그를 분석하세요.

[에러 로그 샘플 100건 이상 붙여넣기]

다음을 수행하세요:
1. 에러를 유형별로 클러스터링 (스택 트레이스 유사도 기반)
2. 각 클러스터의 발생 빈도, 최초/최근 발생 시각, 추세
3. 신규 에러 vs 기존 에러 분류
4. 사용자 영향도 기준 우선순위 매기기 (P0~P3)
5. 각 에러 클러스터별 추정 원인과 수정 방향
6. 동일 에러 재발 방지를 위한 테스트 케이스 제안
```

#### 프롬프트 5: Post-mortem 초안 생성

```text
당신은 SRE 팀의 Post-mortem 작성자입니다. 아래 장애 정보를 바탕으로
Blameless Post-mortem 초안을 작성하세요.

- 장애 제목: [제목]
- 심각도: [SEV1~4]
- 영향 범위: [영향받은 사용자 수/서비스]
- 타임라인: [탐지 ~ 복구까지 시간순 이벤트]
- 근본 원인: [파악된 원인]
- 복구 조치: [수행한 조치]

출력 형식:
1. 요약 (3줄 이내)
2. 영향도 (사용자 수, 매출 영향, SLO 소진량)
3. 타임라인 (분 단위)
4. 근본 원인 분석 (5 Whys 적용)
5. 교훈 (잘한 점 / 개선할 점)
6. 액션 아이템 (담당자, 기한, 우선순위 테이블)
7. 재발 방지 체크리스트
```

### 1.2 AI 기반 장애 자동 분류 및 심각도 판단

Anthropic SDK를 활용하여 장애 알림을 자동 분류하고 심각도(SEV 레벨)를 결정한다.

```typescript
// ai-incident-classifier.ts
import Anthropic from "@anthropic-ai/sdk";

interface IncidentAlert {
  title: string;
  description: string;
  metrics: {
    errorRate: number;
    p99Latency: number;
    affectedUsers: number;
    affectedEndpoints: string[];
  };
  logs: string[];
  timestamp: string;
}

interface ClassificationResult {
  severity: "SEV1" | "SEV2" | "SEV3" | "SEV4";
  category: string;
  rootCauseHypothesis: string;
  suggestedActions: string[];
  estimatedImpact: string;
  confidence: number;
}

const anthropic = new Anthropic();

async function classifyIncident(
  alert: IncidentAlert
): Promise<ClassificationResult> {
  const systemPrompt = `당신은 장애 분류 시스템입니다. 장애 알림을 분석하여 정확한 심각도와 분류를 수행합니다.

심각도 기준:
- SEV1: 전체 서비스 중단, 매출 직접 영향, 데이터 유실 위험 (에러율 >10%, 영향 사용자 >1000명)
- SEV2: 핵심 기능 장애, 부분 서비스 중단 (에러율 >5%, 영향 사용자 >100명)
- SEV3: 비핵심 기능 장애, 성능 저하 (에러율 >1%, p99 >3s)
- SEV4: 미미한 영향, 단일 사용자 이슈, 로그 경고 수준

카테고리: infrastructure | database | network | application | external-dependency | configuration | security

반드시 JSON 형식으로만 응답하세요.`;

  const message = await anthropic.messages.create({
    model: "claude-sonnet-4-20250514",
    max_tokens: 1024,
    system: systemPrompt,
    messages: [
      {
        role: "user",
        content: `장애 알림을 분석하세요:

제목: ${alert.title}
설명: ${alert.description}
에러율: ${alert.metrics.errorRate}%
P99 레이턴시: ${alert.metrics.p99Latency}ms
영향 사용자 수: ${alert.metrics.affectedUsers}
영향 엔드포인트: ${alert.metrics.affectedEndpoints.join(", ")}
관련 로그 (최근 10건): ${alert.logs.slice(0, 10).join("\n")}
발생 시각: ${alert.timestamp}`,
      },
    ],
  });

  const content = message.content[0];
  if (content.type !== "text") {
    throw new Error("Unexpected response type");
  }

  return JSON.parse(content.text) as ClassificationResult;
}

/** 분류 결과에 따른 자동 에스컬레이션 */
async function handleClassification(
  alert: IncidentAlert
): Promise<void> {
  const result = await classifyIncident(alert);

  const escalationMap: Record<string, () => Promise<void>> = {
    SEV1: async () => {
      await notifySlackChannel("#incident-critical", result);
      await pageOnCall("primary", result);
      await pageOnCall("secondary", result);
      await createWarRoom(result);
    },
    SEV2: async () => {
      await notifySlackChannel("#incident-major", result);
      await pageOnCall("primary", result);
    },
    SEV3: async () => {
      await notifySlackChannel("#incident-minor", result);
      await createJiraTicket(result);
    },
    SEV4: async () => {
      await notifySlackChannel("#incident-info", result);
    },
  };

  await escalationMap[result.severity]();
}

// 유틸리티 함수 시그니처 (구현부는 인프라별 상이)
declare function notifySlackChannel(channel: string, result: ClassificationResult): Promise<void>;
declare function pageOnCall(tier: string, result: ClassificationResult): Promise<void>;
declare function createWarRoom(result: ClassificationResult): Promise<void>;
declare function createJiraTicket(result: ClassificationResult): Promise<void>;
```

### 1.3 AI 기반 자동 롤백 판단 시스템

배포 후 에러율/성능 회귀를 실시간 감지하여 자동 롤백 여부를 AI가 판단한다.

```typescript
// auto-rollback-decision.ts
import Anthropic from "@anthropic-ai/sdk";

interface DeploymentMetrics {
  deployId: string;
  service: string;
  version: string;
  previousVersion: string;
  elapsedMinutes: number;
  current: {
    errorRate: number;
    p50Latency: number;
    p99Latency: number;
    rps: number;
    cpuUsage: number;
    memoryUsage: number;
  };
  baseline: {
    errorRate: number;
    p50Latency: number;
    p99Latency: number;
    rps: number;
    cpuUsage: number;
    memoryUsage: number;
  };
  recentErrors: string[];
}

interface RollbackDecision {
  shouldRollback: boolean;
  confidence: number;
  reasoning: string;
  riskLevel: "critical" | "high" | "medium" | "low";
  suggestedAction: "immediate-rollback" | "gradual-rollback" | "pause-rollout" | "continue" | "monitor";
  waitBeforeAction: number; // seconds
}

const anthropic = new Anthropic();

async function evaluateRollback(
  metrics: DeploymentMetrics
): Promise<RollbackDecision> {
  // 1단계: 규칙 기반 즉시 롤백 (AI 판단 불필요)
  if (metrics.current.errorRate > 20) {
    return {
      shouldRollback: true,
      confidence: 1.0,
      reasoning: `에러율 ${metrics.current.errorRate}%로 즉시 롤백 임계치(20%) 초과`,
      riskLevel: "critical",
      suggestedAction: "immediate-rollback",
      waitBeforeAction: 0,
    };
  }

  // 2단계: AI 기반 종합 판단
  const prompt = `배포 메트릭을 분석하여 롤백 여부를 판단하세요.

서비스: ${metrics.service}
배포 버전: ${metrics.previousVersion} -> ${metrics.version}
배포 후 경과: ${metrics.elapsedMinutes}분

현재 vs 베이스라인:
- 에러율: ${metrics.current.errorRate}% vs ${metrics.baseline.errorRate}% (${getDelta(metrics.current.errorRate, metrics.baseline.errorRate)})
- P50 레이턴시: ${metrics.current.p50Latency}ms vs ${metrics.baseline.p50Latency}ms (${getDelta(metrics.current.p50Latency, metrics.baseline.p50Latency)})
- P99 레이턴시: ${metrics.current.p99Latency}ms vs ${metrics.baseline.p99Latency}ms (${getDelta(metrics.current.p99Latency, metrics.baseline.p99Latency)})
- RPS: ${metrics.current.rps} vs ${metrics.baseline.rps}
- CPU: ${metrics.current.cpuUsage}% vs ${metrics.baseline.cpuUsage}%
- Memory: ${metrics.current.memoryUsage}% vs ${metrics.baseline.memoryUsage}%

최근 에러 로그:
${metrics.recentErrors.slice(0, 5).join("\n")}

판단 기준:
1. 에러율이 베이스라인 대비 2배 이상 -> 롤백 강력 권고
2. P99 레이턴시가 베이스라인 대비 3배 이상 -> 롤백 권고
3. 새로운 유형의 에러 발생 -> 면밀 모니터링 또는 롤백
4. 배포 후 5분 미만이면 안정화 대기 고려
5. 메모리 누수 패턴(지속 증가) -> 롤백 권고

반드시 JSON 형식으로 응답하세요.`;

  const message = await anthropic.messages.create({
    model: "claude-sonnet-4-20250514",
    max_tokens: 1024,
    system: "당신은 배포 안전성 판단 시스템입니다. 메트릭을 기반으로 롤백 여부를 판단합니다. JSON으로만 응답하세요.",
    messages: [{ role: "user", content: prompt }],
  });

  const content = message.content[0];
  if (content.type !== "text") {
    throw new Error("Unexpected response type");
  }

  return JSON.parse(content.text) as RollbackDecision;
}

function getDelta(current: number, baseline: number): string {
  const delta = ((current - baseline) / baseline) * 100;
  return `${delta > 0 ? "+" : ""}${delta.toFixed(1)}%`;
}

/** 롤백 판단 결과에 따른 자동 실행 */
async function executeRollbackDecision(
  metrics: DeploymentMetrics
): Promise<void> {
  const decision = await evaluateRollback(metrics);

  switch (decision.suggestedAction) {
    case "immediate-rollback":
      await triggerRollback(metrics.service, metrics.previousVersion);
      await notifyTeam(`[ROLLBACK] ${metrics.service} ${metrics.version} -> ${metrics.previousVersion}: ${decision.reasoning}`);
      break;
    case "gradual-rollback":
      await reduceTrafficWeight(metrics.service, 0);
      await delay(decision.waitBeforeAction * 1000);
      await triggerRollback(metrics.service, metrics.previousVersion);
      break;
    case "pause-rollout":
      await pauseRollout(metrics.deployId);
      await notifyTeam(`[PAUSE] ${metrics.service} 롤아웃 일시정지: ${decision.reasoning}`);
      break;
    case "monitor":
      await notifyTeam(`[WATCH] ${metrics.service} 모니터링 강화: ${decision.reasoning}`);
      break;
    case "continue":
      // 정상 진행
      break;
  }
}

// 유틸리티 함수 시그니처
declare function triggerRollback(service: string, version: string): Promise<void>;
declare function notifyTeam(message: string): Promise<void>;
declare function reduceTrafficWeight(service: string, weight: number): Promise<void>;
declare function pauseRollout(deployId: string): Promise<void>;
declare function delay(ms: number): Promise<void>;
```

### 1.4 AI Post-mortem 초안 자동 생성

장애 복구 후 수집된 데이터를 기반으로 Post-mortem 문서를 자동 생성한다.

```typescript
// ai-postmortem-generator.ts
import Anthropic from "@anthropic-ai/sdk";

interface IncidentData {
  id: string;
  title: string;
  severity: string;
  timeline: Array<{
    timestamp: string;
    event: string;
    actor: string;
  }>;
  metricsSnapshot: {
    peakErrorRate: number;
    peakLatency: number;
    affectedUsers: number;
    downtime: number; // minutes
    sloImpact: number; // error budget consumed (%)
  };
  rootCause: string;
  actions: string[];
  relatedCommits: string[];
  slackThreadUrl: string;
}

interface PostMortemDocument {
  title: string;
  summary: string;
  impact: string;
  timeline: string;
  rootCauseAnalysis: string;
  lessonsLearned: string;
  actionItems: Array<{
    item: string;
    owner: string;
    priority: string;
    dueDate: string;
  }>;
  preventionChecklist: string[];
}

const anthropic = new Anthropic();

async function generatePostMortem(
  incident: IncidentData
): Promise<PostMortemDocument> {
  const timelineText = incident.timeline
    .map((t) => `[${t.timestamp}] ${t.event} (by ${t.actor})`)
    .join("\n");

  const message = await anthropic.messages.create({
    model: "claude-sonnet-4-20250514",
    max_tokens: 4096,
    system: `당신은 SRE Post-mortem 전문 작성자입니다. Blameless 원칙을 엄격히 준수합니다.
- 개인을 비난하지 않는다
- 시스템/프로세스 개선에 집중한다
- 구체적이고 측정 가능한 액션 아이템을 제시한다
- 5 Whys 기법으로 근본 원인을 분석한다
반드시 JSON 형식으로 응답하세요.`,
    messages: [
      {
        role: "user",
        content: `아래 장애 데이터로 Post-mortem 문서를 생성하세요.

장애 ID: ${incident.id}
제목: ${incident.title}
심각도: ${incident.severity}

타임라인:
${timelineText}

메트릭:
- 최대 에러율: ${incident.metricsSnapshot.peakErrorRate}%
- 최대 레이턴시: ${incident.metricsSnapshot.peakLatency}ms
- 영향 사용자: ${incident.metricsSnapshot.affectedUsers}명
- 다운타임: ${incident.metricsSnapshot.downtime}분
- SLO Error Budget 소진: ${incident.metricsSnapshot.sloImpact}%

근본 원인 (초기 파악): ${incident.rootCause}
수행된 조치: ${incident.actions.join(", ")}
관련 커밋: ${incident.relatedCommits.join(", ")}`,
      },
    ],
  });

  const content = message.content[0];
  if (content.type !== "text") {
    throw new Error("Unexpected response type");
  }

  return JSON.parse(content.text) as PostMortemDocument;
}
```

### 1.5 Copilot 기반 핫픽스 패턴

장애 상황에서 AI Copilot을 활용해 핫픽스를 빠르게 작성하는 표준 패턴.

```typescript
// hotfix-patterns.ts -- Copilot에 효과적인 핫픽스 패턴 모음

/**
 * 패턴 1: Circuit Breaker 긴급 삽입
 * Copilot 프롬프트: "이 외부 API 호출에 circuit breaker를 추가해줘.
 *   실패 5회 이상이면 30초 동안 차단, fallback으로 캐시 값 반환"
 */
class CircuitBreaker {
  private failures = 0;
  private lastFailTime = 0;
  private state: "closed" | "open" | "half-open" = "closed";

  constructor(
    private readonly threshold: number = 5,
    private readonly resetTimeout: number = 30_000,
    private readonly fallback?: () => Promise<unknown>
  ) {}

  async execute<T>(fn: () => Promise<T>): Promise<T> {
    if (this.state === "open") {
      if (Date.now() - this.lastFailTime > this.resetTimeout) {
        this.state = "half-open";
      } else if (this.fallback) {
        return this.fallback() as Promise<T>;
      } else {
        throw new Error("Circuit breaker is open");
      }
    }

    try {
      const result = await fn();
      this.onSuccess();
      return result;
    } catch (error) {
      this.onFailure();
      throw error;
    }
  }

  private onSuccess(): void {
    this.failures = 0;
    this.state = "closed";
  }

  private onFailure(): void {
    this.failures++;
    this.lastFailTime = Date.now();
    if (this.failures >= this.threshold) {
      this.state = "open";
    }
  }
}

/**
 * 패턴 2: 긴급 Rate Limiter
 * Copilot 프롬프트: "sliding window 기반 rate limiter 만들어줘.
 *   메모리 기반, 1분에 100요청 제한, 429 반환"
 */
class SlidingWindowRateLimiter {
  private windows = new Map<string, number[]>();

  constructor(
    private readonly maxRequests: number = 100,
    private readonly windowMs: number = 60_000
  ) {}

  isAllowed(key: string): boolean {
    const now = Date.now();
    const timestamps = this.windows.get(key) ?? [];
    const valid = timestamps.filter((t) => now - t < this.windowMs);

    if (valid.length >= this.maxRequests) {
      this.windows.set(key, valid);
      return false;
    }

    valid.push(now);
    this.windows.set(key, valid);
    return true;
  }
}

/**
 * 패턴 3: Graceful Degradation 래퍼
 * Copilot 프롬프트: "이 함수에 graceful degradation 래퍼를 씌워줘.
 *   타임아웃 3초, 실패 시 정적 응답, 재시도 1회"
 */
async function withGracefulDegradation<T>(
  fn: () => Promise<T>,
  options: {
    timeout: number;
    fallbackValue: T;
    retries?: number;
    onDegraded?: (error: Error) => void;
  }
): Promise<T> {
  const { timeout, fallbackValue, retries = 1, onDegraded } = options;

  for (let attempt = 0; attempt <= retries; attempt++) {
    try {
      const result = await Promise.race([
        fn(),
        new Promise<never>((_, reject) =>
          setTimeout(() => reject(new Error("Timeout")), timeout)
        ),
      ]);
      return result;
    } catch (error) {
      if (attempt === retries) {
        onDegraded?.(error as Error);
        return fallbackValue;
      }
    }
  }

  return fallbackValue;
}
```

```typescript
      const healthResponse = await fetch(`${env.url}/health`, {
        signal: AbortSignal.timeout(5000),
      });

      if (!healthResponse.ok) {
        return this.recordFailure(envId);
      }

      const metrics = await this.collectMetrics(env);
      env.metrics = metrics;

      // 메트릭 기반 상태 판정

      return env.status;
    } catch {
      return this.recordFailure(envId);
    }

    const checks = Array.from(this.environments.keys()).map(async (envId) => {
      const status = await this.checkHealth(envId);
      results.set(envId, status);
    });
    await Promise.allSettled(checks);
    return results;
  }

    const failures = (this.healthCheckFailures.get(envId) ?? 0) + 1;
    this.healthCheckFailures.set(envId, failures);

    const env = this.environments.get(envId);
    if (!env) return "unknown";

    if (failures >= this.config.unhealthyThreshold) {
      env.status = "unhealthy";
    } else {
      env.status = "degraded";
    }
    return env.status;
  }

    env: BetaEnvironment
  ): Promise<BetaEnvironment["metrics"]> {
    const metricsResponse = await fetch(`${env.url}/metrics`);
    return metricsResponse.json() as Promise<BetaEnvironment["metrics"]>;
  }
```

### 2.6 카나리 배포 시 베타 환경 사전 검증 프로세스

```typescript
// canary-beta-verification.ts

interface CanaryVerification {
  stage: "beta-validation" | "canary-1pct" | "canary-10pct" | "canary-50pct" | "full-rollout";
  passThreshold: {
    errorRateDelta: number; // 베이스라인 대비 최대 허용 증가율 (%)
    latencyDelta: number; // 베이스라인 대비 최대 허용 증가율 (%)
    minDuration: number; // 최소 관찰 시간 (분)
  };
}

const CANARY_PIPELINE: CanaryVerification[] = [
  {
    stage: "beta-validation",
    passThreshold: { errorRateDelta: 0.5, latencyDelta: 10, minDuration: 10 },
  },
  {
    stage: "canary-1pct",
    passThreshold: { errorRateDelta: 0.3, latencyDelta: 15, minDuration: 15 },
  },
  {
    stage: "canary-10pct",
    passThreshold: { errorRateDelta: 0.2, latencyDelta: 10, minDuration: 20 },
  },
  {
    stage: "canary-50pct",
    passThreshold: { errorRateDelta: 0.1, latencyDelta: 5, minDuration: 30 },
  },
  {
    stage: "full-rollout",
    passThreshold: { errorRateDelta: 0.05, latencyDelta: 3, minDuration: 0 },
  },
];

class CanaryBetaPipeline {
  /** 베타 환경에서 먼저 검증 후 카나리 진행 */
  async runPipeline(
    deployId: string,
    betaEnvId: string
  ): Promise<{ success: boolean; failedAt?: string; metrics?: Record<string, number> }> {
    for (const stage of CANARY_PIPELINE) {
      const result = await this.executeStage(deployId, betaEnvId, stage);

      if (!result.passed) {
        await this.rollbackDeploy(deployId);
        return {
          success: false,
          failedAt: stage.stage,
          metrics: result.metrics,
        };
      }

      await this.promoteToNextStage(deployId, stage.stage);
    }

    return { success: true };
  }

  private async executeStage(
    deployId: string,
    betaEnvId: string,
    stage: CanaryVerification
  ): Promise<{ passed: boolean; metrics: Record<string, number> }> {
    // 최소 관찰 시간 동안 메트릭 수집
    const startTime = Date.now();
    const endTime = startTime + stage.passThreshold.minDuration * 60_000;

    let latestMetrics: Record<string, number> = {};

    while (Date.now() < endTime) {
      await new Promise((resolve) => setTimeout(resolve, 30_000)); // 30초 간격 체크

      const [current, baseline] = await Promise.all([
        this.getMetrics(deployId, stage.stage),
        this.getBaselineMetrics(deployId),
      ]);

      const errorRateDelta = current.errorRate - baseline.errorRate;
      const latencyDelta =
        ((current.p99Latency - baseline.p99Latency) / baseline.p99Latency) * 100;

      latestMetrics = {
        errorRate: current.errorRate,
        baselineErrorRate: baseline.errorRate,
        errorRateDelta,
        p99Latency: current.p99Latency,
        latencyDelta,
      };

      // 즉시 실패 조건: 임계치의 3배 초과
      if (
        errorRateDelta > stage.passThreshold.errorRateDelta * 3 ||
        latencyDelta > stage.passThreshold.latencyDelta * 3
      ) {
        return { passed: false, metrics: latestMetrics };
      }
    }

    // 최종 판정
    const passed =
      (latestMetrics.errorRateDelta ?? 0) <= stage.passThreshold.errorRateDelta &&
      (latestMetrics.latencyDelta ?? 0) <= stage.passThreshold.latencyDelta;

    return { passed, metrics: latestMetrics };
  }

  private async getMetrics(deployId: string, stage: string): Promise<{ errorRate: number; p99Latency: number }> {
    // 메트릭 수집 구현
```

### 2.7 멀티 환경 Chaos Engineering (특정 베타만 장애 주입)

```typescript
// multi-env-chaos.ts

interface ChaosExperiment {
  id: string;
  name: string;
  targetEnvironment: string; // 특정 베타 환경만 대상
  type: "network-delay" | "network-loss" | "cpu-stress" | "memory-stress" | "pod-kill" | "dns-failure";
  parameters: Record<string, string | number>;
  duration: number; // seconds
  safetyGuards: {
    maxErrorRate: number; // 이 에러율 초과 시 자동 중단
    maxLatency: number;
    rollbackOnBreach: boolean;
  };
}

class MultiEnvChaosRunner {
  /** 특정 베타 환경에만 장애 주입 (프로덕션 격리 보장) */
  async runExperiment(experiment: ChaosExperiment): Promise<ChaosResult> {
    // 안전 검증: 프로덕션 환경 대상 차단
    if (experiment.targetEnvironment === "production") {
      throw new Error("Cannot run chaos experiments on production via this runner");
    }

    // 사전 조건: 대상 환경이 healthy 상태인지 확인
    const preHealth = await this.checkEnvironmentHealth(experiment.targetEnvironment);
    if (preHealth !== "healthy") {
      throw new Error(`Target environment is ${preHealth}. Chaos requires healthy baseline.`);
    }

    // 베이스라인 메트릭 스냅샷
    const baselineMetrics = await this.captureMetrics(experiment.targetEnvironment);

    // 장애 주입 실행
    const injectionId = await this.injectFault(experiment);

    // 실험 중 지속 모니터링
    const result = await this.monitorExperiment(
      experiment,
      injectionId,
      baselineMetrics
    );

    // 장애 제거
    await this.removeFault(injectionId);

    // 복구 확인
    await this.waitForRecovery(experiment.targetEnvironment);

    return result;
  }

  private async monitorExperiment(
    experiment: ChaosExperiment,
    injectionId: string,
    baseline: Record<string, number>
  ): Promise<ChaosResult> {
    const startTime = Date.now();
    const endTime = startTime + experiment.duration * 1000;
    let breached = false;

    while (Date.now() < endTime) {
      const current = await this.captureMetrics(experiment.targetEnvironment);

      // 안전 가드 체크
      if (
        current.errorRate > experiment.safetyGuards.maxErrorRate ||
        current.p99Latency > experiment.safetyGuards.maxLatency
      ) {
        if (experiment.safetyGuards.rollbackOnBreach) {
          await this.removeFault(injectionId);
          breached = true;
          break;
        }
      }

      // 다른 환경에 영향 없는지 확인 (격리 검증)
      const otherEnvs = await this.getOtherEnvironments(experiment.targetEnvironment);
      for (const env of otherEnvs) {
        const envMetrics = await this.captureMetrics(env);
        if (envMetrics.errorRate > baseline.errorRate * 1.1) {
          // 다른 환경에 10% 이상 영향 -> 즉시 중단
          await this.removeFault(injectionId);
          return {
            success: false,
            reason: `Blast radius exceeded: ${env} affected`,
            isolationVerified: false,
            metrics: {},
          };
        }
      }

      await new Promise((resolve) => setTimeout(resolve, 10_000));
    }

    return {
      success: !breached,
      reason: breached ? "Safety guard breached" : "Experiment completed",
      isolationVerified: true,
      metrics: await this.captureMetrics(experiment.targetEnvironment),
    };
  }

  private async checkEnvironmentHealth(envId: string): Promise<string> { return "healthy"; }
  private async captureMetrics(envId: string): Promise<Record<string, number>> { return {}; }
  private async injectFault(experiment: ChaosExperiment): Promise<string> { return ""; }
  private async removeFault(injectionId: string): Promise<void> {}
  private async waitForRecovery(envId: string): Promise<void> {}
  private async getOtherEnvironments(excludeId: string): Promise<string[]> { return []; }
}

interface ChaosResult {
  success: boolean;
  reason: string;
  isolationVerified: boolean;
  metrics: Record<string, number>;
}
```

## 4. SLO/SLI/SLA 기반 장애 대응 체계

### 4.1 핵심 지표 정의

| 구분 | 정의 | 측정 방식 |
|------|------|-----------|
| **SLI** (Service Level Indicator) | 서비스 품질의 정량적 측정값 | 가용성: 성공 요청 / 전체 요청, 레이턴시: p99 < 목표 |
| **SLO** (Service Level Objective) | SLI의 목표 수준 | 월간 가용성 99.9%, p99 레이턴시 < 500ms |
| **SLA** (Service Level Agreement) | 고객과의 계약적 약속 | SLO 미달 시 크레딧 보상 등 |

### 4.2 Error Budget 운영

```typescript
// error-budget.ts

interface ErrorBudgetStatus {
  service: string;
  period: string; // "2026-04"
  sloTarget: number; // 0.999 = 99.9%
  totalRequests: number;
  failedRequests: number;
  currentSli: number;
  budgetTotal: number; // 허용 가능한 총 실패 수
  budgetConsumed: number;
  budgetRemaining: number;
  budgetRemainingPercent: number;
  burnRate1h: number; // 최근 1시간 소진 속도
  burnRate6h: number;
  projectedExhaustion: string | null; // 예상 소진 일시
}

function calculateErrorBudget(
  sloTarget: number,
  totalRequests: number,
  failedRequests: number,
  burnRate1h: number,
  burnRate6h: number
): ErrorBudgetStatus {
  const budgetTotal = Math.floor(totalRequests * (1 - sloTarget));
  const budgetConsumed = failedRequests;
  const budgetRemaining = Math.max(0, budgetTotal - budgetConsumed);
  const budgetRemainingPercent = budgetTotal > 0
    ? (budgetRemaining / budgetTotal) * 100
    : 0;

  // 예상 소진 일시 계산
  let projectedExhaustion: string | null = null;
  if (burnRate1h > 0 && budgetRemaining > 0) {
    const hoursUntilExhaustion = budgetRemaining / burnRate1h;
    const exhaustionDate = new Date(
      Date.now() + hoursUntilExhaustion * 3600_000
    );
    projectedExhaustion = exhaustionDate.toISOString();
  }

  return {
    service: "",
    period: "",
    sloTarget,
    totalRequests,
    failedRequests,
    currentSli: totalRequests > 0 ? (totalRequests - failedRequests) / totalRequests : 1,
    budgetTotal,
    budgetConsumed,
    budgetRemaining,
    budgetRemainingPercent,
    burnRate1h,
    burnRate6h,
    projectedExhaustion,
  };
}
```

### 4.3 Burn Rate 기반 대응 정책

| Burn Rate | 의미 | 대응 수준 | 자동 액션 |
|-----------|------|-----------|-----------|
| **> 14.4x** | 1시간 내 일일 예산 소진 | SEV1 긴급 대응 | 자동 롤백 트리거, 온콜 전원 호출 |
| **> 6x** | 4시간 내 일일 예산 소진 | SEV2 신속 대응 | 온콜 프라이머리 호출, 롤아웃 일시정지 |
| **> 3x** | 8시간 내 일일 예산 소진 | SEV3 모니터링 강화 | Slack 알림, 자동 Jira 생성 |
| **> 1x** | 예산 범위 내 소진 중 | SEV4 인지 | 대시보드 경고 색상 변경 |
| **<= 1x** | 정상 범위 | 정상 | - |

```typescript
// burn-rate-alert.ts

interface BurnRateAlert {
  severity: "SEV1" | "SEV2" | "SEV3" | "SEV4";
  burnRate: number;
  window: string;
  action: string;
}

function evaluateBurnRate(
  burnRate1h: number,
  burnRate6h: number
): BurnRateAlert | null {
  // Multi-window 기반 알림 (Google SRE 모델)
  // 단기 창 + 장기 창 모두 초과해야 알림 발생 (노이즈 감소)

  if (burnRate1h > 14.4 && burnRate6h > 6) {
    return {
      severity: "SEV1",
      burnRate: burnRate1h,
      window: "1h+6h",
      action: "자동 롤백 + 전원 호출",
    };
  }

  if (burnRate1h > 6 && burnRate6h > 3) {
    return {
      severity: "SEV2",
      burnRate: burnRate1h,
      window: "1h+6h",
      action: "온콜 호출 + 롤아웃 일시정지",
    };
  }

  if (burnRate6h > 3) {
    return {
      severity: "SEV3",
      burnRate: burnRate6h,
      window: "6h",
      action: "Slack 알림 + Jira 생성",
    };
  }

  if (burnRate6h > 1) {
    return {
      severity: "SEV4",
      burnRate: burnRate6h,
      window: "6h",
      action: "대시보드 경고",
    };
  }

  return null;
}
```

| **Chaos Mesh** | OSS (CNCF) | K8s 네이티브, 대시보드, 다양한 장애 유형 | Kubernetes |
| **AWS FIS** | AWS 관리형 | EC2/ECS/EKS/RDS 장애, CloudWatch 연동 | AWS |
| **Steadybit** | SaaS | 에이전트 기반, 자동 탐지, 실험 템플릿 | 클라우드, K8s |

### 6.2 Game Day 운영 가이드

```text
[Game Day 프로세스]

1. 사전 준비 (1주 전)
   - 가설 수립: "서비스 X의 DB 커넥션이 끊기면 30초 내 자동 복구된다"
   - 실험 시나리오 작성 및 리뷰
   - 안전 가드 설정 (자동 중단 조건)
   - 참여자 역할 배정 (실험 운영자, 관찰자, 안전 담당)
   - 롤백 계획 수립

2. 실험 실행
   - 베이스라인 메트릭 수집 (최소 10분)
   - 장애 주입 시작 (먼저 베타 환경에서 실행 -- 2.7절)
   - 실시간 메트릭/로그 관찰
   - 안전 가드 모니터링
   - 예상 vs 실제 동작 비교 기록

3. 실험 종료 및 복구
   - 장애 제거
   - 시스템 자동 복구 확인
   - 잔여 영향 없는지 검증

4. 결과 분석 (당일)
   - 가설 검증 결과 정리
   - 발견된 약점 목록화
   - 개선 액션 아이템 도출
   - 다음 Game Day 주제 선정

5. 후속 조치 (1주 내)
   - 발견된 약점 수정 작업 착수
   - 모니터링/알림 개선
   - Runbook 업데이트
   - 결과 공유 (전사 기술 블로그 또는 위키)
```

### 6.3 점진적 Chaos 도입 로드맵

```text
[Level 1 -- 기초] (1~2개월)
- 단일 서비스 Health Check 실패 시뮬레이션
- 의도적 HTTP 500 응답 주입
- 타임아웃 시나리오 테스트
- 대상: 베타 환경만

[Level 2 -- 네트워크] (3~4개월)
- 서비스 간 네트워크 지연 주입 (100ms ~ 3s)
- 패킷 유실 시뮬레이션 (1% ~ 30%)
- DNS 장애 시뮬레이션
- 대상: 베타 환경 + 스테이징

[Level 3 -- 인프라] (5~6개월)
- Pod/컨테이너 강제 종료
- CPU/메모리 스트레스 테스트
- 디스크 I/O 제한
- AZ(가용 영역) 장애 시뮬레이션
- 대상: 스테이징 + 프로덕션(비피크)

[Level 4 -- 복합 시나리오] (7개월~)
- 다중 장애 동시 주입
- 카스케이드 장애 시뮬레이션
- 재해 복구(DR) 절체 훈련
- 정기 Game Day (월 1회)
- 대상: 프로덕션 포함
```
