## 1. 온보딩 철학: 자동화 우선, AI 멘토링 중심

신규 멤버의 첫 경험은 곧 팀의 엔지니어링 문화 그 자체다. 계정 생성부터 첫 이슈 할당까지 사람이 개입하는 단계가 적을수록, 신규 멤버는 코드에 집중할 수 있다. AI 멘토는 24시간 상주하며, 코드베이스 RAG를 통해 "실제 코드 기반" 답변을 제공한다.

> **초보자를 위한 한 줄 요약:** 입사 첫날 버튼 하나만 누르면 개발 환경, Slack 초대, 첫 과제 할당까지 전부 자동으로 완료된다. 모르는 건 Slack에서 AI 멘토 봇에게 물어보면 된다.

### 핵심 원칙

| 원칙 | 설명 | 왜 중요한가? |
|------|------|-------------|
| **Zero-Touch Setup** | 계정 생성 -> 권한 -> Codespace -> Slack -> 첫 이슈까지 전부 자동 | 설정에 시간을 낭비하지 않고 코드에 바로 집중할 수 있다 |
| **AI 멘토 상주** | Slack에서 코드베이스 RAG 기반 AI 멘토가 실시간 답변 | 질문하기 부담스러운 초기에 심리적 안전망 역할 |
| **격리된 샌드박스** | 독립 DB + 시드 데이터로 프로덕션 영향 없이 실험 | 실수를 두려워하지 않고 자유롭게 테스트 가능 |
| **First PR 가이드 레일** | 첫 PR에 AI가 친절한 리뷰 + 멘토 자동 태그 | 코드 품질 기준을 자연스럽게 학습 |
| **정량적 성장 추적** | 30/60/90일 AI 기반 성과 자동 분석 | 객관적 지표로 성장 방향을 확인 |

### 온보딩 타임라인 요약

```
  |              |              |              |              |
  v              v              v              v              v
환경 셋업      탐색+첫 PR     도메인 학습    독립적 업무    본격 기여
(자동 완료)   (AI 프롬프트    (멘토 1:1,    (feature task, (중간 규모
               활용)          버그 수정)    PR 리뷰 참여)  개발+회고)
                                                          |
                                                          v
                                                     30일 리뷰
```

## 2. 온보딩 자동화 파이프라인

> **이 섹션이 하는 일:** GitHub Actions 워크플로우 하나가 신규 멤버의 모든 초기 설정을 자동으로 처리한다. 팀 리드가 워크플로우를 수동으로 트리거(workflow_dispatch)하면 아래 5단계가 순서대로 실행된다.

### GitHub Actions: 전체 자동화 워크플로우

```yaml
# .github/workflows/onboarding-pipeline.yml
# 용도: 신규 멤버의 전체 온보딩을 자동화하는 워크플로우
# 실행 방법: GitHub Actions 탭 > "Onboarding Automation Pipeline" > "Run workflow" 버튼 클릭
name: Onboarding Automation Pipeline

on:
  workflow_dispatch:
    inputs:
      github_username:
        description: "신규 멤버 GitHub ID"
        required: true
        type: string
      full_name:
        description: "이름 (한글)"
        required: true
        type: string
      team:
        description: "소속 팀"
        required: true
        type: choice
        options:
          - frontend
          - backend
          - platform
          - mobile
      mentor_github_id:
        description: "멘토 GitHub ID"
        required: true
        type: string

permissions:
  contents: write
  pull-requests: write
  issues: write
  actions: write

jobs:
  setup-accounts:
    runs-on: ubuntu-latest
    outputs:
      codespace_url: ${{ steps.codespace.outputs.url }}
      sandbox_url: ${{ steps.sandbox.outputs.url }}
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - run: pnpm install --frozen-lockfile

      # Step 1: 신규 멤버에게 리포지토리 push 권한을 부여하고, 소속 팀에 추가한다
      - name: "Step 1: Repository 권한 부여"
        uses: actions/github-script@v7
        with:
          github-token: ${{ secrets.ORG_ADMIN_TOKEN }}
          script: |
            // 리포지토리 협업자 추가 (push 권한)
            await github.rest.repos.addCollaborator({
              owner: context.repo.owner,
              repo: context.repo.repo,
              username: '${{ inputs.github_username }}',
              permission: 'push',
            });

            // 팀 추가 (예: frontend 팀, backend 팀 등)
            await github.rest.teams.addOrUpdateMembershipForUserInOrg({
              org: context.repo.owner,
              team_slug: '${{ inputs.team }}',
              username: '${{ inputs.github_username }}',
              role: 'member',
            });

      # Step 2: 미리 빌드된(prebuild) Codespace를 자동 생성한다
      - name: "Step 2: Codespace 자동 생성"
        id: codespace
        run: |
          CODESPACE=$(gh codespace create \
            --repo ${{ github.repository }} \
            --branch main \
            --machine standardLinux32gb \
            --idle-timeout 60m \
            --devcontainer-path .devcontainer/devcontainer.json \
            --display-name "onboard-${{ inputs.github_username }}" \
            2>&1)
          echo "url=https://github.com/codespaces/${CODESPACE}" >> "$GITHUB_OUTPUT"
        env:
          GH_TOKEN: ${{ secrets.ORG_ADMIN_TOKEN }}

      # Step 3: 프로덕션에 영향을 주지 않는 독립 샌드박스 DB를 생성한다
      - name: "Step 3: 샌드박스 환경 생성"
        id: sandbox
        run: npx tsx scripts/create-sandbox.ts
        env:
          MEMBER_ID: ${{ inputs.github_username }}
          TEAM: ${{ inputs.team }}
          AWS_REGION: ap-northeast-2

      # Step 4: 관련 Slack 채널에 자동 초대하고 환영 메시지를 보낸다
      - name: "Step 4: Slack 채널 초대"
        run: npx tsx scripts/slack-onboarding.ts
        env:
          SLACK_BOT_TOKEN: ${{ secrets.SLACK_BOT_TOKEN }}
          MEMBER_NAME: ${{ inputs.full_name }}
          MEMBER_GITHUB: ${{ inputs.github_username }}
          TEAM: ${{ inputs.team }}
          MENTOR_GITHUB: ${{ inputs.mentor_github_id }}

      # Step 5: 온보딩 트래킹 이슈와 첫 번째 과제를 자동으로 할당한다
      - name: "Step 5: 온보딩 이슈 + 첫 이슈 할당"
        uses: actions/github-script@v7
        with:
          script: |
            const member = '${{ inputs.github_username }}';
            const mentor = '${{ inputs.mentor_github_id }}';
            const team = '${{ inputs.team }}';
            const sandboxUrl = '${{ steps.sandbox.outputs.url }}';
            const codespaceUrl = '${{ steps.codespace.outputs.url }}';

            // 온보딩 트래킹 이슈 생성 -- 30일 로드맵을 체크리스트로 포함
            const { data: trackingIssue } = await github.rest.issues.create({
              owner: context.repo.owner,
              repo: context.repo.repo,
              title: `[온보딩] ${{ inputs.full_name }} (@${member})`,
              body: [
                `## 환영합니다, @${member}!`,
                '',
                '### 자동 설정 완료 항목',
                `- [x] Repository 권한 부여 (${team} 팀)`,
                `- [x] Codespace 생성: ${codespaceUrl}`,
                `- [x] 샌드박스 환경: ${sandboxUrl}`,
                '- [x] Slack 채널 초대',
                '',
                '### 30일 온보딩 로드맵',
                '#### Week 1: 환경 + 탐색',
                '- [ ] Codespace 접속 및 `pnpm dev` 실행 확인',
                '- [ ] 샌드박스 환경에서 API 호출 테스트',
                '- [ ] AI 멘토 봇에 질문 3개 이상',
                '- [ ] 첫 PR 생성 (아래 First Issue 참고)',
                '',
                '#### Week 2: 도메인 학습',
                '- [ ] 담당 도메인 코드 리딩 (AI 프롬프트 활용)',
                '- [ ] 멘토 1:1 미팅 2회',
                '- [ ] 버그 수정 PR 1개',
                '',
                '#### Week 3: 독립적 업무',
                '- [ ] 소규모 feature task 완료',
                '- [ ] 다른 멤버 PR 리뷰 3개',
                '',
                '#### Week 4: 본격 기여',
                '- [ ] 중간 규모 feature 개발',
                '- [ ] 온보딩 회고 작성',
                '',
                `### 멘토: @${mentor}`,
              ].join('\n'),
              labels: ['onboarding'],
              assignees: [member, mentor],
            });

            // 첫 이슈 할당 -- "good first issue" 라벨이 붙은 미할당 이슈 중 하나를 자동 배정
            const { data: firstIssues } = await github.rest.issues.listForRepo({
              owner: context.repo.owner,
              repo: context.repo.repo,
              labels: 'good first issue',
              state: 'open',
              assignee: 'none',
              per_page: 1,
            });

            if (firstIssues.length > 0) {
              await github.rest.issues.addAssignees({
                owner: context.repo.owner,
                repo: context.repo.repo,
                issue_number: firstIssues[0].number,
                assignees: [member],
              });

              await github.rest.issues.createComment({
                owner: context.repo.owner,
                repo: context.repo.repo,
                issue_number: firstIssues[0].number,
                body: `@${member} 이 이슈가 첫 번째 과제로 할당되었습니다.\n멘토 @${mentor}에게 질문하거나, Slack에서 AI 멘토 봇(\`@ai-mentor\`)에게 물어보세요.`,
              });
            }
```

### Slack 온보딩 스크립트

아래 스크립트는 위 워크플로우의 Step 4에서 호출된다. 신규 멤버를 팀 채널, 공통 채널, AI 멘토 채널에 자동 초대하고, 환영 메시지와 DM 가이드를 보낸다.

```typescript
// scripts/slack-onboarding.ts
// 용도: 신규 멤버를 Slack 채널에 초대하고 환영 메시지를 전송
import { WebClient } from "@slack/web-api";

// 팀별로 초대할 채널 목록을 정의하는 인터페이스
interface OnboardingChannels {
  team: string;        // 팀 전용 채널 (예: #team-frontend)
  general: string;     // 전체 개발자 채널
  aiMentor: string;    // AI 멘토 봇 채널
  announcements: string; // 공지사항 채널
}

// 팀별 채널 매핑 -- 새로운 팀이 생기면 여기에 추가
const TEAM_CHANNELS: Record<string, OnboardingChannels> = {
  frontend: {
    team: "#team-frontend",
    general: "#dev-general",
    aiMentor: "#ai-mentor",
    announcements: "#announcements",
  },
  backend: {
    team: "#team-backend",
    general: "#dev-general",
    aiMentor: "#ai-mentor",
    announcements: "#announcements",
  },
  platform: {
    team: "#team-platform",
    general: "#dev-general",
    aiMentor: "#ai-mentor",
    announcements: "#announcements",
  },
  mobile: {
    team: "#team-mobile",
    general: "#dev-general",
    aiMentor: "#ai-mentor",
    announcements: "#announcements",
  },
};

async function onboardToSlack(): Promise<void> {
  const slack = new WebClient(process.env.SLACK_BOT_TOKEN);
  const memberName = process.env.MEMBER_NAME!;
  const memberGithub = process.env.MEMBER_GITHUB!;
  const team = process.env.TEAM!;
  const mentorGithub = process.env.MENTOR_GITHUB!;
  const channels = TEAM_CHANNELS[team];

  // GitHub ID로 Slack 사용자 조회 (프로필 커스텀 필드에 GitHub 연동 기준)
  const users = await slack.users.list({});
  const member = users.members?.find(
    (u) => u.profile?.fields?.["Xf01_github"]?.value === memberGithub,
  );

  if (!member?.id) {
    console.log(`Slack 사용자를 찾을 수 없음: ${memberGithub}`);
    return;
  }

  // 정의된 모든 채널에 순차적으로 초대
  for (const channel of Object.values(channels)) {
    try {
      const channelInfo = await slack.conversations.list({
        types: "public_channel",
      });
      const target = channelInfo.channels?.find((c) => `#${c.name}` === channel);
      if (target?.id) {
        await slack.conversations.invite({
          channel: target.id,
          users: member.id,
        });
      }
    } catch {
      // 이미 참여 중인 채널이면 에러가 나지만 무시해도 안전하다
      console.log(`채널 초대 실패 (이미 참여 중일 수 있음): ${channel}`);
    }
  }

  // 공지사항 채널에 환영 메시지 게시
  const announcementsChannel = await slack.conversations.list({
    types: "public_channel",
  });
  const announcements = announcementsChannel.channels?.find(
    (c) => `#${c.name}` === channels.announcements,
  );

  if (announcements?.id) {
    await slack.chat.postMessage({
      channel: announcements.id,
      text: `*새로운 팀원을 환영합니다!*\n${memberName} (@${memberGithub})님이 ${team} 팀에 합류했습니다.\n멘토: @${mentorGithub}\n\nAI 멘토 봇은 ${channels.aiMentor} 채널에서 이용할 수 있습니다.`,
    });
  }

  // DM으로 시작 가이드를 개인 전송 (첫날 볼 핵심 내용)
  const dm = await slack.conversations.open({ users: member.id });
  if (dm.channel?.id) {
    await slack.chat.postMessage({
      channel: dm.channel.id,
      text: `안녕하세요 ${memberName}님, 환영합니다!\n\n*시작 가이드:*\n1. Codespace에 접속하세요 (GitHub 이슈에 링크 있음)\n2. \`pnpm dev\`로 개발 서버를 실행하세요\n3. ${channels.aiMentor} 채널에서 \`@ai-mentor 이 프로젝트 구조 설명해줘\`를 입력해보세요\n4. 할당된 첫 이슈를 확인하세요\n\n궁금한 건 언제든 AI 멘토 봇이나 멘토 @${mentorGithub}에게 물어보세요!`,
    });
  }
}

onboardToSlack();
```

## 3. GitHub Codespaces 심화

> **Codespace란?** 브라우저에서 VS Code를 열어 바로 코드를 편집하고 실행할 수 있는 클라우드 개발 환경이다. 로컬에 아무것도 설치하지 않아도 된다.

### 3.1 devcontainer + Prebuild 설정

`devcontainer.json`은 Codespace가 생성될 때 어떤 도구를 설치하고, 어떤 VS Code 확장을 활성화할지 정의하는 설정 파일이다.

```jsonc
// .devcontainer/devcontainer.json
{
  "name": "Project Dev Environment",
  // 베이스 이미지: Node.js 22 + TypeScript가 미리 설치된 컨테이너
  "image": "mcr.microsoft.com/devcontainers/typescript-node:22",
  // 추가 도구 설치 (AWS CLI, Docker, GitHub CLI 등)
  "features": {
    "ghcr.io/devcontainers/features/aws-cli:1": {},
    "ghcr.io/devcontainers/features/docker-in-docker:2": {},
    "ghcr.io/devcontainers/features/github-cli:1": {},
    "ghcr.io/devcontainers/features/sshd:1": {}
  },
  // Codespace 생성 직후 자동 실행되는 셋업 스크립트
  "postCreateCommand": "bash .devcontainer/setup.sh",
  // Codespace 시작할 때마다 실행되는 스크립트
  "postStartCommand": "bash .devcontainer/post-start.sh",
  // 자동으로 포워딩할 포트 목록 (로컬처럼 접근 가능)
  "forwardPorts": [3000, 3001, 5173, 6006],
  "portsAttributes": {
    "3000": { "label": "App Dev Server", "onAutoForward": "openBrowser" },
    "3001": { "label": "API Server" },
    "5173": { "label": "Vite HMR" },
    "6006": { "label": "Storybook" }
  },
  "customizations": {
    "vscode": {
      // 팀 공통 VS Code 확장 -- Codespace 생성 시 자동 설치
      "extensions": [
        "dbaeumer.vscode-eslint",
        "esbenp.prettier-vscode",
        "bradlc.vscode-tailwindcss",
        "ms-playwright.playwright",
        "github.copilot",
        "github.copilot-chat",
        "eamodio.gitlens",
        "vitest.explorer",
        "yoavbls.pretty-ts-errors"
      ],
      // 팀 공통 VS Code 설정
      "settings": {
        "editor.defaultFormatter": "esbenp.prettier-vscode",
        "editor.formatOnSave": true,
        "editor.codeActionsOnSave": {
          "source.fixAll.eslint": "explicit"
        },
        "typescript.preferences.importModuleSpecifier": "non-relative",
```

## 4. 신규 멤버 전용 샌드박스 환경

> **샌드박스란?** 프로덕션(실제 서비스) 데이터베이스와 완전히 분리된 독립 환경이다. 여기서는 마음껏 API를 호출하고, 데이터를 변경하고, 실험해도 실제 서비스에 영향이 전혀 없다.

### 독립 DB + 시드 데이터 자동 생성

```typescript
// scripts/create-sandbox.ts
// 용도: 신규 멤버 전용 Aurora PostgreSQL 샌드박스 클러스터를 자동 생성
import {
  RDSClient,
  CreateDBClusterSnapshotCommand,
  RestoreDBClusterFromSnapshotCommand,
  DeleteDBClusterCommand,
  DescribeDBClustersCommand,
} from "@aws-sdk/client-rds";
import {
  S3Client,
  CopyObjectCommand,
  ListObjectsV2Command,
} from "@aws-sdk/client-s3";
import { execSync } from "node:child_process";

// 샌드박스 생성에 필요한 설정값
interface SandboxConfig {
  memberId: string;              // 신규 멤버 GitHub ID
  team: string;                  // 소속 팀 (팀별로 시드 데이터가 다름)
  dbClusterIdentifier: string;   // 원본 DB 클러스터 이름
  seedDataBucket: string;        // S3 시드 데이터 버킷
  expiresInDays: number;         // 샌드박스 자동 만료 일수
}

// 샌드박스 생성 결과
interface SandboxResult {
  dbEndpoint: string;     // DB 접속 엔드포인트
  apiUrl: string;         // 샌드박스 전용 API URL
  dashboardUrl: string;   // Grafana 모니터링 대시보드 URL
  expiresAt: string;      // 자동 삭제 예정일
}

async function createSandboxDB(
  config: SandboxConfig,
): Promise<string> {
  const rds = new RDSClient({ region: "ap-northeast-2" });
  const sandboxId = `sandbox-${config.memberId}`;

  // 팀별 시드 스냅샷에서 독립 DB 클러스터를 복원한다
  // (프로덕션 DB가 아닌, 미리 준비된 테스트용 스냅샷)
  const snapshotId = `seed-snapshot-${config.team}`;

  await rds.send(
    new RestoreDBClusterFromSnapshotCommand({
      DBClusterIdentifier: sandboxId,
      SnapshotIdentifier: snapshotId,
      Engine: "aurora-postgresql",
      EngineVersion: "16.4",
      DBSubnetGroupName: "dev-subnet-group",
      VpcSecurityGroupIds: ["sg-sandbox"],
      DeletionProtection: false,   // 샌드박스이므로 삭제 보호 비활성화
      Tags: [
        { Key: "environment", Value: "sandbox" },
        { Key: "owner", Value: config.memberId },
        { Key: "team", Value: config.team },
        {
          Key: "expires-at",
          Value: new Date(
            Date.now() + config.expiresInDays * 86400_000,
          ).toISOString(),
        },
      ],
    }),
  );

  // DB가 "available" 상태가 될 때까지 대기 (최대 약 10분)
  let endpoint = "";
  for (let i = 0; i < 60; i++) {
    const desc = await rds.send(
      new DescribeDBClustersCommand({
        DBClusterIdentifier: sandboxId,
      }),
    );

    const cluster = desc.DBClusters?.[0];
    if (cluster?.Status === "available" && cluster.Endpoint) {
      endpoint = cluster.Endpoint;
      break;
    }

    await new Promise((resolve) => setTimeout(resolve, 10_000));
  }

  return endpoint;
}

// S3에서 팀별 시드 데이터를 샌드박스 전용 경로로 복사
async function seedSandboxData(
  config: SandboxConfig,
): Promise<void> {
  const s3 = new S3Client({ region: "ap-northeast-2" });
  const seedPrefix = `seed-data/${config.team}/`;
  const sandboxPrefix = `sandbox/${config.memberId}/`;

  const list = await s3.send(
    new ListObjectsV2Command({
      Bucket: config.seedDataBucket,
      Prefix: seedPrefix,
    }),
  );

  for (const obj of list.Contents ?? []) {
    if (!obj.Key) continue;
    const destKey = obj.Key.replace(seedPrefix, sandboxPrefix);
    await s3.send(
      new CopyObjectCommand({
        Bucket: config.seedDataBucket,
        CopySource: `${config.seedDataBucket}/${obj.Key}`,
        Key: destKey,
      }),
    );
  }

  console.log(`시드 데이터 복사 완료: ${list.Contents?.length ?? 0}개 파일`);
}

async function createSandbox(): Promise<void> {
  const config: SandboxConfig = {
    memberId: process.env.MEMBER_ID!,
    team: process.env.TEAM!,
    dbClusterIdentifier: "main-cluster",
    seedDataBucket: "project-seed-data",
    expiresInDays: 30,   // 30일 후 자동 삭제
  };

  console.log(`샌드박스 생성 시작: ${config.memberId}`);

  const dbEndpoint = await createSandboxDB(config);
  await seedSandboxData(config);

  const result: SandboxResult = {
    dbEndpoint,
    apiUrl: `https://sandbox-${config.memberId}.dev.example.com`,
    dashboardUrl: `https://grafana.example.com/d/sandbox?var-member=${config.memberId}`,
    expiresAt: new Date(
      Date.now() + config.expiresInDays * 86400_000,
    ).toISOString(),
  };

  // GitHub Actions output으로 결과 전달 (다음 step에서 사용)
  const outputFile = process.env.GITHUB_OUTPUT;
  if (outputFile) {
    const { appendFileSync } = await import("node:fs");
    appendFileSync(outputFile, `url=${result.apiUrl}\n`);
    appendFileSync(outputFile, `db=${result.dbEndpoint}\n`);
  }

  console.log("샌드박스 생성 완료:", JSON.stringify(result, null, 2));
}

createSandbox();

export type { SandboxConfig, SandboxResult };
```

### 샌드박스 자동 만료

매일 새벽 3시(UTC)에 실행되어, `expires-at` 태그가 지난 샌드박스 DB를 자동으로 정리한다. 비용 낭비를 방지하는 핵심 워크플로우이다.

```yaml
# .github/workflows/sandbox-cleanup.yml
name: Sandbox Environment Cleanup

on:
  schedule:
    - cron: "0 3 * * *" # 매일 03:00 UTC (한국시간 12:00)

permissions:
  id-token: write
  contents: read

jobs:
  cleanup:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - run: pnpm install --frozen-lockfile

      - name: Configure AWS credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_DEPLOY_ROLE_ARN }}
          aws-region: ap-northeast-2

      - name: Cleanup expired sandboxes
        run: npx tsx scripts/cleanup-sandboxes.ts
        env:
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_ONBOARDING_WEBHOOK }}
```

```typescript
// scripts/cleanup-sandboxes.ts
// 용도: expires-at 태그가 현재 시점보다 이전인 샌드박스 DB를 자동 삭제
import {
  RDSClient,
  DescribeDBClustersCommand,
  DeleteDBClusterCommand,
  ListTagsForResourceCommand,
} from "@aws-sdk/client-rds";

async function cleanupExpiredSandboxes(): Promise<void> {
  const rds = new RDSClient({ region: "ap-northeast-2" });
  const now = Date.now();

  // 모든 DB 클러스터 조회
  const clusters = await rds.send(
    new DescribeDBClustersCommand({}),
  );

  // "sandbox-"로 시작하는 클러스터만 필터링
  const sandboxes = (clusters.DBClusters ?? []).filter((c) =>
    c.DBClusterIdentifier?.startsWith("sandbox-"),
  );

  for (const cluster of sandboxes) {
    // 태그에서 만료 시각 확인
    const tags = await rds.send(
      new ListTagsForResourceCommand({
        ResourceName: cluster.DBClusterArn!,
      }),
    );

    const expiresAt = tags.TagList?.find(
      (t) => t.Key === "expires-at",
    )?.Value;

    // 만료된 샌드박스만 삭제
    if (expiresAt && new Date(expiresAt).getTime() < now) {
      await rds.send(
        new DeleteDBClusterCommand({
          DBClusterIdentifier: cluster.DBClusterIdentifier!,
          SkipFinalSnapshot: true,  // 샌드박스이므로 스냅샷 불필요
        }),
      );

      const owner =
        tags.TagList?.find((t) => t.Key === "owner")?.Value ?? "unknown";
      console.log(
        `샌드박스 삭제: ${cluster.DBClusterIdentifier} (owner: ${owner})`,
      );
    }
  }
}

cleanupExpiredSandboxes();
```

## 6. AI 멘토링 봇 2.0: Slack + Claude API + 코드베이스 RAG

> **RAG(Retrieval-Augmented Generation)란?** AI가 답변할 때 우리 프로젝트의 실제 코드를 검색해서 참고하는 기술이다. 일반적인 AI 답변이 아니라 "우리 코드베이스에 맞는" 구체적인 답변을 받을 수 있다.

### 6.1 벡터 DB 기반 코드 인덱싱

코드를 함수/클래스/컴포넌트 단위로 쪼개서(chunking) 벡터 DB에 저장한다. 나중에 질문이 들어오면 의미적으로 유사한 코드 조각을 검색하여 AI에게 컨텍스트로 제공한다.

```typescript
// ai-mentor-bot/src/code-indexer.ts
// 용도: 프로젝트의 소스코드를 의미 단위(함수, 클래스 등)로 분할하여 벡터 DB에 저장
import { readFileSync, readdirSync, statSync } from "node:fs";
import { join, extname } from "node:path";

// 코드를 분할한 하나의 조각(chunk)을 나타내는 타입
interface CodeChunk {
  filePath: string;    // 원본 파일 경로
  content: string;     // 코드 내용
  startLine: number;   // 시작 라인 번호
  endLine: number;     // 끝 라인 번호
  type: "function" | "class" | "component" | "hook" | "config" | "type" | "general";
  symbolName: string;  // 함수명, 클래스명 등
  embedding?: number[]; // 벡터 임베딩 (검색용)
}

// 인덱싱 설정 -- 어떤 파일을 포함/제외할지 정의
interface IndexConfig {
  projectRoot: string;
  includeExtensions: string[];  // 인덱싱할 파일 확장자
  excludePatterns: string[];    // 제외할 디렉토리/패턴
  chunkMaxLines: number;        // 한 청크의 최대 라인 수
}

const DEFAULT_INDEX_CONFIG: IndexConfig = {
  projectRoot: process.cwd(),
  includeExtensions: [".ts", ".tsx", ".js", ".jsx", ".json", ".yaml", ".yml"],
  excludePatterns: [
    "node_modules",
    "dist",
    ".next",
    "coverage",
    ".git",
    "__snapshots__",
  ],
  chunkMaxLines: 80,
};

// 디렉토리를 재귀적으로 탐색하며 인덱싱 대상 파일 수집
function collectFiles(dir: string, config: IndexConfig): string[] {
  const files: string[] = [];

  for (const entry of readdirSync(dir)) {
    const fullPath = join(dir, entry);

    // 제외 패턴에 해당하는 경로는 건너뛰기
    if (config.excludePatterns.some((p) => fullPath.includes(p))) {
      continue;
    }

    const stat = statSync(fullPath);
    if (stat.isDirectory()) {
      files.push(...collectFiles(fullPath, config));
    } else if (config.includeExtensions.includes(extname(entry))) {
      files.push(fullPath);
    }
  }

  return files;
}

// 코드 첫 줄을 분석하여 어떤 종류의 코드인지 판별
function detectChunkType(
  content: string,
): CodeChunk["type"] {
  // React Hook (use로 시작하는 함수)
  if (/^export\s+(default\s+)?function\s+use[A-Z]/.test(content)) return "hook";
  // React 컴포넌트 (대문자로 시작하는 함수)
  if (/^export\s+(default\s+)?function\s+[A-Z]/.test(content)) return "component";
  // 일반 함수
  if (/^(export\s+)?(async\s+)?function\s+/.test(content)) return "function";
  // 클래스
  if (/^(export\s+)?class\s+/.test(content)) return "class";
  // 타입/인터페이스
  if (/^(export\s+)?(interface|type)\s+/.test(content)) return "type";
  // 설정 파일
  if (/\.(config|json|yaml)$/.test(content)) return "config";
  return "general";
}

// 코드에서 심볼(함수명, 클래스명 등) 추출
function extractSymbolName(content: string): string {
  const patterns = [
    /(?:export\s+)?(?:default\s+)?(?:async\s+)?function\s+(\w+)/,
    /(?:export\s+)?class\s+(\w+)/,
    /(?:export\s+)?(?:interface|type)\s+(\w+)/,
    /(?:export\s+)?const\s+(\w+)/,
  ];

  for (const pattern of patterns) {
    const match = content.match(pattern);
    if (match) return match[1];
  }

  return "anonymous";
}

// 파일 하나를 의미 단위로 분할
function chunkFile(filePath: string, config: IndexConfig): CodeChunk[] {
  const content = readFileSync(filePath, "utf-8");
  const lines = content.split("\n");
  const chunks: CodeChunk[] = [];

  let currentChunk: string[] = [];
  let chunkStart = 1;

  for (let i = 0; i < lines.length; i++) {
    const line = lines[i];

    // 새 심볼(export, function, class 등) 시작을 감지하면 현재 청크를 저장하고 새로 시작
    const isNewSymbol =
      /^(export|function|class|interface|type|const|async)\s/.test(line.trim()) &&
      currentChunk.length > 0;

    if (isNewSymbol || currentChunk.length >= config.chunkMaxLines) {
      if (currentChunk.length > 0) {
        const chunkContent = currentChunk.join("\n");
        chunks.push({
          filePath,
          content: chunkContent,
          startLine: chunkStart,
          endLine: chunkStart + currentChunk.length - 1,
          type: detectChunkType(chunkContent),
          symbolName: extractSymbolName(chunkContent),
        });
      }
      currentChunk = [line];
      chunkStart = i + 1;
    } else {
      currentChunk.push(line);
    }
  }

  // 마지막 청크 처리
  if (currentChunk.length > 0) {
    const chunkContent = currentChunk.join("\n");
    chunks.push({
      filePath,
      content: chunkContent,
      startLine: chunkStart,
      endLine: chunkStart + currentChunk.length - 1,
      type: detectChunkType(chunkContent),
      symbolName: extractSymbolName(chunkContent),
    });
  }

  return chunks;
}

// 전체 인덱스 빌드 -- 모든 파일을 수집하고 청크로 분할
async function buildIndex(
  config: IndexConfig = DEFAULT_INDEX_CONFIG,
): Promise<CodeChunk[]> {
  const files = collectFiles(config.projectRoot, config);
  const allChunks: CodeChunk[] = [];

  for (const file of files) {
    const chunks = chunkFile(file, config);
    allChunks.push(...chunks);
  }

  console.log(
    `인덱스 빌드 완료: ${files.length}개 파일, ${allChunks.length}개 청크`,
  );
  return allChunks;
}

export { buildIndex, collectFiles, chunkFile, DEFAULT_INDEX_CONFIG };
export type { CodeChunk, IndexConfig };
```

### 6.2 RAG 기반 멘토 봇

Slack에서 `@ai-mentor`를 멘션하면 질문을 받아서, 코드베이스를 검색하고, Claude API로 답변을 생성하여 스레드에 응답한다.

```typescript
// ai-mentor-bot/src/mentor-bot-v2.ts
// 용도: Slack에서 동작하는 AI 멘토 봇 -- 코드베이스 RAG 기반 답변 생성
import Anthropic from "@anthropic-ai/sdk";
import { App as SlackApp } from "@slack/bolt";
import { readFileSync } from "node:fs";
import { join } from "node:path";
import type { CodeChunk } from "./code-indexer";

interface MentorBotV2Config {
  slackBotToken: string;
  slackAppToken: string;
  anthropicApiKey: string;
  projectRoot: string;
  vectorDbUrl: string;    // 벡터 DB 엔드포인트 (코드 검색용)
}

// 벡터 DB 검색 결과 -- 유사도 점수와 코드 조각
interface SearchResult {
  chunk: CodeChunk;
  score: number;   // 0~1 사이 유사도 점수 (1에 가까울수록 관련성 높음)
}

// 스레드별 대화 컨텍스트 (이전 대화를 기억하기 위함)
interface ConversationContext {
  userId: string;
  threadTs: string;
  messages: Array<{ role: "user" | "assistant"; content: string }>;
}

// 대화 컨텍스트 캐시 (스레드별로 관리)
const conversationCache = new Map<string, ConversationContext>();

// 벡터 DB에서 질문과 관련된 코드 조각 검색
async function searchCodebase(
  query: string,
  vectorDbUrl: string,
  topK: number = 5,   // 상위 5개 결과 반환
): Promise<SearchResult[]> {
  const response = await fetch(`${vectorDbUrl}/search`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ query, topK }),
  });

  return (await response.json()) as SearchResult[];
}

// AI 멘토의 시스템 프롬프트 생성 -- CLAUDE.md에서 프로젝트 정보를 읽어서 포함
function buildMentorSystemPrompt(projectRoot: string): string {
  const claudeMd = readFileSync(join(projectRoot, "CLAUDE.md"), "utf-8");

  return `당신은 개발팀의 AI 멘토입니다. 신규 멤버의 질문에 답변합니다.

프로젝트 정보:
${claudeMd}

응답 규칙:
1. 코드베이스 검색 결과를 기반으로 **실제 코드 경로와 예시**를 포함하여 답변하세요.
2. 확실하지 않은 내용은 "코드에서 확인이 필요합니다"라고 솔직히 말하세요.
3. 복잡한 개념은 비유를 사용하여 쉽게 설명하세요.
4. 관련 파일 경로를 항상 포함하세요.
5. 보안에 민감한 정보(시크릿, 토큰)는 절대 포함하지 마세요.
6. 한국어로 친근하게 답변하세요.
7. 신규 멤버가 자신감을 가질 수 있도록 격려하세요.`;
}

function createMentorBotV2(config: MentorBotV2Config) {
  const anthropic = new Anthropic({ apiKey: config.anthropicApiKey });
  const systemPrompt = buildMentorSystemPrompt(config.projectRoot);

  const slack = new SlackApp({
    token: config.slackBotToken,
    appToken: config.slackAppToken,
    socketMode: true,   // 소켓 모드로 실시간 이벤트 수신
  });

  // @ai-mentor 멘션 이벤트 처리
  slack.event("app_mention", async ({ event, say }) => {
    // 멘션 부분을 제거하고 순수 질문만 추출
    const question = event.text.replace(/<@[A-Z0-9]+>/g, "").trim();
    const threadTs = event.thread_ts ?? event.ts;

    // 1단계: 벡터 DB에서 질문과 관련된 코드 조각 검색
    const searchResults = await searchCodebase(
      question,
      config.vectorDbUrl,
    );

    // 검색 결과를 텍스트로 변환하여 AI 컨텍스트에 포함
    const codeContext = searchResults
      .map(
        (r) =>
          `### ${r.chunk.filePath} (L${r.chunk.startLine}-${r.chunk.endLine}) [${r.chunk.type}: ${r.chunk.symbolName}]\n\`\`\`\n${r.chunk.content}\n\`\`\``,
      )
      .join("\n\n");

    // 2단계: 스레드별 대화 히스토리 관리 (같은 스레드에서 이어지는 대화 지원)
    const cacheKey = `${event.channel}-${threadTs}`;
    let context = conversationCache.get(cacheKey);
    if (!context) {
      context = {
        userId: event.user,
        threadTs,
        messages: [],
      };
      conversationCache.set(cacheKey, context);
    }

    context.messages.push({ role: "user", content: question });

    // 최근 10개 메시지만 유지 (토큰 절약)
    if (context.messages.length > 10) {
      context.messages = context.messages.slice(-10);
    }

    // 3단계: Claude API로 답변 생성
    const response = await anthropic.messages.create({
      model: "claude-sonnet-4-20250514",
      max_tokens: 3000,
      system: `${systemPrompt}\n\n관련 코드 검색 결과:\n${codeContext}`,
      messages: context.messages.map((m) => ({
        role: m.role,
        content: m.content,
      })),
    });

    const answer = response.content
      .filter((block): block is Anthropic.TextBlock => block.type === "text")
      .map((block) => block.text)
      .join("\n");

    context.messages.push({ role: "assistant", content: answer });

    // 4단계: Slack 스레드에 답변 전송
    await say({ text: answer, thread_ts: threadTs });
  });

  // 슬래시 커맨드: /code-search -- Slack에서 직접 코드 검색
  slack.command("/code-search", async ({ command, ack, respond }) => {
    await ack();

    const results = await searchCodebase(
      command.text,
      config.vectorDbUrl,
      3,   // 검색 결과 3개만 반환
    );

    const blocks = results.map((r) => ({
      type: "section" as const,
      text: {
        type: "mrkdwn" as const,
        text: `*${r.chunk.filePath}* (L${r.chunk.startLine}-${r.chunk.endLine})\n\`${r.chunk.type}: ${r.chunk.symbolName}\` | score: ${r.score.toFixed(3)}\n\`\`\`${r.chunk.content.slice(0, 300)}\`\`\``,
      },
    }));

    await respond({ blocks });
  });

  return slack;
}

export { createMentorBotV2, searchCodebase };
export type { MentorBotV2Config, ConversationContext };
```

## 7. First PR 가이드 레일

> **이 기능이 하는 일:** 신규 멤버가 첫 번째 PR을 열면, AI가 자동으로 친절한 코드 리뷰를 남기고, 멘토를 리뷰어로 태그한다. 첫 PR의 심리적 부담을 줄이면서도 코드 품질 기준을 자연스럽게 전달하는 것이 목표이다.

### AI 친절 리뷰 + 멘토 자동 태그

```yaml
            한국어로 답변하세요.`,
              messages: [
                {
                  role: 'user',
                  content: `신규 멤버 ${author}의 첫 PR입니다. 친절하게 리뷰해주세요.

            PR 제목: ${context.payload.pull_request.title}
            PR 설명: ${context.payload.pull_request.body ?? '(없음)'}

            Diff:
            ${diff}

            리뷰 형식:
            1. 칭찬할 점 (2-3개)
            2. 개선 제안 (구체적 코드 라인 언급, 친절한 톤)
            3. 프로젝트 컨벤션 안내 (이 PR에서 적용 가능한 것)
            4. 다음 단계 제안`,
                },
              ],
            });

            const review = response.content
              .filter((b) => b.type === 'text')
              .map((b) => b.text)
              .join('\n');

            // PR 코멘트로 AI 리뷰 결과 + 멘토 태그 게시
            const mentorTag = mentor ? `\n\n---\n멘토 @${mentor}님, 첫 PR 리뷰를 부탁드립니다.` : '';

            await github.rest.issues.createComment({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.payload.pull_request.number,
              body: `## 첫 번째 PR을 환영합니다, @${author}!\n\n${review}${mentorTag}`,
            });

            // 멘토를 PR 리뷰어로 자동 배정
            if (mentor) {
              try {
                await github.rest.pulls.requestReviewers({
                  owner: context.repo.owner,
                  repo: context.repo.repo,
                  pull_number: context.payload.pull_request.number,
                  reviewers: [mentor],
                });
              } catch (e) {
                console.log(`멘토 리뷰어 추가 실패: ${e.message}`);
              }
            }

            // 온보딩 이슈의 체크리스트에서 "첫 PR 생성" 항목을 자동 체크
            if (onboardingIssue) {
              const updatedBody = onboardingIssue.body?.replace(
                '- [ ] 첫 PR 생성',
                '- [x] 첫 PR 생성',
              );
              if (updatedBody) {
                await github.rest.issues.update({
                  owner: context.repo.owner,
                  repo: context.repo.repo,
                  issue_number: onboardingIssue.number,
                  body: updatedBody,
                });
              }
            }
```

## 8. 30/60/90일 AI 기반 성과 리뷰

> **이 기능이 하는 일:** 신규 멤버의 GitHub 활동 데이터(커밋, PR, 리뷰)를 자동으로 수집하고, AI가 팀 평균과 비교하여 건설적인 피드백을 생성한다. 매니저와 멘토의 리뷰 부담을 줄이면서도 객관적인 성장 지표를 제공한다.

### 커밋 빈도, PR 크기, 리뷰 참여도 자동 분석

```typescript
// scripts/onboarding-review.ts
// 용도: 신규 멤버의 온보딩 기간 활동을 분석하고 AI 기반 성과 리뷰를 생성
import Anthropic from "@anthropic-ai/sdk";
import { execSync } from "node:child_process";

// 멤버의 활동 데이터를 담는 인터페이스
interface MemberActivity {
  username: string;
  period: "30d" | "60d" | "90d";
  startDate: string;
  endDate: string;
  commits: CommitStats;
  pullRequests: PRStats;
  reviews: ReviewStats;
  codeOwnership: OwnershipStats;
}

// 커밋 관련 통계
interface CommitStats {
  total: number;           // 전체 커밋 수
  perWeek: number;         // 주당 평균 커밋 수
  filesChanged: number;    // 변경한 파일 수
  linesAdded: number;      // 추가한 라인 수
  linesRemoved: number;    // 삭제한 라인 수
  topModifiedPaths: string[];  // 가장 많이 수정한 경로
}

// PR 관련 통계
interface PRStats {
  opened: number;              // 생성한 PR 수
  merged: number;              // 머지된 PR 수
  averageSize: number;         // 평균 변경 라인 수
  averageMergeTime: number;    // 평균 머지까지 걸린 시간(시간 단위)
  averageReviewRounds: number; // 평균 리뷰 라운드 수
}

// 코드 리뷰 관련 통계
interface ReviewStats {
  given: number;              // 작성한 리뷰 수
  commentsPerReview: number;  // 리뷰당 평균 코멘트 수
  approvalRate: number;       // 승인율
  reviewedAuthors: string[];  // 리뷰한 작성자 목록
}

// 코드 소유권 통계
interface OwnershipStats {
  primaryPaths: string[];      // 주로 담당하는 경로
  contributionScore: number;   // 기여도 점수 (0-100)
}

// AI가 생성하는 성과 리뷰 결과
interface PerformanceReview {
  summary: string;
  strengths: string[];
  growthAreas: string[];
  recommendations: string[];
  comparedToAverage: {
    metric: string;
    member: number;
    teamAverage: number;
    assessment: "above" | "at" | "below";
  }[];
  overallRating: "exceptional" | "on-track" | "needs-attention";
}

// GitHub API와 gh CLI를 사용하여 멤버의 활동 데이터 수집
async function collectMemberActivity(
  username: string,
  period: "30d" | "60d" | "90d",
): Promise<MemberActivity> {
  const repo = process.env.GITHUB_REPOSITORY!;
  const daysMap = { "30d": 30, "60d": 60, "90d": 90 };
  const days = daysMap[period];
  const since = new Date(Date.now() - days * 86400_000).toISOString();

  // 커밋 통계 수집
  const commitsJson = execSync(
    `gh api repos/${repo}/commits --paginate -f author=${username} -f since=${since} --jq 'length'`,
    { encoding: "utf-8" },
  ).trim();

  const commitCount = parseInt(commitsJson, 10) || 0;

  // PR 통계 수집
  const prsJson = execSync(
    `gh pr list --repo ${repo} --author ${username} --state all --json number,additions,deletions,createdAt,mergedAt,reviewRequests --limit 100`,
    { encoding: "utf-8" },
  );
  const prs = JSON.parse(prsJson) as Array<{
    number: number;
    additions: number;
    deletions: number;
    createdAt: string;
    mergedAt: string | null;
  }>;

  // 해당 기간 내 PR만 필터링
  const recentPRs = prs.filter(
    (pr) => new Date(pr.createdAt).getTime() > Date.now() - days * 86400_000,
  );
  const mergedPRs = recentPRs.filter((pr) => pr.mergedAt);

  // 평균 PR 크기 계산 (추가 + 삭제 라인 수)
  const avgSize =
    recentPRs.length > 0
      ? recentPRs.reduce((sum, pr) => sum + pr.additions + pr.deletions, 0) /
        recentPRs.length
      : 0;

  // 평균 머지 시간 계산 (시간 단위)
  const avgMergeTime =
    mergedPRs.length > 0
      ? mergedPRs.reduce((sum, pr) => {
          const created = new Date(pr.createdAt).getTime();
          const merged = new Date(pr.mergedAt!).getTime();
          return sum + (merged - created) / 3600_000;
        }, 0) / mergedPRs.length
      : 0;

  // 코드 리뷰 통계 수집
  const reviewsJson = execSync(
    `gh api search/issues --paginate -f q="repo:${repo} is:pr reviewed-by:${username} created:>=${since.split("T")[0]}" --jq '.total_count'`,
    { encoding: "utf-8" },
  ).trim();

  const reviewCount = parseInt(reviewsJson, 10) || 0;

  return {
    username,
    period,
    startDate: since,
    endDate: new Date().toISOString(),
    commits: {
      total: commitCount,
      perWeek: commitCount / (days / 7),
      filesChanged: 0,
      linesAdded: 0,
      linesRemoved: 0,
      topModifiedPaths: [],
    },
    pullRequests: {
      opened: recentPRs.length,
      merged: mergedPRs.length,
      averageSize: Math.round(avgSize),
      averageMergeTime: Math.round(avgMergeTime * 10) / 10,
      averageReviewRounds: 0,
    },
    reviews: {
      given: reviewCount,
      commentsPerReview: 0,
      approvalRate: 0,
      reviewedAuthors: [],
    },
    codeOwnership: {
      primaryPaths: [],
      contributionScore: 0,
    },
  };
}

// Claude API를 사용하여 활동 데이터를 분석하고 성과 리뷰 생성
async function generateAIReview(
  activity: MemberActivity,
): Promise<PerformanceReview> {
  const anthropic = new Anthropic({
    apiKey: process.env.ANTHROPIC_API_KEY,
  });

  const response = await anthropic.messages.create({
    model: "claude-sonnet-4-20250514",
    max_tokens: 2000,
    system: `당신은 엔지니어링 매니저입니다. 신규 멤버의 온보딩 기간 활동 데이터를 분석하여 건설적인 성과 리뷰를 작성합니다.
격려 중심으로, 구체적인 성장 방향을 제시하세요.
결과는 JSON으로 반환하세요.`,
    messages: [
      {
        role: "user",
        content: `${activity.username}의 ${activity.period} 활동 데이터:

커밋: ${activity.commits.total}개 (주당 ${activity.commits.perWeek.toFixed(1)}개)
PR: 생성 ${activity.pullRequests.opened}개, 머지 ${activity.pullRequests.merged}개
평균 PR 크기: ${activity.pullRequests.averageSize} lines
평균 머지 시간: ${activity.pullRequests.averageMergeTime}시간
코드 리뷰: ${activity.reviews.given}개

팀 평균 (참고):
- 주당 커밋: 8개
- PR 머지율: 85%
- 평균 PR 크기: 150 lines
- 코드 리뷰: 주당 3개

PerformanceReview JSON을 반환하세요:
{
  "summary": "한 줄 요약",
  "strengths": ["강점1", "강점2"],
  "growthAreas": ["성장 영역1"],
  "recommendations": ["구체적 제안1"],
  "comparedToAverage": [
    { "metric": "주당 커밋", "member": N, "teamAverage": N, "assessment": "above|at|below" }
  ],
  "overallRating": "exceptional|on-track|needs-attention"
}`,
      },
    ],
  });

  const text = response.content
    .filter((b): b is Anthropic.TextBlock => b.type === "text")
    .map((b) => b.text)
    .join("");

  // AI 응답에서 JSON 부분만 추출하여 파싱
  const jsonMatch = text.match(/\{[\s\S]*\}/);
  return JSON.parse(jsonMatch![0]) as PerformanceReview;
}

// 성과 리뷰 결과를 Markdown 형식으로 포맷팅
function formatReviewMarkdown(
  activity: MemberActivity,
  review: PerformanceReview,
): string {
  const ratingLabel: Record<string, string> = {
    exceptional: "우수",
    "on-track": "정상 궤도",
    "needs-attention": "관심 필요",
  };

  const comparisonRows = review.comparedToAverage
    .map((c) => {
      const icon =
        c.assessment === "above"
          ? "+"
          : c.assessment === "below"
            ? "-"
            : "=";
      return `| ${c.metric} | ${c.member} | ${c.teamAverage} | ${icon} |`;
    })
    .join("\n");

  return `## ${activity.period} 온보딩 리뷰: @${activity.username}

**종합 평가:** ${ratingLabel[review.overallRating]}
**기간:** ${activity.startDate.split("T")[0]} ~ ${activity.endDate.split("T")[0]}

### 요약
${review.summary}

### 강점
${review.strengths.map((s) => `- ${s}`).join("\n")}

### 성장 영역
${review.growthAreas.map((g) => `- ${g}`).join("\n")}

### 팀 평균 대비
| 지표 | 본인 | 팀 평균 | 비교 |
|------|------|---------|------|
${comparisonRows}

### 추천 액션
${review.recommendations.map((r, i) => `${i + 1}. ${r}`).join("\n")}
`;
}

// 메인 실행 -- 활동 수집 -> AI 리뷰 생성 -> GitHub 이슈에 코멘트
async function runReview(): Promise<void> {
  const username = process.env.MEMBER_USERNAME!;
  const period = (process.env.REVIEW_PERIOD ?? "30d") as "30d" | "60d" | "90d";

  const activity = await collectMemberActivity(username, period);
  const review = await generateAIReview(activity);
  const markdown = formatReviewMarkdown(activity, review);

  console.log(markdown);

  // 온보딩 이슈에 리뷰 결과를 코멘트로 게시
  if (process.env.ONBOARDING_ISSUE_NUMBER) {
    const repo = process.env.GITHUB_REPOSITORY!;
    execSync(
      `gh issue comment ${process.env.ONBOARDING_ISSUE_NUMBER} --repo ${repo} --body ${JSON.stringify(markdown)}`,
      { encoding: "utf-8" },
    );
  }
}

runReview();

export { collectMemberActivity, generateAIReview, formatReviewMarkdown };
export type { MemberActivity, PerformanceReview };
```

### Q: Codespace가 느려요. 어떻게 하나요?

Codespace 사양이 부족하면 GitHub Settings > Codespaces에서 머신 타입을 업그레이드할 수 있다. 기본은 4코어/8GB인데, 빌드가 느리다면 8코어/16GB를 사용해 보자. 팀 리드에게 요청하면 된다.

```bash
# 현재 Codespace 리소스 확인
nproc          # CPU 코어 수
free -h        # 메모리 사용량
df -h /        # 디스크 사용량
```

### Q: AI 멘토 봇이 잘못된 답변을 해요.

AI 멘토 봇은 코드베이스 RAG를 기반으로 답변하지만, 100% 정확하지 않을 수 있다. 답변이 이상하면:

1. Slack에서 `@ai-mentor` 대신 사람 멘토에게 직접 물어보기
2. 잘못된 답변은 스레드에 "이 답변은 정확하지 않음"이라고 표시 (봇 개선에 활용)
3. Claude Code에서 직접 코드를 확인: `claude "src/hooks/useAuth.ts 파일 분석해줘"`

### Q: 첫 PR이 너무 무서워요. 어떤 수준이어야 하나요?

첫 PR은 완벽할 필요 없다. "good first issue" 라벨이 붙은 이슈는 의도적으로 범위가 작고 안전하게 설계되어 있다. AI가 친절하게 리뷰해 주고, 멘토가 자동으로 태그되니 부담 갖지 않아도 된다. 자세한 PR 가이드는 [16. AI 협업 코드리뷰 가이드](./16_AI_협업_코드리뷰_가이드.md)를 참고한다.

### Q: 샌드박스 환경은 얼마나 유지되나요?

기본 30일이다. 만료 전에 Slack으로 알림이 온다. 추가 기간이 필요하면 팀 리드에게 요청하면 연장할 수 있다.

### Q: 로컬 환경에서도 개발할 수 있나요?

가능하다. Codespace가 기본이지만, 로컬 환경을 선호하면 아래 단계를 따르면 된다.

```bash
# 1. 리포지토리 클론
git clone https://github.com/{org}/{repo}.git
cd {repo}

# 2. Node.js 22 + pnpm 설치 확인
node --version  # v22.x 확인
pnpm --version  # 9.x 이상 확인

# 3. 의존성 설치
pnpm install

# 4. 환경변수 설정
cp .env.example .env.local
# .env.local 파일을 열어서 필요한 값 채우기

# 5. 로컬 DB 시작 (Docker 필요)
docker compose -f docker-compose.dev.yml up -d

# 6. DB 마이그레이션 + 시드 데이터
pnpm db:migrate
pnpm db:seed

# 7. 개발 서버 실행
pnpm dev
```
