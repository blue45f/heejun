## 1. 배포 철학: Progressive Delivery 2.0

배포는 릴리즈가 아니라 **관측 가능한 실험**이다. 모든 배포는 Canary에서 시작하고, 메트릭이 안전을 증명할 때만 자동으로 승격된다. AI는 사람이 놓치는 리스크를 사전에 탐지하고, 멀티 베타 환경은 검증 범위를 극대화한다.

### 왜 Progressive Delivery인가

전통적인 배포(Big Bang Deploy)는 코드를 한 번에 전체 사용자에게 노출합니다. 문제가 발생하면 모든 사용자가 영향을 받습니다. Progressive Delivery는 이를 근본적으로 바꿉니다.

```
전통적 배포:  코드 머지 → 빌드 → 전체 배포 (100% 한번에)
                                         ↓
                                    문제 발생 시 전체 장애

Progressive:  코드 머지 → 빌드 → 0.1% → 1% → 10% → 50% → 100%
                                  ↓      ↓      ↓      ↓
                              메트릭  메트릭  메트릭  메트릭 검증
                              검증    검증    검증    (각 단계에서 자동 롤백 가능)
```

### 핵심 원칙

| 원칙 | 설명 | 주니어를 위한 요약 |
|------|------|-------------------|
| **Canary First** | 모든 프로덕션 배포는 Canary(0.1%)에서 시작, 메트릭이 안전을 증명할 때만 승격 | 새 코드를 소수 사용자에게 먼저 보여주고, 괜찮으면 점차 확대 |
| **AI 사고 방지** | PR 단계에서 AI가 프로덕션 리스크, 롤백 시 데이터 정합성 이슈를 사전 분석 | AI가 "이 코드 배포하면 위험할 수 있다"를 미리 알려줌 |
| **환경 수명 관리** | 모든 베타/Preview 환경은 TTL 72시간, 자동 만료로 비용 최적화 | 테스트 환경이 자동으로 사라져서 AWS 비용을 아낌 |
| **배포 동결 자동화** | 캘린더 연동으로 Code Freeze 기간 자동 감지, Branch Protection 자동 토글 | 연말/연휴 등 배포 금지 기간에는 자동으로 머지가 차단됨 |
| **관측 가능성** | N개 환경 상태를 단일 대시보드에서 실시간 모니터링 | 모든 환경의 건강 상태를 한 화면에서 확인 |

### 배포 파이프라인 전체 흐름

```
┌─────────────┐     ┌──────────────┐     ┌───────────────┐     ┌──────────────┐
│   PR 생성    │ ──→ │ AI 리스크 분석 │ ──→ │ Preview 자동   │ ──→ │  코드 리뷰    │
│             │     │  (자동 실행)   │     │  환경 생성     │     │  + 승인      │
└─────────────┘     └──────────────┘     └───────────────┘     └──────┬───────┘
                                                                      │
    ┌──────────────────────────────────────────────────────────────────┘
    ▼
┌─────────────┐     ┌──────────────┐     ┌───────────────┐     ┌──────────────┐
│   Beta 배포  │ ──→ │ Staging 배포  │ ──→ │ Production    │ ──→ │  모니터링     │
│  (E2E 테스트)│     │ (24시간 검증) │     │  Canary 배포   │     │  (30분 이상)  │
└─────────────┘     └──────────────┘     └───────────────┘     └──────────────┘
```

> **참고:** CI/CD 파이프라인의 기본 구성은 [11. CI/CD 파이프라인 표준](./11_CICD_파이프라인_표준.md)을, 인프라 프로비저닝 상세는 [10. 인프라 및 AWS CDK 가이드](./10_인프라_및_AWS_CDK_가이드.md)를 참조하세요.

## 2. AI 배포 사고 방지 시나리오

이 섹션에서는 AI(Claude)를 활용하여 배포 전에 잠재적인 장애를 사전에 탐지하는 방법을 설명합니다. 각 시나리오는 실제 프롬프트 템플릿과 함께 제공되므로, 복사-붙여넣기로 바로 사용할 수 있습니다.

### 시나리오 1: 프로덕션 리스크 분석

PR이 프로덕션에 미칠 영향을 사전에 분석합니다. AI가 장애 시나리오, 영향 범위, 탈출 경로를 자동으로 도출합니다.

```text
당신은 시니어 SRE + 프로덕션 사고 전문가입니다.
이 PR이 프로덕션에 영향을 줄 리스크를 분석해줘.

## 분석 관점
1. 장애 시나리오: 이 변경이 프로덕션에서 장애를 일으킬 수 있는 구체적 시나리오 3개
2. Blast Radius: 영향받는 사용자 비율, 매출 영향, SLA 위반 가능성
3. 탈출 경로: 각 장애 시나리오별 즉시 복구 방법 (롤백 / Feature Flag OFF / 핫픽스)
4. 의존성 체인: 이 변경이 트리거하는 다운스트림 서비스 영향
5. 시간대 리스크: 배포 시간대별 위험도 (피크 시간 vs 새벽)

## 출력 형식
- 종합 위험도: [LOW|MEDIUM|HIGH|CRITICAL]
- 배포 가능 여부: [즉시 배포|리뷰 후 배포|동결 기간 이후|배포 차단]
- 필수 사전 조건: (배포 전 반드시 확인할 항목)

## PR Diff:
{diff_content}
```

### 시나리오 2: 롤백 시 데이터 정합성 예측

배포 후 문제가 발생했을 때 롤백이 안전한지를 사전에 분석합니다. 특히 DB 스키마 변경, 캐시 포맷 변경 등 롤백하기 어려운 변경을 미리 감지합니다.

```text
당신은 데이터 정합성 전문가입니다.
이 PR을 배포 후 롤백해야 하는 상황을 가정하고, 데이터 정합성 이슈를 예측해줘.

## 분석 항목
1. 스키마 변경: 롤백 시 새 컬럼/테이블이 남아있을 때 구버전 코드 호환성
2. 데이터 마이그레이션: 롤백하면 마이그레이션된 데이터가 원복 가능한지
3. 캐시 오염: 새 포맷 캐시가 구버전에서 파싱 실패 가능성
4. 이벤트 스트림: 새 이벤트 포맷이 구버전 컨슈머에서 처리 가능한지
5. 외부 연동: 웹훅/콜백 URL 변경 시 롤백 후 외부 시스템 동기화

## 출력 형식 (JSON)
{
  "rollbackSafety": "SAFE | CAUTION | DANGEROUS",
  "dataIssues": [
    {
      "type": "schema | cache | event | external",
      "description": "구체적 이슈 설명",
      "mitigation": "해결 방법",
      "automatable": true | false
    }
  ],
  "recommendedRollbackStrategy": "instant | gradual | manual-with-script",
  "requiredPreRollbackSteps": ["단계1", "단계2"]
}

## PR Diff:
{diff_content}
```

### 시나리오 3: 배포 전 통합 안전 점검

여러 PR이 동시에 릴리즈될 때, PR 간 충돌이나 의도치 않은 부작용을 사전에 탐지합니다. 릴리즈 매니저가 가장 많이 활용하는 시나리오입니다.

```text
당신은 릴리즈 매니저입니다.
현재 릴리즈 후보에 포함된 모든 PR 목록을 보고, 통합 배포 시 발생 가능한 충돌 및 리스크를 분석해줘.

## 분석 항목
1. PR 간 파일 충돌: 동일 파일을 수정한 PR이 합쳐질 때 의도치 않은 동작
2. Feature Flag 교차: 서로 다른 PR의 Feature Flag가 동시에 활성화될 때 부작용
3. API 계약 변경 충돌: PR-A가 요청 포맷을 변경하고 PR-B가 기존 포맷을 전제할 때
4. 배포 순서 의존성: 특정 PR이 먼저 배포되어야 하는 순서 제약
5. 통합 테스트 필요 범위: 개별 PR에서는 안전하지만 합쳐지면 위험한 조합

## PR 목록:
{pr_list_with_diffs}
```

### GitHub Actions: AI 사고 방지 워크플로우

아래 워크플로우는 PR이 열리거나 업데이트될 때 자동으로 AI 리스크 분석을 실행합니다. 결과는 PR 코멘트로 게시됩니다.

```yaml
# .github/workflows/ai-incident-prevention.yml
# PR이 열리거나 업데이트되면 AI가 자동으로 배포 리스크를 분석합니다.
name: AI Incident Prevention

on:
  pull_request:
    types: [opened, synchronize, ready_for_review]
    branches: [main, release/*]

permissions:
  contents: read
  pull-requests: write

jobs:
  risk-analysis:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0 # 전체 히스토리가 있어야 diff를 정확하게 계산 가능

      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - run: pnpm install --frozen-lockfile
      - run: npx tsx scripts/ai-incident-prevention.ts
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
          PR_NUMBER: ${{ github.event.pull_request.number }}
```

```typescript
// scripts/ai-incident-prevention.ts
// PR diff를 Claude API에 전달하여 배포 리스크를 자동 분석하는 스크립트
import Anthropic from "@anthropic-ai/sdk";
import { execSync } from "node:child_process";

// === 타입 정의 ===

/** AI 분석 결과의 최상위 인터페이스 */
interface RiskAnalysisResult {
  overallRisk: "LOW" | "MEDIUM" | "HIGH" | "CRITICAL"; // 종합 위험도
  deployability: string;           // 배포 가능 여부 판단 문자열
  scenarios: IncidentScenario[];   // 장애 시나리오 목록
  rollbackSafety: RollbackAssessment; // 롤백 안전성 평가
  prerequisites: string[];         // 배포 전 필수 확인 사항
}

/** 개별 장애 시나리오 */
interface IncidentScenario {
  title: string;
  probability: "LOW" | "MEDIUM" | "HIGH";
  blastRadius: string;   // 영향 범위 설명 (예: "전체 사용자의 30%")
  escapePath: string;    // 탈출 경로 (예: "Feature Flag OFF")
}

/** 롤백 안전성 평가 */
interface RollbackAssessment {
  safety: "SAFE" | "CAUTION" | "DANGEROUS";
  dataIssues: DataIssue[];
  strategy: "instant" | "gradual" | "manual-with-script";
}

/** 데이터 정합성 이슈 */
interface DataIssue {
  type: "schema" | "cache" | "event" | "external";
  description: string;
  mitigation: string;
}

// === 핵심 로직 ===

/**
 * PR diff를 AI에 전달하여 리스크를 분석합니다.
 * gh CLI를 사용하여 PR 정보를 가져오고, Claude API를 호출합니다.
 */
async function analyzePRRisk(): Promise<RiskAnalysisResult> {
  const prNumber = process.env.PR_NUMBER!;

  // gh CLI로 PR diff 가져오기 (최대 10MB)
  const diff = execSync(
    `gh pr diff ${prNumber} --repo $GITHUB_REPOSITORY`,
    { encoding: "utf-8", maxBuffer: 10 * 1024 * 1024 },
  );

  // PR 메타데이터 가져오기
  const prInfo = JSON.parse(
    execSync(
      `gh pr view ${prNumber} --repo $GITHUB_REPOSITORY --json title,body,files,labels`,
      { encoding: "utf-8" },
    ),
  );

  const anthropic = new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY });

  // Claude API 호출 -- 리스크 분석 요청
  const response = await anthropic.messages.create({
    model: "claude-sonnet-4-20250514",
    max_tokens: 4096,
    system: `당신은 시니어 SRE 전문가입니다. PR 분석 결과를 JSON으로 반환하세요.
응답은 반드시 RiskAnalysisResult JSON만 포함하세요.`,
    messages: [
      {
        role: "user",
        content: `PR #${prNumber}: ${prInfo.title}
변경 파일 수: ${prInfo.files.length}
Labels: ${prInfo.labels.map((l: { name: string }) => l.name).join(", ")}

Diff (처음 8000자):
${diff.slice(0, 8000)}

분석 항목:
1. 장애 시나리오 3개 (probability, blastRadius, escapePath 포함)
2. 롤백 안전성 (데이터 정합성 이슈 포함)
3. 배포 가능 여부 및 필수 사전 조건`,
      },
    ],
  });

  // AI 응답에서 JSON 추출
  const text = response.content
    .filter((b): b is Anthropic.TextBlock => b.type === "text")
    .map((b) => b.text)
    .join("");

  const jsonMatch = text.match(/\{[\s\S]*\}/);
  return JSON.parse(jsonMatch![0]) as RiskAnalysisResult;
}

/**
 * 분석 결과를 Markdown 형식의 PR 코멘트로 변환합니다.
 * 위험도에 따라 이모지를 달리 표시하여 직관적으로 확인할 수 있습니다.
 */
function formatRiskComment(result: RiskAnalysisResult): string {
  const riskEmoji: Record<string, string> = {
    LOW: "🟢", MEDIUM: "🟡", HIGH: "🟠", CRITICAL: "🔴",
  };

  const scenarios = result.scenarios
    .map(
      (s) =>
        `| ${s.title} | ${s.probability} | ${s.blastRadius} | ${s.escapePath} |`,
    )
    .join("\n");

  const dataIssues = result.rollbackSafety.dataIssues
    .map((d) => `- **[${d.type}]** ${d.description} → ${d.mitigation}`)
    .join("\n");

  return `## ${riskEmoji[result.overallRisk]} AI 배포 사고 방지 분석

**종합 위험도:** ${result.overallRisk}
**배포 가능 여부:** ${result.deployability}

### 장애 시나리오
| 시나리오 | 확률 | 영향 범위 | 탈출 경로 |
|---------|------|----------|----------|
${scenarios}

### 롤백 안전성: ${result.rollbackSafety.safety}
**권장 전략:** ${result.rollbackSafety.strategy}
${dataIssues || "데이터 정합성 이슈 없음"}

### 배포 전 필수 확인
${result.prerequisites.map((p) => `- [ ] ${p}`).join("\n")}`;
}

/**
 * 메인 실행 함수
 * CRITICAL 위험도가 감지되면 워크플로우를 실패시켜 배포를 차단합니다.
 */
async function main(): Promise<void> {
  const result = await analyzePRRisk();

  const comment = formatRiskComment(result);
  const prNumber = process.env.PR_NUMBER!;

  // PR에 분석 결과 코멘트 작성
  execSync(
    `gh pr comment ${prNumber} --repo $GITHUB_REPOSITORY --body ${JSON.stringify(comment)}`,
    { encoding: "utf-8" },
  );

  // CRITICAL이면 배포 차단 (워크플로우 실패 처리)
  if (result.overallRisk === "CRITICAL") {
    console.error("CRITICAL 위험도 감지 -- 배포 차단");
    process.exit(1);
  }
}

main();
```

> **주니어 개발자 팁:** 위 스크립트가 동작하려면 GitHub Secrets에 `ANTHROPIC_API_KEY`가 설정되어 있어야 합니다. 설정 방법은 [11. CI/CD 파이프라인 표준](./11_CICD_파이프라인_표준.md)의 Secrets 관리 섹션을 참조하세요.

## 3. GitHub Environments + Deployment Protection Rules

GitHub Environments는 배포 대상 환경(preview, beta, staging, production)을 정의하고, 각 환경별로 보호 규칙을 설정하는 기능입니다. "누가 승인해야 하는가", "몇 분을 대기해야 하는가" 같은 규칙을 환경 단위로 관리합니다.

### 3.1 Environment 설정 자동화

아래 스크립트는 4단계 환경(preview / beta / staging / production)을 자동으로 구성합니다.

```typescript
// scripts/setup-github-environments.ts
// GitHub API를 사용하여 환경별 보호 규칙과 변수를 자동 설정합니다.
import { execSync } from "node:child_process";

/** 단일 환경의 전체 설정을 정의하는 인터페이스 */
interface EnvironmentConfig {
  name: string;                         // 환경 이름
  protectionRules: ProtectionRule[];    // 보호 규칙 (리뷰어, 대기시간 등)
  variables: Record<string, string>;    // 환경 변수
  deploymentBranchPolicy: BranchPolicy; // 배포 허용 브랜치 정책
}

/** 보호 규칙 타입 */
interface ProtectionRule {
  type: "required_reviewers" | "wait_timer" | "custom";
  reviewers?: string[];    // 필수 리뷰어 팀 이름
  waitMinutes?: number;    // 대기 시간 (분)
  integrationId?: number;  // 커스텀 보호 규칙의 App ID
}

/** 배포 허용 브랜치 정책 */
interface BranchPolicy {
  protectedBranches: boolean;    // protected 브랜치만 허용 여부
  customBranches?: string[];     // 커스텀 브랜치 패턴 (예: "feature/*")
}

/**
 * 환경별 설정 정의
 *
 * preview: 모든 PR에 자동 생성, 보호 규칙 없음
 * beta: 5분 대기 후 배포 (자동 스모크 테스트 시간 확보)
 * staging: 테크리드 리뷰 + 15분 대기
 * production: SRE + 테크리드 리뷰 + 30분 대기 (가장 엄격)
 */
const ENVIRONMENTS: EnvironmentConfig[] = [
  {
    name: "preview",
    protectionRules: [],
    variables: {
      CDN_DOMAIN: "preview.example.com",
      CACHE_TTL: "300",       // 5분 -- Preview는 짧은 캐시
      ENV_TTL_HOURS: "72",    // 72시간 후 자동 삭제
    },
    deploymentBranchPolicy: {
      protectedBranches: false,
      customBranches: ["feature/*", "fix/*", "onboard-*"],
    },
  },
  {
    name: "beta",
    protectionRules: [
      { type: "wait_timer", waitMinutes: 5 },
    ],
    variables: {
      CDN_DOMAIN: "beta.example.com",
      CACHE_TTL: "600",              // 10분
      CANARY_INITIAL_WEIGHT: "1",    // Canary 시작 비율 1%
    },
    deploymentBranchPolicy: {
      protectedBranches: false,
      customBranches: ["release/*", "main"],
    },
  },
  {
    name: "staging",
    protectionRules: [
      { type: "required_reviewers", reviewers: ["tech-lead-team"] },
      { type: "wait_timer", waitMinutes: 15 },
    ],
    variables: {
      CDN_DOMAIN: "staging.example.com",
      CACHE_TTL: "1800",             // 30분
      CANARY_INITIAL_WEIGHT: "5",    // Canary 시작 비율 5%
    },
    deploymentBranchPolicy: {
      protectedBranches: true,
    },
  },
  {
    name: "production",
    protectionRules: [
      { type: "required_reviewers", reviewers: ["sre-team", "tech-lead-team"] },
      { type: "wait_timer", waitMinutes: 30 },
    ],
    variables: {
      CDN_DOMAIN: "app.example.com",
      CACHE_TTL: "86400",            // 24시간
      CANARY_INITIAL_WEIGHT: "0.1",  // Canary 시작 비율 0.1% (가장 보수적)
    },
    deploymentBranchPolicy: {
      protectedBranches: true,
    },
  },
];

/** 단일 환경을 GitHub에 설정합니다 */
function setupEnvironment(env: EnvironmentConfig): void {
  const repo = process.env.GITHUB_REPOSITORY!;

  // 환경 생성/업데이트 (gh API 사용)
  execSync(
    `gh api repos/${repo}/environments/${env.name} -X PUT -f wait_timer=${env.protectionRules.find((r) => r.type === "wait_timer")?.waitMinutes ?? 0}`,
    { encoding: "utf-8" },
  );

  // 환경 변수 설정
  for (const [key, value] of Object.entries(env.variables)) {
    execSync(
      `gh variable set ${key} --env ${env.name} --body "${value}" --repo ${repo}`,
      { encoding: "utf-8" },
    );
  }

  console.log(`Environment 설정 완료: ${env.name}`);
}

/** 모든 환경을 한 번에 설정합니다 */
function setupAllEnvironments(): void {
  for (const env of ENVIRONMENTS) {
    setupEnvironment(env);
  }
}

export { setupAllEnvironments, ENVIRONMENTS };
export type { EnvironmentConfig };
```

### 3.2 Deployment Protection Rules 커스텀 게이트

Deployment Gate는 배포 전에 여러 조건을 자동으로 검사하는 "관문"입니다. Code Freeze 여부, AI 위험도, 업무시간 여부, 이전 환경 검증 완료 여부 등을 종합적으로 판단합니다.

```typescript
// scripts/deployment-gate.ts
// 배포 전 자동 검증 -- 모든 조건이 통과해야 배포가 승인됩니다.

/** 게이트 입력값 */
interface DeploymentGateInput {
  environment: string;     // 배포 대상 환경 (preview, beta, staging, production)
  ref: string;             // Git ref (커밋 SHA 또는 브랜치 이름)
  prNumber?: number;       // PR 번호 (있는 경우)
  riskLevel?: string;      // AI가 분석한 위험도
}

/** 게이트 결과 */
interface GateResult {
  approved: boolean;         // 최종 승인 여부
  reason: string;            // 승인/거부 사유
  conditions: GateCondition[]; // 개별 조건 결과 목록
}

/** 개별 조건 */
interface GateCondition {
  name: string;     // 조건 이름
  passed: boolean;  // 통과 여부
  detail: string;   // 상세 설명
}

/**
 * 배포 게이트를 평가합니다.
 * 모든 조건이 통과해야 배포가 승인됩니다.
 *
 * 검사 순서:
 * 1. Code Freeze 여부
 * 2. AI 위험도 (CRITICAL이면 차단)
 * 3. 업무시간 여부 (프로덕션만)
 * 4. 이전 환경 배포 성공 여부
 */
async function evaluateDeploymentGate(
  input: DeploymentGateInput,
): Promise<GateResult> {
  const conditions: GateCondition[] = [];

  // 1. Code Freeze 체크
  const isCodeFrozen = await checkCodeFreeze();
  conditions.push({
    name: "Code Freeze",
    passed: !isCodeFrozen,
    detail: isCodeFrozen ? "현재 Code Freeze 기간입니다" : "Code Freeze 아님",
  });

  // 2. AI 위험도 체크
  if (input.riskLevel === "CRITICAL") {
    conditions.push({
      name: "AI Risk Level",
      passed: false,
      detail: "CRITICAL 위험도 -- 배포 차단",
    });
  } else {
    conditions.push({
      name: "AI Risk Level",
      passed: true,
      detail: `위험도: ${input.riskLevel ?? "UNKNOWN"}`,
    });
  }

  // 3. 업무시간 체크 (프로덕션 환경에서만 적용)
  // 이유: 새벽이나 주말에 프로덕션 배포를 하면 장애 대응이 어렵기 때문
  if (input.environment === "production") {
    const now = new Date();
    const hour = now.getUTCHours() + 9; // KST 변환
    const isBusinessHours = hour >= 10 && hour <= 17;
    const isWeekday = now.getDay() >= 1 && now.getDay() <= 5;
    const passed = isBusinessHours && isWeekday;
    conditions.push({
      name: "Business Hours",
      passed,
      detail: passed
        ? "업무시간 내 배포"
        : "비업무시간 -- 긴급 배포는 SRE 승인 필요",
    });
  }

  // 4. 이전 환경 배포 성공 여부
  // preview -> beta -> staging -> production 순서로 검증이 완료되어야 함
  const previousEnv = getPreviousEnvironment(input.environment);
  if (previousEnv) {
    const prevSuccess = await checkPreviousDeployment(previousEnv, input.ref);
    conditions.push({
      name: `${previousEnv} 검증 완료`,
      passed: prevSuccess,
      detail: prevSuccess
        ? `${previousEnv}에서 검증 완료`
        : `${previousEnv} 배포가 먼저 필요합니다`,
    });
  }

  const allPassed = conditions.every((c) => c.passed);
  return {
    approved: allPassed,
    reason: allPassed
      ? "모든 게이트 조건 통과"
      : conditions.filter((c) => !c.passed).map((c) => c.detail).join(", "),
    conditions,
  };
}

/** 환경의 선행 단계를 반환합니다 */
function getPreviousEnvironment(env: string): string | null {
  const order = ["preview", "beta", "staging", "production"];
  const idx = order.indexOf(env);
  return idx > 0 ? order[idx - 1] : null;
}

/** 내부 API에서 Code Freeze 상태를 조회합니다 */
async function checkCodeFreeze(): Promise<boolean> {
  const response = await fetch(
    `${process.env.INTERNAL_API_URL}/api/code-freeze/status`,
  );
  const data = (await response.json()) as { frozen: boolean };
  return data.frozen;
}

/** 이전 환경에서 특정 ref의 배포가 성공했는지 확인합니다 */
async function checkPreviousDeployment(
  env: string,
  ref: string,
): Promise<boolean> {
  const response = await fetch(
    `${process.env.INTERNAL_API_URL}/api/deployments/${env}/${ref}/status`,
  );
  const data = (await response.json()) as { success: boolean };
  return data.success;
}

export { evaluateDeploymentGate };
export type { DeploymentGateInput, GateResult };
```

## 4. 동적 S3+CloudFront 원클릭 프로비저닝

PR이 열리면 자동으로 독립된 Preview 환경을 생성합니다. 각 PR이 자신만의 URL을 갖게 되므로, QA 담당자나 디자이너가 별도의 설정 없이 바로 확인할 수 있습니다. CloudFront 캐시 전략에 대한 자세한 내용은 [12. CloudFront 캐시 전략](./12_CloudFront_캐시_전략.md)을 참조하세요.

### GitHub Actions: 전체 코드

```yaml
# .github/workflows/dynamic-environment.yml
# PR이 열리면 자동으로 Preview 환경을 생성하고, 수동으로도 환경을 만들 수 있습니다.
name: Dynamic Environment Provisioning

on:
  workflow_dispatch:
    inputs:
      environment_name:
        description: "환경 이름 (영문, 하이픈만)"
        required: true
        type: string
      branch:
        description: "배포할 브랜치"
        required: true
        default: "main"
        type: string
      ttl_hours:
        description: "환경 수명 (시간)"
        required: false
        default: "72"
        type: string
  pull_request:
    types: [opened, synchronize, reopened]

permissions:
  id-token: write    # AWS OIDC 인증에 필요
  contents: read
  pull-requests: write
  deployments: write

env:
  AWS_REGION: ap-northeast-2
  PREVIEW_BUCKET: ${{ vars.PREVIEW_BUCKET }}
  CF_DISTRIBUTION_ID: ${{ vars.CF_DISTRIBUTION_ID }}

jobs:
  # 1단계: 환경 이름과 TTL 결정
  determine-env-name:
    runs-on: ubuntu-latest
    outputs:
      env_name: ${{ steps.name.outputs.value }}
      ttl: ${{ steps.ttl.outputs.value }}
    steps:
      - id: name
        run: |
          # PR이면 "pr-123" 형식, 수동이면 입력값 사용
          if [ "${{ github.event_name }}" = "pull_request" ]; then
            echo "value=pr-${{ github.event.pull_request.number }}" >> "$GITHUB_OUTPUT"
          else
            echo "value=${{ inputs.environment_name }}" >> "$GITHUB_OUTPUT"
          fi
      - id: ttl
        run: |
          # PR이면 72시간 고정, 수동이면 입력값 사용
          if [ "${{ github.event_name }}" = "pull_request" ]; then
            echo "value=72" >> "$GITHUB_OUTPUT"
          else
            echo "value=${{ inputs.ttl_hours || '72' }}" >> "$GITHUB_OUTPUT"
          fi

  # 2단계: 빌드 및 S3 배포
  provision-and-deploy:
    needs: determine-env-name
    runs-on: ubuntu-latest
    environment:
      name: preview
      url: https://${{ vars.CDN_DOMAIN }}/${{ needs.determine-env-name.outputs.env_name }}/
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ github.event_name == 'pull_request' && github.head_ref || inputs.branch }}

      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - run: pnpm install --frozen-lockfile

      - name: Build application
        run: pnpm build
        env:
          # 환경별 base path를 주입하여 라우팅이 올바르게 동작하도록 함
          VITE_BASE_PATH: /${{ needs.determine-env-name.outputs.env_name }}/
          VITE_ENV_LABEL: ${{ needs.determine-env-name.outputs.env_name }}
          VITE_ENV_TTL: ${{ needs.determine-env-name.outputs.ttl }}h

      - name: Configure AWS credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_DEPLOY_ROLE_ARN }}
          aws-region: ${{ env.AWS_REGION }}

      - name: Deploy to S3 with TTL metadata
        run: |
          ENV_NAME="${{ needs.determine-env-name.outputs.env_name }}"
          TTL_HOURS="${{ needs.determine-env-name.outputs.ttl }}"
          # TTL 만료 시각 계산 (Linux/macOS 호환)
          EXPIRES_AT=$(date -u -d "+${TTL_HOURS} hours" +%Y-%m-%dT%H:%M:%SZ 2>/dev/null \
            || date -u -v+${TTL_HOURS}H +%Y-%m-%dT%H:%M:%SZ)

          # S3에 빌드 결과물 업로드 (기존 파일 삭제 후 동기화)
          aws s3 sync dist/ "s3://${PREVIEW_BUCKET}/${ENV_NAME}/" \
            --delete \
            --cache-control "public, max-age=300" \
            --metadata "ttl-hours=${TTL_HOURS},expires-at=${EXPIRES_AT},created-by=github-actions"

      - name: Invalidate CloudFront
        run: |
          # 캐시 무효화로 즉시 최신 버전이 반영되도록 함
          aws cloudfront create-invalidation \
            --distribution-id ${{ env.CF_DISTRIBUTION_ID }} \
            --paths "/${{ needs.determine-env-name.outputs.env_name }}/*"

      - name: Register environment in tracking DB
        run: |
          npx tsx scripts/register-environment.ts
        env:
          ENV_NAME: ${{ needs.determine-env-name.outputs.env_name }}
          ENV_URL: https://${{ vars.CDN_DOMAIN }}/${{ needs.determine-env-name.outputs.env_name }}/
          TTL_HOURS: ${{ needs.determine-env-name.outputs.ttl }}
          BRANCH: ${{ github.event_name == 'pull_request' && github.head_ref || inputs.branch }}
          COMMIT_SHA: ${{ github.sha }}

      - name: Comment PR with environment URL
        if: github.event_name == 'pull_request'
        uses: actions/github-script@v7
        with:
          script: |
            const envName = '${{ needs.determine-env-name.outputs.env_name }}';
            const envUrl = `https://${{ vars.CDN_DOMAIN }}/${envName}/`;
            const ttl = '${{ needs.determine-env-name.outputs.ttl }}';

            const body = [
              `## Preview 환경 배포 완료`,
              '',
              `| 항목 | 값 |`,
              `|------|------|`,
              `| URL | [${envUrl}](${envUrl}) |`,
              `| 환경 | \`${envName}\` |`,
              `| TTL | ${ttl}시간 후 자동 삭제 |`,
              `| 커밋 | \`${context.sha.slice(0, 8)}\` |`,
            ].join('\n');

            // 기존 코멘트가 있으면 업데이트, 없으면 새로 생성
            const { data: comments } = await github.rest.issues.listComments({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.issue.number,
            });

            const existing = comments.find(
              (c) => c.body?.includes('Preview 환경 배포 완료'),
            );

            if (existing) {
              await github.rest.issues.updateComment({
                owner: context.repo.owner,
                repo: context.repo.repo,
                comment_id: existing.id,
                body,
              });
            } else {
              await github.rest.issues.createComment({
                owner: context.repo.owner,
                repo: context.repo.repo,
                issue_number: context.issue.number,
                body,
              });
            }
```

### 환경 등록 스크립트

DynamoDB에 환경 정보를 기록하여, 대시보드에서 모든 환경을 추적할 수 있게 합니다. DynamoDB의 TTL 기능을 활용하여 만료된 레코드도 자동으로 정리됩니다.

```typescript
// scripts/register-environment.ts
// 새로 생성된 Preview 환경 정보를 DynamoDB에 등록합니다.
import { DynamoDBClient } from "@aws-sdk/client-dynamodb";
import {
  DynamoDBDocumentClient,
  PutCommand,
} from "@aws-sdk/lib-dynamodb";

/** DynamoDB에 저장되는 환경 레코드 */
interface EnvironmentRecord {
  envName: string;      // 환경 이름 (파티션 키)
  envUrl: string;       // 접근 URL
  branch: string;       // 배포 브랜치
  commitSha: string;    // 배포 커밋 SHA
  createdAt: string;    // 생성 시각 (ISO 8601)
  expiresAt: string;    // 만료 시각 (ISO 8601)
  ttlEpoch: number;     // DynamoDB TTL용 Unix timestamp
  status: "active" | "expired" | "deleted";
  createdBy: string;    // 생성자 (github-actions)
}

async function registerEnvironment(): Promise<void> {
  const client = DynamoDBDocumentClient.from(
    new DynamoDBClient({ region: "ap-northeast-2" }),
  );

  const ttlHours = parseInt(process.env.TTL_HOURS ?? "72", 10);
  const now = new Date();
  const expiresAt = new Date(now.getTime() + ttlHours * 3600_000);

  const record: EnvironmentRecord = {
    envName: process.env.ENV_NAME!,
    envUrl: process.env.ENV_URL!,
    branch: process.env.BRANCH!,
    commitSha: process.env.COMMIT_SHA!,
    createdAt: now.toISOString(),
    expiresAt: expiresAt.toISOString(),
    ttlEpoch: Math.floor(expiresAt.getTime() / 1000), // DynamoDB TTL은 Unix timestamp 사용
    status: "active",
    createdBy: "github-actions",
  };

  await client.send(
    new PutCommand({
      TableName: "preview-environments",
      Item: record,
    }),
  );

  console.log(`환경 등록: ${record.envName} (만료: ${record.expiresAt})`);
}

registerEnvironment();
```

## 5. 환경 TTL 자동 만료 (72시간)

Preview 환경을 무한히 유지하면 AWS 비용이 누적됩니다. 이 섹션에서는 6시간마다 만료된 환경을 자동으로 정리하는 시스템을 구축합니다.

### 작동 원리

```
[스케줄러 (6시간마다)]
        │
        ▼
[DynamoDB에서 만료된 환경 조회]  ←── ttlEpoch < 현재시각
        │
        ▼
```

### TTL 정리 스크립트

```typescript
// scripts/ttl-cleanup.ts
// 만료된 Preview 환경의 S3 파일을 삭제하고, CloudFront 캐시를 무효화합니다.
import {
  S3Client,
  ListObjectsV2Command,
  DeleteObjectsCommand,
} from "@aws-sdk/client-s3";
import {
  CloudFrontClient,
  CreateInvalidationCommand,
} from "@aws-sdk/client-cloudfront";
import { DynamoDBClient } from "@aws-sdk/client-dynamodb";
import {
  DynamoDBDocumentClient,
  ScanCommand,
  UpdateCommand,
} from "@aws-sdk/lib-dynamodb";

/** 만료된 환경 정보 */
interface ExpiredEnvironment {
  envName: string;
  expiresAt: string;
  createdBy: string;
  objectCount: number; // 삭제된 S3 오브젝트 수
}

/**
 * DynamoDB에서 TTL이 지난 환경 목록을 조회합니다.
 * status가 "active"이고 ttlEpoch가 현재 시각보다 이전인 레코드를 찾습니다.
 */
async function findExpiredEnvironments(
  docClient: DynamoDBDocumentClient,
): Promise<ExpiredEnvironment[]> {
  const now = Math.floor(Date.now() / 1000);

  const result = await docClient.send(
    new ScanCommand({
      TableName: "preview-environments",
      FilterExpression: "#s = :active AND #ttl < :now",
      ExpressionAttributeNames: { "#s": "status", "#ttl": "ttlEpoch" },
      ExpressionAttributeValues: { ":active": "active", ":now": now },
    }),
  );

  return (result.Items ?? []).map((item) => ({
    envName: item.envName as string,
    expiresAt: item.expiresAt as string,
    createdBy: item.createdBy as string,
    objectCount: 0,
  }));
}

/**
 * S3에서 특정 prefix 아래의 모든 오브젝트를 삭제합니다.
 * 페이지네이션을 처리하여 1000개 이상의 파일도 안전하게 삭제합니다.
 */
async function deleteS3Prefix(
  s3: S3Client,
  bucket: string,
  prefix: string,
): Promise<number> {
  let deleted = 0;
  let continuationToken: string | undefined;

  do {
    const list = await s3.send(
      new ListObjectsV2Command({
        Bucket: bucket,
        Prefix: prefix,
        ContinuationToken: continuationToken,
      }),
    );

    if (list.Contents?.length) {
      await s3.send(
        new DeleteObjectsCommand({
          Bucket: bucket,
          Delete: {
            Objects: list.Contents.map((obj) => ({ Key: obj.Key })),
          },
        }),
      );
      deleted += list.Contents.length;
    }

    continuationToken = list.NextContinuationToken;
  } while (continuationToken);

  return deleted;
}

/** Slack으로 정리 결과를 알립니다 */
async function notifySlack(
  webhookUrl: string,
  environments: ExpiredEnvironment[],
): Promise<void> {
  const envList = environments
    .map((e) => `- \`${e.envName}\` (만료: ${e.expiresAt}, 파일: ${e.objectCount}개)`)
    .join("\n");

  await fetch(webhookUrl, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      text: `*TTL 만료 환경 정리 완료*\n정리된 환경: ${environments.length}개\n${envList}`,
    }),
  });
}

/** 메인 정리 로직 */
async function runCleanup(): Promise<void> {
  const region = "ap-northeast-2";
  const bucket = process.env.PREVIEW_BUCKET!;
  const distributionId = process.env.CF_DISTRIBUTION_ID!;

  const s3 = new S3Client({ region });
  const cf = new CloudFrontClient({ region });
  const docClient = DynamoDBDocumentClient.from(
    new DynamoDBClient({ region }),
  );

  // 1. 만료된 환경 찾기
  const expired = await findExpiredEnvironments(docClient);

  if (expired.length === 0) {
    console.log("만료된 환경 없음");
    return;
  }

  console.log(`만료 환경 ${expired.length}개 정리 시작`);

  for (const env of expired) {
    // 2. S3 파일 삭제
    const prefix = `${env.envName}/`;
    env.objectCount = await deleteS3Prefix(s3, bucket, prefix);

    // 3. CloudFront 캐시 무효화
    await cf.send(
      new CreateInvalidationCommand({
        DistributionId: distributionId,
        InvalidationBatch: {
          CallerReference: `ttl-${env.envName}-${Date.now()}`,
          Paths: { Quantity: 1, Items: [`/${env.envName}/*`] },
        },
      }),
    );

    // 4. DynamoDB 상태 업데이트
    await docClient.send(
      new UpdateCommand({
        TableName: "preview-environments",
        Key: { envName: env.envName },
        UpdateExpression: "SET #s = :expired, deletedAt = :now",
        ExpressionAttributeNames: { "#s": "status" },
        ExpressionAttributeValues: {
          ":expired": "expired",
          ":now": new Date().toISOString(),
        },
      }),
    );

    console.log(`정리 완료: ${env.envName} (${env.objectCount}개 파일)`);
  }

  // 5. Slack 알림
  if (process.env.SLACK_WEBHOOK_URL) {
    await notifySlack(process.env.SLACK_WEBHOOK_URL, expired);
  }
}

runCleanup();
```

## 6. 배포 매트릭스 시각화 대시보드

모든 환경의 상태를 한눈에 파악할 수 있는 대시보드입니다. 15분마다 자동으로 갱신되며, 각 환경의 건강 상태, 남은 수명, 응답 시간 등을 표시합니다.

### 환경 상태 API

```typescript
// scripts/environment-dashboard.ts
// 모든 활성 환경의 상태를 조회하고, Markdown 대시보드를 생성합니다.
import { DynamoDBClient } from "@aws-sdk/client-dynamodb";
import {
  DynamoDBDocumentClient,
  ScanCommand,
} from "@aws-sdk/lib-dynamodb";

/** 단일 환경의 상태 정보 */
interface EnvironmentStatus {
  name: string;
  url: string;
  branch: string;
  commitSha: string;
  status: "active" | "expired" | "deploying" | "failed";
  health: "healthy" | "degraded" | "down" | "unknown";
  createdAt: string;
  expiresAt: string;
  remainingHours: number;    // 남은 수명 (시간)
  metrics: EnvironmentMetrics;
}

/** 환경별 메트릭 */
interface EnvironmentMetrics {
  p99Latency: number;        // P99 응답 시간 (ms)
  errorRate: number;         // 에러율 (0~1)
  requestsPerMinute: number; // 분당 요청 수
  lastHealthCheck: string;   // 마지막 헬스체크 시각
}

/** 대시보드 전체 데이터 */
interface DashboardData {
  timestamp: string;
  totalEnvironments: number;
  activeEnvironments: number;
  expiringWithin24h: number; // 24시간 내 만료 예정 환경 수
  environments: EnvironmentStatus[];
  matrix: EnvironmentMatrix;
}

/** 환경-기능 매트릭스 (어떤 기능이 어떤 환경에 배포되었는지) */
interface EnvironmentMatrix {
  headers: string[];
  rows: MatrixRow[];
}

interface MatrixRow {
  feature: string;
  cells: MatrixCell[];
}

interface MatrixCell {
  environment: string;
  deployed: boolean;
  version: string;
  flagEnabled: boolean;
}

/**
 * DynamoDB에서 활성 환경을 조회하고, 각 환경에 대해 헬스체크를 실행합니다.
 *
 * 헬스체크: 각 환경의 /health 엔드포인트에 HTTP 요청을 보내서
 * 응답 여부와 응답 시간을 측정합니다.
 */
async function buildDashboard(): Promise<DashboardData> {
  const docClient = DynamoDBDocumentClient.from(
    new DynamoDBClient({ region: "ap-northeast-2" }),
  );

  const result = await docClient.send(
    new ScanCommand({
      TableName: "preview-environments",
      FilterExpression: "#s = :active",
      ExpressionAttributeNames: { "#s": "status" },
      ExpressionAttributeValues: { ":active": "active" },
    }),
  );

  const now = Date.now();
  const environments: EnvironmentStatus[] = (result.Items ?? []).map(
    (item) => {
      const expiresAt = new Date(item.expiresAt as string).getTime();
      const remainingHours = Math.max(
        0,
        Math.round((expiresAt - now) / 3600_000),
      );

      return {
        name: item.envName as string,
        url: item.envUrl as string,
        branch: item.branch as string,
        commitSha: item.commitSha as string,
        status: "active",
        health: "unknown",
        createdAt: item.createdAt as string,
        expiresAt: item.expiresAt as string,
        remainingHours,
        metrics: {
          p99Latency: 0,
          errorRate: 0,
          requestsPerMinute: 0,
          lastHealthCheck: "",
        },
      };
    },
  );

  // 각 환경에 대해 헬스체크 실행
  for (const env of environments) {
    try {
      const start = Date.now();
      const response = await fetch(`${env.url}health`);
      const latency = Date.now() - start;

      env.health = response.ok ? "healthy" : "degraded";
      env.metrics.p99Latency = latency;
      env.metrics.lastHealthCheck = new Date().toISOString();
    } catch {
      env.health = "down";
    }
  }

  const expiringWithin24h = environments.filter(
    (e) => e.remainingHours <= 24,
  ).length;

  return {
    timestamp: new Date().toISOString(),
    totalEnvironments: environments.length,
    activeEnvironments: environments.filter((e) => e.health === "healthy")
      .length,
    expiringWithin24h,
    environments,
    matrix: {
      headers: environments.map((e) => e.name),
      rows: [],
    },
  };
}

/**
 * 대시보드 데이터를 Markdown 형식으로 변환합니다.
 * GitHub Pages나 Wiki에 게시하여 브라우저에서 확인할 수 있습니다.
 */
function renderDashboardMarkdown(data: DashboardData): string {
  const statusIcon = (health: string): string => {
    const icons: Record<string, string> = {
      healthy: "🟢",     // 정상
      degraded: "🟡",    // 성능 저하
      down: "🔴",        // 다운
      unknown: "⚪",     // 미확인
    };
    return icons[health] ?? "⚪";
  };

  const envRows = data.environments
    .map(
      (e) =>
        `| ${statusIcon(e.health)} ${e.name} | ${e.branch} | \`${e.commitSha.slice(0, 8)}\` | ${e.remainingHours}h | ${e.metrics.p99Latency}ms | [열기](${e.url}) |`,
    )
    .join("\n");

  return `# 배포 매트릭스 대시보드

**갱신:** ${data.timestamp}
**총 환경:** ${data.totalEnvironments} | **활성:** ${data.activeEnvironments} | **24시간 내 만료:** ${data.expiringWithin24h}

## 환경 상태

| 환경 | 브랜치 | 커밋 | 남은 시간 | P99 | 링크 |
|------|--------|------|----------|-----|------|
${envRows}
`;
}

export { buildDashboard, renderDashboardMarkdown };
export type { DashboardData, EnvironmentStatus };
```

## 7. Canary + 메트릭 기반 자동 프로모션 (Argo Rollouts)

Canary 배포는 새 버전을 극소수 사용자에게만 먼저 노출하는 전략입니다. Argo Rollouts는 이를 Kubernetes 환경에서 자동화해주는 도구입니다. 메트릭(에러율, 응답 시간 등)이 임계값을 넘지 않으면 자동으로 트래픽 비율을 올려줍니다.

### Canary 승격 단계 시각화

```
트래픽 비율    0.1%     1%      10%      50%     100%
              │       │        │        │        │
시간 ─────────┼───5m──┼──10m───┼──15m───┼──30m───┼──→
              │       │        │        │        │
검증 항목   헬스체크  메트릭   전체분석   전체분석  완료
              │    분석(x3)   (x3)     (x5)     │
              │       │        │        │        │
실패 시     즉시 롤백  즉시 롤백  즉시 롤백  즉시 롤백
```

### 7.1 Argo Rollouts + Prometheus 설정

```typescript
// scripts/generate-rollout-manifest.ts
// Argo Rollouts의 Rollout 매니페스트와 AnalysisTemplate을 생성합니다.

/** Canary 단계 정의 */
interface CanaryStep {
  setWeight?: number;                    // 트래픽 비율 (%)
  pause?: { duration?: string };         // 대기 시간
  analysis?: AnalysisTemplate;           // 메트릭 분석 템플릿
}

/** 분석 템플릿 -- Prometheus 쿼리를 실행하여 메트릭을 검증합니다 */
interface AnalysisTemplate {
  templateName: string;
  args: Record<string, string>;
  requiredSuccess: number; // 연속 성공 횟수 (높을수록 엄격)
}

/** Rollout 전체 설정 */
interface RolloutConfig {
  serviceName: string;
  image: string;
  tag: string;
  canarySteps: CanaryStep[];
  metricsProvider: "prometheus" | "datadog" | "cloudwatch";
  successThresholds: MetricThresholds;
}

/** 메트릭 임계값 -- 이 값을 넘으면 승격을 중단하거나 롤백합니다 */
interface MetricThresholds {
  errorRateMax: number;     // 최대 허용 에러율 (예: 0.01 = 1%)
  p99LatencyMax: number;    // 최대 허용 P99 응답시간 (ms)
  successRateMin: number;   // 최소 성공률 (예: 0.995 = 99.5%)
}

/**
 * 5단계 Canary 스텝을 생성합니다.
 *
 * 0.1% → 1% → 10% → 50% → 100%
 * 각 단계마다 대기 + 메트릭 분석을 수행합니다.
 * 단계가 올라갈수록 requiredSuccess가 증가하여 더 엄격하게 검증합니다.
 */
function generateCanarySteps(
  thresholds: MetricThresholds,
): CanaryStep[] {
  return [
    // 0.1% -- 최소 검증 (헬스체크 수준)
    {
      setWeight: 0.1,
    },
    {
      pause: { duration: "5m" },
    },
    {
      analysis: {
        templateName: "canary-health-check",
        args: {
          "error-rate-max": String(thresholds.errorRateMax),
          "p99-latency-max": String(thresholds.p99LatencyMax),
        },
        requiredSuccess: 1,
      },
    },
    // 1% -- 메트릭 분석 시작
    {
      setWeight: 1,
    },
    {
      pause: { duration: "10m" },
    },
    {
      analysis: {
        templateName: "canary-metrics-analysis",
        args: {
          "success-rate-min": String(thresholds.successRateMin),
          "p99-latency-max": String(thresholds.p99LatencyMax),
        },
        requiredSuccess: 3, // 3회 연속 성공 필요
      },
    },
    // 10% -- 본격적인 트래픽 투입
    {
      setWeight: 10,
    },
    {
      pause: { duration: "15m" },
    },
    {
      analysis: {
        templateName: "canary-full-analysis",
        args: {
          "error-rate-max": String(thresholds.errorRateMax),
          "p99-latency-max": String(thresholds.p99LatencyMax),
          "success-rate-min": String(thresholds.successRateMin),
        },
        requiredSuccess: 3,
      },
    },
    // 50% -- 대규모 트래픽
    {
      setWeight: 50,
    },
    {
      pause: { duration: "30m" },
    },
    {
      analysis: {
        templateName: "canary-full-analysis",
        args: {
          "error-rate-max": String(thresholds.errorRateMax),
          "p99-latency-max": String(thresholds.p99LatencyMax),
          "success-rate-min": String(thresholds.successRateMin),
        },
        requiredSuccess: 5, // 5회 연속 성공 필요 (가장 엄격)
      },
    },
    // 100% -- 전체 트래픽 전환
    {
      setWeight: 100,
    },
  ];
}

/** Argo Rollouts YAML 매니페스트를 생성합니다 */
function generateRolloutYAML(config: RolloutConfig): string {
  const stepsYaml = config.canarySteps
    .map((step) => {
      if (step.setWeight !== undefined) {
        return `        - setWeight: ${step.setWeight}`;
      }
      if (step.pause) {
        return `        - pause:\n            duration: "${step.pause.duration}"`;
      }
      if (step.analysis) {
        const argsYaml = Object.entries(step.analysis.args)
          .map(([k, v]) => `              - name: ${k}\n                value: "${v}"`)
          .join("\n");
        return `        - analysis:
            templates:
              - templateName: ${step.analysis.templateName}
            args:
${argsYaml}`;
      }
      return "";
    })
    .join("\n");

  return `apiVersion: argoproj.io/v1alpha1
kind: Rollout
metadata:
  name: ${config.serviceName}
spec:
  replicas: 4
  selector:
    matchLabels:
      app: ${config.serviceName}
  template:
    metadata:
      labels:
        app: ${config.serviceName}
    spec:
      containers:
        - name: ${config.serviceName}
          image: ${config.image}:${config.tag}
          ports:
            - containerPort: 3000
  strategy:
    canary:
      canaryService: ${config.serviceName}-canary
      stableService: ${config.serviceName}-stable
      trafficRouting:
        istio:
          virtualService:
            name: ${config.serviceName}-vsvc
      steps:
${stepsYaml}`;
}

/**
 * AnalysisTemplate YAML을 생성합니다.
 * Prometheus 쿼리를 사용하여 에러율, P99 레이턴시, 성공률을 측정합니다.
 */
function generateAnalysisTemplate(): string {
  return `apiVersion: argoproj.io/v1alpha1
kind: AnalysisTemplate
metadata:
  name: canary-full-analysis
spec:
  args:
    - name: error-rate-max
    - name: p99-latency-max
    - name: success-rate-min
  metrics:
    - name: error-rate
      interval: 60s
      successCondition: result[0] <= {{args.error-rate-max}}
      provider:
        prometheus:
          address: http://prometheus.monitoring:9090
          query: |
            sum(rate(http_requests_total{status=~"5..",app="{{args.service-name}}",canary="true"}[5m]))
            /
            sum(rate(http_requests_total{app="{{args.service-name}}",canary="true"}[5m]))
    - name: p99-latency
      interval: 60s
      successCondition: result[0] <= {{args.p99-latency-max}}
      provider:
        prometheus:

            histogram_quantile(0.99,
              sum(rate(http_request_duration_seconds_bucket{app="{{args.service-name}}",canary="true"}[5m]))
              by (le)
            )

      interval: 60s

            sum(rate(http_requests_total{status=~"2..",app="{{args.service-name}}",canary="true"}[5m]))
            /
            sum(rate(http_requests_total{app="{{args.service-name}}",canary="true"}[5m]))`;
}

// 기본 임계값 -- 대부분의 서비스에 적합한 보수적인 값
```

## 8. Feature Flag 5단계 자동 승격

Feature Flag는 코드를 배포하되 기능을 즉시 노출하지 않는 기법입니다. 배포와 릴리즈를 분리함으로써, 문제가 발생하면 재배포 없이 Flag만 끄면 됩니다.

### 승격 프로세스 개요

```
0.1% ──→ 1% ──→ 10% ──→ 50% ──→ 100%
 │        │       │        │        │
 30분     60분    120분    240분     완료
 │        │       │        │        │
 자동     자동    자동     수동승인   -
 
각 단계에서 검사하는 항목:
- 에러율이 임계값 이하인가?
- P99 응답시간이 임계값 이하인가?
- 최소 샘플 수를 충족했는가?

롤백 조건: 에러율이 임계값의 3배를 초과하면 즉시 0%로 롤백
```

### 0.1% -> 1% -> 10% -> 50% -> 100%

```typescript
// scripts/feature-flag-rollout.ts
// Feature Flag의 5단계 점진적 승격을 자동으로 관리합니다.

/** 승격 단계 정의 */
interface RolloutStage {
  percentage: number;              // 노출 비율 (%)
  minDuration: number;             // 최소 유지 시간 (분)
  requiredMetrics: StageMetrics;   // 이 단계의 승격 조건
  autoPromote: boolean;            // 자동 승격 여부 (false면 수동 승인 필요)
}

/** 단계별 메트릭 조건 */
interface StageMetrics {
  errorRateBelow: number;    // 에러율 상한 (예: 0.02 = 2%)
  p99LatencyBelow: number;   // P99 응답시간 상한 (ms)
  sampleSizeMin: number;     // 최소 샘플 수 (통계적 유의성 확보)
}

/** Feature Flag 롤아웃 상태 */
interface FeatureFlagRollout {
  flagKey: string;                   // Feature Flag 키 이름
  stages: RolloutStage[];            // 승격 단계 목록
  currentStage: number;              // 현재 단계 인덱스
  startedAt: string;                 // 롤아웃 시작 시각
  lastPromotedAt: string;            // 마지막 승격 시각
  status: "rolling" | "paused" | "completed" | "rolled-back";
}

/**
 * 5단계 롤아웃 설정
 *
 * 단계가 올라갈수록:
 * - 에러율 허용치가 낮아지고 (더 엄격)
 * - 최소 샘플 수가 높아지고 (통계적 신뢰도 확보)
 * - 유지 시간이 길어집니다 (안정성 확인)
 *
 * 50% → 100% 승격만 수동 승인이 필요합니다.
 * 이는 전체 사용자에게 영향을 주는 최종 판단이므로 사람이 확인합니다.
 */
const FIVE_STAGE_ROLLOUT: RolloutStage[] = [
  {
    percentage: 0.1,
    minDuration: 30,           // 30분 유지
    requiredMetrics: {
      errorRateBelow: 0.02,    // 2% 이하
      p99LatencyBelow: 800,    // 800ms 이하
      sampleSizeMin: 100,      // 최소 100건
    },
    autoPromote: true,
  },
  {
    percentage: 1,
    minDuration: 60,           // 1시간 유지
    requiredMetrics: {
      errorRateBelow: 0.015,   // 1.5% 이하
      p99LatencyBelow: 600,    // 600ms 이하
      sampleSizeMin: 500,      // 최소 500건
    },
    autoPromote: true,
  },
  {
    percentage: 10,
    minDuration: 120,          // 2시간 유지
    requiredMetrics: {
      errorRateBelow: 0.01,    // 1% 이하
      p99LatencyBelow: 500,    // 500ms 이하
      sampleSizeMin: 5000,     // 최소 5000건
    },
    autoPromote: true,
  },
  {
    percentage: 50,
    minDuration: 240,          // 4시간 유지
    requiredMetrics: {
      errorRateBelow: 0.005,   // 0.5% 이하
      p99LatencyBelow: 500,    // 500ms 이하
      sampleSizeMin: 50000,    // 최소 50000건
    },
    autoPromote: false,        // 50% → 100%는 수동 승인 필요
  },
  {
    percentage: 100,
    minDuration: 0,
    requiredMetrics: {
      errorRateBelow: 0.005,
      p99LatencyBelow: 500,
      sampleSizeMin: 0,
    },
    autoPromote: false,
  },
];

/** 실시간 메트릭 스냅샷 */
interface MetricsSnapshot {
  errorRate: number;
  p99Latency: number;
  sampleSize: number;
  timestamp: string;
}

/** 메트릭 API에서 현재 메트릭을 조회합니다 */
async function fetchCurrentMetrics(
  flagKey: string,
): Promise<MetricsSnapshot> {
  const response = await fetch(
    `${process.env.METRICS_API_URL}/api/flags/${flagKey}/metrics`,
  );
  return (await response.json()) as MetricsSnapshot;
}

/** Feature Flag의 노출 비율을 변경합니다 */
async function updateFlagPercentage(
  flagKey: string,
  percentage: number,
): Promise<void> {
  await fetch(
    `${process.env.FEATURE_FLAG_API_URL}/api/flags/${flagKey}/rollout`,
    {
      method: "PATCH",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ percentage }),
    },
  );
}

/**
 * 승격/유지/롤백을 결정합니다.
 *
 * 결정 로직:
 * 1. 에러율이 임계값의 3배를 초과하면 → 즉시 롤백
 * 2. 최소 유지 시간이 지나지 않았으면 → 유지
 * 3. 모든 메트릭이 조건을 충족하면 → 승격
 * 4. 그 외 → 유지 (조건이 충족될 때까지 대기)
 */
async function evaluatePromotion(
  rollout: FeatureFlagRollout,
): Promise<"promote" | "hold" | "rollback"> {
  const currentStage = rollout.stages[rollout.currentStage];
  if (!currentStage) return "hold";

  const metrics = await fetchCurrentMetrics(rollout.flagKey);

  // 롤백 조건: 에러율이 임계값의 3배 이상이면 즉시 롤백
  if (metrics.errorRate > currentStage.requiredMetrics.errorRateBelow * 3) {
    return "rollback";
  }

  // 최소 유지 시간 체크
  const lastPromoted = new Date(rollout.lastPromotedAt).getTime();
  const elapsedMinutes = (Date.now() - lastPromoted) / 60_000;

  if (elapsedMinutes < currentStage.minDuration) {
    return "hold";
  }

  // 모든 메트릭 조건 충족 여부
  if (
    metrics.errorRate <= currentStage.requiredMetrics.errorRateBelow &&
    metrics.p99Latency <= currentStage.requiredMetrics.p99LatencyBelow &&
    metrics.sampleSize >= currentStage.requiredMetrics.sampleSizeMin
  ) {
    return "promote";
  }

  return "hold";
}

/**
 * 롤아웃 루프 -- 주기적으로 호출되어 승격/롤백을 판단합니다.
 * GitHub Actions의 cron이나 별도의 스케줄러에서 실행합니다.
 */
async function runRolloutLoop(
  rollout: FeatureFlagRollout,
): Promise<void> {
  const decision = await evaluatePromotion(rollout);

  switch (decision) {
    case "promote": {
      const nextStageIdx = rollout.currentStage + 1;
      if (nextStageIdx >= rollout.stages.length) {
        rollout.status = "completed";
        console.log(`${rollout.flagKey}: 롤아웃 완료 (100%)`);
        return;
      }

      const nextStage = rollout.stages[nextStageIdx];

      // 수동 승인이 필요한 단계라면 Slack으로 승인 요청
      if (!nextStage.autoPromote && nextStageIdx === rollout.stages.length - 1) {
        console.log(
          `${rollout.flagKey}: ${nextStage.percentage}% 승격 대기 (수동 승인 필요)`,
        );
        await notifySlackForApproval(rollout, nextStage.percentage);
        return;
      }

      // 자동 승격 실행
      await updateFlagPercentage(rollout.flagKey, nextStage.percentage);
      rollout.currentStage = nextStageIdx;
      rollout.lastPromotedAt = new Date().toISOString();
      console.log(
        `${rollout.flagKey}: ${nextStage.percentage}%로 승격`,
      );
      break;
    }
    case "rollback": {
      // 에러율 초과 -- 즉시 0%로 롤백
      await updateFlagPercentage(rollout.flagKey, 0);
      rollout.status = "rolled-back";
      console.log(`${rollout.flagKey}: 롤백 (0%)`);
      await notifySlackRollback(rollout);
      break;
    }
    case "hold": {
      // 조건 미충족 -- 현재 비율 유지
      const stage = rollout.stages[rollout.currentStage];
      console.log(
        `${rollout.flagKey}: ${stage.percentage}% 유지 (조건 미충족)`,
      );
      break;
    }
  }
}

/** Slack으로 수동 승격 승인 요청을 보냅니다 */
async function notifySlackForApproval(
  rollout: FeatureFlagRollout,
  nextPercentage: number,
): Promise<void> {
  await fetch(process.env.SLACK_WEBHOOK_URL!, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      text: `*Feature Flag 승격 승인 요청*\nFlag: \`${rollout.flagKey}\`\n현재: ${rollout.stages[rollout.currentStage].percentage}% → 다음: ${nextPercentage}%\n승인하려면 \`/flag-promote ${rollout.flagKey}\` 실행`,
    }),
  });
}

/** Slack으로 자동 롤백 알림을 보냅니다 */
async function notifySlackRollback(
  rollout: FeatureFlagRollout,
): Promise<void> {
  await fetch(process.env.SLACK_WEBHOOK_URL!, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      text: `*Feature Flag 자동 롤백*\nFlag: \`${rollout.flagKey}\`\n사유: 에러율 임계값 초과\n즉시 조사가 필요합니다.`,
    }),
  });
}

export {
  runRolloutLoop,
  evaluatePromotion,
  FIVE_STAGE_ROLLOUT,
};
export type { FeatureFlagRollout, RolloutStage };
```

## 9. 배포 동결(Code Freeze) 자동화

연말, 연휴, 대규모 이벤트 전후 등 배포를 금지해야 하는 기간이 있습니다. 이를 사람이 수동으로 관리하면 실수가 발생하기 쉽습니다. 이 시스템은 Google Calendar와 연동하여 Code Freeze 기간을 자동으로 감지하고, GitHub Branch Protection을 자동으로 강화합니다.

### 작동 원리

```
[Google Calendar에 "Code Freeze" 이벤트 등록]
        │
        ▼ (30분마다 체크)
[Code Freeze 일정 조회]
        │
        ├── Code Freeze 기간 → Branch Protection 강화 (머지 차단)
        │                       + Slack "Code Freeze 활성화" 알림
        │
        └── Code Freeze 아님 → Branch Protection 원복
                                + Slack "Code Freeze 해제" 알림

예외: `hotfix` 또는 `security` 라벨이 붙은 PR은 Code Freeze 기간에도 배포 가능
```

### 캘린더 연동 + GitHub Branch Protection 자동 토글

```typescript
// scripts/code-freeze-automation.ts
// Google Calendar의 "Code Freeze" 이벤트를 감지하여
// GitHub Branch Protection을 자동으로 강화/해제합니다.
import { execSync } from "node:child_process";

/** Code Freeze 일정 */
interface CodeFreezeSchedule {
  id: string;
  title: string;
  startTime: string;            // ISO 8601 형식
  endTime: string;
  reason: string;               // 동결 사유
  exceptions: string[];         // 허용되는 라벨 (예: "hotfix", "security")
}

/** Branch Protection 상태 (원복에 사용) */
interface BranchProtectionState {
  branch: string;
  enforcedBefore: boolean;
  requiredReviewers: number;
  restrictions: string[];
}

/** Google Calendar API에서 Code Freeze 일정을 조회합니다 */
async function fetchCodeFreezeSchedule(): Promise<CodeFreezeSchedule[]> {
  const calendarId = process.env.GOOGLE_CALENDAR_ID!;
  const apiKey = process.env.GOOGLE_API_KEY!;

  const now = new Date().toISOString();
  const oneWeekLater = new Date(
    Date.now() + 7 * 86400_000,
  ).toISOString();

  const response = await fetch(
    `https://www.googleapis.com/calendar/v3/calendars/${calendarId}/events?` +
      `key=${apiKey}&timeMin=${now}&timeMax=${oneWeekLater}&q=Code+Freeze`,
  );

  const data = (await response.json()) as {
    items: Array<{
      id: string;
      summary: string;
      start: { dateTime: string };
      end: { dateTime: string };
      description?: string;
    }>;
  };

  return data.items.map((event) => ({
    id: event.id,
    title: event.summary,
    startTime: event.start.dateTime,
    endTime: event.end.dateTime,
    reason: event.description ?? "정기 Code Freeze",
    exceptions: ["hotfix", "security"],
  }));
}

/** 현재 시각이 Code Freeze 기간인지 확인합니다 */
function isCurrentlyFrozen(
  schedules: CodeFreezeSchedule[],
): CodeFreezeSchedule | null {
  const now = Date.now();
  return (
    schedules.find((s) => {
      const start = new Date(s.startTime).getTime();
      const end = new Date(s.endTime).getTime();
      return now >= start && now <= end;
    }) ?? null
  );
}

/**
 * Code Freeze를 활성화합니다.
 * required_approving_review_count를 99로 설정하여 사실상 머지를 차단합니다.
 * (hotfix/security 라벨 PR은 별도 워크플로우에서 예외 처리)
 */
function enableCodeFreeze(repo: string, branches: string[]): void {
  for (const branch of branches) {
    execSync(
      `gh api repos/${repo}/branches/${branch}/protection -X PUT \
        -f "required_status_checks[strict]=true" \
        -f "enforce_admins=true" \
        -f "required_pull_request_reviews[required_approving_review_count]=99" \
        -f "restrictions=null"`,
      { encoding: "utf-8" },
    );

    console.log(`Code Freeze 활성화: ${branch}`);
  }

  notifyCodeFreezeStatus("activated", branches);
}

/** Code Freeze를 해제하여 정상 상태로 복구합니다 */
function disableCodeFreeze(repo: string, branches: string[]): void {
  for (const branch of branches) {
    execSync(
      `gh api repos/${repo}/branches/${branch}/protection -X PUT \
        -f "required_status_checks[strict]=true" \
        -f "enforce_admins=false" \
        -f "required_pull_request_reviews[required_approving_review_count]=1" \
        -f "restrictions=null"`,
      { encoding: "utf-8" },
    );

    console.log(`Code Freeze 해제: ${branch}`);
  }

  notifyCodeFreezeStatus("deactivated", branches);
}

/** Slack으로 Code Freeze 상태 변경을 알립니다 */
function notifyCodeFreezeStatus(
  action: "activated" | "deactivated",
  branches: string[],
): void {
  const webhookUrl = process.env.SLACK_WEBHOOK_URL;
  if (!webhookUrl) return;

  const message =
    action === "activated"
      ? `*Code Freeze 활성화*\n대상 브랜치: ${branches.map((b) => `\`${b}\``).join(", ")}\n긴급 배포는 \`hotfix\` 또는 \`security\` 라벨 PR만 허용됩니다.`
      : `*Code Freeze 해제*\n대상 브랜치: ${branches.map((b) => `\`${b}\``).join(", ")}\n정상 배포가 가능합니다.`;

  fetch(webhookUrl, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ text: message }),
  });
}

/** 메인 실행 -- 30분마다 호출됩니다 */
async function runCodeFreezeCheck(): Promise<void> {
  const repo = process.env.GITHUB_REPOSITORY!;
  const targetBranches = ["main", "release/current"];

  const schedules = await fetchCodeFreezeSchedule();
  const activeFreeeze = isCurrentlyFrozen(schedules);

  if (activeFreeeze) {
    console.log(`Code Freeze 감지: ${activeFreeeze.title}`);
    console.log(`종료: ${activeFreeeze.endTime}`);
    enableCodeFreeze(repo, targetBranches);
  } else {
    console.log("Code Freeze 없음 -- 정상 상태");
    disableCodeFreeze(repo, targetBranches);
  }
}

export {
  runCodeFreezeCheck,
  fetchCodeFreezeSchedule,
  isCurrentlyFrozen,
};
export type { CodeFreezeSchedule };
```

## 10. 배포 체크리스트

배포 단계별로 반드시 확인해야 하는 항목입니다. 하나라도 빠뜨리면 장애로 이어질 수 있으므로, **배포 전에 반드시 전체 항목을 순서대로 체크**하세요.

### Preview / Beta 배포

- [ ] PR에 AI 사고 방지 분석 결과가 코멘트로 게시되었는가
- [ ] 위험도가 HIGH 이상일 경우 시니어 리뷰어가 배정되었는가
- [ ] Preview 환경이 자동 생성되고 TTL이 설정되었는가
- [ ] E2E 테스트가 Preview 환경에서 통과했는가 ([07. 테스팅 가이드](./07_테스팅_가이드.md) 참조)
- [ ] Feature Flag가 설정된 경우 0.1% 단계에서 시작하는가
- [ ] 빌드 아티팩트 크기가 비정상적으로 증가하지 않았는가 ([08. 성능 최적화 가이드](./08_성능_최적화_가이드.md) 참조)

### Staging 배포

- [ ] Beta 환경에서 최소 24시간 검증을 완료했는가
- [ ] Canary 메트릭(에러율, P99 레이턴시)이 임계값 이하인가
- [ ] 롤백 안전성 분석에서 DANGEROUS가 아닌가
- [ ] 배포 순서 의존성이 있는 PR이 먼저 배포되었는가
- [ ] DB 마이그레이션이 포함된 경우, 롤백 스크립트가 준비되었는가
- [ ] API 변경이 포함된 경우, 하위 호환성이 유지되는가 ([05. API 통신 가이드](./05_API_통신_및_모킹_가이드.md) 참조)

### Production 배포

- [ ] Code Freeze 기간이 아닌가 (자동 체크)
- [ ] GitHub Environment Protection Rules 승인을 받았는가
- [ ] Canary 0.1%에서 시작하여 메트릭 기반 자동 프로모션이 설정되었는가
- [ ] 롤백 스크립트가 준비되었는가 (아래 "롤백 전략 상세 가이드" 참조)
- [ ] 배포 후 30분간 모니터링 담당자가 지정되었는가
- [ ] 배포 매트릭스 대시보드에서 모든 환경 상태가 정상인가
- [ ] Sentry 릴리즈 태그가 설정되었는가 ([09. 장애 대응 및 Sentry 표준](./09_장애_대응_및_Sentry_표준.md) 참조)
- [ ] CloudFront 캐시 무효화 계획이 수립되었는가 ([12. CloudFront 캐시 전략](./12_CloudFront_캐시_전략.md) 참조)

### 긴급 배포 (Code Freeze 기간)

- [ ] PR에 `hotfix` 또는 `security` 라벨이 붙어있는가
- [ ] SRE 팀 승인을 받았는가
- [ ] 변경 범위가 최소한인가 (핫픽스만 포함)
- [ ] 롤백 계획이 문서화되었는가
- [ ] 배포 후 영향받는 메트릭이 정상으로 돌아왔는지 확인했는가

### 배포 후 확인 (Post-Deployment)

- [ ] Sentry에서 새로운 에러가 발생하지 않는가
- [ ] Core Web Vitals(LCP, CLS, INP)가 악화되지 않았는가 ([08. 성능 최적화 가이드](./08_성능_최적화_가이드.md) 참조)
- [ ] 주요 사용자 플로우(회원가입, 결제 등)가 정상 동작하는가
- [ ] 배포 관련 알림(Slack, PagerDuty 등)이 정상 발송되었는가
- [ ] 배포 기록이 대시보드에 반영되었는가

## 11. 롤백 전략 상세 가이드

배포 후 문제가 발생했을 때 빠르고 안전하게 이전 상태로 돌아가는 것이 중요합니다. 상황에 따라 적절한 롤백 전략을 선택하세요.

### 롤백 유형별 비교

| 전략 | 소요 시간 | 적용 상황 | 위험도 |
|------|----------|----------|--------|
| **Instant Rollback** | 수 초 | 정적 자산(S3/CloudFront), Feature Flag OFF | 낮음 |
| **Canary Abort** | 수 초 | Canary 진행 중 문제 감지 시 | 낮음 |
| **Blue-Green Switch** | 수 분 | 이전 버전 환경이 살아있을 때 | 낮음 |
| **Gradual Rollback** | 수십 분 | 트래픽을 점진적으로 구버전으로 이전 | 중간 |
| **Manual with Script** | 수 시간 | DB 스키마 변경이 포함된 배포 | 높음 |

### 프론트엔드 즉시 롤백 스크립트

프론트엔드(S3 + CloudFront) 환경에서는 이전 빌드 결과물로 즉시 전환할 수 있습니다.

```bash
#!/bin/bash
# scripts/rollback-frontend.sh
# 프론트엔드 즉시 롤백 스크립트
# 사용법: ./rollback-frontend.sh <이전_커밋_SHA>

set -euo pipefail

PREVIOUS_SHA="${1:?이전 커밋 SHA를 입력하세요}"
BUCKET="${S3_BUCKET:?S3_BUCKET 환경변수가 필요합니다}"
DISTRIBUTION_ID="${CF_DISTRIBUTION_ID:?CF_DISTRIBUTION_ID 환경변수가 필요합니다}"

echo "=== 프론트엔드 롤백 시작 ==="
echo "대상 커밋: ${PREVIOUS_SHA}"
echo "S3 버킷: ${BUCKET}"

# 1. 이전 버전의 빌드 아티팩트가 S3 버전 관리에 존재하는지 확인
echo "이전 버전 확인 중..."
aws s3 ls "s3://${BUCKET}/versions/${PREVIOUS_SHA}/" || {
  echo "ERROR: 이전 버전을 찾을 수 없습니다: ${PREVIOUS_SHA}"
  exit 1
}

# 2. 이전 버전으로 S3 동기화
echo "이전 버전으로 복원 중..."
aws s3 sync "s3://${BUCKET}/versions/${PREVIOUS_SHA}/" "s3://${BUCKET}/current/" \
  --delete \
  --cache-control "public, max-age=0, must-revalidate"

# 3. CloudFront 캐시 전체 무효화
echo "CloudFront 캐시 무효화 중..."
INVALIDATION_ID=$(aws cloudfront create-invalidation \
  --distribution-id "${DISTRIBUTION_ID}" \
  --paths "/*" \
  --query 'Invalidation.Id' \
  --output text)

echo "캐시 무효화 ID: ${INVALIDATION_ID}"

# 4. 캐시 무효화 완료 대기
echo "캐시 무효화 완료 대기 중..."
aws cloudfront wait invalidation-completed \
  --distribution-id "${DISTRIBUTION_ID}" \
  --id "${INVALIDATION_ID}"

echo "=== 롤백 완료 ==="
echo "확인: https://${CDN_DOMAIN}/ 에서 이전 버전이 서빙되는지 확인하세요"
```

### Feature Flag 기반 즉시 롤백

코드 자체를 롤백하지 않고, Feature Flag만 OFF 하여 새 기능을 비활성화하는 방법입니다. 가장 빠르고 안전한 롤백 방법입니다.

```typescript
// scripts/emergency-flag-off.ts
// 긴급 상황에서 Feature Flag를 즉시 비활성화합니다.
// 사용법: npx tsx scripts/emergency-flag-off.ts <flag-key> <사유>

async function emergencyFlagOff(): Promise<void> {
  const flagKey = process.argv[2];
  const reason = process.argv[3] ?? "긴급 비활성화";

  if (!flagKey) {
    console.error("사용법: npx tsx scripts/emergency-flag-off.ts <flag-key> <사유>");
    process.exit(1);
  }

  // Feature Flag를 0%로 설정
  const response = await fetch(
    `${process.env.FEATURE_FLAG_API_URL}/api/flags/${flagKey}/rollout`,
    {
      method: "PATCH",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        percentage: 0,
        reason: `[긴급] ${reason}`,
        triggeredBy: process.env.USER ?? "unknown",
      }),
    },
  );

  if (!response.ok) {
    console.error(`Flag 비활성화 실패: ${response.status}`);
    process.exit(1);
  }

  console.log(`Flag "${flagKey}" 비활성화 완료 (0%)`);

  // Slack 알림
  if (process.env.SLACK_WEBHOOK_URL) {
    await fetch(process.env.SLACK_WEBHOOK_URL, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        text: `*긴급 Feature Flag 비활성화*\nFlag: \`${flagKey}\`\n사유: ${reason}\n실행자: ${process.env.USER ?? "unknown"}`,
      }),
    });
  }
}

emergencyFlagOff();
```

## 12. AI와 함께하는 배포 프로세스

### 💡 AI와 함께하는 배포 리스크 분석

AI 도구(Claude Code 등)를 활용하면 배포 전 리스크를 빠르게 파악할 수 있습니다. 아래는 실무에서 바로 사용할 수 있는 프롬프트 모음입니다.

#### 배포 전 코드 변경 영향도 분석

```text
이 PR의 변경 사항을 분석해줘.

1. 변경된 파일 목록과 각 파일의 역할을 요약해줘
2. 이 변경이 영향을 미치는 컴포넌트/페이지를 나열해줘
3. 브라우저 호환성 이슈가 있는지 확인해줘
4. 성능에 영향을 줄 수 있는 변경이 있는지 분석해줘
5. 접근성(a11y)에 영향을 주는 변경이 있는지 확인해줘

가능하다면 각 항목에 대해 [영향 없음 / 주의 / 위험] 수준으로 표시해줘.
```

#### 배포 후 모니터링 가이드 자동 생성

```text
이 PR이 배포된 후 모니터링해야 할 항목을 정리해줘.

변경 내용을 기반으로:
1. 특별히 주시해야 할 Sentry 에러 패턴
2. 모니터링해야 할 메트릭 (API 응답시간, 에러율 등)
3. 확인해야 할 사용자 플로우
4. 문제 발생 시 즉시 실행할 롤백 명령어

형식은 체크리스트로 만들어줘.
```

#### 릴리즈 노트 자동 생성

```text
아래 PR 목록을 기반으로 릴리즈 노트를 작성해줘.

## 형식
- 사용자에게 보이는 변경 (유저 대상)
- 내부 개선 (개발팀 대상)
- 버그 수정
- 알려진 이슈

PR 목록:
{pr_list}
```

```text
프로덕션에서 다음 증상이 관찰되고 있어:
- {증상 설명}
- {관련 에러 로그}
- {영향받는 사용자 비율}

다음을 분석해줘:
1. 가장 가능성 높은 원인 3가지
2. 각 원인에 대한 확인 방법
3. 즉시 실행할 수 있는 완화 조치
4. 최근 배포와의 관련성 (배포 시점과 증상 발생 시점 비교)

장애 대응 매뉴얼은 09번 가이드를 참조하고 있어.
```

## 용어 정리

| 용어 | 설명 |
|------|------|
| **Canary** | 새 버전을 소수 사용자에게만 먼저 배포하는 전략. 카나리아(광산의 카나리아 새)에서 유래 |
| **Progressive Delivery** | 배포를 점진적으로 확대하는 전략의 총칭. Canary, Blue-Green, Feature Flag 등을 포함 |
| **Feature Flag** | 코드 내 조건문으로 기능의 ON/OFF를 제어하는 기법. 배포와 릴리즈를 분리 |
| **Code Freeze** | 배포를 금지하는 기간. 연말/연휴/대규모 이벤트 전후에 설정 |
| **Blast Radius** | 장애 발생 시 영향받는 범위. 사용자 수, 매출 영향 등으로 측정 |
| **Rollback** | 배포 후 문제 발생 시 이전 버전으로 되돌리는 것 |
| **TTL (Time To Live)** | 리소스의 수명. 만료되면 자동으로 삭제/비활성화 |
| **P99 Latency** | 전체 요청의 99%가 이 시간 이내에 완료됨을 의미하는 지표 |
| **SRE (Site Reliability Engineering)** | 서비스 안정성을 담당하는 엔지니어링 분야/팀 |
