## 핵심 원칙: 서버 상태 vs 클라이언트 상태 분리

현대 프론트엔드 상태 관리의 가장 중요한 원칙은 **서버 상태(Server State)와 클라이언트 상태(Client State)를 명확히 분리**하는 것이다. 이 두 가지는 본질적으로 다른 특성을 가진다.

| 특성 | 서버 상태 | 클라이언트 상태 |
|------|----------|----------------|
| **소유권** | 서버가 원본(source of truth) | 클라이언트가 원본 |
| **동기화** | 서버와 동기화 필요 | 동기화 불필요 |
| **예시** | 사용자 목록, 상품 정보, 주문 내역 | 테마, 모달 열림/닫힘, 사이드바 상태 |
| **도구** | TanStack Query v5 | Zustand, Jotai, useState |
| **캐싱** | 필수 (stale-while-revalidate) | 불필요 |

### 권장 스택: TanStack Query v5 + Zustand

2025-2026년 기준, 대부분의 React 프로젝트에서 **TanStack Query v5 (서버 상태) + Zustand (클라이언트 상태)** 조합이 가장 실용적인 선택이다.

- **TanStack Query v5**: 서버 데이터의 캐싱, 동기화, 백그라운드 업데이트, 낙관적 업데이트를 선언적으로 처리
- **Zustand**: 최소한의 보일러플레이트로 전역 클라이언트 상태를 관리. Redux 대비 훨씬 간결
- 두 라이브러리 모두 TypeScript 1급 지원, 작은 번들 사이즈, 뛰어난 DevTools 제공

```
[서버 상태]                    [클라이언트 상태]
TanStack Query v5              Zustand / Jotai / useState
- API 데이터 캐싱              - UI 상태 (모달, 사이드바)
- 자동 재검증                  - 사용자 설정 (테마, 언어)
- 낙관적 업데이트              - 폼 입력 (임시 데이터)
- 무한 스크롤/페이지네이션      - 인증 토큰/세션
- 백그라운드 동기화            - 장바구니 (로컬 전용)
```

## 상태 관리 라이브러리 선택 가이드

### 상황별 추천

| 요구사항 | 추천 라이브러리 | 이유 |
|---------|----------------|------|
| **서버 데이터** | TanStack Query v5 | 캐싱, 동기화, 백그라운드 업데이트, streaming 지원 |
| **전역 클라이언트 상태** | Zustand | 간단한 API, 보일러플레이트 없음, TypeScript 최적화 |
| **Atomic 상태** | Jotai | React 친화적, 작은 번들 사이즈, 파생 상태에 강점 |
| **폼 상태** | React Hook Form | 성능, 검증 기능, Zod 연동 |
| **로컬 상태** | useState / useReducer | 컴포넌트 범위의 단순 상태에 가장 적합 |

> **참고**: Redux Toolkit은 여전히 유효한 선택이지만, 신규 프로젝트에서는 Zustand가 더 간결한 대안으로 널리 채택되고 있다. 기존 Redux 프로젝트를 마이그레이션할 필요는 없다.

## 1. TanStack Query v5 (React Query)

### 설치
```bash
npm install @tanstack/react-query@5 @tanstack/react-query-devtools@5
```

### 기본 설정

```typescript
// app/providers.tsx
'use client';

import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { ReactQueryDevtools } from '@tanstack/react-query-devtools';
import { useState } from 'react';

export function Providers({ children }: { children: React.ReactNode }) {
  const [queryClient] = useState(
    () =>
      new QueryClient({
        defaultOptions: {
          queries: {
            staleTime: 60 * 1000, // 1분
            gcTime: 5 * 60 * 1000, // 5분 (v5에서 cacheTime -> gcTime으로 변경)
            refetchOnWindowFocus: false,
            retry: 1,
          },
        },
      })
  );

  return (
    <QueryClientProvider client={queryClient}>
      {children}
      <ReactQueryDevtools initialIsOpen={false} />
    </QueryClientProvider>
  );
}
```

### useQuery (데이터 조회)

```typescript
import { useQuery } from '@tanstack/react-query';

interface User {
  id: string;
  name: string;
  email: string;
}

function UserProfile({ userId }: { userId: string }) {
  const {
    data,
    error,
    isLoading,
    isError,
    refetch,
  } = useQuery({
    queryKey: ['user', userId],
    queryFn: async () => {
      const response = await fetch(`/api/users/${userId}`);
      if (!response.ok) throw new Error('Failed to fetch');
      return response.json() as Promise<User>;
    },
    // 옵션
    staleTime: 5 * 60 * 1000, // 5분간 fresh
    gcTime: 10 * 60 * 1000, // 10분간 캐시 유지
    enabled: !!userId, // userId가 있을 때만 실행
  });

  if (isLoading) return <div>로딩 중...</div>;
  if (isError) return <div>에러: {error.message}</div>;

  return (
    <div>
      <h1>{data.name}</h1>
      <p>{data.email}</p>
      <button onClick={() => refetch()}>새로고침</button>
    </div>
  );
}
```

### useMutation (데이터 변경)

```typescript
import { useMutation, useQueryClient } from '@tanstack/react-query';

interface CreateUserDto {
  name: string;
  email: string;
}

function CreateUserForm() {
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: async (newUser: CreateUserDto) => {
      const response = await fetch('/api/users', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(newUser),
      });
      return response.json();
    },
    onSuccess: (data) => {
      // 성공 시 캐시 무효화
      queryClient.invalidateQueries({ queryKey: ['users'] });
      
      // 또는 직접 캐시 업데이트
      queryClient.setQueryData(['user', data.id], data);
    },
    onError: (error) => {
      console.error('Error creating user:', error);
    },
  });

  const handleSubmit = (e: React.FormEvent<HTMLFormElement>) => {
    e.preventDefault();
    const formData = new FormData(e.currentTarget);
    mutation.mutate({
      name: formData.get('name') as string,
      email: formData.get('email') as string,
    });
  };

  return (
    <form onSubmit={handleSubmit}>
      <input name="name" required />
      <input name="email" type="email" required />
      <button disabled={mutation.isPending}>
        {mutation.isPending ? '생성 중...' : '사용자 생성'}
      </button>
      {mutation.isError && <p>에러 발생!</p>}
      {mutation.isSuccess && <p>생성 완료!</p>}
    </form>
  );
}
```

### 낙관적 업데이트 (Optimistic Updates)

```typescript
function TodoList() {
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: async (newTodo: { title: string }) => {
      const response = await fetch('/api/todos', {
        method: 'POST',
        body: JSON.stringify(newTodo),
      });
      return response.json();
    },
    onMutate: async (newTodo) => {
      // 진행 중인 쿼리 취소
      await queryClient.cancelQueries({ queryKey: ['todos'] });

      // 이전 데이터 백업
      const previousTodos = queryClient.getQueryData(['todos']);

      // 낙관적 업데이트
      queryClient.setQueryData(['todos'], (old: any[]) => [
        ...old,
        { id: 'temp', ...newTodo, pending: true },
      ]);

      return { previousTodos };
    },
    onError: (err, newTodo, context) => {
      // 에러 시 롤백
      queryClient.setQueryData(['todos'], context?.previousTodos);
    },
    onSettled: () => {
      // 성공/실패 관계없이 다시 조회
      queryClient.invalidateQueries({ queryKey: ['todos'] });
    },
  });

  return (
    <div>
      <button onClick={() => mutation.mutate({ title: 'New Todo' })}>
        할일 추가
      </button>
    </div>
  );
}
```

### 무한 스크롤 (Infinite Queries)

```typescript
import { useInfiniteQuery } from '@tanstack/react-query';

function InfiniteList() {
  const {
    data,
    fetchNextPage,
    hasNextPage,
    isFetchingNextPage,
  } = useInfiniteQuery({
    queryKey: ['products'],
    queryFn: async ({ pageParam = 1 }) => {
      const response = await fetch(`/api/products?page=${pageParam}`);
      return response.json();
    },
    getNextPageParam: (lastPage, pages) => {
      return lastPage.hasMore ? pages.length + 1 : undefined;
    },
    initialPageParam: 1,
  });

  return (
    <div>
      {data?.pages.map((page, i) => (
        <div key={i}>
          {page.items.map((item: any) => (
            <div key={item.id}>{item.name}</div>
          ))}
        </div>
      ))}

      <button
        onClick={() => fetchNextPage()}
        disabled={!hasNextPage || isFetchingNextPage}
      >
        {isFetchingNextPage
          ? '로딩 중...'
          : hasNextPage
          ? '더 보기'
          : '마지막 페이지'}
      </button>
    </div>
  );
}
```

### Query Key Factory 패턴 (v5 권장)

대규모 프로젝트에서 쿼리 키를 체계적으로 관리하기 위한 팩토리 패턴이다.

```typescript
// queries/keys.ts
export const userKeys = {
  all: ['users'] as const,
  lists: () => [...userKeys.all, 'list'] as const,
  list: (filters: UserFilters) => [...userKeys.lists(), filters] as const,
  details: () => [...userKeys.all, 'detail'] as const,
  detail: (id: string) => [...userKeys.details(), id] as const,
};

// 사용 예시
const { data } = useQuery({
  queryKey: userKeys.detail(userId),
  queryFn: () => fetchUser(userId),
});

// 관련 쿼리 일괄 무효화
queryClient.invalidateQueries({ queryKey: userKeys.all });
```

### useSuspenseQuery (v5 신규)

v5에서는 `suspense: true` 옵션 대신 전용 훅을 제공한다. 반환 타입에서 `undefined`가 제거되어 타입 안전성이 향상된다.

```typescript
import { useSuspenseQuery } from '@tanstack/react-query';
import { Suspense } from 'react';

function UserProfile({ userId }: { userId: string }) {
  // data의 타입이 User (undefined 아님) - 타입 안전
  const { data } = useSuspenseQuery({
    queryKey: userKeys.detail(userId),
    queryFn: () => fetchUser(userId),
  });

  return <h1>{data.name}</h1>; // 타입 단언 불필요
}

function App() {
  return (
    <Suspense fallback={<div>로딩 중...</div>}>
      <UserProfile userId="1" />
    </Suspense>
  );
}
```

### queryOptions 헬퍼 (v5 신규)

쿼리 설정을 재사용 가능한 단위로 추출하여 타입 안전성을 유지한다.

```typescript
import { queryOptions, useQuery } from '@tanstack/react-query';

// 쿼리 설정을 함수로 추출
function userQueryOptions(userId: string) {
  return queryOptions({
    queryKey: userKeys.detail(userId),
    queryFn: () => fetchUser(userId),
    staleTime: 5 * 60 * 1000,
  });
}

// 컴포넌트에서 사용
function UserProfile({ userId }: { userId: string }) {
  const { data } = useQuery(userQueryOptions(userId));
  return <h1>{data?.name}</h1>;
}

// prefetch에서도 동일한 설정 재사용
async function prefetchUser(queryClient: QueryClient, userId: string) {
  await queryClient.prefetchQuery(userQueryOptions(userId));
}
```

## 2. Zustand (전역 클라이언트 상태)

### 설치
```bash
npm install zustand
```

### 기본 Store

```typescript
// stores/useUserStore.ts
import { create } from 'zustand';

interface User {
  id: string;
  name: string;
  email: string;
}

interface UserState {
  user: User | null;
  setUser: (user: User) => void;
  logout: () => void;
}

export const useUserStore = create<UserState>((set) => ({
  user: null,
  setUser: (user) => set({ user }),
  logout: () => set({ user: null }),
}));

// 사용
function Header() {
  const user = useUserStore((state) => state.user);
  const logout = useUserStore((state) => state.logout);

  if (!user) return <LoginButton />;

  return (
    <div>
      <span>{user.name}</span>
      <button onClick={logout}>로그아웃</button>
    </div>
  );
}
```

### 성능 최적화 (Selector)

```typescript
// ❌ Bad: 전체 상태 구독
function Component() {
  const store = useUserStore(); // user 변경 시 항상 리렌더링
  return <div>{store.user?.name}</div>;
}

// ✅ Good: 필요한 부분만 구독
function Component() {
  const userName = useUserStore((state) => state.user?.name);
  return <div>{userName}</div>;
}

// ✅ Good: useShallow로 여러 값 선택 (Zustand v4.5+ 권장 방식)
import { useShallow } from 'zustand/react/shallow';

function Component() {
  const { user, logout } = useUserStore(
    useShallow((state) => ({ user: state.user, logout: state.logout }))
  );
  return <div>{user?.name}</div>;
}

// ✅ Good: useShallow 배열 형태도 지원
function Component() {
  const [user, logout] = useUserStore(
    useShallow((state) => [state.user, state.logout])
  );
  return <div>{user?.name}</div>;
}
```

### 미들웨어

**Persist (로컬 스토리지)**
```typescript
import { create } from 'zustand';
import { persist } from 'zustand/middleware';

interface CartState {
  items: Array<{ id: string; quantity: number }>;
  addItem: (id: string) => void;
  removeItem: (id: string) => void;
}

export const useCartStore = create<CartState>()(
  persist(
    (set) => ({
      items: [],
      addItem: (id) =>
        set((state) => ({
          items: [...state.items, { id, quantity: 1 }],
        })),
      removeItem: (id) =>
        set((state) => ({
          items: state.items.filter((item) => item.id !== id),
        })),
    }),
    {
      name: 'cart-storage', // localStorage key
    }
  )
);
```

**Immer (불변성 관리)**
```typescript
import { create } from 'zustand';
import { immer } from 'zustand/middleware/immer';

interface TodoState {
  todos: Array<{ id: string; text: string; done: boolean }>;
  toggleTodo: (id: string) => void;
}

export const useTodoStore = create<TodoState>()(
  immer((set) => ({
    todos: [],
    toggleTodo: (id) =>
      set((state) => {
        const todo = state.todos.find((t) => t.id === id);
        if (todo) {
          todo.done = !todo.done; // Immer가 불변성 처리
        }
      }),
  }))
);
```

### Slice 패턴 (대규모 Store 분리)

Store가 커질 때 slice 패턴으로 관심사를 분리할 수 있다.

```typescript
// stores/slices/authSlice.ts
import { StateCreator } from 'zustand';

export interface AuthSlice {
  user: User | null;
  token: string | null;
  login: (user: User, token: string) => void;
  logout: () => void;
}

export const createAuthSlice: StateCreator<
  AuthSlice & UISlice, // 전체 Store 타입
  [],
  [],
  AuthSlice
> = (set) => ({
  user: null,
  token: null,
  login: (user, token) => set({ user, token }),
  logout: () => set({ user: null, token: null }),
});

// stores/slices/uiSlice.ts
export interface UISlice {
  sidebarOpen: boolean;
  toggleSidebar: () => void;
}

export const createUISlice: StateCreator<
  AuthSlice & UISlice,
  [],
  [],
  UISlice
> = (set) => ({
  sidebarOpen: true,
  toggleSidebar: () => set((state) => ({ sidebarOpen: !state.sidebarOpen })),
});

// stores/useAppStore.ts
import { create } from 'zustand';
import { createAuthSlice } from './slices/authSlice';
import { createUISlice } from './slices/uiSlice';

export const useAppStore = create<AuthSlice & UISlice>()((...a) => ({
  ...createAuthSlice(...a),
  ...createUISlice(...a),
}));
```

### Zustand + TanStack Query 연동 패턴

서버 상태와 클라이언트 상태를 조합하는 실용적 패턴이다.

```typescript
// Zustand: 클라이언트 상태 (필터, 정렬 등 UI 상태)
const useProductFilters = create<ProductFilterState>((set) => ({
  category: 'all',
  sortBy: 'newest',
  setCategory: (category) => set({ category }),
  setSortBy: (sortBy) => set({ sortBy }),
}));

// TanStack Query: 서버 상태 (Zustand의 필터를 queryKey에 반영)
function useProducts() {
  const category = useProductFilters((s) => s.category);
  const sortBy = useProductFilters((s) => s.sortBy);

  return useQuery({
    queryKey: ['products', { category, sortBy }],
    queryFn: () => fetchProducts({ category, sortBy }),
    // 필터가 변경되면 자동으로 새로운 데이터를 가져옴
  });
}
```

## 3. Jotai (Atomic 상태)

### 설치
```bash
npm install jotai
```

### 기본 Atom

```typescript
// atoms/userAtoms.ts
import { atom } from 'jotai';

interface User {
  id: string;
  name: string;
}

// Primitive atom
export const userAtom = atom<User | null>(null);

// Derived atom (읽기 전용)
export const userNameAtom = atom(
  (get) => get(userAtom)?.name ?? 'Guest'
);

// Write atom (쓰기 가능)
export const updateUserAtom = atom(
  null, // 읽기 값 없음
  (get, set, newName: string) => {
    const currentUser = get(userAtom);
    if (currentUser) {
      set(userAtom, { ...currentUser, name: newName });
    }
  }
);

// 사용
```

## 5. React 19의 상태 관리 개선사항

React 19에서는 상태 관리와 관련된 여러 개선이 이루어졌다.

### use() 훅

`use()`는 Promise와 Context를 컴포넌트 내에서 직접 읽을 수 있는 새로운 API이다. 기존 훅과 달리 조건문/반복문 내에서도 호출 가능하다.

```typescript
import { use, Suspense } from 'react';

// Context를 use()로 읽기 - 조건부 사용 가능
function UserPanel({ showDetails }: { showDetails: boolean }) {
  if (showDetails) {
    const theme = use(ThemeContext); // 조건문 안에서 사용 가능
    return <div className={theme}>상세 정보</div>;
  }
  return <div>요약</div>;
}

// Promise를 use()로 읽기 (Suspense와 함께)
function UserProfile({ userPromise }: { userPromise: Promise<User> }) {
  const user = use(userPromise); // Promise가 resolve될 때까지 Suspense
  return <h1>{user.name}</h1>;
}

function App() {
  const userPromise = fetchUser('1'); // 렌더링 중이 아닌 곳에서 Promise 생성

  return (
    <Suspense fallback={<div>로딩 중...</div>}>
      <UserProfile userPromise={userPromise} />
    </Suspense>
  );
}
```

### useActionState (폼 상태 관리)

서버 액션과 연동되는 폼 상태 관리에 유용하다.

```typescript
import { useActionState } from 'react';

function LoginForm() {
  const [state, formAction, isPending] = useActionState(
    async (prevState: LoginState, formData: FormData) => {
      const email = formData.get('email') as string;
      const password = formData.get('password') as string;

      try {
        await login(email, password);
        return { success: true, error: null };
      } catch (e) {
        return { success: false, error: '로그인 실패' };
      }
    },
    { success: false, error: null }
  );

  return (
    <form action={formAction}>
      <input name="email" type="email" required />
      <input name="password" type="password" required />
      <button disabled={isPending}>
        {isPending ? '로그인 중...' : '로그인'}
      </button>
      {state.error && <p>{state.error}</p>}
    </form>
  );
}
```

### useOptimistic (낙관적 UI 업데이트)

서버 응답을 기다리지 않고 즉시 UI를 업데이트하는 패턴이 내장 훅으로 제공된다.

```typescript
import { useOptimistic } from 'react';

function TodoList({ todos }: { todos: Todo[] }) {
  const [optimisticTodos, addOptimisticTodo] = useOptimistic(
    todos,
    (currentTodos, newTodo: Todo) => [...currentTodos, newTodo]
  );

  async function handleAdd(formData: FormData) {
    const title = formData.get('title') as string;
    const tempTodo = { id: 'temp', title, done: false };

    addOptimisticTodo(tempTodo); // 즉시 UI 반영
    await createTodo(title);     // 서버에 요청
  }

  return (
    <div>
      <form action={handleAdd}>
        <input name="title" required />
        <button type="submit">추가</button>
      </form>
      <ul>
        {optimisticTodos.map((todo) => (
          <li key={todo.id}>{todo.title}</li>
        ))}
      </ul>
    </div>
  );
}
```

### React 19 + TanStack Query 함께 사용하기

React 19의 `use()`와 TanStack Query는 상호 보완적이다. 단순한 일회성 데이터 로딩에는 `use()`를, 캐싱/재검증/뮤테이션이 필요한 서버 데이터에는 TanStack Query를 사용한다.

```typescript

  return <ConfigProvider value={config}>...</ConfigProvider>;
}

function UserList() {
  const { data } = useQuery({
    queryKey: ['users'],
    queryFn: fetchUsers,  // 캐싱, 재검증, 낙관적 업데이트 활용
  });
  return <ul>{data?.map(u => <li key={u.id}>{u.name}</li>)}</ul>;
}
```

```typescript
// 2. 장바구니 (Zustand + Persist)
import { create } from 'zustand';
import { persist } from 'zustand/middleware';

interface CartItem {
  productId: string;
  quantity: number;
}

interface CartStore {
  items: CartItem[];
  addItem: (productId: string) => void;
  removeItem: (productId: string) => void;
  clearCart: () => void;
}

export const useCartStore = create<CartStore>()(
  persist(
    (set) => ({
      items: [],
      addItem: (productId) =>
        set((state) => {
          const existing = state.items.find(
            (item) => item.productId === productId
          );
          if (existing) {
            return {
              items: state.items.map((item) =>
                item.productId === productId
                  ? { ...item, quantity: item.quantity + 1 }
                  : item
              ),
            };
          }
          return {
            items: [...state.items, { productId, quantity: 1 }],
          };
        }),
      removeItem: (productId) =>
        set((state) => ({
          items: state.items.filter((item) => item.productId !== productId),
        })),
      clearCart: () => set({ items: [] }),
    }),
    { name: 'cart-storage' }
  )
);
```

## Best Practices

### 1. 올바른 도구 선택 (상태 유형별)

```typescript
// ✅ TanStack Query: 서버 데이터 (캐싱, 동기화 필요)
const { data } = useQuery({ queryKey: ['users'], queryFn: fetchUsers });

// ✅ Zustand: 전역 클라이언트 상태 (여러 컴포넌트 공유)
const theme = useThemeStore((state) => state.theme);

// ✅ useState: 로컬 상태 (단일 컴포넌트 범위)
const [isOpen, setIsOpen] = useState(false);

// ✅ useActionState: 서버 액션 연동 폼 (React 19)
const [state, action, isPending] = useActionState(submitForm, initialState);

// ❌ 서버 데이터를 Zustand/Redux에 저장 (TanStack Query 사용)
// ❌ 로컬 상태를 전역 store에 저장 (useState 사용)
```

### 2. 성능 최적화

```typescript
// ✅ Selector로 필요한 부분만 구독
const userName = useUserStore((state) => state.user?.name);

// ✅ useShallow로 여러 값을 안전하게 선택
const { user, theme } = useUserStore(
  useShallow((state) => ({ user: state.user, theme: state.theme }))
);

// ✅ TanStack Query의 select로 필요한 데이터만 추출
const { data: userNames } = useQuery({
  queryKey: ['users'],
  queryFn: fetchUsers,
  select: (users) => users.map((u) => u.name), // 변환된 결과만 구독
});

// ❌ 전체 상태 구독
const store = useUserStore();
```
