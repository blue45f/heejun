## 1. AI 기반 테스팅 혁명

AI 도구를 테스팅 워크플로에 통합하면 테스트 작성 속도와 품질을 동시에 끌어올릴 수 있다. 이 섹션에서는 실무에서 바로 적용 가능한 AI 활용 패턴을 다룬다.

### 1.1 Claude Code로 테스트 코드 자동 생성

Claude Code는 프로젝트 컨텍스트를 이해하고 테스트를 생성할 수 있다. 핵심은 **구체적인 프롬프트**를 작성하는 것이다.

#### 프롬프트 예시 1: 컴포넌트 테스트 생성

```
이 컴포넌트에 대한 Vitest + Testing Library 테스트를 작성해줘.
- 렌더링 확인, 사용자 상호작용, 에러 상태, 로딩 상태를 각각 테스트
- MSW로 API 호출을 모킹하고, 성공/실패 케이스 모두 포함
- describe 블록으로 시나리오별 그룹핑
- 접근성: role 기반 쿼리 사용, getByText 최소화
```

#### 프롬프트 예시 2: 커스텀 훅 테스트

```
이 커스텀 훅의 테스트를 작성해줘.
- renderHook 사용
- 초기 상태, 상태 변경, 클린업, 에러 핸들링 케이스 포함
- act()로 비동기 상태 업데이트 래핑
- 엣지 케이스: 빈 입력, null, undefined, 대량 데이터
```

#### 프롬프트 예시 3: E2E 테스트 시나리오 생성

```
아래 사용자 플로우에 대한 Playwright E2E 테스트를 작성해줘.
플로우: 로그인 -> 상품 검색 -> 장바구니 추가 -> 결제 진행
- Page Object Model 패턴 적용
- 각 단계에서 assertions 포함
- 네트워크 요청 인터셉트로 결제 API 모킹
- 실패 시 스크린샷 자동 캡처 설정
```

#### 프롬프트 예시 4: 기존 코드 기반 테스트 갭 분석

```
이 파일의 테스트 커버리지 갭을 분석하고, 누락된 테스트 케이스를 모두 작성해줘.
- 분기(if/else, switch, try/catch) 중 테스트되지 않은 경로 식별
- 경계값과 엣지 케이스 추가
- 각 테스트에 왜 이 케이스가 필요한지 주석 추가
```

### 1.2 GitHub Copilot 테스트 자동완성 활용

#### 인라인 제안 극대화

테스트 파일에서 `describe` 블록과 첫 번째 `it`을 작성하면 Copilot이 패턴을 인식하여 나머지 테스트 케이스를 제안한다.

```typescript
// 파일명: useDebounce.test.ts
// Copilot은 파일명과 import에서 컨텍스트를 추론한다.
import { renderHook, act } from '@testing-library/react';
import { useDebounce } from './useDebounce';

describe('useDebounce', () => {
  beforeEach(() => {
    vi.useFakeTimers();
  });

  afterEach(() => {
    vi.useRealTimers();
  });

  it('초기값을 즉시 반환한다', () => {
    const { result } = renderHook(() => useDebounce('hello', 500));
    expect(result.current).toBe('hello');
  });

  // 여기서 Enter를 누르면 Copilot이 다음 케이스들을 자동 제안:
  // - 지연 시간 내 값 변경 시 이전 값 유지
  // - 지연 시간 경과 후 새 값 반환
  // - 연속 변경 시 마지막 값만 반영
});
```

#### Copilot Chat 모드 활용

에디터에서 테스트 대상 코드를 선택한 뒤 Copilot Chat에 다음과 같이 요청한다:

- `/tests` - 선택한 코드에 대한 테스트 자동 생성
- `이 함수의 엣지 케이스를 포함한 테스트를 작성해줘` - 자연어 요청
- `기존 테스트에 에러 핸들링 케이스를 추가해줘` - 기존 테스트 보강

### 1.3 Cursor AI로 테스트 리팩토링

Cursor의 AI 기능을 활용한 테스트 리팩토링 패턴:

```typescript
// Before: 반복적인 테스트 코드
describe('Button', () => {
  it('primary 버튼 렌더링', () => {
    render(<Button variant="primary">Click</Button>);
    expect(screen.getByRole('button')).toHaveClass('btn-primary');
  });

  it('secondary 버튼 렌더링', () => {
    render(<Button variant="secondary">Click</Button>);
    expect(screen.getByRole('button')).toHaveClass('btn-secondary');
  });

  it('danger 버튼 렌더링', () => {
    render(<Button variant="danger">Click</Button>);
    expect(screen.getByRole('button')).toHaveClass('btn-danger');
  });
});

// After: Cursor에게 "이 테스트를 parametrize해줘" 요청 결과
describe('Button', () => {
  it.each([
    ['primary', 'btn-primary'],
    ['secondary', 'btn-secondary'],
    ['danger', 'btn-danger'],
  ] as const)('%s 버튼 렌더링', (variant, expectedClass) => {
    render(<Button variant={variant}>Click</Button>);
    expect(screen.getByRole('button')).toHaveClass(expectedClass);
  });
});
```

Cursor CMD+K로 테스트 파일을 선택하고 다음과 같은 리팩토링을 요청할 수 있다:

- "반복되는 setup을 beforeEach로 추출해줘"
- "하드코딩된 테스트 데이터를 factory 패턴으로 변환해줘"
- "이 테스트를 AAA(Arrange-Act-Assert) 패턴으로 정리해줘"

### 1.5 Stryker 뮤테이션 테스트 + AI 분석

뮤테이션 테스트는 테스트의 **품질**을 검증한다. 코드를 의도적으로 변형(mutate)하고, 테스트가 이를 감지하는지 확인한다.

```bash
npm install --save-dev @stryker-mutator/core @stryker-mutator/vitest-runner
```

```typescript
// stryker.config.mts
import { defineConfig } from '@stryker-mutator/core';

export default defineConfig({
  mutate: ['src/**/*.ts', '!src/**/*.test.ts', '!src/**/*.d.ts'],
  testRunner: 'vitest',
  reporters: ['html', 'clear-text', 'progress', 'json'],
  thresholds: {
    high: 80,
    low: 60,
    break: 50,
  },
  incremental: true,        // 변경된 파일만 뮤테이션 실행
  concurrency: 4,
});
```

```bash
# 뮤테이션 테스트 실행
npx stryker run

# 결과를 Claude Code에 전달하여 분석
# "stryker 리포트에서 살아남은(survived) 뮤턴트를 분석해줘.
#  각 뮤턴트에 대해 왜 테스트가 잡지 못했는지 설명하고,
#  해당 뮤턴트를 죽이는 테스트 코드를 작성해줘."
```

살아남은 뮤턴트 분석 예시:

```typescript
// 원본 코드
function calculateDiscount(price: number, rate: number): number {
  if (rate < 0 || rate > 100) {
    throw new Error('Invalid rate');
  }
  return price * (rate / 100);
}

// 살아남은 뮤턴트: rate > 100 -> rate >= 100
// 원인: rate === 100인 경우를 테스트하지 않음

// 뮤턴트를 잡는 테스트 추가
it('할인율 100%일 때 전체 금액을 반환한다', () => {
  expect(calculateDiscount(10000, 100)).toBe(10000);
});

it('할인율 100 초과 시 에러를 던진다', () => {
  expect(() => calculateDiscount(10000, 101)).toThrow('Invalid rate');
});
```

### 1.7 AI 기반 플레이키 테스트 자동 탐지 및 수정

플레이키 테스트(간헐적 실패 테스트)는 CI 신뢰도를 떨어뜨린다.

```typescript
// vitest.config.ts - 플레이키 테스트 감지 설정
export default defineConfig({
  test: {
    retry: 2,                    // 실패 시 2회 재시도
    reporters: ['default', 'json'],
    outputFile: 'test-results.json',
  },
});
```

```typescript
// scripts/detect-flaky-tests.ts
// 테스트 결과를 수집하여 플레이키 테스트를 식별하는 스크립트
import { readFileSync, writeFileSync } from 'fs';

interface TestResult {
  name: string;
  status: 'passed' | 'failed';
  retries: number;
  duration: number;
}

function detectFlakyTests(resultsPath: string): TestResult[] {
  const results = JSON.parse(readFileSync(resultsPath, 'utf-8'));

  // 재시도 후 성공한 테스트 = 플레이키 테스트
  const flakyTests = results.testResults
    .flatMap((suite: any) => suite.assertionResults)
    .filter((test: any) => test.status === 'passed' && test.retryReasons?.length > 0);

  return flakyTests;
}

// Claude Code에 플레이키 테스트 분석 요청:
// "이 테스트가 간헐적으로 실패하는 원인을 분석하고 수정해줘.
//  일반적인 원인: 타이밍 의존, 전역 상태 오염, 네트워크 의존,
//  비결정적 데이터, 테스트 간 순서 의존성"
```

플레이키 테스트의 일반적인 수정 패턴:

```typescript
// Bad: 타이밍에 의존하는 테스트
it('디바운스 후 검색 실행', async () => {
  await userEvent.type(input, 'test');
  await new Promise((r) => setTimeout(r, 500)); // 플레이키!
  expect(searchFn).toHaveBeenCalled();
});

// Good: 명시적 대기
it('디바운스 후 검색 실행', async () => {
  await userEvent.type(input, 'test');
  await waitFor(() => {
    expect(searchFn).toHaveBeenCalled();
  });
});

// Bad: 전역 상태 오염
let counter = 0;
it('첫 번째 테스트', () => { counter++; });
it('두 번째 테스트', () => { expect(counter).toBe(0); }); // 순서 의존!

// Good: 테스트 격리
beforeEach(() => {
  vi.restoreAllMocks();
  // 각 테스트에서 필요한 상태를 명시적으로 설정
});
```

### 5.1 Core Web Vitals 자동 회귀 테스트

```typescript
// tests/performance/web-vitals.spec.ts
import { test, expect, type Page } from '@playwright/test';

interface WebVitalsMetrics {
  LCP: number;
  FID: number;
  CLS: number;
  INP: number;
  TTFB: number;
}

async function measureWebVitals(page: Page): Promise<WebVitalsMetrics> {
  return page.evaluate(() => {
    return new Promise<WebVitalsMetrics>((resolve) => {
      const metrics: Partial<WebVitalsMetrics> = {};
      let collected = 0;
      const total = 5;

      function checkDone() {
        if (++collected >= total) {
          resolve(metrics as WebVitalsMetrics);
        }
      }

      new PerformanceObserver((list) => {
        const entries = list.getEntries();
        const lastEntry = entries[entries.length - 1] as any;
        metrics.LCP = lastEntry.startTime;
        checkDone();
      }).observe({ type: 'largest-contentful-paint', buffered: true });

      new PerformanceObserver((list) => {
        const entries = list.getEntries();
        metrics.CLS = entries.reduce((sum, e: any) => sum + e.value, 0);
        checkDone();
      }).observe({ type: 'layout-shift', buffered: true });

      new PerformanceObserver((list) => {
        const entries = list.getEntries();
        metrics.INP = Math.max(...entries.map((e: any) => e.duration));
        checkDone();
      }).observe({ type: 'event', buffered: true });

      // TTFB
      const navEntry = performance.getEntriesByType('navigation')[0] as any;
      metrics.TTFB = navEntry.responseStart;
      checkDone();

      // FID (첫 입력이 없으면 0)
      metrics.FID = 0;
      checkDone();
    });
  });
}

test.describe('Core Web Vitals', () => {
  test('메인 페이지 성능 기준 충족', async ({ page }) => {
    await page.goto('/');
    await page.waitForLoadState('networkidle');

    // 사용자 상호작용 트리거 (INP 측정용)
    await page.click('body');

    const metrics = await measureWebVitals(page);

    // Google 권장 기준
    expect(metrics.LCP).toBeLessThan(2500);   // Good: < 2.5s
    expect(metrics.CLS).toBeLessThan(0.1);    // Good: < 0.1
    expect(metrics.INP).toBeLessThan(200);    // Good: < 200ms
    expect(metrics.TTFB).toBeLessThan(800);   // Good: < 800ms
  });

  test('상품 목록 페이지 성능 기준 충족', async ({ page }) => {
    await page.goto('/products');
```

```typescript
    bail: process.env.CI ? 3 : 0,
    // 테스트 타임아웃
```
