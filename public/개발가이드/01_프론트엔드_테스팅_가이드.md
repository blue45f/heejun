## 테스팅 전략 개요

### Testing Trophy (2026년 권장)

```
        /\
       /  \    E2E (핵심 시나리오만)
      /    \
     /------\  Integration (최대 비중)
    /--------\
   /----------\ Component (중간)
  /------------\
 /--------------\ Unit (유틸/로직만)
```

통합 테스트가 **비용 대비 효과가 가장 높다**. 실제 사용자 시나리오와 유사하고, 리팩토링에도 강하다.

### 커버리지 목표

| 레이어 | 목표 커버리지 | 대상 |
|--------|-------------|------|
| 통합 테스트 | 40-50% | 페이지 단위 시나리오, API 연동 |
| 컴포넌트 테스트 | 20-30% | 재사용 UI 컴포넌트 |
| E2E 테스트 | 5-10% | 결제, 인증 등 핵심 플로우 |
| 단위 테스트 | 나머지 | 유틸, 커스텀 훅, 순수 함수 |

**전체 목표**: 60-80%. 100% 커버리지는 유지보수 비용 대비 효과가 낮다.

### Vitest 3.x 최신 기능

Vitest 3.x는 단순한 테스트 러너를 넘어 풀스택 테스팅 플랫폼으로 진화했다.

#### Browser Mode

실제 브라우저 환경에서 컴포넌트 테스트를 실행한다. happy-dom/jsdom의 한계를 완전히 극복한다.

```typescript
// vitest.config.ts
import { defineConfig } from 'vitest/config';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  test: {
    // 기본 환경 (유닛 테스트용)
    environment: 'happy-dom',
    setupFiles: './src/tests/setup.ts',
    css: true,
    pool: 'forks',
    coverage: {
      provider: 'v8',
      reporter: ['text', 'json', 'html', 'lcov'],
      exclude: [
        'node_modules/',
        'src/tests/',
        '**/*.d.ts',
        '**/*.config.*',
        '**/mockData',
      ],
      thresholds: {
        lines: 60,
        functions: 60,
        branches: 60,
        statements: 60,
      },
    },
    // Vitest 3.x: 타입 테스트
    typecheck: {
      enabled: true,
      tsconfig: './tsconfig.json',
    },
    // Vitest 3.x: 벤치마크 설정

      include: ['**/*.bench.{ts,tsx}'],
      outputJson: './bench-results.json',

    // Browser Mode 프로젝트 분리
    workspace: [
      {
        test: {
          name: 'unit',
          include: ['src/**/*.test.{ts,tsx}'],
          environment: 'happy-dom',
        },
      },
      {
        test: {
          name: 'browser',
          include: ['src/**/*.browser.test.{ts,tsx}'],
          browser: {
            enabled: true,

          },
        },
      },
```

### Vitest vs Bun Test Runner 비교

| 항목 | Vitest 3.x | Bun test |
|------|-----------|----------|
| 생태계 호환 | Jest API 완전 호환 | 자체 API, Jest 부분 호환 |
| Vite 통합 | 네이티브 | 미지원 |
| Browser Mode | Playwright 기반 지원 | 미지원 |
| 타입 테스트 | `expectTypeOf` 내장 | 미지원 |
| 벤치마크 | 내장 지원 | 미지원 |
| 커버리지 | V8/Istanbul | 실험적 |
| 워크스페이스 | 다중 환경 프로젝트 | 미지원 |
| 순수 속도 | 빠름 | 매우 빠름 (네이티브 런타임) |
| 모킹 | `vi.mock` 완전 지원 | `mock.module` 지원 |
| MSW 호환 | 완전 호환 | 제한적 |

**결론**: Bun test는 순수 속도에서 우위이나, 프론트엔드 프로젝트에서는 Vitest의 생태계 호환성, Browser Mode, Vite 통합이 훨씬 실용적이다. Bun은 순수 TypeScript 라이브러리나 서버 로직 테스트에 적합하다.

### Playwright 1.52+ 최신 기능

#### Component Testing 안정화

Playwright의 컴포넌트 테스트가 안정 버전으로 졸업했다. 실제 브라우저에서 개별 컴포넌트를 마운트하여 테스트한다.

```typescript
// components/DatePicker.spec.tsx (Playwright Component Test)
import { test, expect } from '@playwright/experimental-ct-react';
import { DatePicker } from './DatePicker';

test.describe('DatePicker', () => {
  test('날짜를 선택할 수 있다', async ({ mount }) => {
    let selectedDate: Date | null = null;
    const component = await mount(
      <DatePicker
        onSelect={(date) => { selectedDate = date; }}
        locale="ko-KR"
      />
    );

    await component.getByRole('button', { name: '15' }).click();
    expect(selectedDate?.getDate()).toBe(15);
  });

  test('비활성 날짜는 선택할 수 없다', async ({ mount }) => {
    const component = await mount(
      <DatePicker
        minDate={new Date('2026-04-05')}
        maxDate={new Date('2026-04-20')}
      />

    await expect(disabledDay).toBeDisabled();
```

#### 자동 생성 파이프라인 구축

```typescript
// scripts/generate-tests.ts
// AI 기반 테스트 자동 생성 스크립트
import { execSync } from 'child_process';
import { readFileSync, writeFileSync, existsSync } from 'fs';
import { glob } from 'glob';

interface TestGenerationConfig {
  /** 테스트 파일이 없는 소스 파일을 탐지 */
  findUntested: boolean;
  /** 커버리지 리포트 기반 갭 분석 */
  coverageGapAnalysis: boolean;
  /** 생성된 테스트에 대한 리뷰 프롬프트 */
  requireReview: boolean;
}

async function findUntestedFiles(): Promise<string[]> {
  const sourceFiles = glob.sync('src/**/*.{ts,tsx}', {
    ignore: ['**/*.test.*', '**/*.spec.*', '**/*.d.ts', '**/tests/**'],
  });

  return sourceFiles.filter((file) => {
    const testFile = file.replace(/\.(ts|tsx)$/, '.test.$1');
    return !existsSync(testFile);
  });
}

async function analyzeCoverageGaps(): Promise<Map<string, string[]>> {
  const coverageJson = JSON.parse(
    readFileSync('./coverage/coverage-final.json', 'utf-8')
  );

  const gaps = new Map<string, string[]>();

  for (const [file, data] of Object.entries(coverageJson)) {
    const uncoveredLines: string[] = [];
    const statementMap = (data as any).statementMap;
    const s = (data as any).s;

    for (const [key, count] of Object.entries(s)) {
      if (count === 0) {
        const loc = statementMap[key];
        uncoveredLines.push(
          `L${loc.start.line}-${loc.end.line}`
        );
      }
    }

    if (uncoveredLines.length > 0) {
      gaps.set(file, uncoveredLines);
    }
  }

  return gaps;
}
```


### AI 기반 테스트 커버리지 분석 및 갭 탐지

```typescript
// scripts/ai-coverage-analysis.ts
import { readFileSync } from 'fs';

interface CoverageGap {
  file: string;
  uncoveredFunctions: string[];
  uncoveredBranches: string[];
  suggestedTests: string[];
  priority: 'high' | 'medium' | 'low';
}

/**
 * 커버리지 리포트를 분석하여 AI 기반 테스트 제안을 생성한다.
 *
 * 활용법:
 * 1. `vitest --coverage` 로 커버리지 리포트 생성
 * 2. 이 스크립트로 갭 분석 실행
 * 3. 분석 결과를 AI 어시스턴트에 전달하여 테스트 코드 생성
 */
function analyzeCoverageWithPriority(
  coveragePath: string
): CoverageGap[] {
  const coverage = JSON.parse(readFileSync(coveragePath, 'utf-8'));
  const gaps: CoverageGap[] = [];

  for (const [filePath, fileData] of Object.entries(coverage)) {
    const data = fileData as any;
    const uncoveredFns = Object.entries(data.f)
      .filter(([, count]) => count === 0)
      .map(([key]) => data.fnMap[key]?.name || `anonymous@L${data.fnMap[key]?.loc.start.line}`);

    const uncoveredBranches = Object.entries(data.b)
      .filter(([, counts]) => (counts as number[]).some((c) => c === 0))
      .map(([key]) => `branch@L${data.branchMap[key]?.loc.start.line}`);

    if (uncoveredFns.length > 0 || uncoveredBranches.length > 0) {
      // 우선순위 산정: 공통 컴포넌트/유틸리티 > 페이지 > 설정 파일
      const priority = filePath.includes('/components/') || filePath.includes('/hooks/')
        ? 'high'
        : filePath.includes('/pages/') || filePath.includes('/features/')
          ? 'medium'
          : 'low';

      gaps.push({
        file: filePath,
        uncoveredFunctions: uncoveredFns,
        uncoveredBranches: uncoveredBranches,
        suggestedTests: generateTestSuggestions(filePath, uncoveredFns),
        priority,
      });
    }
  }

  return gaps.sort((a, b) => {
    const order = { high: 0, medium: 1, low: 2 };
    return order[a.priority] - order[b.priority];
  });
}

function generateTestSuggestions(
  filePath: string,
  uncoveredFns: string[]
): string[] {
  return uncoveredFns.map((fn) =>
    `it('${fn}이 올바르게 동작한다', () => { /* AI로 구현 생성 */ })`
  );
}
```

### 뮤테이션 테스트와 AI 결합 (Stryker + AI 분석)

뮤테이션 테스트는 "테스트의 테스트"다. 소스 코드를 의도적으로 변형(mutate)하여, 기존 테스트가 그 변형을 탐지하는지 확인한다.

```javascript
// stryker.config.mjs
/** @type {import('@stryker-mutator/api/core').PartialStrykerOptions} */
export default {
  packageManager: 'npm',
  reporters: ['html', 'clear-text', 'progress', 'json'],
  testRunner: 'vitest',
  vitest: {
    configFile: 'vitest.config.ts',
  },
  coverageAnalysis: 'perTest',
  mutate: [
    'src/**/*.ts',
    'src/**/*.tsx',
    '!src/**/*.test.*',
    '!src/**/*.spec.*',
    '!src/**/*.d.ts',
  ],
  thresholds: {
    high: 80,
    low: 60,
    break: 50,
  },
  // 뮤테이션 연산자 설정
  mutator: {
    excludedMutations: [
      'StringLiteral', // UI 텍스트 변경은 의미 없음
    ],
  },
};
```

```typescript
// scripts/analyze-mutations.ts
// Stryker 결과를 AI로 분석하여 테스트 개선점을 도출한다
import { readFileSync } from 'fs';

interface MutationResult {
  id: string;
  mutatorName: string;
  status: 'Killed' | 'Survived' | 'Timeout' | 'NoCoverage';
  location: { start: { line: number; column: number } };
  replacement: string;
}

function analyzeSurvivedMutants(reportPath: string) {
  const report = JSON.parse(readFileSync(reportPath, 'utf-8'));
  const survived: MutationResult[] = [];

  for (const file of Object.values(report.files) as any[]) {
    for (const mutant of file.mutants) {
      if (mutant.status === 'Survived') {
        survived.push(mutant);
      }
    }
  }

  // 생존한 뮤턴트를 분류하여 개선 방향 제시
  const analysis = {
    conditionalBoundary: survived.filter(
      (m) => m.mutatorName === 'ConditionalExpression'
    ),
    arithmeticOperator: survived.filter(
      (m) => m.mutatorName === 'ArithmeticOperator'
    ),
    equalityOperator: survived.filter(
      (m) => m.mutatorName === 'EqualityOperator'
    ),
    blockStatement: survived.filter(
      (m) => m.mutatorName === 'BlockStatement'
    ),
  };

  console.log('=== 뮤테이션 테스트 AI 분석 결과 ===');
  console.log(`총 생존 뮤턴트: ${survived.length}개`);
  console.log(`- 조건문 경계값 누락: ${analysis.conditionalBoundary.length}개`);
  console.log(`  -> 경계값 테스트 케이스 추가 권장`);
  console.log(`- 산술 연산자 미검증: ${analysis.arithmeticOperator.length}개`);
  console.log(`  -> 계산 로직 결과값 검증 강화 권장`);
  console.log(`- 동등 연산자 미검증: ${analysis.equalityOperator.length}개`);
  console.log(`  -> 엣지 케이스(null, undefined, 0) 테스트 추가 권장`);
  console.log(`- 블록 제거 미탐지: ${analysis.blockStatement.length}개`);
  console.log(`  -> 해당 코드 블록의 부수 효과를 검증하는 테스트 추가 권장`);
```

### OpenAPI 스키마 기반 자동 테스트 생성

```typescript
// scripts/generate-api-tests.ts
import { readFileSync, writeFileSync } from 'fs';
import yaml from 'js-yaml';

interface OpenAPISpec {
  paths: Record<string, Record<string, {
    operationId: string;
    summary: string;
    parameters?: any[];
    requestBody?: any;
    responses: Record<string, any>;
  }>>;
}

/**
 * OpenAPI 스펙에서 MSW 핸들러와 기본 테스트를 자동 생성한다.
 *
 * 사용법:
 *   npx tsx scripts/generate-api-tests.ts ./openapi.yaml
 */
function generateHandlersFromSpec(specPath: string): string {
  const spec = yaml.load(readFileSync(specPath, 'utf-8')) as OpenAPISpec;
  const handlers: string[] = [];

  for (const [path, methods] of Object.entries(spec.paths)) {
    for (const [method, operation] of Object.entries(methods)) {
      const mswPath = path.replace(/{(\w+)}/g, ':$1');
      const statusCodes = Object.keys(operation.responses);
      const successCode = statusCodes.find((c) => c.startsWith('2')) || '200';
      const responseSchema = operation.responses[successCode];

      handlers.push(`
  // ${operation.summary || operation.operationId}
  http.${method}('${mswPath}', () => {
    return HttpResponse.json(
      ${generateMockFromSchema(responseSchema?.content?.['application/json']?.schema)},
      { status: ${successCode} }
    );
  }),`);
    }
  }

  return `import { http, HttpResponse } from 'msw';

export const generatedHandlers = [${handlers.join('\n')}
];`;
}

function generateMockFromSchema(schema: any): string {
  if (!schema) return '{}';

  if (schema.type === 'object') {
    const props = Object.entries(schema.properties || {})
      .map(([key, prop]: [string, any]) => {
        const value = prop.type === 'string' ? `'mock-${key}'`
          : prop.type === 'number' || prop.type === 'integer' ? '0'
          : prop.type === 'boolean' ? 'true'
          : prop.type === 'array' ? '[]'
          : '{}';
        return `${key}: ${value}`;
      })
      .join(', ');
    return `{ ${props} }`;
  }

  return '{}';
}
```

React 19.1의 `use()` 훅은 컴포넌트 내에서 Promise를 직접 소비한다. Suspense와 함께 사용된다.

```typescript
// components/UserProfile.tsx
import { use, Suspense } from 'react';

async function fetchUser(id: string) {
  const res = await fetch(`/api/users/${id}`);
  if (!res.ok) throw new Error('사용자를 찾을 수 없습니다');
  return res.json();
}

function UserInfo({ userPromise }: { userPromise: Promise<any> }) {
  const user = use(userPromise);
  return (
    <div>
      <h2>{user.name}</h2>
      <p>{user.email}</p>
    </div>
  );
}

export function UserProfile({ userId }: { userId: string }) {
  const userPromise = fetchUser(userId);
  return (
    <Suspense fallback={<div>프로필 로딩중...</div>}>
      <UserInfo userPromise={userPromise} />
    </Suspense>
  );
}
```

```typescript
// app/actions/product.ts
'use server';

import { revalidateTag } from 'next/cache';
import { redirect } from 'next/navigation';
import { z } from 'zod';

const ProductSchema = z.object({
  name: z.string().min(1, '상품명은 필수입니다'),
  price: z.number().positive('가격은 양수여야 합니다'),
  category: z.enum(['top', 'bottom', 'shoes', 'accessory']),
  description: z.string().max(500, '설명은 500자 이하여야 합니다'),
});

export type ProductFormState = {
  errors?: Record<string, string[]>;
  message?: string;
  success?: boolean;
};

export async function createProduct(
  prevState: ProductFormState,
  formData: FormData
): Promise<ProductFormState> {
  const rawData = {
    name: formData.get('name'),
    price: Number(formData.get('price')),
    category: formData.get('category'),
    description: formData.get('description'),
  };

  const validation = ProductSchema.safeParse(rawData);

  if (!validation.success) {
    return {
      errors: validation.error.flatten().fieldErrors,
      message: '입력값을 확인해주세요',
    };
  }

  try {
    await db.product.create({ data: validation.data });
    revalidateTag('products');
  } catch (error) {
    return { message: '상품 등록에 실패했습니다' };
  }

  redirect('/admin/products');
}
```

### React Profiler 기반 렌더링 성능 테스트 자동화

```typescript
// tests/helpers/profiler.tsx
import { Profiler, ProfilerOnRenderCallback, ReactNode } from 'react';

interface RenderMetrics {
  id: string;
  phase: 'mount' | 'update';
  actualDuration: number;
  baseDuration: number;
  startTime: number;
  commitTime: number;
}

export function createProfilerCollector() {
  const metrics: RenderMetrics[] = [];

  const onRender: ProfilerOnRenderCallback = (
    id,
    phase,
    actualDuration,
    baseDuration,
    startTime,
    commitTime
  ) => {
    metrics.push({
      id,
      phase: phase as 'mount' | 'update',
      actualDuration,
      baseDuration,
      startTime,
      commitTime,
    });
  };

  function ProfilerWrapper({
    id,
    children,
  }: {
    id: string;
    children: ReactNode;
  }) {
    return (
      <Profiler id={id} onRender={onRender}>
        {children}
      </Profiler>
    );
  }

  return {
    ProfilerWrapper,
    getMetrics: () => [...metrics],
    getLastRender: () => metrics[metrics.length - 1],
    getMountDuration: () =>
      metrics.find((m) => m.phase === 'mount')?.actualDuration ?? 0,
    getUpdateDurations: () =>
      metrics.filter((m) => m.phase === 'update').map((m) => m.actualDuration),
    getAverageUpdateDuration: () => {
      const updates = metrics.filter((m) => m.phase === 'update');
      if (updates.length === 0) return 0;
      return updates.reduce((sum, m) => sum + m.actualDuration, 0) / updates.length;
    },
    reset: () => { metrics.length = 0; },
  };
}
```

```typescript
// packages/test-utils/src/render.tsx
import { render, RenderOptions } from '@testing-library/react';
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { MemoryRouter } from 'react-router-dom';
import { ThemeProvider } from '@myapp/ui';
import { ReactElement, ReactNode } from 'react';

interface CustomRenderOptions extends Omit<RenderOptions, 'wrapper'> {
  initialRoute?: string;
  queryClient?: QueryClient;
}

function createTestQueryClient() {
  return new QueryClient({
    defaultOptions: {
      queries: { retry: false, gcTime: 0 },
      mutations: { retry: false },
    },
  });
}

export function renderWithProviders(
  ui: ReactElement,
  options: CustomRenderOptions = {}
) {
  const {
    initialRoute = '/',
    queryClient = createTestQueryClient(),
    ...renderOptions
  } = options;

  function Wrapper({ children }: { children: ReactNode }) {
    return (
      <QueryClientProvider client={queryClient}>
        <MemoryRouter initialEntries={[initialRoute]}>
          <ThemeProvider>
            {children}
          </ThemeProvider>
        </MemoryRouter>
      </QueryClientProvider>
    );
  }

  return {
    ...render(ui, { wrapper: Wrapper, ...renderOptions }),
    queryClient,
  };
}

    };
  },
});
```
