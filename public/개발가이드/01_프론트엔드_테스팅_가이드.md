## 테스팅 전략

### Testing Trophy vs Testing Pyramid

**2025-2026년 권장: Testing Trophy 방식**

```
        /\
       /  \    E2E (소수)
      /    \   
     /------\  Integration (다수) ⭐ 중점
    /--------\ 
   /----------\ Component (적당)
  /------------\
 /--------------\ Unit (기본)
```

**이유**:
- 통합 테스트가 **가성비가 가장 높음**
- 실제 사용자 시나리오와 가장 유사
- 리팩토링에 강함 (구현 세부사항에 덜 의존)

### 테스트 커버리지 목표

```
전체 커버리지: 60-80%
├─ 통합 테스트: 40-50%
├─ 컴포넌트 테스트: 20-30%
├─ E2E 테스트: 5-10%
└─ 단위 테스트: 기본 유틸리티만
```

**주의**: 100% 커버리지는 비용 대비 효과 낮음

### Vitest vs Jest: 왜 Vitest인가?

Vitest는 Vite 기반 프로젝트의 사실상 표준 테스트 러너로 자리잡았다.

| 항목 | Vitest | Jest |
|------|--------|------|
| Vite 통합 | 네이티브 (설정 공유) | 별도 설정 필요 |
| 속도 | HMR 기반, 매우 빠름 | 상대적으로 느림 |
| ESM 지원 | 네이티브 | 실험적/불완전 |
| TypeScript | 별도 트랜스폼 불필요 | ts-jest 또는 babel 필요 |
| Jest 호환성 | expect, mock 등 API 호환 | - |
| UI 모드 | `@vitest/ui` 내장 | 서드파티 필요 |
| 워크스페이스 | `vitest.workspace.ts` 지원 | `--projects` 옵션 |

> **참고**: Jest에서 마이그레이션하는 경우, 대부분의 테스트 코드는 import 경로만 변경하면 된다 (`jest.fn()` -> `vi.fn()` 등).

### React Testing Library Best Practices (2025-2026)

**1. 쿼리 우선순위를 반드시 지킨다**

```
1순위: getByRole       (접근성 기반, 가장 권장)
2순위: getByLabelText  (폼 요소)
3순위: getByPlaceholderText
4순위: getByText       (비인터랙티브 요소)
5순위: getByDisplayValue
---
6순위: getByAltText    (이미지)
7순위: getByTitle
---
최후: getByTestId      (다른 방법이 없을 때만)
```

**2. `screen` 객체를 항상 사용한다** (구조 분해 대신)

```typescript
// 나쁨
const { getByText } = render(<App />);
getByText('hello');

// 좋음
render(<App />);
screen.getByText('hello');
```

**3. `userEvent`를 `fireEvent` 대신 사용한다**

```typescript
// 나쁨: 이벤트만 발생
fireEvent.click(button);

// 좋음: 실제 사용자 동작 시뮬레이션 (포커스, 포인터 이벤트 포함)
const user = userEvent.setup();
await user.click(button);
```

**4. `waitFor` 내부에서 사이드 이펙트를 실행하지 않는다**

```typescript
// 나쁨: waitFor 안에서 클릭
await waitFor(() => {
  user.click(button);  // 여러 번 실행될 수 있음
});

// 좋음: 클릭 후 결과를 waitFor로 대기
await user.click(button);
await waitFor(() => {
  expect(screen.getByText('완료')).toBeInTheDocument();
});
```

**5. `findBy*` 쿼리로 비동기 요소를 기다린다**

```typescript
// 나쁨
await waitFor(() => {
  expect(screen.getByText('로드됨')).toBeInTheDocument();
});

// 좋음: findBy는 내부적으로 waitFor + getBy
expect(await screen.findByText('로드됨')).toBeInTheDocument();
```

```typescript
// utils/format.ts
export function formatPrice(price: number): string {
  return new Intl.NumberFormat('ko-KR').format(price) + '원';
}

export function truncateText(text: string, maxLength: number): string {
  if (text.length <= maxLength) return text;
  return text.slice(0, maxLength) + '...';
}

export function isValidEmail(email: string): boolean {
  return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email);
}
```

### 커스텀 Hook 테스트

```typescript
// hooks/useDebounce.test.ts
import { renderHook, act } from '@testing-library/react';
import { vi, describe, it, expect, beforeEach } from 'vitest';
import { useDebounce } from './useDebounce';

describe('useDebounce', () => {
  beforeEach(() => {
    vi.useFakeTimers();
  });

  it('지정 시간 후에 값이 업데이트된다', () => {
    const { result, rerender } = renderHook(
      ({ value }) => useDebounce(value, 500),
      { initialProps: { value: 'hello' } }
    );

    expect(result.current).toBe('hello');

    rerender({ value: 'world' });
    expect(result.current).toBe('hello'); // 아직 업데이트 안 됨

    act(() => { vi.advanceTimersByTime(500); });
    expect(result.current).toBe('world'); // 500ms 후 업데이트
  });

  it('연속 호출 시 마지막 값만 반영된다', () => {
    const { result, rerender } = renderHook(
      ({ value }) => useDebounce(value, 300),
      { initialProps: { value: 'a' } }
    );

    rerender({ value: 'b' });
    act(() => { vi.advanceTimersByTime(100); });
    rerender({ value: 'c' });
    act(() => { vi.advanceTimersByTime(300); });

    expect(result.current).toBe('c');
  });
});
```

```typescript
// components/Button.test.tsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { describe, it, expect, vi } from 'vitest';
import { Button } from './Button';

describe('Button', () => {
  it('텍스트를 렌더링한다', () => {
    render(<Button>확인</Button>);
    expect(screen.getByRole('button', { name: '확인' })).toBeInTheDocument();
  });

  it('클릭 시 onClick 핸들러를 호출한다', async () => {
    const user = userEvent.setup();
    const handleClick = vi.fn();
    render(<Button onClick={handleClick}>확인</Button>);

    await user.click(screen.getByRole('button'));
    expect(handleClick).toHaveBeenCalledTimes(1);
  });

  it('disabled 상태에서는 클릭이 동작하지 않는다', async () => {
    const user = userEvent.setup();
    const handleClick = vi.fn();
    render(<Button onClick={handleClick} disabled>확인</Button>);

    await user.click(screen.getByRole('button'));
    expect(handleClick).not.toHaveBeenCalled();
    expect(screen.getByRole('button')).toBeDisabled();
  });

  it('로딩 상태를 표시한다', () => {
    render(<Button loading>확인</Button>);
    expect(screen.getByRole('button')).toBeDisabled();
    expect(screen.getByText('로딩중...')).toBeInTheDocument();
  });
});
```

```typescript
import { render, screen, waitFor } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { describe, it, expect, vi } from 'vitest';
import { LoginForm } from './LoginForm';

describe('LoginForm', () => {

    await user.type(screen.getByLabelText('비밀번호'), 'password123');
    await user.click(screen.getByRole('button', { name: '로그인' }));

    await waitFor(() => {
      expect(mockOnSubmit).toHaveBeenCalledWith({
        email: 'user@test.com',
        password: 'password123',
      });
    });
  });

  it('이메일이 비어있으면 에러 메시지를 표시한다', async () => {
    const user = userEvent.setup();
    render(<LoginForm onSubmit={mockOnSubmit} />);

    await user.click(screen.getByRole('button', { name: '로그인' }));

    expect(await screen.findByText('이메일을 입력해주세요')).toBeInTheDocument();
    expect(mockOnSubmit).not.toHaveBeenCalled();
  });

  it('잘못된 이메일 형식이면 에러를 표시한다', async () => {
    const user = userEvent.setup();
    render(<LoginForm onSubmit={mockOnSubmit} />);

    await user.click(screen.getByRole('button', { name: '로그인' }));
```

```typescript
// mocks/handlers.ts
import { http, HttpResponse } from 'msw';

export const handlers = [
  http.get('/api/products', ({ request }) => {
    const url = new URL(request.url);
    const category = url.searchParams.get('category');

    const products = [
      { id: '1', name: '티셔츠', price: 29000, category: 'top' },
      { id: '2', name: '청바지', price: 59000, category: 'bottom' },
      { id: '3', name: '자켓', price: 89000, category: 'top' },
    ];

    const filtered = category
      ? products.filter(p => p.category === category)
      : products;

    return HttpResponse.json({ products: filtered });
  }),

  http.post('/api/cart', async ({ request }) => {
    const body = await request.json() as { productId: string; quantity: number };
    return HttpResponse.json({
      success: true,
      cartItem: { ...body, addedAt: new Date().toISOString() },
    });
  }),

  http.post('/api/orders', async ({ request }) => {
    const body = await request.json() as { items: any[] };
    if (!body.items?.length) {
      return HttpResponse.json(
        { error: '주문 상품이 없습니다' },
        { status: 400 }
      );
    }
    return HttpResponse.json({
      orderId: 'ORD-12345',
      status: 'confirmed',
    });
  }),
];
```

## React Server Components 테스트

React Server Components(RSC)는 서버에서만 실행되는 컴포넌트이므로, 기존 RTL 방식과는 다른 접근이 필요하다.

### RSC 테스트 전략

```
서버 컴포넌트 → 단위 테스트 (직접 호출) + E2E 테스트
클라이언트 컴포넌트 → 기존 RTL 방식
서버 액션 → 단위 테스트 (함수 호출) + 통합 테스트
```

### 서버 컴포넌트 단위 테스트

서버 컴포넌트는 `async` 함수이므로 직접 호출하여 반환된 JSX를 테스트할 수 있다.

```typescript
// app/products/ProductList.tsx (Server Component)
export default async function ProductList({ category }: { category: string }) {
  const products = await fetchProducts(category);
  return (
    <ul>
      {products.map((product) => (
        <li key={product.id}>{product.name} - {product.price}원</li>
      ))}
    </ul>
  );
}
```

### Zustand 테스트

#### 스토어 테스트

```typescript
// stores/cartStore.ts
import { create } from 'zustand';

interface CartItem {
  id: string;
  name: string;
  price: number;
  quantity: number;
}

interface CartStore {
  items: CartItem[];
  addItem: (item: Omit<CartItem, 'quantity'>) => void;
  removeItem: (id: string) => void;
  updateQuantity: (id: string, quantity: number) => void;
  clearCart: () => void;
  totalPrice: () => number;
}

export const useCartStore = create<CartStore>((set, get) => ({
  items: [],

  addItem: (item) =>
    set((state) => {
      const existing = state.items.find((i) => i.id === item.id);
      if (existing) {
        return {
          items: state.items.map((i) =>
            i.id === item.id ? { ...i, quantity: i.quantity + 1 } : i
          ),
        };
      }
      return { items: [...state.items, { ...item, quantity: 1 }] };
    }),

  removeItem: (id) =>
    set((state) => ({ items: state.items.filter((i) => i.id !== id) })),

  updateQuantity: (id, quantity) =>
    set((state) => ({
      items: state.items.map((i) => (i.id === id ? { ...i, quantity } : i)),
    })),

  clearCart: () => set({ items: [] }),

  totalPrice: () => get().items.reduce((sum, i) => sum + i.price * i.quantity, 0),
}));
```

### Playwright vs Cypress 비교

| 항목 | Playwright | Cypress |
|------|-----------|---------|
| 브라우저 지원 | Chromium, Firefox, WebKit | Chromium 계열 중심 |
| 속도 | 빠름 (병렬 실행 기본) | 상대적으로 느림 |
| 다중 탭/창 | 지원 | 미지원 |
| 네트워크 인터셉트 | 강력한 route API | cy.intercept |
| 모바일 에뮬레이션 | 내장 | 제한적 |
| API 테스트 | request 컨텍스트 지원 | cy.request |
| 컴포넌트 테스트 | 실험적 | 안정적 지원 |
| 커뮤니티 | 빠르게 성장 | 성숙한 생태계 |

**권장**: 신규 프로젝트에서는 Playwright를 우선 고려한다. 크로스 브라우저 지원, 병렬 실행, 서버 컴포넌트 환경과의 호환성이 뛰어나다.

```typescript
        let clsValue = 0;
        new PerformanceObserver((list) => {
          for (const entry of list.getEntries() as any[]) {
            if (!entry.hadRecentInput) {
              clsValue += entry.value;
            }
          }
        }).observe({ type: 'layout-shift', buffered: true });

        setTimeout(() => resolve(clsValue), 3000);
      });
    });

    expect(cls).toBeLessThan(0.1);
  });
});
```

## 테스트 Best Practices

### 테스트 ID 전략

`data-testid`는 최후의 수단으로만 사용하되, 필요한 경우 일관된 네이밍 컨벤션을 적용한다.

```typescript
// 컨벤션: [컴포넌트]-[요소]-[식별자]
<div data-testid="product-card-123" />
<button data-testid="cart-add-button" />

// E2E에서는 data-testid보다 접근성 기반 선택자를 우선 사용
await page.getByRole('button', { name: '장바구니 담기' });  // 좋음
await page.getByTestId('cart-add-button');                   // 차선
```

### F.I.R.S.T 원칙

- **Fast**: 빠르게 실행 (밀리초 단위)
- **Independent**: 독립적으로 실행 가능
- **Repeatable**: 반복 가능한 결과
- **Self-Validating**: 자동으로 검증
- **Timely**: 코드 작성과 동시에 작성

### Given-When-Then 패턴

```typescript
test('장바구니에 상품 추가', async () => {
  // Given: 초기 상태 설정
  const user = userEvent.setup();
  render(<ProductPage productId="123" />);

  // When: 동작 수행
  await user.selectOption(screen.getByLabelText('사이즈'), 'L');
  await user.click(screen.getByRole('button', { name: '장바구니 담기' }));

  // Then: 결과 검증
  await waitFor(() => {
    expect(screen.getByText('장바구니에 추가되었습니다')).toBeInTheDocument();
  });
});
```
