## 1. 멀티 베타 테스팅 아키텍처

> 모든 PR은 독립된 Preview 환경에서 테스트되고, N개의 베타 환경이 동시에 동작한다. Feature Flag 조합, 브라우저, 환경별 테스트를 매트릭스로 실행하여 배포 전 모든 변형을 검증한다.

### 1.1 PR별 Preview 환경 자동 E2E 테스트

PR이 생성되면 Preview URL을 자동으로 감지하고, 해당 URL에 대해 Playwright E2E 테스트를 실행한다.

#### GitHub Actions: Preview E2E 파이프라인

```yaml
# .github/workflows/preview-e2e.yml
name: Preview E2E Tests
on:
  deployment_status:

jobs:
  e2e-on-preview:
    if: github.event.deployment_status.state == 'success'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Extract Preview URL
        id: preview
        run: echo "url=${{ github.event.deployment_status.target_url }}" >> $GITHUB_OUTPUT

      - uses: actions/setup-node@v4
        with:
          node-version: 22

      - run: npm ci
      - run: npx playwright install --with-deps chromium

      - name: Run E2E on Preview
        run: npx playwright test --project=chromium
        env:
          BASE_URL: ${{ steps.preview.outputs.url }}

      - uses: actions/upload-artifact@v4
        if: failure()
        with:
          name: playwright-report-${{ github.event.deployment.sha }}
          path: playwright-report/
```

#### Preview 상태 대기 유틸

```typescript
// e2e/utils/waitForPreview.ts
interface PreviewCheckOptions {
  url: string;
  timeoutMs?: number;
  intervalMs?: number;
}

export async function waitForPreview({
  url,
  timeoutMs = 120_000,
  intervalMs = 5_000,
}: PreviewCheckOptions): Promise<void> {
  const start = Date.now();

  while (Date.now() - start < timeoutMs) {
    try {
      const res = await fetch(url, { method: "HEAD" });
      if (res.ok) return;
    } catch {
      // Preview가 아직 준비되지 않음
    }
    await new Promise((r) => setTimeout(r, intervalMs));
  }

  throw new Error(`Preview not ready after ${timeoutMs}ms: ${url}`);
}
```

### 1.3 Feature Flag 조합별 테스트 자동 생성

Feature Flag의 ON/OFF 경우의 수를 자동 생성하여 모든 조합에 대해 테스트를 실행한다.

#### Flag 조합 생성기

```typescript
// e2e/utils/featureFlagMatrix.ts
interface FlagDefinition {
  name: string;
  description: string;
  testRelevant: boolean; // UI에 영향을 주는 플래그만 조합 대상
}

interface FlagCombination {
  id: string;
  flags: Record<string, boolean>;
}

/**
 * N개의 플래그에 대해 2^N 조합을 생성한다.
 * testRelevant가 true인 플래그만 조합 대상으로 포함한다.
 * maxCombinations로 상한을 제한하여 CI 시간을 통제한다.
 */
export function generateFlagCombinations(
  definitions: FlagDefinition[],
  maxCombinations = 16,
): FlagCombination[] {
  const relevant = definitions.filter((d) => d.testRelevant);
  const total = Math.pow(2, relevant.length);
  const step =
    total > maxCombinations ? Math.floor(total / maxCombinations) : 1;
  const combinations: FlagCombination[] = [];

  for (
    let i = 0;
    i < total && combinations.length < maxCombinations;
    i += step
  ) {
    const flags: Record<string, boolean> = {};
    relevant.forEach((def, idx) => {
      flags[def.name] = Boolean(i & (1 << idx));
    });
    combinations.push({
      id: Object.entries(flags)
        .map(([k, v]) => `${k}=${v ? "on" : "off"}`)
        .join("_"),
      flags,
    });
  }

  return combinations;
}
```

#### Playwright에서 Flag 조합 테스트 실행

```typescript
// e2e/tests/featureFlag.spec.ts
import { test, expect } from "@playwright/test";
import { generateFlagCombinations } from "../utils/featureFlagMatrix";
import { getEnvironment } from "../config/environments";

const flagDefs = [
  { name: "newCheckout", description: "새 결제 플로우", testRelevant: true },
  { name: "darkMode", description: "다크 모드", testRelevant: true },
  {
    name: "recommendations",
    description: "AI 추천",
    testRelevant: true,
  },
  { name: "analytics_v2", description: "분석 v2", testRelevant: false },
];

const combinations = generateFlagCombinations(flagDefs);

for (const combo of combinations) {
  test.describe(`Flag 조합: ${combo.id}`, () => {
    test.beforeEach(async ({ page }) => {
      const env = getEnvironment();
      await page.goto(env.baseUrl);
      await page.evaluate((flags) => {
        Object.entries(flags).forEach(([key, value]) => {
          localStorage.setItem(`ff_${key}`, String(value));
        });
      }, combo.flags);
      await page.reload();
    });

    test("페이지가 에러 없이 렌더링된다", async ({ page }) => {
      const errors: string[] = [];
      page.on("pageerror", (err) => errors.push(err.message));

      await page.goto("/");
      await page.waitForLoadState("networkidle");

      expect(errors).toHaveLength(0);
    });

    test("주요 네비게이션이 동작한다", async ({ page }) => {
      const nav = page.getByRole("navigation");
      await expect(nav).toBeVisible();

      const links = await nav.getByRole("link").all();
      expect(links.length).toBeGreaterThan(0);
    });

    if (combo.flags.newCheckout) {
      test("새 결제 플로우가 활성화되어 있다", async ({ page }) => {
        await page.goto("/checkout");

      });
    }

    if (combo.flags.darkMode) {
      test("다크 모드가 적용되어 있다", async ({ page }) => {
        const html = page.locator("html");
        await expect(html).toHaveAttribute("data-theme", "dark");
      });
    }
  });
}
```

### 1.4 환경별 테스트 데이터 격리

Preview 환경은 목업 데이터, Staging은 실 데이터 미러를 사용한다. 환경별로 데이터 전략을 자동 선택한다.

#### 데이터 프로바이더

```typescript
// e2e/data/dataProvider.ts
interface TestUser {
  email: string;
  password: string;
  name: string;
}

interface TestProduct {
  id: string;
  name: string;
  price: number;
}

export interface TestData {
  users: TestUser[];
  products: TestProduct[];
}

const mockData: TestData = {
  users: [
    { email: "test@mock.local", password: "Test1234!", name: "Mock User" },
    {
      email: "admin@mock.local",
      password: "Admin1234!",
      name: "Mock Admin",
    },
  ],
  products: [
    { id: "mock-1", name: "Mock Product A", price: 10000 },
    { id: "mock-2", name: "Mock Product B", price: 25000 },
  ],
};

async function fetchSeedData(apiUrl: string): Promise<TestData> {
  const [usersRes, productsRes] = await Promise.all([
    fetch(`${apiUrl}/test/seed-users`),
    fetch(`${apiUrl}/test/seed-products`),
  ]);
  return {
    users: await usersRes.json(),
    products: await productsRes.json(),
  };
}

async function fetchProductionMirror(apiUrl: string): Promise<TestData> {
  const [usersRes, productsRes] = await Promise.all([
    fetch(`${apiUrl}/test/mirror-users?anonymized=true`),
    fetch(`${apiUrl}/test/mirror-products?limit=100`),
  ]);
  return {
    users: await usersRes.json(),
    products: await productsRes.json(),
  };
}

export async function getTestData(
  env: { apiUrl: string; dataStrategy: string },
): Promise<TestData> {
  switch (env.dataStrategy) {
    case "mock":
      return mockData;
    case "seed":
      return fetchSeedData(env.apiUrl);
    case "production-mirror":
      return fetchProductionMirror(env.apiUrl);
    default:
      throw new Error(`Unknown data strategy: ${env.dataStrategy}`);
  }
}
```

### 1.6 멀티 베타 성능 테스트 비교

main 브랜치와 PR 브랜치의 성능을 자동 비교하여 성능 회귀를 사전에 탐지한다.

#### 성능 비교 수집기

```typescript
// e2e/performance/collector.ts
import type { Page } from "@playwright/test";

interface PerformanceMetrics {
  lcp: number;
  fid: number;
  cls: number;
  ttfb: number;
  fcp: number;
  domContentLoaded: number;
  bundleSize: number;
}

interface PerformanceComparison {
  metric: string;
  main: number;
  pr: number;
  diffPercent: number;
  status: "improved" | "degraded" | "neutral";
}

export async function collectMetrics(
  page: Page,
): Promise<PerformanceMetrics> {
  await page.waitForLoadState("networkidle");

  const metrics = await page.evaluate(() => {
    const nav = performance.getEntriesByType(
      "navigation",
    )[0] as PerformanceNavigationTiming;
    const paint = performance.getEntriesByType("paint");
    const fcp =
      paint.find((e) => e.name === "first-contentful-paint")?.startTime ?? 0;

    return {
      ttfb: nav.responseStart - nav.requestStart,
      domContentLoaded: nav.domContentLoadedEventEnd - nav.startTime,
      fcp,
      transferSize: nav.transferSize,
    };
  });

  const lcpEntry = await page.evaluate(() => {
    return new Promise<number>((resolve) => {
      new PerformanceObserver((list) => {
        const entries = list.getEntries();
        resolve(entries[entries.length - 1]?.startTime ?? 0);
      }).observe({ type: "largest-contentful-paint", buffered: true });
      setTimeout(() => resolve(0), 5000);
    });
  });

  const clsValue = await page.evaluate(() => {
    return new Promise<number>((resolve) => {
      let cls = 0;
      new PerformanceObserver((list) => {
        for (const entry of list.getEntries()) {
          if (!(entry as any).hadRecentInput) cls += (entry as any).value;
        }
      }).observe({ type: "layout-shift", buffered: true });
      setTimeout(() => resolve(cls), 3000);
    });
  });

  return {
    lcp: lcpEntry,
    fid: 0,
    cls: clsValue,
    ttfb: metrics.ttfb,
    fcp: metrics.fcp,
    domContentLoaded: metrics.domContentLoaded,
    bundleSize: metrics.transferSize,
  };
}

export function compareMetrics(
  mainMetrics: PerformanceMetrics,
  prMetrics: PerformanceMetrics,
  thresholdPercent = 10,
): PerformanceComparison[] {
  const keys = Object.keys(mainMetrics) as (keyof PerformanceMetrics)[];

  return keys.map((key) => {
    const mainVal = mainMetrics[key];
    const prVal = prMetrics[key];
    const diffPercent =
      mainVal === 0 ? 0 : ((prVal - mainVal) / mainVal) * 100;

    let status: PerformanceComparison["status"] = "neutral";
    if (Math.abs(diffPercent) > thresholdPercent) {
      status = diffPercent < 0 ? "improved" : "degraded";
    }

    return { metric: key, main: mainVal, pr: prVal, diffPercent, status };
  });
}
```

```yaml
    if: github.event.deployment_status.state == 'success'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: npm ci
      - run: npx playwright install --with-deps chromium

      - name: Collect PR Metrics
        run: npx playwright test e2e/performance/ --project=chromium
        env:
          BASE_URL: ${{ github.event.deployment_status.target_url }}
          PERF_TARGET: pr

      - name: Collect Main Metrics
        run: npx playwright test e2e/performance/ --project=chromium
        env:
          BASE_URL: https://main.example.com
          PERF_TARGET: main

      - name: Compare & Report
        uses: actions/github-script@v7
        with:
          script: |
            const fs = require('fs');
            const prMetrics = JSON.parse(fs.readFileSync('perf-results/pr.json', 'utf8'));
            const mainMetrics = JSON.parse(fs.readFileSync('perf-results/main.json', 'utf8'));

            let body = '## Performance Comparison\n\n';
            body += '| Metric | Main | PR | Diff | Status |\n';
            body += '|--------|------|-----|------|--------|\n';
            for (const key of Object.keys(mainMetrics)) {
              const diff = ((prMetrics[key] - mainMetrics[key]) / mainMetrics[key] * 100).toFixed(1);
              const status = Math.abs(diff) < 10 ? 'neutral' : (diff < 0 ? 'improved' : 'DEGRADED');
              body += `| ${key} | ${mainMetrics[key]} | ${prMetrics[key]} | ${diff}% | ${status} |\n`;
            }

            github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              body
            });
```

## 2. AI 기반 테스팅 완전 자동화

> AI를 테스팅의 보조가 아닌 **주도적 엔진**으로 활용한다. 테스트 생성, 커버리지 분석, 뮤테이션 탐지, E2E 시나리오 설계, 플레이키 수정까지 5가지 핵심 프롬프트로 전 과정을 AI가 수행하고 사람은 최종 검증만 담당한다.

### 2.1 프롬프트 1: 컴포넌트 테스트 자동 생성

```text
당신은 프론트엔드 테스트 전문가입니다.
아래 컴포넌트의 통합 테스트를 Vitest + @testing-library/react로 작성하세요.

[컴포넌트 코드 붙여넣기]

요구사항:
1. 테스트 구조: describe > context(시나리오) > it(검증) 3단계 중첩
2. 필수 시나리오:
   - 정상 렌더링 (핵심 요소 존재 확인)
   - 사용자 인터랙션 (클릭, 입력 등의 콜백 호출 검증)
   - 로딩/스켈레톤 상태

   - 반응형 레이아웃 변화
3. 쿼리 우선순위: getByRole > getByLabelText > getByTestId
4. Fishery 팩토리로 props 생성 (하드코딩 금지)
5. 각 테스트에 // Arrange / Act / Assert 주석
6. Feature Flag가 있다면 ON/OFF 양쪽 모두 테스트
7. MSW 핸들러가 필요하면 test별 오버라이드 패턴 사용

출력: 바로 실행 가능한 .test.tsx 파일 전체
```

```typescript
import { PactV4, MatchersV3 } from "@pact-foundation/pact";

const provider = new PactV4({

  provider: "order-service",

describe("Order API Contract", () => {
```

### 6.2 AI 테스트 리뷰 (PR 코멘트)

```yaml
# .github/workflows/ai-test-review.yml
name: AI Test Review
on:
  pull_request:
    paths:
      - "src/**"
      - "tests/**"
      - "e2e/**"

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Get Changed Files
        id: changed
        run: |
          echo "files=$(git diff --name-only origin/main...HEAD | grep -E '\.(ts|tsx)$' | tr '\n' ' ')" >> $GITHUB_OUTPUT

      - name: AI Review
        uses: actions/github-script@v7
        with:
          script: |
            const changedFiles = '${{ steps.changed.outputs.files }}'.split(' ').filter(Boolean);
            const srcFiles = changedFiles.filter(f => f.startsWith('src/'));
            const testFiles = changedFiles.filter(f => f.startsWith('tests/') || f.startsWith('e2e/'));

            const untestedSrc = srcFiles.filter(src => {
              const testPath = src
                .replace('src/', 'tests/')
                .replace('.ts', '.test.ts')
                .replace('.tsx', '.test.tsx');
              return !testFiles.includes(testPath) && !changedFiles.includes(testPath);
            });

            if (untestedSrc.length > 0) {
              let body = '## AI Test Review\n\n';
              body += '### 테스트가 누락된 변경 파일\n\n';
              untestedSrc.forEach(f => { body += `- [ ] \`${f}\`\n`; });
              body += '\n> AI 프롬프트 2 (커버리지 갭 분석)를 사용하여 테스트를 생성하세요.';

              github.rest.issues.createComment({
                issue_number: context.issue.number,
                owner: context.repo.owner,
                repo: context.repo.repo,
                body
              });
            }
```
