## 1. AI-First 개발 철학과 멀티 베타 전략

AI는 보조 도구가 아니라 **핵심 인프라**다. 코드의 70% 이상이 AI 협업으로 작성되며, 개발자는 "AI 오케스트레이터"로서 설계 의도를 전달하고 품질을 검증한다. 여기에 **멀티 베타 환경**을 결합하면 PR마다 독립 Preview가 생성되어 AI 리뷰와 배포 검증이 자동화된다.

### 핵심 원칙

| 원칙 | 설명 |
|------|------|
| **AI First** | 모든 작업의 시작점은 AI 도구. 직접 코딩 전에 AI에게 먼저 물어본다 |
| **검증 중심** | AI 생성 코드는 반드시 인간이 검증. 신뢰하되 확인한다 |
| **컨텍스트 최적화** | AI 품질은 컨텍스트 품질에 비례. 프로젝트 메타데이터를 체계적으로 관리 |
| **도구 조합** | 단일 AI에 의존하지 않고 각 도구의 강점을 조합 |
| **멀티 베타 통합** | PR마다 Preview 환경이 생성되고 AI가 해당 환경에서 자동 검증 수행 |
| **비용 인식** | AI 사용량을 추적하고 ROI를 측정 |

### AI 도구 포지셔닝 맵

| 도구 | 주요 용도 | 강점 | 월 비용 (팀) |
|------|-----------|------|-------------|
| **Claude Code** | 설계, 리팩토링, 디버깅, 멀티 에이전트 | 긴 컨텍스트, 깊은 추론, 스킬 시스템 | $20~$100 |
| **GitHub Copilot** | 인라인 완성, 테스트, Agent | IDE 통합, Workspace Agent | $10~$39 |
| **Cursor** | 멀티파일 편집, Composer | 자연어 편집, .cursorrules | $20~$40 |
| **CodeRabbit** | PR 리뷰 자동화, 보안 검사 | path_instructions, Preview URL 통합 | $15~$30 |

## 2. Claude Code 완벽 활용

### 2.1 CLAUDE.md 작성법

`CLAUDE.md`는 Claude Code가 프로젝트를 이해하는 핵심 컨텍스트 파일이다. 프로젝트 루트에 위치하며 세션 시작 시 자동으로 읽힌다.

```markdown
<!-- CLAUDE.md -->
# 프로젝트 컨텍스트

## 기술 스택
- Runtime: Node.js 22, TypeScript 5.7 strict
- Framework: React 19 + Next.js 15 (App Router)
- 상태관리: Zustand 5 + TanStack Query v5
- 스타일: Tailwind CSS 4 + CVA
- 테스트: Vitest 3 + Playwright 1.50
- 빌드: Turbopack (Next.js), pnpm 9

## 아키텍처 원칙
- Feature-Sliced Design (shared/entities/features/widgets/pages)
- Server Components 우선, Client Components는 최소화
- API 계층은 반드시 /src/shared/api/ 아래 위치
- 에러 바운더리로 모든 페이지 감싸기

## 코딩 규칙
- 함수형 컴포넌트만 사용, class 컴포넌트 금지
- named export만 사용 (default export 금지)
- 모든 함수에 JSDoc 또는 TSDoc 작성
- 매직 넘버 금지, 상수 파일로 분리
- any 타입 사용 금지, unknown + type guard 사용

## 멀티 베타 환경
- Preview URL 패턴: https://preview-{branch}.example.com
- Feature Flag: LaunchDarkly SDK 사용
- 환경 변수: NEXT_PUBLIC_DEPLOY_ENV (production|preview|development)

## 금지 사항
- console.log 커밋 금지 (logger 유틸 사용)
- 직접 DOM 조작 금지 (ref 제외)
- index.ts에 비즈니스 로직 금지
```

### 2.3 멀티 에이전트 워크플로우

Claude Code는 `--agent` 플래그나 스킬 시스템으로 멀티 에이전트 패턴을 구현할 수 있다.

```typescript
// claude-agents.config.ts
// Claude Code 멀티 에이전트 오케스트레이션 설정

interface AgentTask {
  name: string;
  prompt: string;
  dependsOn?: string[];
  timeout?: number;
}

const agentPipeline: AgentTask[] = [
  {
    name: 'architect',
    prompt: `
      요구사항을 분석하고 기술 설계서를 작성해라.
      포함: 컴포넌트 구조, 데이터 흐름, API 설계, 에러 시나리오.
      출력 형식: JSON Schema
    `,
  },
  {
    name: 'implementer',
    prompt: `
      architect의 설계서를 기반으로 구현 코드를 작성해라.
      CLAUDE.md의 코딩 규칙을 반드시 따를 것.
      파일별로 구분하여 출력.
    `,
    dependsOn: ['architect'],
  },
  {
    name: 'tester',
    prompt: `
      implementer의 코드에 대한 테스트를 작성해라.
      커버리지 목표: 라인 90%, 브랜치 85%.
      에러/에지 케이스 포함.
    `,
    dependsOn: ['implementer'],
  },
  {
    name: 'reviewer',
    prompt: `
      implementer의 코드와 tester의 테스트를 리뷰해라.
      SOLID, 성능, 보안, 접근성 관점에서 평가.
      개선점이 있으면 수정 코드까지 제시.
    `,
    dependsOn: ['implementer', 'tester'],
  },
];
```

### 6.2 AI 기반 배포 위험도 분석

```typescript
// scripts/ai-deploy-risk-analysis.ts
import { execSync } from 'node:child_process';

interface RiskAssessment {
  level: 'low' | 'medium' | 'high' | 'critical';
  score: number;
  factors: RiskFactor[];
  recommendation: string;
}

interface RiskFactor {
  category: string;
  description: string;
  weight: number;
}

function analyzeDeployRisk(baseBranch: string = 'main'): RiskAssessment {
  const diff = execSync(`git diff ${baseBranch}...HEAD --stat`).toString();
  const diffFiles = execSync(`git diff ${baseBranch}...HEAD --name-only`).toString().split('\n').filter(Boolean);

  const factors: RiskFactor[] = [];

  // 1. 변경 규모 분석
  const fileCount = diffFiles.length;
  if (fileCount > 50) {
    factors.push({ category: '규모', description: `${fileCount}개 파일 변경 (대규모)`, weight: 3 });
  } else if (fileCount > 20) {
    factors.push({ category: '규모', description: `${fileCount}개 파일 변경 (중규모)`, weight: 2 });
  }

  // 2. 핵심 파일 변경 감지
  const criticalPaths = [
    { pattern: /\.env/, label: '환경변수' },
    { pattern: /middleware\.ts/, label: '미들웨어' },
    { pattern: /next\.config/, label: 'Next.js 설정' },
    { pattern: /package\.json/, label: '의존성' },
    { pattern: /prisma\/.*\.prisma/, label: 'DB 스키마' },
    { pattern: /src\/shared\/api/, label: 'API 계층' },
  ];

  for (const { pattern, label } of criticalPaths) {
    if (diffFiles.some((f) => pattern.test(f))) {
      factors.push({ category: '핵심 파일', description: `${label} 변경 감지`, weight: 3 });
    }
  }

  // 3. 마이그레이션 파일 확인
  if (diffFiles.some((f) => f.includes('migration'))) {
    factors.push({ category: 'DB', description: '마이그레이션 파일 포함', weight: 4 });
  }

  // 4. 테스트 커버리지 확인
  const testFiles = diffFiles.filter((f) => f.includes('.test.'));
  const srcFiles = diffFiles.filter((f) => f.startsWith('src/') && !f.includes('.test.'));
  if (srcFiles.length > 0 && testFiles.length === 0) {
    factors.push({ category: '테스트', description: '소스 변경에 대한 테스트 없음', weight: 2 });
  }

  // 점수 계산
  const score = factors.reduce((sum, f) => sum + f.weight, 0);
  const level = score >= 10 ? 'critical' : score >= 6 ? 'high' : score >= 3 ? 'medium' : 'low';

  const recommendations: Record<string, string> = {
    low: '자동 배포 가능. Preview 환경에서 기본 스모크 테스트 권장.',
    medium: 'Preview 환경에서 수동 검증 후 배포. 변경 영역별 확인 필요.',
    high: '팀 리뷰 필수. Preview 환경에서 전체 회귀 테스트 수행.',
    critical: '배포 동결 검토. 아키텍트 승인 + 단계적 롤아웃(Canary) 필수.',
  };

  return { level, score, factors, recommendation: recommendations[level] };
}
```

```typescript
interface FeatureFlagOptions {
  /** Preview 환경에서 강제 활성화 */
  enableInPreview?: boolean;
  /** Preview 환경에서 강제 비활성화 */
  disableInPreview?: boolean;

export function useFeatureFlag(
  flagKey: string,
  defaultValue: boolean = false,
  options: FeatureFlagOptions = {}
): boolean {
  const flags = useFlags();

  // Preview 환경 오버라이드

    if (options.disableInPreview) return false;

export function useFeatureFlagDebug(): {
  flags: Record<string, boolean>;
  toggle: (key: string) => void;

  const flags = useFlags();
  const client = useLDClient();

  const toggle = (key: string): void => {

      key: 'debug-user',
      custom: { [key]: !(flags[key] as boolean) },
    });
  };

}
```

```typescript
// src/shared/lib/monitoring.ts
// AI 기반 이상 탐지 연동

import * as Sentry from '@sentry/nextjs';
import { envConfig } from '@/shared/config/environment';

interface MonitoringEvent {
  type: 'error' | 'performance' | 'business';
  name: string;
  metadata: Record<string, unknown>;
}

export function trackEvent(event: MonitoringEvent): void {
  // Preview 환경에서는 콘솔 출력만
  if (envConfig.deployEnv === 'preview') {
    console.log('[Preview Monitor]', event);
    return;
  }

  // Development 환경에서는 무시
  if (envConfig.deployEnv === 'development') return;

  // Production: Sentry + 커스텀 메트릭
  if (event.type === 'error') {
    Sentry.captureException(new Error(event.name), {
      tags: { eventType: event.type },
      extra: event.metadata,
    });
  }

  if (event.type === 'performance') {
    Sentry.metrics.distribution(event.name, event.metadata.value as number, {
      unit: (event.metadata.unit as string) ?? 'millisecond',
    });
  }
}

// Web Vitals 자동 수집
export function reportWebVitals(metric: { name: string; value: number; id: string }): void {
  trackEvent({
    type: 'performance',
    name: `web_vital_${metric.name}`,
    metadata: { value: metric.value, id: metric.id },
  });
}
```

## 8. 프롬프트 엔지니어링 for 개발자

### 8.1 효과적인 프롬프트 구조

```
[역할] + [컨텍스트] + [구체적 요구사항] + [제약 조건] + [출력 형식]
```

| 요소 | 설명 | 예시 |
|------|------|------|
| **역할** | AI의 전문성 범위 설정 | "시니어 TypeScript 개발자로서" |
| **컨텍스트** | 프로젝트/상황 정보 | "Next.js 15 App Router 프로젝트에서" |
| **구체적 요구사항** | 무엇을 해야 하는지 | "이 API 응답 타입을 Zod 스키마로 변환해줘" |
| **제약 조건** | 지켜야 할 규칙 | "any 타입 금지, strict mode" |
| **출력 형식** | 결과물 형태 | "파일별로 분리해서 코드 블록으로" |

### 8.2 체인 프롬프트 (단계적 접근)

```
# Step 1: 분석
"이 코드베이스의 의존성 그래프를 분석해줘. 순환 참조가 있는지 확인."

# Step 2: 계획 (Step 1 결과 기반)
"순환 참조를 해결하기 위한 리팩토링 계획을 세워줘. 단계별로."

# Step 3: 실행 (Step 2 계획 기반)
"계획의 1단계를 실행해줘. 변경되는 파일과 코드를 보여줘."

# Step 4: 검증 (Step 3 결과 기반)
"변경 후 기존 테스트가 모두 통과하는지 확인해줘."
```

### 8.3 Anti-Pattern 피하기

| Anti-Pattern | 문제 | 개선 |
|-------------|------|------|
| "코드 짜줘" | 컨텍스트 부족 → 제네릭한 결과 | 구체적 요구사항 + 제약 조건 명시 |
| 너무 긴 프롬프트 | 핵심 요구사항 희석 | 단계별 체인 프롬프트 분리 |
| 결과 검증 안 함 | AI 환각(hallucination) 미발견 | 항상 타입 체크 + 테스트 실행 |
| 하나의 도구만 사용 | 도구별 강점 미활용 | Claude(설계) → Copilot(구현) → CodeRabbit(리뷰) |
| 프롬프트 재사용 안 함 | 매번 처음부터 작성 | 프롬프트 라이브러리 구축 |

## 9. AI 도구 비용 최적화

### 9.1 비용 추적 대시보드

```typescript
// src/shared/lib/ai-cost-tracker.ts

interface AIUsageRecord {
  tool: 'claude' | 'copilot' | 'cursor' | 'coderabbit';
  action: string;
  tokensUsed: number;
  estimatedCost: number;
  timestamp: Date;
  developer: string;
}

interface MonthlySummary {
  totalCost: number;
  byTool: Record<string, number>;
  byDeveloper: Record<string, number>;
  topActions: Array<{ action: string; count: number; totalCost: number }>;
  recommendations: string[];
}

function generateRecommendations(records: AIUsageRecord[]): string[] {
  const recommendations: string[] = [];

  // 1. 반복 프롬프트 감지 → 스킬/스니펫화 추천
  const actionCounts = new Map<string, number>();
  for (const r of records) {
    actionCounts.set(r.action, (actionCounts.get(r.action) ?? 0) + 1);
  }
  for (const [action, count] of actionCounts) {
    if (count > 10) {
      recommendations.push(`"${action}" 작업이 ${count}회 반복됨 → CLAUDE.md 스킬 또는 Copilot 스니펫으로 자동화 권장`);
    }
  }

  // 2. 고비용 작업 식별
  const highCostActions = records
    .filter((r) => r.estimatedCost > 1)
    .map((r) => r.action);
  if (highCostActions.length > 0) {
    recommendations.push(`고비용 작업 감지: ${[...new Set(highCostActions)].join(', ')} → 컨텍스트 축소 또는 캐싱 검토`);
  }

  // 3. 도구 선택 최적화
  const claudeSimpleActions = records.filter(
    (r) => r.tool === 'claude' && r.tokensUsed < 500 && r.action.includes('완성')
  );
  if (claudeSimpleActions.length > 5) {
    recommendations.push('단순 코드 완성에 Claude 사용 감지 → Copilot 인라인 완성으로 대체 권장 (비용 90% 절감)');
  }

  return recommendations;
}
```

| 전략 | 설명 | 절감 효과 |

| **도구 선택 최적화** | 단순 작업은 Copilot, 복잡 작업은 Claude | ~40% 비용 절감 |
| **프롬프트 캐싱** | 자주 쓰는 프롬프트를 스킬/스니펫으로 | ~20% 시간 절감 |

| **Preview 환경 활용** | AI 리뷰와 수동 검증 병행 → 재작업 감소 | ~50% 반복 비용 절감 |
